# Moving or copying virtual environments

## 1. Catalog record

- **Catalog identifier:** 10.4.1
- **Impact:** medium
- **Consensus:** high
- **Definition:** Recreate virtual environments at their destination rather than treating an existing environment directory as portable.

## 2. Example

### 2.1 Scenario

A project is moved from one workstation path to another and needs its development environment restored.

### 2.2 Preferred form

```python
# Run these shell commands from the destination project directory:
# python -m venv .venv
# .venv/bin/python -m pip install -r requirements.txt

project_environment = ".venv"
print(f"Recreated {project_environment}")
```

### 2.3 Hazardous form

```python
# Run this shell command after moving the project directory:
# cp -R /old/path/project/.venv /new/path/project/.venv

project_environment = "/new/path/project/.venv"
print(f"Copied {project_environment}")
```

### 2.4 Why this difference matters

Virtual-environment scripts commonly embed absolute interpreter paths, so copying the directory can leave entry points referring to the old location.

## 3. Boundaries and distinctions

An environment can be cached or rebuilt from pinned inputs for speed, but the destination should still create a valid environment for its own interpreter and path.
