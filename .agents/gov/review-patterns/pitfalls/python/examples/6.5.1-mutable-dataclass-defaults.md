# Mutable dataclass defaults

## 1. Catalog record

- **Catalog identifier:** 6.5.1
- **Impact:** medium
- **Consensus:** high
- **Definition:** For per-instance mutable dataclass fields, use `field(default_factory=list)` or another factory rather than a shared mutable default.

## 2. Example

### 2.1 Scenario

Each task record needs an independent list of notes.

### 2.2 Preferred form

```python
from dataclasses import dataclass, field


@dataclass
class Task:
    notes: list[str] = field(default_factory=list)


first = Task()
second = Task()
first.notes.append("reviewed")
assert second.notes == []
```

### 2.3 Hazardous form

```python
from dataclasses import dataclass, field


shared_notes: list[str] = []


@dataclass
class Task:
    notes: list[str] = field(default_factory=lambda: shared_notes)


first = Task()
second = Task()
first.notes.append("reviewed")
assert second.notes == ["reviewed"]
```

### 2.4 Why this difference matters

Sharing one mutable list across instances makes edits leak between records. `default_factory` calls the factory for each new instance.

## 3. Boundaries and distinctions

Modern dataclasses reject many direct unhashable mutable defaults, but a shared object can still be passed explicitly or hidden behind other constructions.
