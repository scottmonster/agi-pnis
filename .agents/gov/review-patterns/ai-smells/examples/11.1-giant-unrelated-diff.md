# Giant unrelated diff

## 1. Catalog record

- **Catalog identifier:** 11.1
- **Evidence:** a/se
- **Definition:** Changes far more files or behavior than the request requires, making correctness and review harder.

## 2. Scenario

### 2.1 Context

A request asks to correct the message shown when a user uploads an unsupported image format.

### 2.2 Safer approach

The agent updates the validation message and its focused test, then reviews the diff to ensure only those files changed.

### 2.3 Failure mode

Alongside the message fix, the agent reformats the upload package, replaces its logger, and rewrites several unrelated helpers.

### 2.4 Why this difference matters

Reviewers cannot easily establish whether the requested fix is correct, and unrelated changes raise regression and merge-conflict risk.

## 3. Boundaries and distinctions

An adjacent change belongs in the patch when it is necessary for the requested behavior; this failure is about unrelated scope, not file count alone.
