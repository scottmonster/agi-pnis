# Failing to ask a clarification when ambiguity materially changes the implementation

## 1. Catalog record

- **Catalog identifier:** 13.12
- **Evidence:** a
- **Definition:** Guesses among consequential interpretations when repository evidence cannot safely resolve them.

## 2. Scenario

### 2.1 Context

A request says to archive inactive users, but neither the issue nor repository defines whether archived users may still sign in.

### 2.2 Safer approach

The agent investigates existing status semantics, finds no decisive policy, and asks whether archiving should block authentication before changing account flow.

### 2.3 Failure mode

The agent assumes archiving deletes login access and changes authentication, notifications, and retention behavior without confirmation.

### 2.4 Why this difference matters

The choice affects product policy and data access, so a guess can create a costly incompatible implementation.

## 3. Boundaries and distinctions

Clarification is unnecessary when repository evidence safely resolves the ambiguity. It matters when plausible choices have materially different outcomes.
