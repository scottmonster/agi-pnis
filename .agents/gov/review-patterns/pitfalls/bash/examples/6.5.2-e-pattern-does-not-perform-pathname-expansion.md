# `[[ -e pattern* ]]` does not perform pathname expansion

## 1. Catalog record

- **Catalog identifier:** 6.5.2
- **Impact:** medium
- **Consensus:** high
- **Definition:** Do not expect a glob supplied as a file operand inside `[[ ]]` to enumerate matching files. Expand the pattern in a context where filename expansion actually occurs, then test the resulting paths.

## 2. Example

### 2.1 Scenario

A deployment check detects `.ready` marker files.

### 2.2 Preferred form

```bash
#!/usr/bin/env bash
markers=("$1"/*.ready)
if ((${#markers[@]} != 1)) || [[ -e ${markers[0]} ]]; then echo 'ready'; fi
```

### 2.3 Hazardous form

```bash
#!/usr/bin/env bash
if [[ -e "$1"/*.ready ]]; then echo 'ready'; fi
```

### 2.4 Why this difference matters

The `[[ ]]` operand tests a literal pathname containing `*`, rather than expanding marker names.

## 3. Boundaries and distinctions

`[[ ]]` does pattern matching on the right side of `==`; the distinction here is a pathname operand passed to `-e`.
