# Zero-argument `super()` inside nested functions

## 1. Catalog record

- **Catalog identifier:** 16.15.1
- **Impact:** low
- **Consensus:** high
- **Definition:** Do not expect zero-argument `super()` to infer the intended method arguments inside a nested function or generator expression. Use an explicit form or restructure the call.

## 2. Example

### 2.1 Scenario

A derived formatter uses a small nested helper to add a prefix to its parent class's formatting result.

### 2.2 Preferred form

```python
class Formatter:
    def format(self, value: str) -> str:
        return value.upper()


class PrefixedFormatter(Formatter):
    def format(self, value: str) -> str:
        def add_prefix(text: str) -> str:
            return f"result: {text}"

        return add_prefix(super().format(value))


print(PrefixedFormatter().format("ready"))
```

### 2.3 Hazardous form

```python
class Formatter:
    def format(self, value: str) -> str:
        return value.upper()


class PrefixedFormatter(Formatter):
    def format(self, value: str) -> str:
        def parent_value() -> str:
            return super().format(value)

        return f"result: {parent_value()}"


print(PrefixedFormatter().format("ready"))
```

### 2.4 Why this difference matters

Zero-argument `super()` depends on context supplied for the immediately enclosing method. Inside the nested helper it cannot infer the intended instance and raises at runtime.

## 3. Boundaries and distinctions

Zero-argument `super()` is the normal choice directly inside a method. A nested helper can use an explicit `super(PrefixedFormatter, self)` form, although restructuring is often clearer.
