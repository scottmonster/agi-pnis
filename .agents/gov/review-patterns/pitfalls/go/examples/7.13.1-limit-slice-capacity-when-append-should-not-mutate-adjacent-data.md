# Limit slice capacity when append should not mutate adjacent data

## 1. Catalog record

- **Catalog identifier:** 7.13.1
- **Impact:** medium
- **Consensus:** high
- **Definition:** When passing a sub-slice whose caller must not overwrite following elements by appending, copy it or restrict capacity with a full slice expression such as `s[:len(s):len(s)]` or `slices.Clip`.

## 2. Example

### 2.1 Scenario

A parser passes a header segment to a helper that is allowed to append an annotation.

### 2.2 Preferred form

```go
package parser

func annotate(header []string) []string {
	return append(header, "checked")
}

func safeHeader(parts []string) []string {
	header := parts[:1:1]
	return annotate(header)
}
```

### 2.3 Hazardous form

```go
package parser

func annotate(header []string) []string { return append(header, "checked") }

func unsafeHeader(parts []string) []string {
	return annotate(parts[:1]) // Can overwrite parts[1].
}
```

### 2.4 Why this difference matters

An append within spare capacity reuses the original backing array and can corrupt adjacent data.

## 3. Boundaries and distinctions

No capacity restriction is needed if the callee must intentionally share and extend the same backing array.
