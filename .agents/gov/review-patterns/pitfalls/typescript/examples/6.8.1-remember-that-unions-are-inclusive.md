# Remember that unions are inclusive

## 1. Catalog record

- **Catalog identifier:** 6.8.1
- **Impact:** medium
- **Consensus:** high
- **Definition:** `A | B` allows a value satisfying both `A` and `B`; use a discriminant or an explicit XOR construction when mutual exclusivity is required.

## 2. Example

### 2.1 Scenario

A notification request must choose exactly one delivery channel.

### 2.2 Preferred form

```typescript
type Notification =
  | { channel: 'email'; email: string }
  | { channel: 'sms'; phone: string };

function destination(notification: Notification): string {
  return notification.channel === 'email'
    ? notification.email
    : notification.phone;
}

console.log(destination({ channel: 'email', email: 'ada@example.test' }));
```

### 2.3 Hazardous form

```typescript
type EmailNotification = { email: string };
type SmsNotification = { phone: string };

const notification: EmailNotification | SmsNotification = {
  email: 'ada@example.test',
  phone: '+15551234567',
};
// This value satisfies both sides, despite violating the one-channel rule.
```

### 2.4 Why this difference matters

Structural typing can otherwise admit semantically invalid combinations that happen to satisfy both sides.

## 3. Boundaries and distinctions

Apply this guidance in the conditions described by the catalog record. Deliberate exceptions need a documented runtime guarantee, compatible toolchain behavior, or an explicit local unsafe boundary.
