# Non-prompted behavior

## 1. Catalog record

- **Catalog identifier:** 1.4
- **Evidence:** e
- **Definition:** Adds behavior, validation, transformation, fallback logic, or policy the user never requested.

## 2. Scenario

### 2.1 Context

A maintainer asks to expose an existing profile display-name field in an API response. Clients already accept the stored value unchanged.

### 2.2 Safer approach

Add the existing field to the response serializer and verify the contract with the established API test style.

### 2.3 Failure mode

The agent also trims, title-cases, and rejects display names containing punctuation without any request or product policy.

### 2.4 Why this difference matters

The unrelated policy changes stored values and can break clients or invalidate names users were already allowed to use.

## 3. Boundaries and distinctions

Necessary validation required by an established schema or security boundary is not non-prompted behavior. The failure is inventing a new behavior without a requirement or repository basis.
