# Remember that sourcing mutates the current shell

## 1. Catalog record

- **Catalog identifier:** 9.4.1
- **Impact:** medium
- **Consensus:** high
- **Definition:** `source` executes code in the current shell, so isolate sourced code when its state changes must not persist.

## 2. Example

### 2.1 Scenario

A script reads a vendor environment helper but must retain its own working directory and shell options.

### 2.2 Preferred form

```bash
#!/usr/bin/env bash
set -euo pipefail

workspace=$(pwd -P)
(
  source "./vendor-environment.sh"
  run_vendor_tool
)
printf 'still in %s\n' "$workspace"
```

### 2.3 Hazardous form

```bash
#!/usr/bin/env bash
set -euo pipefail

source "./vendor-environment.sh"
run_vendor_tool
printf 'still in %s\n' "$(pwd -P)"
```

### 2.4 Why this difference matters

A sourced helper can change variables, the directory, options, and traps in the caller, affecting commands that run later.

## 3. Boundaries and distinctions

Source directly when the helper is intentionally designed to configure the current shell, such as an activation script.
