# Executor tasks waiting on the same exhausted executor

## 1. Catalog record

- **Catalog identifier:** 3.8.1
- **Impact:** high
- **Consensus:** high
- **Definition:** Do not have work running in a bounded executor synchronously wait for other work that can only run in that same exhausted executor.

## 2. Example

### 2.1 Scenario

A service uses a one-worker thread pool to calculate a total. The calculation should compose work without waiting on work that cannot begin.

### 2.2 Preferred form

```python
from concurrent.futures import ThreadPoolExecutor


def double(value: int) -> int:
    return value * 2


with ThreadPoolExecutor(max_workers=1) as executor:
    result = executor.submit(double, 21).result()
    print(result)
```

### 2.3 Hazardous form

```python
from concurrent.futures import ThreadPoolExecutor


def parent(executor: ThreadPoolExecutor) -> int:
    child = executor.submit(lambda: 21)
    return child.result()


with ThreadPoolExecutor(max_workers=1) as executor:
    print(executor.submit(parent, executor).result())
```

### 2.4 Why this difference matters

The only worker runs `parent` and waits for `child`, but no worker remains to run `child`. The executor deadlocks.

## 3. Boundaries and distinctions

Waiting can be safe when capacity is guaranteed or work runs in a different executor. Prefer designs that return work to an orchestrator instead of nesting synchronous waits.
