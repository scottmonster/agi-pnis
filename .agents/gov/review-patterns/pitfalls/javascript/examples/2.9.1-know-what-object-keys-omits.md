# Know what Object.keys omits

## 1. Catalog record

- **Catalog identifier:** 2.9.1
- **Impact:** medium
- **Consensus:** high
- **Definition:** Use an enumeration API that includes the key kinds and property attributes your reflection requires.

## 2. Example

### 2.1 Scenario

A serializer needs to inspect every own property, including non-enumerable and symbol keys.

### 2.2 Preferred form

```javascript
const token = Symbol("token");
const record = { visible: true, [token]: "secret" };
Object.defineProperty(record, "internal", { value: 1 });

console.log(Reflect.ownKeys(record));
```

### 2.3 Hazardous form

```javascript
const token = Symbol("token");
const record = { visible: true, [token]: "secret" };
Object.defineProperty(record, "internal", { value: 1 });

console.log(Object.keys(record));
```

### 2.4 Why this difference matters

`Object.keys()` returns only enumerable own string keys, omitting both `internal` and the symbol property.

## 3. Boundaries and distinctions

`Object.keys()` is the right concise choice when enumerable own string keys are exactly what the operation needs.
