# Quote the right side of `[[ = ]]` for literal equality

## 1. Catalog record

- **Catalog identifier:** 4.8.1
- **Impact:** medium
- **Consensus:** high
- **Definition:** Quote the right side of `[[ = ]]` when comparison data must be literal rather than a pattern.

## 2. Example

### 2.1 Scenario

A release tool must accept only the literal branch name `release-*`, including its asterisk.

### 2.2 Preferred form

```bash
#!/usr/bin/env bash

branch=${1:?provide a branch}
expected='release-*'
if [[ $branch = "$expected" ]]; then
  printf 'literal branch name accepted\n'
fi
```

### 2.3 Hazardous form

```bash
#!/usr/bin/env bash

branch=${1:?provide a branch}
expected='release-*'
if [[ $branch = $expected ]]; then
  printf 'branch accepted\n'
fi
```

### 2.4 Why this difference matters

An unquoted right-hand operand of `=` is a pattern. The hazardous condition accepts names such as `release-2026` even though the policy requires the literal asterisk.

## 3. Boundaries and distinctions

Leave the right side unquoted only when pattern matching is intentional. Quote it when the value is data that must compare literally.
