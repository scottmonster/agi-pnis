# Use subshell grouping when temporary state should not escape

## 1. Catalog record

- **Catalog identifier:** 8.9.1
- **Impact:** medium
- **Consensus:** high
- **Definition:** `( commands )` runs in a subshell environment, whereas `{ commands; }` normally runs in the current shell; use a subshell when directory or variable changes should be temporary.

## 2. Example

### 2.1 Scenario

A build script runs a command in a project directory but must retain its caller's working directory.

### 2.2 Preferred form

```bash
project_dir=./project
(
  cd "$project_dir" || exit 1
  printf 'building in %s\n' "$PWD"
)
printf 'caller remains in %s\n' "$PWD"
```

### 2.3 Hazardous form

```bash
project_dir=./project
{
  cd "$project_dir" || exit 1
  printf 'building in %s\n' "$PWD"
}
printf 'caller remains in %s\n' "$PWD"
```

### 2.4 Why this difference matters

Brace grouping changes the current shell, so later commands run in the project directory. A subshell contains the directory change and restores the caller state automatically.

## 3. Boundaries and distinctions

Use braces when state changes are intentionally needed by following commands. A subshell cannot return changed shell variables or a directory to its parent.
