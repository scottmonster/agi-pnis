# Account for `BASH_ENV` in non-interactive execution

## 1. Catalog record

- **Catalog identifier:** 3.10.1
- **Impact:** high
- **Consensus:** high
- **Definition:** Treat `BASH_ENV` as startup code for non-interactive Bash when the environment may be hostile.

## 2. Example

### 2.1 Scenario

A CI runner executes a security-sensitive Bash script with environment variables inherited from an external job.

### 2.2 Preferred form

```bash
env -u BASH_ENV bash ./deploy.sh
```

### 2.3 Hazardous form

```bash
BASH_ENV='/tmp/runner-startup.sh' bash ./deploy.sh
```

### 2.4 Why this difference matters

For non-interactive Bash, `BASH_ENV` can cause another file to be sourced before the script's first command, so the script cannot repair effects that already occurred.

## 3. Boundaries and distinctions

This matters for Bash non-interactive execution when the environment is not trusted; interactive startup files use different variables and rules.
