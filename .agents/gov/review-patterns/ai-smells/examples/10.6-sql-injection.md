# SQL injection

## 1. Catalog record

- **Catalog identifier:** 10.6
- **Evidence:** e
- **Definition:** Concatenates untrusted input into a database query so it can alter the query’s meaning or data access.

## 2. Scenario

### 2.1 Context

An admin search page filters customers by an email fragment.

### 2.2 Safer approach

Use the database driver’s parameter binding for the fragment and allowlist any dynamic identifiers separately.

### 2.3 Failure mode

The agent builds the SQL text by inserting the query parameter directly into a `WHERE` clause.

### 2.4 Why this difference matters

Input can change query structure rather than remaining data, exposing or changing records outside the intended search.

## 3. Boundaries and distinctions

Parameterized values protect values, not arbitrary table or column names. Dynamic identifiers need a constrained design or an allowlist.
