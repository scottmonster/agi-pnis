# Quote literal variables inside parameter-removal patterns

## 1. Catalog record

- **Catalog identifier:** 5.8.1
- **Impact:** medium
- **Consensus:** high
- **Definition:** In expressions such as `${value%$suffix}`, the suffix expansion participates as a pattern. Use the appropriate inner quoting, such as `${value%"$suffix"}`, when the expanded text should be treated literally.

## 2. Example

### 2.1 Scenario

A packaging script removes an exact user-provided suffix from an artifact label that can itself contain glob characters.

### 2.2 Preferred form

```bash
label='release-v1.2*backup'
suffix='*backup'

base=${label%"$suffix"}
printf '%s\n' "$base"
```

### 2.3 Hazardous form

```bash
label='release-v1.2*backup'
suffix='*backup'

base=${label%$suffix}
printf '%s\n' "$base"
```

### 2.4 Why this difference matters

The unquoted suffix is a shell pattern, so `*backup` removes the longest matching suffix rather than the literal characters `*backup`. Quoting the inner expansion preserves the intended literal boundary.

## 3. Boundaries and distinctions

Leave the expansion unquoted when the variable intentionally contains a pattern. This rule applies when data is meant to be literal prefix or suffix text.
