# Incorrect input parsing

## 1. Catalog record

- **Catalog identifier:** 6.10
- **Evidence:** e
- **Definition:** Assumes the wrong delimiter, encoding, shape, order, or representation.

## 2. Scenario

### 2.1 Context

An import job receives a CSV file whose fields can contain quoted commas.

### 2.2 Safer approach

The agent uses the repository's CSV parser and verifies its handling of quoted fields.

### 2.3 Failure mode

It parses each line with `line.split(",")`.

### 2.4 Why this difference matters

Valid names or addresses containing commas shift columns and corrupt imported records.

## 3. Boundaries and distinctions

This is a wrong assumption about representation; validation may still be needed after correct parsing.
