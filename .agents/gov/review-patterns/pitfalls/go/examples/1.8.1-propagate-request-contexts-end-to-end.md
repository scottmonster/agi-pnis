# Propagate request contexts end to end

## 1. Catalog record

- **Catalog identifier:** 1.8.1
- **Impact:** high
- **Consensus:** high
- **Definition:** Pass the incoming context through database, RPC, HTTP, and other request-scoped calls. Do not replace it with `context.Background()` in the middle of the call chain.

## 2. Example

### 2.1 Scenario

An HTTP handler calls a backend while the client may disconnect or time out.

### 2.2 Preferred form

```go
package main

import (
	"context"
	"net/http"
)

func lookup(ctx context.Context, client *http.Client, req *http.Request) (*http.Response, error) {
	return client.Do(req.WithContext(ctx))
}
```

### 2.3 Hazardous form

```go
package main

import (
	"context"
	"net/http"
)

func lookup(_ context.Context, client *http.Client, req *http.Request) (*http.Response, error) {
	return client.Do(req.WithContext(context.Background()))
}
```

### 2.4 Why this difference matters

Replacing the request context discards cancellation, deadlines, and request-scoped values. The backend call can continue after the caller is gone.

## 3. Boundaries and distinctions

Use `context.Background` only to create a new independent root operation, such as a deliberately detached maintenance job. Do not store contexts in long-lived structs.
