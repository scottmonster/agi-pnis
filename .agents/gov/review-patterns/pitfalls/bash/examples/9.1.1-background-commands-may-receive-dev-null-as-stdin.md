# Background commands may receive `/dev/null` as stdin

## 1. Catalog record

- **Catalog identifier:** 9.1.1
- **Impact:** medium
- **Consensus:** high
- **Definition:** Background commands without explicit input can receive standard input from `/dev/null` when job control is inactive.

## 2. Example

### 2.1 Scenario

A deployment script starts a background worker that must read a one-line token from a file.

### 2.2 Preferred form

```bash
#!/usr/bin/env bash
set -euo pipefail

token_file="/run/deploy/token"
process_token() {
  local token
  IFS= read -r token
  printf 'processing token: %s\n' "$token"
}

process_token < "$token_file" &
worker_pid=$!
wait "$worker_pid"
```

### 2.3 Hazardous form

```bash
#!/usr/bin/env bash
set -euo pipefail

process_token() {
  local token
  IFS= read -r token
  printf 'processing token: %s\n' "$token"
}

process_token &
wait "$!"
```

### 2.4 Why this difference matters

Without an explicit redirection, a non-interactive background job can read immediate EOF from `/dev/null` instead of the intended input.

## 3. Boundaries and distinctions

Explicit input is unnecessary for a background command that does not read standard input or deliberately expects EOF.
