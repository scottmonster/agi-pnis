# Over-generalized types/generics

## 1. Catalog record

- **Catalog identifier:** 3.31
- **Evidence:** se
- **Definition:** Type parameters and extensible schemas support possibilities no caller needs.

## 2. Scenario

### 2.1 Context

A function returns a list of `Invoice` records to its only consumer.

### 2.2 Safer approach

Use the concrete invoice type and schema that the consumer requires.

### 2.3 Failure mode

Introduce generic type parameters and an extensible record schema for arbitrary entity kinds without callers for them.

### 2.4 Why this difference matters

Unneeded generality expands type signatures and constraints, making the actual contract less evident.

## 3. Boundaries and distinctions

Generics are useful when current consumers need type-safe variation; unsupported possible types do not require them.
