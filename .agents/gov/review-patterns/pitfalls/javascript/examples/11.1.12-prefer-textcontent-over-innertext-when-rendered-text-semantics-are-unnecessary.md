# Prefer textContent over innerText when rendered-text semantics are unnecessary

## 1. Catalog record

- **Catalog identifier:** 11.1.12
- **Impact:** low
- **Consensus:** high
- **Definition:** Use textContent when CSS-aware rendered-text behavior is not needed.

## 2. Example

### 2.1 Scenario

A search index collects a card's source text without needing to know how CSS renders that text.

### 2.2 Preferred form

```javascript
const card = document.querySelector(".article-card");
const indexedText = card.textContent.trim();

console.log(indexedText);
```

### 2.3 Hazardous form

```javascript
const card = document.querySelector(".article-card");
const indexedText = card.innerText.trim();

console.log(indexedText);
```

### 2.4 Why this difference matters

`innerText` reflects rendered text and can require layout-aware processing, while the index needs the DOM's text content regardless of styling or visibility.

## 3. Boundaries and distinctions

Use `innerText` when the visible, CSS-aware rendered text is specifically the required result.
