# Use out-of-band status instead of sentinel result values

## 1. Catalog record

- **Catalog identifier:** 12.17.1
- **Impact:** medium
- **Consensus:** high
- **Definition:** Prefer `(value, ok)` or `(value, error)` over values such as `-1`, `""`, or nil when those values can also be legitimate results.

## 2. Example

### 2.1 Scenario

An inventory service stores a quantity for each SKU. Negative quantities are legitimate because they represent backorders.

### 2.2 Preferred form

```go
package inventory

type Stock struct {
	quantityBySKU map[string]int
}

func (s Stock) Quantity(sku string) (int, bool) {
	quantity, ok := s.quantityBySKU[sku]
	return quantity, ok
}

func needsReorder(s Stock, sku string) bool {
	quantity, found := s.Quantity(sku)
	return found && quantity < 0
}
```

### 2.3 Hazardous form

```go
package inventory

type Stock struct {
	quantityBySKU map[string]int
}

func (s Stock) Quantity(sku string) int {
	if quantity, ok := s.quantityBySKU[sku]; ok {
		return quantity
	}
	return -1 // Collides with a valid backorder quantity.
}

func needsReorder(s Stock, sku string) bool {
	return s.Quantity(sku) < 0
}
```

### 2.4 Why this difference matters

The sentinel form makes a missing SKU look exactly like a backorder, so callers can reorder an item that the service does not track. The boolean keeps absence separate from every valid quantity.

## 3. Boundaries and distinctions

A sentinel is acceptable only when the result domain reserves it permanently and the contract makes that reservation clear. For most lookup APIs, `(value, ok)` is less fragile as the domain evolves.
