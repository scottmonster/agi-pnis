# Speculative configuration surface

## 1. Catalog record

- **Catalog identifier:** 3.2
- **Evidence:** se
- **Definition:** Settings object exposes numerous knobs that no current caller uses.

## 2. Scenario

### 2.1 Context

A new exporter has one known timeout and format requirement.

### 2.2 Safer approach

Keep the few required settings local and expose a configuration field only for an actual caller need.

### 2.3 Failure mode

Publish an `ExporterSettings` object with unused retry, buffer, strategy, and formatting knobs.

### 2.4 Why this difference matters

Each public knob becomes an apparent contract that must be explained and maintained.

## 3. Boundaries and distinctions

Configuration is useful for real, independently varying deployments; this failure is the unused surface, not configuration itself.
