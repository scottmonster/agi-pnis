# Create temporary resources atomically

## 1. Catalog record

- **Catalog identifier:** 1.10.1
- **Impact:** high
- **Consensus:** high
- **Definition:** Do not create predictable temporary paths such as `/tmp/script.$$`. Use `mktemp`, preferably a private temporary directory where multiple related files are needed, and arrange cleanup.

## 2. Example

### 2.1 Scenario

A reporting script needs a private workspace for an intermediate data file before it publishes a result. Several instances can run at the same time on a shared host.

### 2.2 Preferred form

```bash
#!/usr/bin/env bash

tmp_dir=$(mktemp -d -- "${TMPDIR:-/tmp}/report.XXXXXXXX") || exit 1
trap 'rm -rf -- "$tmp_dir"' EXIT

intermediate_file=$tmp_dir/data.txt
printf '%s\n' 'compiled report data' > "$intermediate_file"
cat "$intermediate_file"
```

### 2.3 Hazardous form

```bash
#!/usr/bin/env bash

tmp_dir=/tmp/report.$$
mkdir "$tmp_dir"

intermediate_file=$tmp_dir/data.txt
printf '%s\n' 'compiled report data' > "$intermediate_file"
cat "$intermediate_file"
rm -rf "$tmp_dir"
```

### 2.4 Why this difference matters

The process ID does not make a path safe to create. Another process can create the predictable directory first, or arrange a symlink or collision that redirects the script's work. `mktemp -d` creates a uniquely named directory as one operation, and the trap cleans it up on normal exit or failure.

## 3. Boundaries and distinctions

Use a temporary directory when related files need a private namespace. For one temporary file, use `mktemp` with a file template and still check its status. Cleanup traps should be scoped so they do not remove a resource that was never successfully created.
