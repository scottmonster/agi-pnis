# Comparing booleans to `True` or `False`

## 1. Catalog record

- **Catalog identifier:** 16.2.2
- **Impact:** low
- **Consensus:** high
- **Definition:** Prefer direct truth-value tests when actual boolean identity is not specifically required rather than `x == True` or `x == False`.

## 2. Example

### 2.1 Scenario

A feature is enabled whenever its configuration value is truthy.

### 2.2 Preferred form

```python
def enabled_message(enabled: object) -> str:
    if enabled:
        return "feature enabled"
    return "feature disabled"
```

### 2.3 Hazardous form

```python
def enabled_message(enabled: object) -> str:
    if enabled == True:
        return "feature enabled"
    return "feature disabled"
```

### 2.4 Why this difference matters

The direct form states a truth-value test clearly and works with Python's general truthiness protocol. Equality obscures that intent and can trigger custom equality behavior.

## 3. Boundaries and distinctions

Use `value is True` or `value is False` when an API requires an actual boolean singleton, rather than merely a truthy or falsey value.
