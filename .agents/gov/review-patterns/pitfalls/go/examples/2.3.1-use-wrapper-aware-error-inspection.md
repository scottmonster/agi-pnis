# Use wrapper-aware error inspection

## 1. Catalog record

- **Catalog identifier:** 2.3.1
- **Impact:** high
- **Consensus:** high
- **Definition:** Use `errors.Is` for sentinel identity and `errors.AsType` in Go 1.26+ where appropriate for wrapped error types, rather than direct equality or one-level type assertions.

## 2. Example

### 2.1 Scenario

A storage layer adds operation context to a not-found error. Its HTTP adapter still needs to map the wrapped sentinel to a 404 response.

### 2.2 Preferred form

```go
package example

import (
	"errors"
	"fmt"
)

var ErrNotFound = errors.New("not found")

func loadUser(id string) error {
	return fmt.Errorf("load user %q: %w", id, ErrNotFound)
}

func isNotFound(err error) bool {
	return errors.Is(err, ErrNotFound)
}
```

### 2.3 Hazardous form

```go
package example

import (
	"errors"
	"fmt"
)

var ErrNotFound = errors.New("not found")

func loadUser(id string) error {
	return fmt.Errorf("load user %q: %w", id, ErrNotFound)
}

func isNotFound(err error) bool {
	return err == ErrNotFound // false after the contextual wrapper is added
}
```

### 2.4 Why this difference matters

Direct equality sees only the outer `fmt.wrapError`, so it misses the sentinel that defines the response behavior. `errors.Is` walks the wrapping chain and preserves intentional error identity.

## 3. Boundaries and distinctions

Use direct equality only when wrapping is impossible by contract. For typed wrapped errors, use `errors.As` on supported releases, or `errors.AsType` where Go 1.26 or newer is the required baseline.
