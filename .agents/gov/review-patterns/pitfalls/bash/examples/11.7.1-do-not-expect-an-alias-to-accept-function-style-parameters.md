# Do not expect an alias to accept function-style parameters

## 1. Catalog record

- **Catalog identifier:** 11.7.1
- **Impact:** low
- **Consensus:** high
- **Definition:** Aliases perform lexical replacement rather than defining callable parameterized routines. Use a function when reusable behavior needs positional arguments or structured control flow.

## 2. Example

### 2.1 Scenario

An interactive Bash setup needs a reusable command that creates and enters a named directory.

### 2.2 Preferred form

```bash
#!/usr/bin/env bash

croot() {
  mkdir -p -- "$1" && cd -- "$1"
}

croot ./scratch
echo "current directory: $PWD"
```

### 2.3 Hazardous form

```bash
#!/usr/bin/env bash

alias croot='mkdir -p -- "$1" && cd -- "$1"'
croot ./scratch
```

### 2.4 Why this difference matters

An alias is text substitution, not a call frame. Its `$1` refers to the surrounding shell's positional parameter rather than the argument placed after `croot`.

## 3. Boundaries and distinctions

Aliases are useful for simple fixed interactive abbreviations. Use functions for arguments, branching, local variables, or reusable command behavior.
