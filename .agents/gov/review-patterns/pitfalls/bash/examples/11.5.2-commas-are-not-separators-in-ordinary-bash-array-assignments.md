# Commas are not separators in ordinary Bash array assignments

## 1. Catalog record

- **Catalog identifier:** 11.5.2
- **Impact:** low
- **Consensus:** high
- **Definition:** Bash compound array assignments separate words according to shell syntax, not comma-list syntax. A comma written into an element is normally part of the element.

## 2. Example

### 2.1 Scenario

A script defines the deployment regions that a release job should process.

### 2.2 Preferred form

```bash
#!/usr/bin/env bash

regions=(us-east-1 us-west-2 eu-central-1)
for region in "${regions[@]}"; do
  echo "deploying to $region"
done
```

### 2.3 Hazardous form

```bash
#!/usr/bin/env bash

regions=(us-east-1, us-west-2, eu-central-1)
for region in "${regions[@]}"; do
  echo "deploying to $region"
done
```

### 2.4 Why this difference matters

The hazardous assignment creates elements such as `us-east-1,`, causing later commands to receive region names with commas.

## 3. Boundaries and distinctions

Commas can be deliberate data inside an array element. They are not separators in ordinary Bash compound assignments.
