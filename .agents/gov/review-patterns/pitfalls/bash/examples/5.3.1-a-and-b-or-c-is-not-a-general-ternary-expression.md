# `A && B || C` is not a general ternary expression

## 1. Catalog record

- **Catalog identifier:** 5.3.1
- **Impact:** medium
- **Consensus:** high
- **Definition:** Do not assume `A && B || C` means exactly `if A; then B; else C; fi`. If `A` succeeds but `B` fails, `C` also runs.

## 2. Example

### 2.1 Scenario

A publish job should report a missing artifact only when the artifact check fails, not when publishing itself fails.

### 2.2 Preferred form

```bash
upload_artifact() {
  local artifact_path=$1
  [[ -s $artifact_path ]]
}

artifact=${1:-build/app.tar.gz}

if [[ -f $artifact ]]; then
  if upload_artifact "$artifact"; then
    printf 'published %s\n' "$artifact"
  else
    printf 'upload failed\n' >&2
    exit 1
  fi
else
  printf 'artifact is missing: %s\n' "$artifact" >&2
fi
```

### 2.3 Hazardous form

```bash
upload_artifact() {
  local artifact_path=$1
  [[ -s $artifact_path ]]
}

artifact=${1:-build/app.tar.gz}

[[ -f $artifact ]] && upload_artifact "$artifact" || printf 'artifact is missing: %s\n' "$artifact" >&2
```

### 2.4 Why this difference matters

When the artifact exists but `upload_artifact` fails, its failure makes the final `||` branch run. The resulting message falsely claims that the artifact is missing and can hide the actual upload failure.

## 3. Boundaries and distinctions

Short `&&` or `||` chains are suitable when every failed left-hand command should trigger the next branch. Use `if` when the branches distinguish failures from different operations.
