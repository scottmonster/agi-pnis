# Failure to notice existing vulnerable code while answering a nearby programming question

## 1. Catalog record

- **Catalog identifier:** 10.20
- **Evidence:** e
- **Definition:** Makes a local change while overlooking an evident adjacent vulnerability that the change touches or preserves.

## 2. Scenario

### 2.1 Context

An agent is asked to add a new filter to a search endpoint that already assembles SQL from request text.

### 2.2 Safer approach

Inspect the touched query path, recognize the existing unsafe construction, and raise or address the adjacent vulnerability within the agreed scope before extending it.

### 2.3 Failure mode

The agent appends the new filter to the same string-built query and reports the requested feature complete.

### 2.4 Why this difference matters

The change preserves or expands an evident security flaw in the very code path it modifies.

## 3. Boundaries and distinctions

This does not require an unrelated security audit of the whole repository. It concerns an evident adjacent vulnerability that the local change touches or preserves.
