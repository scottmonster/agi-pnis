# Use deterministic disposal for disposable resources when supported

## 1. Catalog record

- **Catalog identifier:** 12.1.8
- **Impact:** medium
- **Consensus:** medium
- **Definition:** Use scope-bound deterministic disposal when the runtime and resource support it.

## 2. Example

### 2.1 Scenario

A report writer must close its file-like resource even if producing the report throws.

### 2.2 Preferred form

```javascript
class ReportWriter {
  constructor(name) {
    this.name = name;
    this.closed = false;
  }

  write(text) {
    if (this.closed) throw new Error("Writer is closed");
    console.log(`${this.name}: ${text}`);
  }

  [Symbol.dispose]() {
    this.closed = true;
  }
}

function writeReport() {
  using writer = new ReportWriter("daily.csv");
  writer.write("total,42");
}
```

### 2.3 Hazardous form

```javascript
class ReportWriter {
  constructor(name) {
    this.name = name;
    this.closed = false;
  }

  write(text) {
    if (this.closed) throw new Error("Writer is closed");
    console.log(`${this.name}: ${text}`);
  }

  close() {
    this.closed = true;
  }
}

function writeReport() {
  const writer = new ReportWriter("daily.csv");
  writer.write("total,42");
  throw new Error("Disk full");
  writer.close();
}
```

### 2.4 Why this difference matters

The `using` declaration calls the resource's disposal method when its scope exits, including an abrupt exit. Manual cleanup after work is easy to skip on a return or exception.

## 3. Boundaries and distinctions

Use `using` only where the JavaScript runtime and the resource's disposal protocol support it. Otherwise, use `try` and `finally` to provide the same deterministic lifetime.
