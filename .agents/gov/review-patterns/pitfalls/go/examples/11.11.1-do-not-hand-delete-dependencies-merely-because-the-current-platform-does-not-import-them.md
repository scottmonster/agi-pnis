# Do not hand-delete dependencies merely because the current platform does not import them

## 1. Catalog record

- **Catalog identifier:** 11.11.1
- **Impact:** medium
- **Consensus:** high
- **Definition:** Let `go mod tidy` determine module requirements across supported build configurations.

## 2. Example

### 2.1 Scenario

A Windows-only source file imports a platform package, but the maintainer runs maintenance on Linux.

### 2.2 Preferred form

```go
package example

import "os/exec"

func tidyModule() error {
	return exec.Command("go", "mod", "tidy").Run()
}
```

### 2.3 Hazardous form

```go
//go:build windows

package example

import driver "example.com/windows-driver"

func connect() error {
	return driver.Connect() // manually removing its requirement breaks Windows
}
```

### 2.4 Why this difference matters

`go mod tidy` considers packages across build tags and platforms more broadly than a single local build. Hand-editing requirements based on one machine can break supported configurations.

## 3. Boundaries and distinctions

Removing an obsolete dependency is appropriate after the code no longer needs it in supported configurations. Use tidy and configuration-aware tests to establish that condition.
