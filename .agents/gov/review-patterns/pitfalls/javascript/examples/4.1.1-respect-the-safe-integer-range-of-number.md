# Respect the safe integer range of Number

## 1. Catalog record

- **Catalog identifier:** 4.1.1
- **Impact:** high
- **Consensus:** high
- **Definition:** Do not assume every integer representable by a decimal string can be represented exactly as a JavaScript `Number`. Validate with `Number.isSafeInteger()` or use `BigInt` or strings when exact large integers are required.

## 2. Example

### 2.1 Scenario

An order service receives an identifier larger than JavaScript's safe integer range and must preserve it exactly.

### 2.2 Preferred form

```javascript
function parseOrderId(text) {
  return BigInt(text);
}

const orderId = parseOrderId("9007199254740993");
console.log(orderId === 9007199254740993n);
```

### 2.3 Hazardous form

```javascript
const firstOrderId = 9007199254740992;
const secondOrderId = 9007199254740993;

console.log(firstOrderId === secondOrderId);
```

### 2.4 Why this difference matters

The two distinct numeric literals collapse to the same `Number`, so an identifier can be mistaken for another identifier.

## 3. Boundaries and distinctions

`Number` represents integers exactly through `Number.MAX_SAFE_INTEGER`. It remains appropriate for values that have been validated as safe integers.
