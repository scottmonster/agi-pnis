# Prefer `printf` to `echo` for predictable output

## 1. Catalog record

- **Catalog identifier:** 9.10.1
- **Impact:** medium
- **Consensus:** high
- **Definition:** Use `printf '%s\\n'` for exact output because `echo` handles options and backslashes inconsistently across environments.

## 2. Example

### 2.1 Scenario

A script writes a user-supplied value to a configuration file without interpreting its contents.

### 2.2 Preferred form

```bash
#!/usr/bin/env bash
set -euo pipefail

value='-n path\\to\\file'
printf '%s\n' "$value"
```

### 2.3 Hazardous form

```bash
#!/usr/bin/env bash
set -euo pipefail

value='-n path\\to\\file'
echo "$value"
```

### 2.4 Why this difference matters

An option-like value or backslashes can cause `echo` to suppress output details or interpret data differently across implementations.

## 3. Boundaries and distinctions

`echo` can be sufficient for simple human-facing messages when exact, portable treatment of data is not required.
