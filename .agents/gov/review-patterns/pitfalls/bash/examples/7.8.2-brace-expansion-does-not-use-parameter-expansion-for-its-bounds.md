# Brace expansion does not use parameter expansion for its bounds

## 1. Catalog record

- **Catalog identifier:** 7.8.2
- **Impact:** medium
- **Consensus:** high
- **Definition:** Constructs such as `{1..$n}` do not create a runtime range from `$n`, because brace expansion happens before parameter expansion. Use an arithmetic loop when bounds are dynamic.

## 2. Example

### 2.1 Scenario

A script creates one report line per requested retry number. The upper bound is read at runtime.

### 2.2 Preferred form

```bash
retry_count=3

for ((retry = 1; retry <= retry_count; retry++)); do
  printf 'attempt %d\n' "$retry"
done
```

### 2.3 Hazardous form

```bash
retry_count=3

printf 'attempt %s\n' {1..$retry_count}
```

### 2.4 Why this difference matters

Brace expansion occurs before the shell expands `$retry_count`, so the hazardous form does not build the expected runtime sequence. The arithmetic loop evaluates the bound when the script runs.

## 3. Boundaries and distinctions

Brace expansion is convenient for small, literal ranges known in the script. Use a loop or another runtime mechanism whenever either bound is dynamic.
