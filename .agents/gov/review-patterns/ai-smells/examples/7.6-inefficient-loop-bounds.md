# Inefficient loop bounds

## 1. Catalog record

- **Catalog identifier:** 7.6
- **Evidence:** e
- **Definition:** Iterates farther or more often than the required result demands.

## 2. Scenario

### 2.1 Context

An agent writes a search helper that needs the first enabled feature flag in priority order.

### 2.2 Safer approach

It stops at the first enabled flag because later flags cannot change the required answer.

### 2.3 Failure mode

It scans every flag and continues doing the same checks after finding the first enabled one.

### 2.4 Why this difference matters

Avoidable iterations waste time and can trigger unnecessary downstream work.

## 3. Boundaries and distinctions

Scanning every item is required when the result depends on all items, such as collecting every enabled flag; this failure applies when the needed result has a narrower bound.
