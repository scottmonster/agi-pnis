# Imported bindings are read-only live bindings

## 1. Catalog record

- **Catalog identifier:** 8.1.3
- **Impact:** medium
- **Consensus:** high
- **Definition:** Treat imports as read-only live bindings, not copied local values.

## 2. Example

### 2.1 Scenario

A status view displays a counter that another module updates.

### 2.2 Preferred form

```javascript
// counter.js
export let count = 0;

export function increment() {
  count += 1;
}

// status-view.js
import { count, increment } from "./counter.js";

increment();
console.log(`items: ${count}`); // items: 1
```

### 2.3 Hazardous form

```javascript
// counter.js
export let count = 0;

// status-view.js
import { count } from "./counter.js";

count += 1;
console.log(`items: ${count}`);
```

### 2.4 Why this difference matters

The hazardous module fails because an import cannot be reassigned. Updates must be made through an exporting module's API, while import reads remain live.

## 3. Boundaries and distinctions

Copy an imported value into a local binding only when a deliberate snapshot is required. That local copy will not follow later exporter updates.
