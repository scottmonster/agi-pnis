# Declare the interpreter that matches the script language

## 1. Catalog record

- **Catalog identifier:** 3.2.1
- **Impact:** high
- **Consensus:** high
- **Definition:** Declare Bash for scripts that use Bash syntax, and keep POSIX `sh` scripts free of Bash-specific constructs.

## 2. Example

### 2.1 Scenario

A maintenance script uses Bash arrays to process a list of changed files.

### 2.2 Preferred form

```bash
#!/usr/bin/env bash

files=("report one.txt" "report two.txt")
printf 'processing %s\n' "${files[@]}"
```

### 2.3 Hazardous form

```bash
#!/bin/sh

files=("report one.txt" "report two.txt")
printf 'processing %s\n' "${files[@]}"
```

### 2.4 Why this difference matters

Many systems implement `/bin/sh` with a shell that does not support Bash arrays, causing a script that works in an interactive Bash session to fail at runtime.

## 3. Boundaries and distinctions

Use `sh` only for deliberately portable POSIX shell code; a Bash declaration does not make a script portable to other shells.
