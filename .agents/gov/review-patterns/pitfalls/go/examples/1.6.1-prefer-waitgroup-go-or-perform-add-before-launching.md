# Prefer `WaitGroup.Go` or perform `Add` before launching

## 1. Catalog record

- **Catalog identifier:** 1.6.1
- **Impact:** high
- **Consensus:** high
- **Definition:** On current Go, prefer `WaitGroup.Go` for ordinary goroutine accounting. When manually using `Add`, increment before starting the goroutine rather than from inside it.

## 2. Example

### 2.1 Scenario

A function launches tasks and must wait until every task finishes.

### 2.2 Preferred form

```go
package main

import "sync"

func run(tasks []func()) {
	var wg sync.WaitGroup
	for _, task := range tasks {
		wg.Go(task)
	}
	wg.Wait()
}
```

### 2.3 Hazardous form

```go
package main

import "sync"

func run(tasks []func()) {
	var wg sync.WaitGroup
	for _, task := range tasks {
		go func() {
			wg.Add(1)
			defer wg.Done()
			task()
		}()
	}
	wg.Wait()
}
```

### 2.4 Why this difference matters

`Wait` can observe a zero counter before a newly started goroutine calls `Add`, allowing `run` to return early. `WaitGroup.Go` performs the accounting before work begins.

## 3. Boundaries and distinctions

For Go versions before `WaitGroup.Go`, call `wg.Add(1)` in the launching goroutine immediately before `go`. Do not copy a `WaitGroup` after it is first used.
