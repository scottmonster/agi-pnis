# Do not identify processes with `ps | grep`

## 1. Catalog record

- **Catalog identifier:** 9.12.1
- **Impact:** medium
- **Consensus:** high
- **Definition:** Track launched PIDs or use a purpose-built process interface instead of identifying processes with `ps | grep`.

## 2. Example

### 2.1 Scenario

A script starts a local worker and must stop that exact worker during cleanup.

### 2.2 Preferred form

```bash
#!/usr/bin/env bash
set -euo pipefail

./worker --queue jobs &
worker_pid=$!

kill "$worker_pid"
wait "$worker_pid" || true
```

### 2.3 Hazardous form

```bash
#!/usr/bin/env bash
set -euo pipefail

./worker --queue jobs &
worker_pid=$(ps -ef | grep '[w]orker --queue jobs' | awk 'NR == 1 { print $2 }')
kill "$worker_pid"
```

### 2.4 Why this difference matters

`ps | grep` can match unrelated processes and races with process creation and exit, so it can select the wrong PID.

## 3. Boundaries and distinctions

`pgrep` can be appropriate for genuine name-based discovery, but its matching scope and race behavior still need explicit handling.
