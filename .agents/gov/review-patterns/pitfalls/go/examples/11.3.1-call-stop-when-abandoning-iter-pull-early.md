# Call `stop` when abandoning `iter.Pull` early

## 1. Catalog record

- **Catalog identifier:** 11.3.1
- **Impact:** medium
- **Consensus:** high
- **Definition:** When a pull iterator has not naturally reached its end, arrange `defer stop()` or otherwise call `stop` before abandoning it.

## 2. Example

### 2.1 Scenario

A caller only needs the first row from an iterator that may own a producer goroutine.

### 2.2 Preferred form

```go
package example

import "iter"

func first(seq iter.Seq[int]) (int, bool) {
	next, stop := iter.Pull(seq)
	defer stop()
	return next()
}
```

### 2.3 Hazardous form

```go
package example

import "iter"

func first(seq iter.Seq[int]) (int, bool) {
	next, _ := iter.Pull(seq)
	return next() // producer is abandoned without stop
}
```

### 2.4 Why this difference matters

`stop` tells the iterator that no more values are wanted, allowing it to finish and release resources or a blocked goroutine.

## 3. Boundaries and distinctions

Calling `stop` is unnecessary after natural exhaustion, but it is safe to defer it and necessary when a pull sequence is abandoned early.
