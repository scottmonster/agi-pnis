# Fake fallback/default

## 1. Catalog record

- **Catalog identifier:** 6.17
- **Evidence:** se
- **Definition:** Converts a real error into `None`, `0`, `[]`, or another plausible value that hides failure.

## 2. Scenario

### 2.1 Context

The dashboard requests current inventory from the inventory service.

### 2.2 Safer approach

The agent distinguishes a successful empty inventory from a service failure and surfaces the latter through the established error path.

### 2.3 Failure mode

On a network error, it returns an empty inventory list.

### 2.4 Why this difference matters

Users conclude that stock is empty and may make incorrect business decisions.

## 3. Boundaries and distinctions

A documented fallback is valid when it remains distinguishable from success and preserves the required operational semantics.
