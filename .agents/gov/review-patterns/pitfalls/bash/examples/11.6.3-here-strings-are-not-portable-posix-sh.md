# Here strings are not portable POSIX `sh`

## 1. Catalog record

- **Catalog identifier:** 11.6.3
- **Impact:** low
- **Consensus:** high
- **Definition:** The `<<<` here-string operator is a Bash feature and should not appear in scripts whose interpreter contract is portable POSIX `sh`.

## 2. Example

### 2.1 Scenario

A portable script passes one configuration value to `read`.

### 2.2 Preferred form

```bash
#!/bin/sh

config_value='feature=true'
IFS= read -r parsed_value <<EOF
$config_value
EOF
echo "parsed: $parsed_value"
```

### 2.3 Hazardous form

```bash
#!/bin/sh

config_value='feature=true'
IFS= read -r parsed_value <<<"$config_value"
echo "parsed: $parsed_value"
```

### 2.4 Why this difference matters

The here-string operator is not portable POSIX syntax, so the script can fail to parse under a non-Bash `/bin/sh`.

## 3. Boundaries and distinctions

Here strings are fine when Bash is the declared interpreter. For a POSIX-shell contract, use a portable input mechanism.
