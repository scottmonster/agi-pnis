# Do not assume object properties enumerate purely in insertion order

## 1. Catalog record

- **Catalog identifier:** 2.18.1
- **Impact:** low
- **Consensus:** high
- **Definition:** Do not rely on pure insertion order when integer-index-like property keys are possible.

## 2. Example

### 2.1 Scenario

A display needs a stable ordering for user-entered labels.

### 2.2 Preferred form

```javascript
const labels = new Map();
labels.set("10", "ten");
labels.set("2", "two");

console.log([...labels.keys()]);
```

### 2.3 Hazardous form

```javascript
const labels = {};
labels["10"] = "ten";
labels["2"] = "two";

console.log(Object.keys(labels));
```

### 2.4 Why this difference matters

Integer-index-like object keys enumerate in numeric order, so the hazardous result is `["2", "10"]` rather than insertion order.

## 3. Boundaries and distinctions

For non-index string keys, ordinary object enumeration has a defined order. Use `Map` when insertion order must hold across arbitrary keys.
