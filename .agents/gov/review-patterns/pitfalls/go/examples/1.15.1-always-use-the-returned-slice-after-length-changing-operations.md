# Always use the returned slice after length-changing operations

## 1. Catalog record

- **Catalog identifier:** 1.15.1
- **Impact:** high
- **Consensus:** high
- **Definition:** Assign the result of `append`, `slices.Delete`, `slices.Compact`, `slices.Insert`, `slices.Replace`, and similar functions back to the slice you intend to continue using.

## 2. Example

### 2.1 Scenario

A function removes a completed task from a task slice.

### 2.2 Preferred form

```go
package main

import "slices"

func removeTask(tasks []string, index int) []string {
	tasks = slices.Delete(tasks, index, index+1)
	return tasks
}
```

### 2.3 Hazardous form

```go
package main

import "slices"

func removeTask(tasks []string, index int) []string {
	slices.Delete(tasks, index, index+1)
	return tasks
}
```

### 2.4 Why this difference matters

`slices.Delete` returns the new slice header with the shortened length. Ignoring it leaves the caller using the old length, so the supposedly removed task remains visible.

## 3. Boundaries and distinctions

Some operations mutate elements without changing the header, but APIs that return a slice should be treated as returning the authoritative result. Consider clearing removed pointer elements when retention matters.
