# Protect operands that begin with `-`

## 1. Catalog record

- **Catalog identifier:** 1.4.1
- **Impact:** high
- **Consensus:** high
- **Definition:** When filenames or other data may begin with a hyphen, terminate options with `--` where supported, as in `rm -- "$file"`, or make pathnames unambiguous with forms such as `./*`.

## 2. Example

### 2.1 Scenario

A cleanup command removes generated files from the current directory. A generated filename can begin with a hyphen.

### 2.2 Preferred form

```bash
shopt -s nullglob
for file in ./*; do
    rm -- "$file"
done
```

### 2.3 Hazardous form

```bash
shopt -s nullglob
for file in *; do
    rm "$file"
done
```

### 2.4 Why this difference matters

Without `--`, a name such as `-r` is parsed as an option instead of an operand. In destructive commands, unexpected options can change what is removed or how the removal proceeds.

## 3. Boundaries and distinctions

Use `--` only with commands that document it as an option terminator. When it is unsupported, pass an unambiguous path such as `./$file` or an absolute pathname, and still quote the expansion.
