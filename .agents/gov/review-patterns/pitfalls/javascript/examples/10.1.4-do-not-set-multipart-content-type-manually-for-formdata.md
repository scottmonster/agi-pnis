# Do not set multipart Content-Type manually for FormData

## 1. Catalog record

- **Catalog identifier:** 10.1.4
- **Impact:** medium
- **Consensus:** high
- **Definition:** Let fetch set multipart Content-Type and its boundary when FormData is the body.

## 2. Example

### 2.1 Scenario

A profile form uploads an avatar image with the user’s display name.

### 2.2 Preferred form

```javascript
async function uploadProfile(name, avatarFile) {
  const body = new FormData();
  body.set("name", name);
  body.set("avatar", avatarFile);

  return fetch("/api/profile", { method: "POST", body });
}
```

### 2.3 Hazardous form

```javascript
async function uploadProfile(name, avatarFile) {
  const body = new FormData();
  body.set("name", name);
  body.set("avatar", avatarFile);

  return fetch("/api/profile", {
    method: "POST",
    headers: { "Content-Type": "multipart/form-data" },
    body,
  });
}
```

### 2.4 Why this difference matters

The browser generates a multipart boundary for the body. Replacing its header without that boundary can make the server unable to parse the submitted fields.

## 3. Boundaries and distinctions

Set `Content-Type` yourself for a deliberately encoded non-FormData body, such as JSON. Leave it unset when the platform must attach multipart boundary metadata.
