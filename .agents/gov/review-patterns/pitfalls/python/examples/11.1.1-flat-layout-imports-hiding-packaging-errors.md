# Flat-layout imports hiding packaging errors

## 1. Catalog record

- **Catalog identifier:** 11.1.1
- **Impact:** medium
- **Consensus:** high
- **Definition:** Consider `src/` layout when accidental imports directly from the working tree could hide missing package data, import configuration, or installation errors.

## 2. Example

### 2.1 Scenario

A package test suite should exercise the same installed distribution that users receive.

### 2.2 Preferred form

```python
# Project layout:
# src/invoice_tools/__init__.py
# tests/test_import.py

from invoice_tools import __version__

assert isinstance(__version__, str)
```

### 2.3 Hazardous form

```python
# Project layout:
# invoice_tools/__init__.py
# tests/test_import.py

from invoice_tools import __version__

assert isinstance(__version__, str)
```

### 2.4 Why this difference matters

In a flat layout, the working directory can make the source tree importable even when the built package omits files or has incorrect installation configuration.

## 3. Boundaries and distinctions

A flat layout can work when installation verification is disciplined. A `src/` layout adds friction that makes accidental source-tree imports less likely.
