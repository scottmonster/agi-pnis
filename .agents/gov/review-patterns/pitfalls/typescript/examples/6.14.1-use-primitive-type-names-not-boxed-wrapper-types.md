# Use primitive type names, not boxed wrapper types

## 1. Catalog record

- **Catalog identifier:** 6.14.1
- **Impact:** medium
- **Consensus:** high
- **Definition:** Use `string`, `number`, `boolean`, `symbol`, and `object`, not `String`, `Number`, `Boolean`, `Symbol`, or `Object`.

## 2. Example

### 2.1 Scenario

A cache must treat equivalent textual keys as the same key.

### 2.2 Preferred form

```typescript
const cache = new Map<string, number>();

function cacheKey(value: string): string {
  return value;
}

cache.set(cacheKey('user:42'), 1);
console.log(cache.get(cacheKey('user:42')));
```

### 2.3 Hazardous form

```typescript
const cache = new Map<String, number>();

function cacheKey(value: String): String {
  return value;
}

cache.set(cacheKey('user:42'), 1);
console.log(cache.get(cacheKey(new String('user:42')))); // undefined: this is a different object.
```

### 2.4 Why this difference matters

The capitalized forms describe boxed objects with materially different and usually unintended semantics.

## 3. Boundaries and distinctions

Apply this guidance in the conditions described by the catalog record. Deliberate exceptions need a documented runtime guarantee, compatible toolchain behavior, or an explicit local unsafe boundary.
