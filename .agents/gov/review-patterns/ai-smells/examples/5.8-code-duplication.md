# Code duplication

## 1. Catalog record

- **Catalog identifier:** 5.8
- **Evidence:** e
- **Definition:** Similar implementations appear repeatedly instead of maintaining one authoritative representation.

## 2. Scenario

### 2.1 Context

Three endpoints each normalize phone numbers with nearly identical regular expressions and error messages.

### 2.2 Safer approach

After confirming the stable shared behavior, centralize the normalization policy and test it once.

### 2.3 Failure mode

Copy the first endpoint's regex into a fourth endpoint and edit only its message.

### 2.4 Why this difference matters

Later policy changes can diverge across endpoints and create inconsistent behavior.

## 3. Boundaries and distinctions

Do not abstract coincidental similarity prematurely. This applies when genuine duplication needs one authoritative representation.
