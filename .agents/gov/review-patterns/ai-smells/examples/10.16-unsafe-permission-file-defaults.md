# Unsafe permission/file defaults

## 1. Catalog record

- **Catalog identifier:** 10.16
- **Evidence:** e
- **Definition:** Creates files, directories, or resources with access rights broader than their sensitivity permits.

## 2. Scenario

### 2.1 Context

A service writes an export file containing customer records.

### 2.2 Safer approach

Create the export in a service-controlled location with the minimum required owner and group access, then verify inherited defaults do not broaden it.

### 2.3 Failure mode

The agent creates the file with world-readable permissions so support staff can download it easily.

### 2.4 Why this difference matters

Other local users or services can read sensitive data without the intended authorization path.

## 3. Boundaries and distinctions

Public assets can require broad read access. Permissions should reflect the sensitivity and intended consumers of each resource.
