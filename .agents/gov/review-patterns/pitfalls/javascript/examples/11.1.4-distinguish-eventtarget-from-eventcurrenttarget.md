# Distinguish event.target from event.currentTarget

## 1. Catalog record

- **Catalog identifier:** 11.1.4
- **Impact:** medium
- **Consensus:** high
- **Definition:** Use target for event origin and currentTarget for the registered listener target.

## 2. Example

### 2.1 Scenario

A task list uses one click listener for buttons whose labels contain nested icons. A click may originate at the icon while the listener runs on the list.

### 2.2 Preferred form

```javascript
const taskList = document.querySelector("#task-list");

taskList.addEventListener("click", (event) => {
  const button = event.target.closest("button[data-task-id]");
  if (button === null || !taskList.contains(button)) return;

  console.log(`Complete task ${button.dataset.taskId} from ${event.currentTarget.id}`);
});
```

### 2.3 Hazardous form

```javascript
const taskList = document.querySelector("#task-list");

taskList.addEventListener("click", (event) => {
  console.log(`Complete task ${event.target.dataset.taskId} from ${event.target.id}`);
});
```

### 2.4 Why this difference matters

`event.target` is the innermost element that initiated the event, so it can be an icon without task data. `event.currentTarget` is consistently the element whose listener is running, while `closest()` maps the origin to the intended delegated button.

## 3. Boundaries and distinctions

`currentTarget` is meaningful only while the listener is executing and becomes `null` afterward. For events that do not bubble, delegation from an ancestor requires a suitable capturing listener or a listener on the originating element.
