# Config flags / env vars nobody requested

## 1. Catalog record

- **Catalog identifier:** 3.1
- **Evidence:** se
- **Definition:** `enable_x_v2`, `legacy_mode`, `use_new_parser` with only one real code path.

## 2. Scenario

### 2.1 Context

A parser change has one required behavior for every deployed environment.

### 2.2 Safer approach

Implement the required parser behavior directly and add a focused test.

### 2.3 Failure mode

Add `USE_NEW_PARSER`, `LEGACY_MODE`, and branching despite no caller needing alternatives.

### 2.4 Why this difference matters

Unused switches expand testing, documentation, and support burden without providing a real choice.

## 3. Boundaries and distinctions

A flag is appropriate when current deployments genuinely need distinct supported behavior; this differs from configuration that merely anticipates it.
