# Process bytes before handling a simultaneous read error

## 1. Catalog record

- **Catalog identifier:** 2.7.1
- **Impact:** high
- **Consensus:** high
- **Definition:** An `io.Reader` may return both `n > 0` and a non-nil error. Process the `n` bytes before acting on the error.

## 2. Example

### 2.1 Scenario

A parser reads a record from a source whose final call returns the last bytes and `io.EOF` together.

### 2.2 Preferred form

```go
package example

import (
	"bytes"
	"io"
)

func readRecord(r io.Reader) ([]byte, error) {
	buf := make([]byte, 16)
	n, err := r.Read(buf)
	record := bytes.Clone(buf[:n])
	if err != nil && err != io.EOF {
		return record, err
	}
	return record, nil
}
```

### 2.3 Hazardous form

```go
package example

import "io"

func readRecord(r io.Reader) ([]byte, error) {
	buf := make([]byte, 16)
	n, err := r.Read(buf)
	if err != nil {
		return nil, err // discards buf[:n] when n > 0
	}
	return buf[:n], nil
}
```

### 2.4 Why this difference matters

Readers may return useful data and an error in the same call, particularly at the end of a stream. Handling the error first silently loses the final record fragment.

## 3. Boundaries and distinctions

The caller should still handle the returned error after consuming `buf[:n]`, and should preserve any partial data only when the surrounding protocol permits it. A reader returning `n == 0` has no bytes to process.
