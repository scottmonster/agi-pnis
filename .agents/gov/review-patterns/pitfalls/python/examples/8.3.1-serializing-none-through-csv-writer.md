# Serializing `None` through `csv.writer`

## 1. Catalog record

- **Catalog identifier:** 8.3.1
- **Impact:** medium
- **Consensus:** high
- **Definition:** Do not rely on the CSV writer to preserve the distinction between `None` and an empty string. Encode nullable values explicitly when round-trip fidelity matters.

## 2. Example

### 2.1 Scenario

An export distinguishes a missing telephone number from an intentionally empty value.

### 2.2 Preferred form

```python
import csv
import io

def encode_cell(value: str | None) -> str:
    return "<NULL>" if value is None else value

stream = io.StringIO(newline="")
csv.writer(stream).writerow([encode_cell(None), encode_cell("")])
assert stream.getvalue() == "<NULL>,\r\n"
```

### 2.3 Hazardous form

```python
import csv
import io

stream = io.StringIO(newline="")
csv.writer(stream).writerow([None, ""])
assert stream.getvalue() == ",\r\n"  # The two values are indistinguishable.
```

### 2.4 Why this difference matters

`csv.writer` writes `None` as an empty field, so a later reader cannot recover whether the source was missing or empty.

## 3. Boundaries and distinctions

An empty field is sufficient when the application intentionally treats missing and empty values as equivalent.
