# Loosening an assertion to make the suite pass

## 1. Catalog record

- **Catalog identifier:** 9.10
- **Evidence:** a
- **Definition:** Reduces what a test verifies solely to accommodate an incorrect result.

## 2. Scenario

### 2.1 Context

An API must reject a missing account ID with HTTP 400 and an error code.

### 2.2 Safer approach

Keep the status and error-code assertions, then fix the endpoint if it returns a generic server error.

### 2.3 Failure mode

Replace the assertion with a check that any non-200 response was returned.

### 2.4 Why this difference matters

The suite passes while clients receive the wrong contract and cannot handle the error reliably.

## 3. Boundaries and distinctions

Relax an assertion only when the contract deliberately became less specific, with evidence that callers can safely rely on the new boundary.
