# Inspecting mutated mock arguments after the call

## 1. Catalog record

- **Catalog identifier:** 13.1.2
- **Impact:** medium
- **Consensus:** high
- **Definition:** If a test must assert the state of mutable arguments at call time, copy them in a side effect or otherwise capture their original state.

## 2. Example

### 2.1 Scenario

A function submits a mutable order dictionary, then adds local bookkeeping to the same dictionary.

### 2.2 Preferred form

```python
from copy import deepcopy
from unittest.mock import Mock


def submit(sender: object, order: dict[str, object]) -> None:
    sender.send(order)
    order["submitted"] = True


sender = Mock()
captured: list[dict[str, object]] = []
sender.send.side_effect = lambda order: captured.append(deepcopy(order))

submit(sender, {"id": 7})
assert captured == [{"id": 7}]
```

### 2.3 Hazardous form

```python
from unittest.mock import Mock


def submit(sender: object, order: dict[str, object]) -> None:
    sender.send(order)
    order["submitted"] = True


sender = Mock()
submit(sender, {"id": 7})
assert sender.send.call_args.args[0] == {"id": 7}
```

### 2.4 Why this difference matters

Mocks retain a reference to the passed object, not a snapshot. Later mutation changes the value observed through `call_args`, producing misleading assertions.

## 3. Boundaries and distinctions

No copy is needed for immutable arguments or when the assertion intentionally concerns their post-call state. Select shallow or deep copying based on the nested state the test must preserve.
