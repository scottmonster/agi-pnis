# Temporary environment assignments do not affect same-command shell expansion

## 1. Catalog record

- **Catalog identifier:** 8.8.1
- **Impact:** medium
- **Consensus:** high
- **Definition:** In `VAR=new command "$VAR"`, the shell expands `$VAR` before making the temporary assignment available to `command`; separate the assignment when the new value must affect shell-side expansion.

## 2. Example

### 2.1 Scenario

A script passes a configured label to a command and needs its argument to match the new environment value.

### 2.2 Preferred form

```bash
label=release
LABEL=$label
env LABEL="$LABEL" printf 'label=%s\n' "$LABEL"
```

### 2.3 Hazardous form

```bash
LABEL=debug
LABEL=release env printf 'label=%s\n' "$LABEL"
```

### 2.4 Why this difference matters

The hazardous argument expands to `debug` before the temporary `LABEL=release` assignment is applied to `env`. Separating the shell assignment gives both expansions the intended value.

## 3. Boundaries and distinctions

The temporary assignment is available in the invoked command's environment. It does not retroactively change expansions the current shell has already performed.
