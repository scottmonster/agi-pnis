# Ignoring architectural invariants

## 1. Catalog record

- **Catalog identifier:** 2.16
- **Evidence:** e/a
- **Definition:** Produces locally reasonable code that conflicts with relationships elsewhere in the system.

## 2. Scenario

### 2.1 Context

The application requires all account balance changes to be appended to an immutable ledger before the read model updates.

### 2.2 Safer approach

The agent finds the ledger write boundary and adds the new adjustment through that established flow.

### 2.3 Failure mode

It updates the balance column directly because that makes the local endpoint return the expected number.

### 2.4 Why this difference matters

Reconciliation, audit history, and downstream projections no longer agree with the visible balance.

## 3. Boundaries and distinctions

This is not a claim that all designs need event logs; it applies when the repository already relies on a cross-system invariant.
