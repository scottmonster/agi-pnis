# Deferred-call arguments are evaluated immediately

## 1. Catalog record

- **Catalog identifier:** 8.10.1
- **Impact:** medium
- **Consensus:** high
- **Definition:** If a deferred action should observe a later variable value, capture it deliberately in a closure rather than passing the value as a normal argument to `defer`.

## 2. Example

### 2.1 Scenario

A function records its final byte count when it returns after completing more work.

### 2.2 Preferred form

```go
package transfer

func copyCount(record func(int)) {
	n := 0
	defer func() { record(n) }()

	n += 512
	n += 512
}
```

### 2.3 Hazardous form

```go
package transfer

func copyCount(record func(int)) {
	n := 0
	defer record(n)

	n += 512
	n += 512
}
```

### 2.4 Why this difference matters

Arguments to a deferred call are evaluated when `defer` executes. The hazardous version records zero, while the closure reads `n` during deferred execution and records the final count.

## 3. Boundaries and distinctions

Immediate evaluation is useful when the deferred action should preserve the current value, such as a start time or initial rollback state. Choose the form that states which moment supplies the value.
