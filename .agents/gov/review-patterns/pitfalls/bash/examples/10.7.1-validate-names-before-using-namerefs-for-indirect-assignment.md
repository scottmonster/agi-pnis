# Validate names before using namerefs for indirect assignment

## 1. Catalog record

- **Catalog identifier:** 10.7.1
- **Impact:** medium
- **Consensus:** medium
- **Definition:** `declare -n` lets one variable refer to another by name, so externally supplied target names must be validated and constrained.

## 2. Example

### 2.1 Scenario

A configuration command accepts a setting name and value from a trusted command-line interface.

### 2.2 Preferred form

```bash
target='log_level'
value='debug'
log_level='info'
output_format='text'

if [[ $target =~ ^(log_level|output_format)$ ]]; then
  declare -n setting="$target"
  setting=$value
fi

printf '%s\n' "$log_level"
```

### 2.3 Hazardous form

```bash
target='PATH'
value='/unexpected/bin'

declare -n setting="$target"
setting=$value
printf '%s\n' "$PATH"
```

### 2.4 Why this difference matters

Without an allowlist, the supplied name becomes authority to overwrite unrelated shell variables such as `PATH`.

## 3. Boundaries and distinctions

Namerefs are useful for controlled internal abstractions. The target name must be treated as privileged input when it is selected outside trusted code.
