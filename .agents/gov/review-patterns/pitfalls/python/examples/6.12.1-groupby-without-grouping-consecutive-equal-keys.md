# `groupby()` without grouping consecutive equal keys

## 1. Catalog record

- **Catalog identifier:** 6.12.1
- **Impact:** medium
- **Consensus:** high
- **Definition:** Use `itertools.groupby()` only when equal-key elements are already consecutive, commonly by sorting first when global grouping is intended.

## 2. Example

### 2.1 Scenario

A report needs all events grouped by their service name, regardless of arrival order.

### 2.2 Preferred form

```python
from itertools import groupby

events = [("api", 1), ("worker", 2), ("api", 3)]
ordered = sorted(events, key=lambda event: event[0])
groups = {name: list(items) for name, items in groupby(ordered, key=lambda event: event[0])}
print(groups["api"])  # [('api', 1), ('api', 3)]
```

### 2.3 Hazardous form

```python
from itertools import groupby

events = [("api", 1), ("worker", 2), ("api", 3)]
groups = {name: list(items) for name, items in groupby(events, key=lambda event: event[0])}
print(groups["api"])  # [('api', 3)]
```

### 2.4 Why this difference matters

`groupby()` creates a new group whenever the key changes, and the dictionary comprehension overwrites the first `api` group with the later one.

## 3. Boundaries and distinctions

Do not sort when adjacent-run grouping is the intended operation, such as processing already ordered log segments.
