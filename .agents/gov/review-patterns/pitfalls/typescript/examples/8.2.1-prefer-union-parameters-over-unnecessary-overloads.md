# Prefer union parameters over unnecessary overloads

## 1. Catalog record

- **Catalog identifier:** 8.2.1
- **Impact:** medium
- **Consensus:** high
- **Definition:** If multiple overloads have the same arity and return behavior and differ mainly by argument type, prefer one signature with a union parameter.

## 2. Example

### 2.1 Scenario

A loader accepts either a path string or a URL and produces the same file text for both.

### 2.2 Preferred form

```typescript
function readSource(source: string | URL): string {
  return source instanceof URL ? source.pathname : source;
}

const configuredSource: string | URL = Math.random() > 0.5 ? 'notes.md' : new URL('file:///notes.md');
console.log(readSource(configuredSource));
```

### 2.3 Hazardous form

```typescript
function readSource(source: string): string;
function readSource(source: URL): string;
function readSource(source: string | URL): string {
  return source instanceof URL ? source.pathname : source;
}

const configuredSource: string | URL = Math.random() > 0.5 ? 'notes.md' : new URL('file:///notes.md');
readSource(configuredSource); // Error: no overload accepts a string | URL argument
```

### 2.4 Why this difference matters

Union signatures are easier to call with union-typed values and reduce overload-resolution complexity.

## 3. Boundaries and distinctions

Apply this guidance in the conditions described by the catalog record. Deliberate exceptions need a documented runtime guarantee, compatible toolchain behavior, or an explicit local unsafe boundary.
