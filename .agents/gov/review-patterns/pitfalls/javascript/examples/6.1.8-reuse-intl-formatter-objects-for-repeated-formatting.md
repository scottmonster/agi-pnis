# Reuse Intl formatter objects for repeated formatting

## 1. Catalog record

- **Catalog identifier:** 6.1.8
- **Impact:** low
- **Consensus:** high
- **Definition:** When formatting many values with identical locale/options, construct the relevant `Intl` formatter once rather than repeatedly invoking convenience locale-formatting methods.

## 2. Example

### 2.1 Scenario

A report renders thousands of prices using the same locale and currency.

### 2.2 Preferred form

```javascript
const usdFormatter = new Intl.NumberFormat("en-US", {
  style: "currency",
  currency: "USD",
});

function formatPrices(prices) {
  return prices.map((price) => usdFormatter.format(price));
}

console.log(formatPrices([12.5, 99]));
```

### 2.3 Hazardous form

```javascript
function formatPrices(prices) {
  return prices.map((price) => price.toLocaleString("en-US", {
    style: "currency",
    currency: "USD",
  }));
}

console.log(formatPrices([12.5, 99]));
```

### 2.4 Why this difference matters

The hazardous form can repeat locale-data lookup and formatter setup for every value, adding avoidable overhead in a large render.

## 3. Boundaries and distinctions

For an occasional format call, the convenience method is usually fine. Reuse matters when identical formatting is performed repeatedly on a meaningful volume of data.
