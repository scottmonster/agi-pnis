# Parameterize SQL instead of formatting SQL text

## 1. Catalog record

- **Catalog identifier:** 3.4.1
- **Impact:** high
- **Consensus:** high
- **Definition:** Pass values as query parameters rather than using `fmt.Sprintf` or string concatenation to construct SQL containing data.

## 2. Example

### 2.1 Scenario

A service looks up an account by an email address supplied by an HTTP request. The email is data, not SQL syntax.

### 2.2 Preferred form

```go
package example

import (
	"context"
	"database/sql"
)

func accountID(ctx context.Context, db *sql.DB, email string) (int64, error) {
	var id int64
	err := db.QueryRowContext(
		ctx,
		"SELECT id FROM accounts WHERE email = $1",
		email,
	).Scan(&id)
	return id, err
}
```

### 2.3 Hazardous form

```go
package example

import (
	"context"
	"database/sql"
	"fmt"
)

func accountID(ctx context.Context, db *sql.DB, email string) (int64, error) {
	query := fmt.Sprintf("SELECT id FROM accounts WHERE email = '%s'", email)
	var id int64
	err := db.QueryRowContext(ctx, query).Scan(&id)
	return id, err
}
```

### 2.4 Why this difference matters

Parameters keep the value separate from the statement grammar, so quotes and malicious input remain data. Formatting a value into SQL can change the query's meaning and enable injection.

## 3. Boundaries and distinctions

Placeholders generally represent values, not identifiers or SQL keywords. If a table name or sort direction must vary, select it from a small trusted allowlist rather than formatting untrusted input.
