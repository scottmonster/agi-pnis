# Do not treat `IFS=, read` as a CSV parser

## 1. Catalog record

- **Catalog identifier:** 6.7.1
- **Impact:** medium
- **Consensus:** high
- **Definition:** `IFS` field splitting can handle simple delimiter-separated records but does not implement CSV quoting and escaping rules, and Bash splitting has edge cases around empty fields. Use a real CSV parser for CSV.

## 2. Example

### 2.1 Scenario

A script imports customer records whose names can include commas.

### 2.2 Preferred form

```bash
#!/usr/bin/env bash
python3 - "$1" <<'PY'
import csv, sys
with open(sys.argv[1], newline='', encoding='utf-8') as source:
    for customer_id, name, status in csv.reader(source):
        print(f"{customer_id}: {name} ({status})")
PY
```

### 2.3 Hazardous form

```bash
#!/usr/bin/env bash
while IFS=, read -r customer_id name status; do
  echo "$customer_id: $name ($status)"
done < "$1"
```

### 2.4 Why this difference matters

A valid row such as `7,"Smith, Ana",active` is split at its quoted comma and assigns incorrect fields.

## 3. Boundaries and distinctions

`IFS` splitting is suitable for a deliberately simple delimiter format, but CSV requires a parser that implements quoting and escaping.
