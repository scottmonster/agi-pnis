# Use `html/template` for HTML output

## 1. Catalog record

- **Catalog identifier:** 4.3.1
- **Impact:** high
- **Consensus:** high
- **Definition:** Render untrusted data into HTML with `html/template`, not `text/template`, and do not convert untrusted strings to trusted `template.HTML`, `template.JS`, or related safe-content types.

## 2. Example

### 2.1 Scenario

A profile page displays a visitor-provided display name inside an HTML heading.

### 2.2 Preferred form

```go
package example

import (
	"html/template"
	"io"
)

func renderProfile(w io.Writer, displayName string) error {
	t, err := template.New("profile").Parse("<h1>{{.}}</h1>")
	if err != nil {
		return err
	}
	return t.Execute(w, displayName)
}
```

### 2.3 Hazardous form

```go
package example

import (
	"io"
	"text/template"
)

func renderProfile(w io.Writer, displayName string) error {
	t, err := template.New("profile").Parse("<h1>{{.}}</h1>")
	if err != nil {
		return err
	}
	return t.Execute(w, displayName)
}
```

### 2.4 Why this difference matters

`html/template` contextually escapes the display name. `text/template` emits it unchanged, so input such as a script element can become executable markup.

## 3. Boundaries and distinctions

Use `text/template` for plain text formats, not HTML. Trusted safe-content template types are an escape hatch for reviewed constant or sanitized content, not a conversion to apply to user input.
