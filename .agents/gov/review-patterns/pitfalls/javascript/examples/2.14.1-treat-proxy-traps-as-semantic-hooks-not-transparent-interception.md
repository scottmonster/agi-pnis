# Treat Proxy traps as semantic hooks, not transparent interception

## 1. Catalog record

- **Catalog identifier:** 2.14.1
- **Impact:** medium
- **Consensus:** high
- **Definition:** Design proxy traps as observable behavior, including invariants and receiver effects.

## 2. Example

### 2.1 Scenario

A proxy provides a readable fallback for unknown configuration values.

### 2.2 Preferred form

```javascript
const target = Object.freeze({ mode: "safe" });
const settings = new Proxy(target, {
  get(object, key, receiver) {
    if (Reflect.has(object, key)) return Reflect.get(object, key, receiver);
    return "default";
  },
});

console.log(settings.mode);
```

### 2.3 Hazardous form

```javascript
const target = Object.freeze({ mode: "safe" });
const settings = new Proxy(target, {
  get() {
    return "overridden";
  },
});

console.log(settings.mode);
```

### 2.4 Why this difference matters

The hazardous trap violates the invariant for a frozen non-configurable, non-writable property and throws instead of transparently returning a replacement value.

## 3. Boundaries and distinctions

Proxy traps can intentionally transform behavior, but they must respect language invariants and should use `Reflect` when normal receiver semantics are needed.
