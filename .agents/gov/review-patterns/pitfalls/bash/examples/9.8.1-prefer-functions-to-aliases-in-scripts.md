# Prefer functions to aliases in scripts

## 1. Catalog record

- **Catalog identifier:** 9.8.1
- **Impact:** medium
- **Consensus:** high
- **Definition:** Use functions for reusable scripted commands because aliases are parse-time interactive conveniences without normal parameter behavior.

## 2. Example

### 2.1 Scenario

A build script needs a reusable command that accepts an artifact name.

### 2.2 Preferred form

```bash
#!/usr/bin/env bash
set -euo pipefail

publish_artifact() {
  local artifact_name=$1
  printf 'publishing %s\n' "$artifact_name"
}

publish_artifact "service-api"
```

### 2.3 Hazardous form

```bash
#!/usr/bin/env bash
set -euo pipefail

alias publish_artifact='printf "publishing %s\\n"'
publish_artifact "service-api"
```

### 2.4 Why this difference matters

Aliases are normally disabled in non-interactive scripts and expand while the shell parses commands, so they do not provide dependable parameterized behavior.

## 3. Boundaries and distinctions

Aliases remain useful as interactive shortcuts when their parse-time expansion and lack of parameters are intentional.
