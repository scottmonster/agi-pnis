# Partially satisfying the requirement

## 1. Catalog record

- **Catalog identifier:** 1.2
- **Evidence:** e
- **Definition:** Gets the central case right while silently omitting secondary requirements.

## 2. Scenario

### 2.1 Context

A task asks to add account deletion, revoke existing sessions, and write an audit event. The deletion endpoint and session store already exist.

### 2.2 Safer approach

Turn each stated outcome into an acceptance check, implement deletion plus session revocation and audit logging, then test all three effects.

### 2.3 Failure mode

The agent adds the deletion endpoint and its success response but never revokes sessions or records the audit event.

### 2.4 Why this difference matters

The obvious path works while the account remains usable through existing sessions and the required operational record is missing.

## 3. Boundaries and distinctions

This is not a request to add unstated features. The missing work is explicitly required but secondary to the central deletion action.
