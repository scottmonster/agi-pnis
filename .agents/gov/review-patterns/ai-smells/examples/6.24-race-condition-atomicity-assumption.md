# Race condition / atomicity assumption

## 1. Catalog record

- **Catalog identifier:** 6.24
- **Evidence:** se
- **Definition:** Assumes separate reads and writes occur as one indivisible operation when concurrent execution can interleave them.

## 2. Scenario

### 2.1 Context

Two workers can redeem the last remaining coupon at the same time.

### 2.2 Safer approach

The agent uses an atomic conditional update or transaction that records redemption only if capacity remains.

### 2.3 Failure mode

Each worker reads one available redemption, then both write a successful redemption.

### 2.4 Why this difference matters

Concurrent execution violates the one-redemption limit even though each isolated code path looks correct.

## 3. Boundaries and distinctions

This matters only where concurrent interleaving is possible; a single serialized execution path does not create the same race.
