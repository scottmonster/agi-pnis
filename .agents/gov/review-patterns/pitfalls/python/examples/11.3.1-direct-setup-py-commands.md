# Direct `setup.py` commands

## 1. Catalog record

- **Catalog identifier:** 11.3.1
- **Impact:** medium
- **Consensus:** high
- **Definition:** Do not run commands such as `python setup.py install`, `develop`, or `sdist` as the normal modern workflow. Use standards-based frontends such as `pip` and `build`.

## 2. Example

### 2.1 Scenario

A maintainer needs to build and install a package during local development.

### 2.2 Preferred form

```python
# Shell commands:
# python -m build
# python -m pip install dist/invoice_tools-1.0.0-py3-none-any.whl

build_frontend = "python -m build"
print(build_frontend)
```

### 2.3 Hazardous form

```python
# Shell command:
# python setup.py install

legacy_command = "python setup.py install"
print(legacy_command)
```

### 2.4 Why this difference matters

Direct execution uses a deprecated command interface and can bypass standardized build and installation behavior expected by modern tooling.

## 3. Boundaries and distinctions

Existing projects may retain `setup.py` for compatibility, but build and install actions should go through standards-based frontends.
