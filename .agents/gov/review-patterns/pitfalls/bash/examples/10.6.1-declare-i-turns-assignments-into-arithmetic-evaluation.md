# `declare -i` turns assignments into arithmetic evaluation

## 1. Catalog record

- **Catalog identifier:** 10.6.1
- **Impact:** medium
- **Consensus:** medium
- **Definition:** Integer-attributed variables evaluate assigned values as arithmetic expressions, so uncontrolled strings should not be assigned to them implicitly.

## 2. Example

### 2.1 Scenario

A script receives a count that must be a nonnegative decimal number.

### 2.2 Preferred form

```bash
input='42'

if [[ $input =~ ^[0-9]+$ ]]; then
  count=$((10#$input))
  printf 'count: %d\n' "$count"
else
  printf 'invalid count: %s\n' "$input" >&2
  exit 1
fi
```

### 2.3 Hazardous form

```bash
input='2 + 2'
declare -i count

count=$input
printf 'count: %d\n' "$count"
```

### 2.4 Why this difference matters

The hazardous assignment looks like data storage but evaluates the input and prints `4`, turning an ordinary assignment into an evaluation boundary.

## 3. Boundaries and distinctions

Integer attributes are convenient for trusted internal values. Prefer explicit validation and arithmetic when data crosses a trust boundary.
