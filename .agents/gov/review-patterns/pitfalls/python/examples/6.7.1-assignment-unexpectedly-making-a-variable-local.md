# Assignment unexpectedly making a variable local

## 1. Catalog record

- **Catalog identifier:** 6.7.1
- **Impact:** medium
- **Consensus:** high
- **Definition:** Remember that assigning to a name anywhere in a function normally makes it local throughout that function unless declared `global` or `nonlocal`.

## 2. Example

### 2.1 Scenario

A nested function updates a counter owned by its enclosing function.

### 2.2 Preferred form

```python
def make_incrementer() -> callable:
    count = 0

    def increment() -> int:
        nonlocal count
        count += 1
        return count

    return increment


increment = make_incrementer()
assert increment() == 1
```

### 2.3 Hazardous form

```python
count = 0


def increment() -> int:
    count += 1
    return count


increment()
```

### 2.4 Why this difference matters

Because `increment()` assigns to `count`, Python treats it as local throughout that function. The attempted read for `count += 1` therefore raises `UnboundLocalError`.

## 3. Boundaries and distinctions

Use `nonlocal` only for a known enclosing binding and `global` only when shared module state is intentional. Passing state explicitly is often easier to test.
