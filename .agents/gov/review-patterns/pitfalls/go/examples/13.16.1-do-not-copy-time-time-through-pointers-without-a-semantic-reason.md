# Do not copy `time.Time` through pointers without a semantic reason

## 1. Catalog record

- **Catalog identifier:** 13.16.1
- **Impact:** low
- **Consensus:** high
- **Definition:** Store and pass ordinary `time.Time` values directly rather than using `*time.Time` merely because the type is a struct. Use a pointer only when optionality or mutation semantics require one.

## 2. Example

### 2.1 Scenario

A report formats the timestamp that is always present on a completed job.

### 2.2 Preferred form

```go
package example

import "time"

func completedAt(t time.Time) string {
	return t.UTC().Format(time.RFC3339)
}
```

### 2.3 Hazardous form

```go
package example

import "time"

func completedAt(t *time.Time) string {
	return t.UTC().Format(time.RFC3339)
}
```

### 2.4 Why this difference matters

`time.Time` is a value type designed to be copied and passed directly. The pointer version burdens every caller with a possible nil value even though completion time is required.

## 3. Boundaries and distinctions

Use `*time.Time` when nil represents an absent time, or when an API genuinely needs pointer identity or mutation semantics.
