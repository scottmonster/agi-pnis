# Use top-level await deliberately

## 1. Catalog record

- **Catalog identifier:** 8.1.2
- **Impact:** medium
- **Consensus:** high
- **Definition:** Do not put top-level await on a critical dependency path unless delayed evaluation is intended.

## 2. Example

### 2.1 Scenario

An application loads optional remote configuration during startup.

### 2.2 Preferred form

```javascript
// config.js
export async function loadConfig() {
  const response = await fetch("/api/config");
  return response.json();
}

// app.js
import { loadConfig } from "./config.js";

async function start() {
  const config = await loadConfig();
  console.log(`started in ${config.mode} mode`);
}

start().catch(console.error);
```

### 2.3 Hazardous form

```javascript
// config.js
const response = await fetch("/api/config");
export const config = await response.json();

// app.js
import { config } from "./config.js";

console.log(`started in ${config.mode} mode`);
```

### 2.4 Why this difference matters

The hazardous module prevents its importers from evaluating until the network request completes, putting remote latency and failure on their dependency path.

## 3. Boundaries and distinctions

Top-level await is appropriate when a module must not become usable before asynchronous initialization completes and its importers are designed for that delay.
