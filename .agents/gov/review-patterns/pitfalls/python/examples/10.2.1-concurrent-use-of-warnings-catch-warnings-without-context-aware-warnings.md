# Concurrent use of `warnings.catch_warnings()` without context-aware warnings

## 1. Catalog record

- **Catalog identifier:** 10.2.1
- **Impact:** medium
- **Consensus:** high
- **Definition:** In concurrent code, account for `sys.flags.context_aware_warnings`; without it, simultaneous `catch_warnings()` use is not concurrency-safe.

## 2. Example

### 2.1 Scenario

A test helper temporarily changes warning handling while several threads may execute at the same time.

### 2.2 Preferred form

```python
import sys
import warnings

def run_with_warning_capture() -> list[warnings.WarningMessage]:
    if not sys.flags.context_aware_warnings:
        raise RuntimeError("warning capture requires serialized execution")
    with warnings.catch_warnings(record=True) as captured:
        warnings.simplefilter("always")
        warnings.warn("check configuration", UserWarning)
        return captured
```

### 2.3 Hazardous form

```python
import warnings

def run_with_warning_capture() -> list[warnings.WarningMessage]:
    with warnings.catch_warnings(record=True) as captured:
        warnings.simplefilter("always")
        warnings.warn("check configuration", UserWarning)
        return captured
```

### 2.4 Why this difference matters

Without context-aware warnings, the hazardous form temporarily changes global warning state, so concurrent callers can interfere with one another's filters or captured messages.

## 3. Boundaries and distinctions

The context-aware setting permits safer concurrent use. Otherwise, serialize warning-state changes or avoid changing global warning policy during concurrent execution.
