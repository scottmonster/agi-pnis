# Compare enums through enum members rather than raw underlying values

## 1. Catalog record

- **Catalog identifier:** 10.8.1
- **Impact:** low
- **Consensus:** high
- **Definition:** Prefer `status === Status.Ready` over `status === 2` or the equivalent raw string when the value is conceptually an enum.

## 2. Example

### 2.1 Scenario

An import worker retries only imports that reached the failed stage.

### 2.2 Preferred form

```typescript
enum ImportStage {
  Queued = 10,
  Processing = 20,
  Failed = 30,
}

function shouldRetry(stage: ImportStage): boolean {
  return stage === ImportStage.Failed;
}
```

### 2.3 Hazardous form

```typescript
enum ImportStage {
  Queued = 10,
  Processing = 20,
  Failed = 500,
}

function shouldRetry(stage: ImportStage, failedWireValue = 30): boolean {
  return stage === failedWireValue;
}
```

### 2.4 Why this difference matters

The raw number hides the enum abstraction and remains stale when the member's representation changes. Comparing with the member name preserves the domain meaning and follows the updated value.

## 3. Boundaries and distinctions

Use raw literals at a serialization or protocol boundary where the literal itself is the documented contract. Convert there, then use enum members within the domain model.
