# Eager string formatting in disabled logging calls

## 1. Catalog record

- **Catalog identifier:** 13.4.1
- **Impact:** medium
- **Consensus:** high
- **Definition:** When formatting work is material, pass the format string and arguments separately, such as `logger.debug("value=%s", value)`, rather than eagerly constructing the final message.

## 2. Example

### 2.1 Scenario

A service emits debug information containing an expensive representation while production logging is set above debug level.

### 2.2 Preferred form

```python
import logging


logger = logging.getLogger(__name__)
logger.setLevel(logging.INFO)

payload = list(range(1_000))
logger.debug("payload=%s", payload)
```

### 2.3 Hazardous form

```python
import logging


logger = logging.getLogger(__name__)
logger.setLevel(logging.INFO)

payload = list(range(1_000))
logger.debug(f"payload={payload}")
```

### 2.4 Why this difference matters

The f-string is evaluated before `debug()` can reject the disabled message. Deferred logger formatting avoids constructing the final representation unless the record is emitted.

## 3. Boundaries and distinctions

For truly expensive argument creation, guard the computation with `logger.isEnabledFor(logging.DEBUG)`. The benefit is negligible for simple values whose evaluation is already required.
