# Wrong-file persistence

## 1. Catalog record

- **Catalog identifier:** 13.10
- **Evidence:** a
- **Definition:** Keeps modifying an incorrect location rather than re-localizing the problem.

## 2. Scenario

### 2.1 Context

The repository contains a generated OpenAPI client and its source schema. A behavior change disappears whenever code generation runs.

### 2.2 Safer approach

The agent recognizes the overwrite, identifies the schema as the owned source, changes it, and regenerates the client through the documented command.

### 2.3 Failure mode

The agent edits the generated client again and again after each regeneration removes the change.

### 2.4 Why this difference matters

Repeated edits to the wrong ownership layer cannot make the change durable.

## 3. Boundaries and distinctions

An initially plausible location may prove wrong. The failure is continuing there after evidence calls for renewed localization.
