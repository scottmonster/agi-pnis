# Treat associative-array subscripts as version-sensitive evaluation contexts

## 1. Catalog record

- **Catalog identifier:** 4.4.1
- **Impact:** high
- **Consensus:** medium
- **Definition:** Avoid untrusted associative-array keys in evaluative contexts and verify idioms on supported Bash versions.

## 2. Example

### 2.1 Scenario

A script looks up a user-supplied label in an associative array while supporting a defined Bash version range.

### 2.2 Preferred form

```bash
#!/usr/bin/env bash

if (( BASH_VERSINFO[0] < 5 )); then
  printf 'Bash 5 or later is required\n' >&2
  exit 2
fi

declare -A labels=([prod]=production [stage]=staging)
key=${1:?provide a label key}
printf '%s\n' "${labels[$key]-unknown}"
```

### 2.3 Hazardous form

```bash
#!/usr/bin/env bash

declare -A values=([safe]=10)
key=${1:?provide a key}
total=0
(( total += values[$key] ))
printf '%s\n' "$total"
```

### 2.4 Why this difference matters

Associative-array subscripts have had version-dependent repeated-evaluation behavior in arithmetic and related expressions. Feeding untrusted key text into those contexts can create unexpected expansion or execution risks.

## 3. Boundaries and distinctions

Verify subscript idioms against every Bash version you support. The direct lookup shown here avoids placing the key in an arithmetic expression.
