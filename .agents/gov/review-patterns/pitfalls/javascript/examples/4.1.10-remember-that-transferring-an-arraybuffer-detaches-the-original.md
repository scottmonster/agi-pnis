# Remember that transferring an ArrayBuffer detaches the original

## 1. Catalog record

- **Catalog identifier:** 4.1.10
- **Impact:** medium
- **Consensus:** high
- **Definition:** After an `ArrayBuffer` is transferred, do not continue using the original buffer or its views as if they still own the memory.

## 2. Example

### 2.1 Scenario

A worker-bound message transfers a binary payload so ownership can move without copying its bytes.

### 2.2 Preferred form

```javascript
const original = new Uint8Array([65, 66]).buffer;
const received = structuredClone({ payload: original }, { transfer: [original] });
const bytes = new Uint8Array(received.payload);

console.log(bytes[0]);
```

### 2.3 Hazardous form

```javascript
const original = new Uint8Array([65, 66]).buffer;
const bytes = new Uint8Array(original);
structuredClone({ payload: original }, { transfer: [original] });

console.log(bytes[0]);
```

### 2.4 Why this difference matters

Transfer detaches the original buffer, so its previous views no longer provide their former data and code can fail or observe an empty view.

## 3. Boundaries and distinctions

Transfer is useful when exclusive ownership should move. Clone without transfer when both sides need independent copies, accepting the memory and copy cost.
