# Changing array length can delete data or create holes

## 1. Catalog record

- **Catalog identifier:** 3.1.5
- **Impact:** medium
- **Consensus:** high
- **Definition:** Assigning a smaller `length` deletes elements beyond the new length. Increasing it creates empty slots rather than initialized `undefined` elements.

## 2. Example

### 2.1 Scenario

A queue implementation needs to retain its entries while preparing capacity for future work.

### 2.2 Preferred form

```javascript
const queue = ["first", "second"];
const reservedSlots = Array.from({ length: 2 }, () => undefined);
const expandedQueue = [...queue, ...reservedSlots];

console.log(expandedQueue); // ["first", "second", undefined, undefined]
```

### 2.3 Hazardous form

```javascript
const queue = ["first", "second", "third"];
queue.length = 2;
queue.length = 4;

console.log(queue); // ["first", "second", <2 empty items>]
```

### 2.4 Why this difference matters

Shortening `length` permanently deletes later elements, and growing it back creates holes rather than restoring values or initializing entries.

## 3. Boundaries and distinctions

Changing `length` is useful for deliberate truncation. Treat it as a destructive array operation, not ordinary metadata assignment.
