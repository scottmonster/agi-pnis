# Patching where an object is defined rather than looked up

## 1. Catalog record

- **Catalog identifier:** 12.5.1
- **Impact:** medium
- **Consensus:** high
- **Definition:** With `unittest.mock.patch`, patch the name in the namespace where the code under test looks it up, not necessarily the module where the original object was defined.

## 2. Example

### 2.1 Scenario

An order module imported a notification function and a test must stop that imported reference from sending a message.

### 2.2 Preferred form

```python
# notifier.py
def send(address: str) -> None:
    print(f"sent to {address}")


# orders.py
from notifier import send


def complete_order(address: str) -> None:
    send(address)


# test_orders.py
from unittest.mock import patch
from orders import complete_order


with patch("orders.send") as mocked_send:
    complete_order("customer@example.com")
    mocked_send.assert_called_once_with("customer@example.com")
```

### 2.3 Hazardous form

```python
# notifier.py defines send, while orders.py has already imported it.
from unittest.mock import patch
from orders import complete_order


with patch("notifier.send") as mocked_send:
    complete_order("customer@example.com")
    mocked_send.assert_called_once()
```

### 2.4 Why this difference matters

`orders` looks up its own imported `send` name, so replacing `notifier.send` later does not replace the reference used by `complete_order`. The hazardous test can trigger real behavior and fail to observe the call.

## 3. Boundaries and distinctions

If code accesses `notifier.send` through the module object at call time, patching `notifier.send` is correct. Patch the lookup location used by the code path under test.
