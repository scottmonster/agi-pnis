# `slices.Clone` is shallow

## 1. Catalog record

- **Catalog identifier:** 7.15.1
- **Impact:** medium
- **Consensus:** high
- **Definition:** `slices.Clone` separates the outer backing array but copies elements by assignment. Elements containing pointers, maps, slices, or other references still alias their original targets.

## 2. Example

### 2.1 Scenario

A service clones a list of configuration maps before allowing a caller to edit it.

### 2.2 Preferred form

```go
package config

import "slices"

func copySettings(source []map[string]string) []map[string]string {
	result := slices.Clone(source)
	for index, setting := range result { result[index] = mapsClone(setting) }
	return result
}

func mapsClone(source map[string]string) map[string]string {
	result := make(map[string]string, len(source))
	for key, value := range source { result[key] = value }
	return result
}
```

### 2.3 Hazardous form

```go
package config

import "slices"

func change(source []map[string]string) {
	copy := slices.Clone(source)
	copy[0]["mode"] = "debug" // Also changes source[0].
}
```

### 2.4 Why this difference matters

Only the outer slice's backing array is copied. Each map element still refers to its original map.

## 3. Boundaries and distinctions

`slices.Clone` is enough for values that have no mutable referenced state, or when that sharing is intentional.
