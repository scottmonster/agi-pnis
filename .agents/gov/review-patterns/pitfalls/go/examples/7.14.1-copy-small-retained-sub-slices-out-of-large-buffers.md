# Copy small retained sub-slices out of large buffers

## 1. Catalog record

- **Catalog identifier:** 7.14.1
- **Impact:** medium
- **Consensus:** high
- **Definition:** If a tiny slice must outlive a large backing array, copy the needed elements into a right-sized allocation.

## 2. Example

### 2.1 Scenario

A log parser retains only the first field from a multi-megabyte input buffer.

### 2.2 Preferred form

```go
package logs

import "bytes"

func firstField(buffer []byte) []byte {
	field, _, _ := bytes.Cut(buffer, []byte(" "))
	return append([]byte(nil), field...)
}
```

### 2.3 Hazardous form

```go
package logs

import "bytes"

func firstField(buffer []byte) []byte {
	field, _, _ := bytes.Cut(buffer, []byte(" "))
	return field // Retains buffer's entire backing array.
}
```

### 2.4 Why this difference matters

Retaining a small view keeps the whole large allocation reachable, increasing long-lived memory use.

## 3. Boundaries and distinctions

Avoid an extra allocation when the original buffer is already small or must remain retained for other reasons.
