# Check `cd` before operating on relative paths

## 1. Catalog record

- **Catalog identifier:** 1.11.1
- **Impact:** high
- **Consensus:** high
- **Definition:** Use forms such as `cd -- "$dir" || exit` or `cd -- "$dir" || return` before commands whose meaning depends on the directory change.

## 2. Example

### 2.1 Scenario

A deployment cleanup script must remove generated files only from the supplied project directory. Its removal command uses a relative path after changing directories.

### 2.2 Preferred form

```bash
#!/usr/bin/env bash

project_dir=${1:?Usage: "$0" PROJECT_DIR}

cd -- "$project_dir" || exit 1
rm -f -- build/*.tmp
```

### 2.3 Hazardous form

```bash
#!/usr/bin/env bash

project_dir=${1:?Usage: "$0" PROJECT_DIR}

cd -- "$project_dir"
rm -f -- build/*.tmp
```

### 2.4 Why this difference matters

If the directory does not exist or cannot be entered, the hazardous script continues in its original working directory. It can then delete that directory's `build` files instead of the intended project's files. The explicit failure branch prevents relative operations after an unsuccessful `cd`.

## 3. Boundaries and distinctions

When a function changes directory, use `return` instead of `exit` so the caller can decide how to handle the failure. Absolute-path operations do not rely on a successful `cd`, though they still need their own path validation.
