# Use `ParseInLocation` for location-dependent local times

## 1. Catalog record

- **Catalog identifier:** 7.4.1
- **Impact:** medium
- **Consensus:** high
- **Definition:** When input without an offset is intended to represent time in a known location, use `time.ParseInLocation`. Prefer numeric offsets over ambiguous zone abbreviations in interchange formats.

## 2. Example

### 2.1 Scenario

A store receives `2026-09-04 09:00` as a customer appointment in Chicago time.

### 2.2 Preferred form

```go
package appointments

import "time"

func parseLocal(value string) (time.Time, error) {
	chicago, err := time.LoadLocation("America/Chicago")
	if err != nil { return time.Time{}, err }
	return time.ParseInLocation("2006-01-02 15:04", value, chicago)
}
```

### 2.3 Hazardous form

```go
package appointments

import "time"

func parseLocal(value string) (time.Time, error) {
	return time.Parse("2006-01-02 15:04", value)
}
```

### 2.4 Why this difference matters

`time.Parse` treats a zone-less value as UTC, shifting the customer's intended local appointment.

## 3. Boundaries and distinctions

For interchange, include a numeric offset in the input. Zone abbreviations can be ambiguous.
