# Run independent asynchronous operations concurrently when appropriate

## 1. Catalog record

- **Catalog identifier:** 7.1.10
- **Impact:** medium
- **Consensus:** high
- **Definition:** If operations are independent, start them before awaiting their combined result rather than serially awaiting each operation. `Promise.all()` is often appropriate.

## 2. Example

### 2.1 Scenario

A dashboard needs an independent user profile and notification count before rendering.

### 2.2 Preferred form

```javascript
function loadProfile() {
  return Promise.resolve({ name: "Ari" });
}

function loadNotificationCount() {
  return Promise.resolve(3);
}

async function loadDashboard() {
  const [profile, notifications] = await Promise.all([loadProfile(), loadNotificationCount()]);
  return { profile, notifications };
}

loadDashboard().then(console.log, console.error);
```

### 2.3 Hazardous form

```javascript
function loadProfile() {
  return Promise.resolve({ name: "Ari" });
}

function loadNotificationCount() {
  return Promise.resolve(3);
}

async function loadDashboard() {
  const profile = await loadProfile();
  const notifications = await loadNotificationCount();
  return { profile, notifications };
}

loadDashboard().then(console.log, console.error);
```

### 2.4 Why this difference matters

The serial form unnecessarily waits for one independent operation before beginning the next, increasing wall-clock latency.

## 3. Boundaries and distinctions

Keep operations serial when the second needs the first result, ordering, rate limiting, or resource constraints require it.
