# Hardcoded credentials in build/config files

## 1. Catalog record

- **Catalog identifier:** 8.14
- **Evidence:** e
- **Definition:** Stores a password, token, or other secret in tracked build or configuration material.

## 2. Scenario

### 2.1 Context

An agent configures publishing a package to the organization's private registry from continuous integration.

### 2.2 Safer approach

It references the CI platform's protected secret variable, keeps the checked-in configuration credential-free, and verifies that logs redact the token.

### 2.3 Failure mode

It places a registry access token directly in the tracked build configuration so publishing works immediately from a local machine.

### 2.4 Why this difference matters

Anyone with repository, build-log, artifact, or copied-config access may obtain the credential and use it beyond the intended publishing workflow.

## 3. Boundaries and distinctions

Nonsecret identifiers, such as a registry hostname or token variable name, may belong in tracked configuration. The failure is placing the secret value itself in material likely to be committed, copied, or deployed.
