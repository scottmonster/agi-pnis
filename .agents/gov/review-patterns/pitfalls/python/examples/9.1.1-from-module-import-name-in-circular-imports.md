# `from module import name` in circular imports

## 1. Catalog record

- **Catalog identifier:** 9.1.1
- **Impact:** medium
- **Consensus:** high
- **Definition:** Avoid circular imports where partially initialized modules must satisfy `from module import name`. Refactor dependencies or, where appropriate, import the module and defer attribute access.

## 2. Example

### 2.1 Scenario

An order service needs a shared currency constant while the currency module also imports the service.

### 2.2 Preferred form

```python
# currency.py
DEFAULT_CURRENCY = "USD"

# order_service.py
import currency

def format_total(amount: int) -> str:
    return f"{amount} {currency.DEFAULT_CURRENCY}"
```

### 2.3 Hazardous form

```python
# currency.py
from order_service import format_total
DEFAULT_CURRENCY = "USD"

# order_service.py
from currency import DEFAULT_CURRENCY

def format_total(amount: int) -> str:
    return f"{amount} {DEFAULT_CURRENCY}"
```

### 2.4 Why this difference matters

The second arrangement can request `DEFAULT_CURRENCY` before `currency.py` has finished defining it, causing an import-time failure.

## 3. Boundaries and distinctions

Importing a module and accessing a value later can help in a small cycle, but extracting shared code into a third module is usually the clearer long-term design.
