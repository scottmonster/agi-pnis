# `http.server` in production

## 1. Catalog record

- **Catalog identifier:** 2.21.1
- **Impact:** high
- **Consensus:** high
- **Definition:** Do not use `http.server` as a production HTTP server.

## 2. Example

### 2.1 Scenario

A small application needs to serve its API to internet users. Its deployment must provide production-grade request handling and security controls.

### 2.2 Preferred form

```python
# app.py
def application(environ, start_response):
    body = b"healthy\n"
    start_response("200 OK", [("Content-Type", "text/plain")])
    return [body]


# Deploy with a production-capable WSGI server, for example:
# gunicorn --workers 4 app:application
```

### 2.3 Hazardous form

```python
from http.server import SimpleHTTPRequestHandler, ThreadingHTTPServer


server = ThreadingHTTPServer(("0.0.0.0", 8000), SimpleHTTPRequestHandler)
server.serve_forever()
```

### 2.4 Why this difference matters

`http.server` is intended for basic development and utility use, not an exposed production service. Treating it as production infrastructure can leave availability and security responsibilities unmet.

## 3. Boundaries and distinctions

`http.server` is useful for local development, tests, and controlled temporary file sharing. The preferred application must still be deployed with a production-capable server and appropriate operational controls.
