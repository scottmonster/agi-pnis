# No regression test for the original failure

## 1. Catalog record

- **Catalog identifier:** 9.19
- **Evidence:** a/se
- **Definition:** Fixes a defect without adding or preserving an automated check that fails on the old behavior.

## 2. Scenario

### 2.1 Context

A user reports that a null optional address causes checkout to crash.

### 2.2 Safer approach

Add a test that reproduces the null address, observe it fail on the old code, then retain it after the fix.

### 2.3 Failure mode

Add a null guard and manually verify checkout once, without any automated regression test.

### 2.4 Why this difference matters

Future edits can reintroduce the original crash with no persistent signal in the suite.

## 3. Boundaries and distinctions

If an automated reproduction is infeasible, preserve the strongest practical verification and document the constraint rather than claiming a regression test exists.
