# Confusing or inconsistent naming

## 1. Catalog record

- **Catalog identifier:** 5.19
- **Evidence:** e
- **Definition:** Names shadow built-ins, drift between concepts, or fail to follow local conventions.

## 2. Scenario

### 2.1 Context

A Python service names a list `list`, calls customer IDs `accountId` in one module and `user_key` in another, and ignores the repository's snake_case convention.

### 2.2 Safer approach

Follow local naming conventions and choose names that distinguish the actual domain concepts.

### 2.3 Failure mode

Introduce `dict` as a variable and call the same identifier `client_ref` in only one neighboring module.

### 2.4 Why this difference matters

Ambiguous names mislead readers and can hide incorrect data flow or misuse of language facilities.

## 3. Boundaries and distinctions

Different layers can legitimately use translated names. The problem is unexplained drift, shadowing, or inconsistency within a shared codebase.
