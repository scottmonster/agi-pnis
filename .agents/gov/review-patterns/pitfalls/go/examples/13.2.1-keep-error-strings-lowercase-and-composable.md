# Keep error strings lowercase and composable

## 1. Catalog record

- **Catalog identifier:** 13.2.1
- **Impact:** low
- **Consensus:** high
- **Definition:** Normally start error strings with lowercase text and omit terminal punctuation unless a proper noun or other grammatical requirement dictates otherwise.

## 2. Example

### 2.1 Scenario

A parser returns an error that its caller adds context to before showing it to an operator.

### 2.2 Preferred form

```go
package example

import "fmt"

func parsePort(text string) error {
	return fmt.Errorf("invalid port %q", text)
}

func load() error {
	return fmt.Errorf("load configuration: %w", parsePort("abc"))
}
```

### 2.3 Hazardous form

```go
package example

import "fmt"

func parsePort(text string) error {
	return fmt.Errorf("Invalid port %q.", text)
}

func load() error {
	return fmt.Errorf("load configuration: %w", parsePort("abc"))
}
```

### 2.4 Why this difference matters

Lowercase fragments compose naturally as "load configuration: invalid port \"abc\"". A capitalized, punctuated fragment reads awkwardly after a caller has added context.

## 3. Boundaries and distinctions

Capitalize names that require it, such as proper nouns, and use sentence punctuation when an error is deliberately presented as standalone prose.
