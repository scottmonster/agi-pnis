# SQL construction with Python string formatting

## 1. Catalog record

- **Catalog identifier:** 2.15.1
- **Impact:** high
- **Consensus:** high
- **Definition:** Pass SQL values through database parameter placeholders rather than f-strings, concatenation, `%`, or `.format()`.

## 2. Example

### 2.1 Scenario

A lookup endpoint retrieves a customer row from a SQLite database using an email address supplied in a request.

### 2.2 Preferred form

```python
import sqlite3


def find_customer(connection: sqlite3.Connection, email: str) -> tuple | None:
    return connection.execute(
        "SELECT id, email FROM customers WHERE email = ?", (email,)
    ).fetchone()
```

### 2.3 Hazardous form

```python
import sqlite3


def find_customer(connection: sqlite3.Connection, email: str) -> tuple | None:
    query = f"SELECT id, email FROM customers WHERE email = '{email}'"
    return connection.execute(query).fetchone()
```

### 2.4 Why this difference matters

String formatting mixes SQL syntax with data, allowing a value to alter the query. Parameters keep values separate and let the driver escape them correctly.

## 3. Boundaries and distinctions

Placeholders bind values, not SQL identifiers. Choose identifiers from a trusted allowlist when they must vary dynamically.
