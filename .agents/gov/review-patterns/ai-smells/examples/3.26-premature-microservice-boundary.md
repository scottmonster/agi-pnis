# Premature microservice boundary

## 1. Catalog record

- **Catalog identifier:** 3.26
- **Evidence:** se
- **Definition:** Splits a local concern into an independently deployed service without operational justification.

## 2. Scenario

### 2.1 Context

One application calculates tax as part of checkout.

### 2.2 Safer approach

Keep tax calculation as a well-tested local module in the application.

### 2.3 Failure mode

Extract it into a separately deployed service with HTTP contracts, credentials, and release coordination for no operational need.

### 2.4 Why this difference matters

The split adds network failures, deployment overhead, and distributed contract maintenance.

## 3. Boundaries and distinctions

A service boundary can be justified by independent ownership, scaling, or deployment needs; local code should not be split merely for architecture style.
