# Force-terminating processes that hold shared resources

## 1. Catalog record

- **Catalog identifier:** 3.6.1
- **Impact:** high
- **Consensus:** high
- **Definition:** Prefer cooperative process shutdown when a worker uses queues, pipes, locks, semaphores, or other shared state. Reserve `terminate()` for cases where those resources are not at risk.

## 2. Example

### 2.1 Scenario

A worker receives jobs through a multiprocessing queue. The parent needs it to finish safely before shutdown.

### 2.2 Preferred form

```python
from multiprocessing import Process, Queue


def worker(jobs: Queue[str]) -> None:
    for job in iter(jobs.get, None):
        print(f"processed {job}")


if __name__ == "__main__":
    jobs: Queue[str] = Queue()
    process = Process(target=worker, args=(jobs,))
    process.start()
    jobs.put("invoice-42")
    jobs.put(None)
    process.join()
```

### 2.3 Hazardous form

```python
from multiprocessing import Process, Queue


def worker(jobs: Queue[str]) -> None:
    while True:
        print(f"processed {jobs.get()}")


if __name__ == "__main__":
    jobs: Queue[str] = Queue()
    process = Process(target=worker, args=(jobs,))
    process.start()
    jobs.put("invoice-42")
    process.terminate()
    process.join()
```

### 2.4 Why this difference matters

`terminate()` can stop a process while it owns a shared resource or is writing IPC data. That can corrupt communication or leave other participants blocked.

## 3. Boundaries and distinctions

Forced termination can be necessary for an unresponsive worker when no shared state is at risk. Treat it as an escalation path with recovery handling, not routine shutdown.
