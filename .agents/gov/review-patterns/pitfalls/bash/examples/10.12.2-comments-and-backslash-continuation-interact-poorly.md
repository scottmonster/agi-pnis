# Comments and backslash continuation interact poorly

## 1. Catalog record

- **Catalog identifier:** 10.12.2
- **Impact:** low
- **Consensus:** high
- **Definition:** A comment cannot safely act as an invisible item within a backslash-continued command; move it or restructure the command.

## 2. Example

### 2.1 Scenario

A script documents the second argument of a multi-line command.

### 2.2 Preferred form

```bash
# Print the current deployment state and its source.
printf '%s: %s\n' \
  'state' \
  'generated'
```

### 2.3 Hazardous form

```bash
printf '%s: %s\n' \
  'state' \
  # The source is generated.
  'generated'
```

### 2.4 Why this difference matters

The comment terminates at its newline, leaving `generated` to be parsed as a command instead of the final `printf` argument.

## 3. Boundaries and distinctions

Comments are safe before or after a complete command. Keep them outside the token sequence formed by line continuations.
