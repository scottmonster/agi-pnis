# Poor cohesion

## 1. Catalog record

- **Catalog identifier:** 5.15
- **Evidence:** se
- **Definition:** A module or class contains responsibilities that change for unrelated reasons.

## 2. Scenario

### 2.1 Context

`UserService` manages profile edits, sends marketing emails, calculates tax, and rotates API keys.

### 2.2 Safer approach

Organize behavior around responsibilities that share domain ownership and change together.

### 2.3 Failure mode

Add subscription billing logic to `UserService` because it already has access to user IDs.

### 2.4 Why this difference matters

Independent policy changes repeatedly modify the same module and make its purpose unclear.

## 3. Boundaries and distinctions

A domain service may coordinate several closely related operations. Poor cohesion arises when responsibilities have unrelated reasons to change.
