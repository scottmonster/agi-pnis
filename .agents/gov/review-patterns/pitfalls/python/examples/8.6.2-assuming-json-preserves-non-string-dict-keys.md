# Assuming JSON preserves non-string dict keys

## 1. Catalog record

- **Catalog identifier:** 8.6.2
- **Impact:** medium
- **Consensus:** high
- **Definition:** Encode non-string mapping keys explicitly if their types must survive a JSON round trip.

## 2. Example

### 2.1 Scenario

An application stores integer account identifiers in JSON and needs them to remain integers after loading.

### 2.2 Preferred form

```python
import json

balances = {7: 1250}
encoded = json.dumps([[account_id, balance] for account_id, balance in balances.items()])
decoded = {account_id: balance for account_id, balance in json.loads(encoded)}

assert decoded == {7: 1250}
```

### 2.3 Hazardous form

```python
import json

balances = {7: 1250}
decoded = json.loads(json.dumps(balances))

assert decoded == {"7": 1250}
```

### 2.4 Why this difference matters

JSON object member names are strings, so direct encoding silently changes non-string dictionary keys.

## 3. Boundaries and distinctions

Direct JSON objects are appropriate when string keys are part of the intended external representation.
