# Secret embedded in source, config, build, test, or example files

## 1. Catalog record

- **Catalog identifier:** 10.2
- **Evidence:** e
- **Definition:** Includes sensitive credentials in material likely to be committed, copied, or deployed beyond its intended boundary.

## 2. Scenario

### 2.1 Context

A new integration test needs a cloud-service token.

### 2.2 Safer approach

Inject a short-lived test credential through the CI secret mechanism and document the required variable without recording its value.

### 2.3 Failure mode

The agent places a working token in `.env.example` so contributors can run the test immediately.

### 2.4 Why this difference matters

Files intended as examples or configuration are routinely copied, committed, and published, extending the credential's exposure.

## 3. Boundaries and distinctions

The issue is the credential's sensitive value and distribution path, not merely the presence of a configuration key or an obvious fake value.
