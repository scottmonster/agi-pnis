# Environment-specific constants disguised as universal defaults

## 1. Catalog record

- **Catalog identifier:** 12.14
- **Evidence:** se
- **Definition:** Bakes one environment’s hostnames, paths, limits, or credentials assumptions into defaults used elsewhere.

## 2. Scenario

### 2.1 Context

A shared service library defaults its API base URL to `https://staging.internal.example` because that is convenient for the development environment.

### 2.2 Safer approach

Require an explicit endpoint or select a documented environment-specific configuration, with safe defaults only when they genuinely apply across supported environments.

### 2.3 Failure mode

Publish the staging hostname as the library default and rely on production callers to remember to override it.

### 2.4 Why this difference matters

Production or test deployments can connect to the wrong service, fail unexpectedly, or apply an environment-specific assumption where it is invalid.

## 3. Boundaries and distinctions

Shared defaults are useful when they are truly portable. This failure concerns values that encode one environment’s assumptions while presenting themselves as universal.
