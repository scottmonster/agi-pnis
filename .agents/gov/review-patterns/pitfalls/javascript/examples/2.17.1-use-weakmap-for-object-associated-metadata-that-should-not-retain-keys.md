# Use WeakMap for object-associated metadata that should not retain keys

## 1. Catalog record

- **Catalog identifier:** 2.17.1
- **Impact:** medium
- **Consensus:** high
- **Definition:** Use `WeakMap` for metadata that must not keep its object keys alive.

## 2. Example

### 2.1 Scenario

A renderer associates layout metadata with temporary DOM elements.

### 2.2 Preferred form

```javascript
const layoutMetadata = new WeakMap();

function measure(element) {
  layoutMetadata.set(element, { measuredAt: Date.now() });
}
```

### 2.3 Hazardous form

```javascript
const layoutMetadata = new Map();

function measure(element) {
  layoutMetadata.set(element, { measuredAt: Date.now() });
}
```

### 2.4 Why this difference matters

A `Map` strongly retains its element keys, potentially keeping discarded elements and their metadata reachable. A `WeakMap` does not keep keys alive by itself.

## 3. Boundaries and distinctions

Use `Map` when entries must be enumerable, sized, or independently retained. WeakMap keys must be objects or non-null functions.
