# Assignment does not copy objects

## 1. Catalog record

- **Catalog identifier:** 6.1.1
- **Impact:** medium
- **Consensus:** high
- **Definition:** Remember that `b = a` creates another reference to the same object. Explicitly copy when independent mutable state is required.

## 2. Example

### 2.1 Scenario

A caller needs a working list that can be changed without changing the original request values.

### 2.2 Preferred form

```python
request_tags = ["new", "priority"]
working_tags = request_tags.copy()
working_tags.append("reviewed")

assert request_tags == ["new", "priority"]
```

### 2.3 Hazardous form

```python
request_tags = ["new", "priority"]
working_tags = request_tags
working_tags.append("reviewed")

assert request_tags == ["new", "priority", "reviewed"]
```

### 2.4 Why this difference matters

Assignment binds a second name to the same list, so mutation through either name is visible through both names.

## 3. Boundaries and distinctions

Assignment is efficient and correct when shared identity is intended. A shallow copy is sufficient only when nested mutable objects may also be shared.
