# Map elements are not addressable

## 1. Catalog record

- **Catalog identifier:** 7.9.1
- **Impact:** medium
- **Consensus:** high
- **Definition:** You cannot directly assign through a struct field of `m[k]`. Read, modify, and assign the entire value back, or store pointers when pointer semantics are actually desired.

## 2. Example

### 2.1 Scenario

A game tracks player scores as structs stored by name in a map.

### 2.2 Preferred form

```go
package game

type Player struct{ Score int }

func addPoint(players map[string]Player, name string) {
	player := players[name]
	player.Score++
	players[name] = player
}
```

### 2.3 Hazardous form

```go
package game

type Player struct{ Score int }

func addPoint(players map[string]Player, name string) {
	players[name].Score++ // does not compile: map element is not addressable
}
```

### 2.4 Why this difference matters

Map lookup produces a copy of the value, and Go does not allow a field assignment through that temporary copy.

## 3. Boundaries and distinctions

Store `*Player` values when shared mutable identity is intentional, and then handle nil and synchronization concerns explicitly.
