# Tickers may drop ticks

## 1. Catalog record

- **Catalog identifier:** 6.16.1
- **Impact:** medium
- **Consensus:** high
- **Definition:** Do not use ticker receives as a guaranteed count of elapsed periods.

## 2. Example

### 2.1 Scenario

A service runs potentially slow reconciliation periodically.

### 2.2 Preferred form

```go
package main

import "time"

func reconcile(ticker *time.Ticker) { for range ticker.C { reconcileCurrentState() } }
func reconcileCurrentState() {}
```

### 2.3 Hazardous form

```go
package main

import "time"

func charge(ticker *time.Ticker) int {
	count := 0
	for range ticker.C { count++; time.Sleep(2 * time.Minute); if count == 10 { return count } }
	return count
}
```

### 2.4 Why this difference matters

A slow receiver can miss ticks rather than queueing all of them. Counting receives must not drive billing or guaranteed scheduling.

## 3. Boundaries and distinctions

Tickers suit best-effort triggers. Compute elapsed time or use a durable scheduler when every interval matters.
