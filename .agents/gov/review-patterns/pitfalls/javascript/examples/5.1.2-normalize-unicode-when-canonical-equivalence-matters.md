# Normalize Unicode when canonical equivalence matters

## 1. Catalog record

- **Catalog identifier:** 5.1.2
- **Impact:** medium
- **Consensus:** high
- **Definition:** Use `String.prototype.normalize()` when text from different sources must compare according to Unicode canonical equivalence rather than raw code-unit identity.

## 2. Example

### 2.1 Scenario

A service compares a user-entered name with a value imported from another system.

### 2.2 Preferred form

```javascript
function sameCanonicalText(left, right) {
  return left.normalize("NFC") === right.normalize("NFC");
}

const fromImport = "Cafe\u0301";
const fromForm = "Café";
console.log(sameCanonicalText(fromImport, fromForm)); // true
```

### 2.3 Hazardous form

```javascript
const fromImport = "Cafe\u0301";
const fromForm = "Café";
console.log(fromImport === fromForm); // false
```

### 2.4 Why this difference matters

The same displayed text can have distinct Unicode sequences, so raw equality can create duplicate identities or failed lookups.

## 3. Boundaries and distinctions

Normalization changes code-unit representation. Apply a deliberately selected normalization form only at boundaries where canonical equivalence is part of the domain contract.
