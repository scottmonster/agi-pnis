# Dead code left after experimentation

## 1. Catalog record

- **Catalog identifier:** 11.14
- **Evidence:** e/se
- **Definition:** Leaves unreachable, unused, superseded, or permanently disabled code after the final approach is known.

## 2. Scenario

### 2.1 Context

While fixing an export bug, the agent tries two parsing approaches and keeps the second.

### 2.2 Safer approach

The agent removes the abandoned helper and disabled branch, then verifies the selected implementation and tests remain clear.

### 2.3 Failure mode

The agent leaves the first helper unused and wraps its old invocation in `if False` for possible future use.

### 2.4 Why this difference matters

Readers must distinguish active behavior from experiments, and obsolete code can be accidentally revived or maintained.

## 3. Boundaries and distinctions

Temporarily unreachable rollout code may be justified with ownership and an expiry; permanently abandoned experimentation should be removed.
