# Mark test helpers with `t.Helper`

## 1. Catalog record

- **Catalog identifier:** 13.13.1
- **Impact:** low
- **Consensus:** high
- **Definition:** Call `t.Helper()` in reusable functions that report test failures on behalf of their caller.

## 2. Example

### 2.1 Scenario

A reusable test helper reports a mismatch for the test that called it.

### 2.2 Preferred form

```go
package example

import "testing"

func requireEqual(t *testing.T, got, want int) {
	t.Helper()
	if got != want {
		t.Fatalf("got %d, want %d", got, want)
	}
}

func TestTotal(t *testing.T) { requireEqual(t, 2+2, 4) }
```

### 2.3 Hazardous form

```go
package example

import "testing"

func requireEqual(t *testing.T, got, want int) {
	if got != want {
		t.Fatalf("got %d, want %d", got, want)
	}
}

func TestTotal(t *testing.T) { requireEqual(t, 2+2, 4) }
```

### 2.4 Why this difference matters

Marking the helper moves failure reporting to the test call site. Without it, the reported line points inside the helper, slowing diagnosis as helpers are reused.

## 3. Boundaries and distinctions

Call `t.Helper` only in helpers that delegate failure reporting. A direct test body does not need to mark itself as a helper.
