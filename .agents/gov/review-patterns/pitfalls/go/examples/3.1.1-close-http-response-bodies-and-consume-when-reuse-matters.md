# Close HTTP response bodies and consume when reuse matters

## 1. Catalog record

- **Catalog identifier:** 3.1.1
- **Impact:** high
- **Consensus:** high
- **Definition:** When `Client.Do` succeeds, close `resp.Body`. For HTTP/1.x connection reuse, also read the body to EOF when appropriate and safely bounded.

## 2. Example

### 2.1 Scenario

A service polls a health endpoint whose documented payload is small and bounded. It uses a shared client, so reusable HTTP/1.x connections are valuable.

### 2.2 Preferred form

```go
package example

import (
	"io"
	"net/http"
)

func pollHealth(client *http.Client, url string) error {
	resp, err := client.Get(url)
	if err != nil {
		return err
	}
	defer resp.Body.Close()

	_, err = io.Copy(io.Discard, resp.Body)
	return err
}
```

### 2.3 Hazardous form

```go
package example

import "net/http"

func pollHealth(client *http.Client, url string) error {
	resp, err := client.Get(url)
	if err != nil {
		return err
	}
	if resp.StatusCode != http.StatusOK {
		return nil
	}
	return nil // The body is neither consumed nor closed.
}
```

### 2.4 Why this difference matters

Closing releases the response resource, and bounded consumption lets an HTTP/1.x transport reuse the connection when the complete body is safe to read. Leaving the body open can exhaust connections and eventually stall callers.

## 3. Boundaries and distinctions

Do not blindly consume an unbounded or untrusted body just to obtain reuse. Close every successful response, but use an appropriate limit or skip draining when reading the remainder is unsafe or unnecessary.
