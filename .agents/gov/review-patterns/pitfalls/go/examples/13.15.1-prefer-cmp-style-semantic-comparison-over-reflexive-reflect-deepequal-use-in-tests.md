# Prefer `cmp`-style semantic comparison over reflexive `reflect.DeepEqual` use in tests

## 1. Catalog record

- **Catalog identifier:** 13.15.1
- **Impact:** low
- **Consensus:** medium
- **Definition:** Choose comparison behavior deliberately rather than using `reflect.DeepEqual` for every structured test value.

## 2. Example

### 2.1 Scenario

A test compares API users where a server-generated update timestamp is intentionally outside the response contract.

### 2.2 Preferred form

```go
package example

import (
	"testing"
	"time"
)

type user struct { ID string; UpdatedAt time.Time }

func sameUser(got, want user) bool { return got.ID == want.ID }

func TestUser(t *testing.T) {
	got := user{ID: "42", UpdatedAt: time.Now()}
	want := user{ID: "42"}
	if !sameUser(got, want) { t.Fatalf("got %#v, want %#v", got, want) }
}
```

### 2.3 Hazardous form

```go
package example

import (
	"reflect"
	"testing"
	"time"
)

type user struct { ID string; UpdatedAt time.Time }

func TestUser(t *testing.T) {
	got := user{ID: "42", UpdatedAt: time.Now()}
	want := user{ID: "42"}
	if !reflect.DeepEqual(got, want) { t.Fatalf("users differ") }
}
```

### 2.4 Why this difference matters

The preferred comparison states that only the ID is part of this test's contract. Reflexive `DeepEqual` includes volatile implementation data and produces a failure unrelated to the behavior under test.

## 3. Boundaries and distinctions

Use direct equality for comparable values when all fields matter. A `cmp` package can express richer deliberate choices, such as ignoring fields or equating empty collections.
