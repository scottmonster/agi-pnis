# Assuming `NewType` constructs a runtime wrapper object

## 1. Catalog record

- **Catalog identifier:** 16.18.2
- **Impact:** low
- **Consensus:** high
- **Definition:** Use `NewType` to create a static distinction, not for runtime validation or wrapping.

## 2. Example

### 2.1 Scenario

An application distinguishes user IDs from ordinary integers in static type checking while accepting values from an API.

### 2.2 Preferred form

```python
from typing import NewType


UserId = NewType("UserId", int)


def parse_user_id(raw: str) -> UserId:
    value = int(raw)
    if value < 1:
        raise ValueError("user ID must be positive")
    return UserId(value)


print(parse_user_id("42"))
```

### 2.3 Hazardous form

```python
from typing import NewType


UserId = NewType("UserId", int)


def parse_user_id(raw: str) -> UserId:
    return UserId(raw)


print(parse_user_id("not-a-number"))
```

### 2.4 Why this difference matters

At runtime `NewType` returns its argument essentially unchanged, so the hazardous function returns a string while claiming to have validated and wrapped an integer ID.

## 3. Boundaries and distinctions

`NewType` is useful for static distinctions between compatible runtime values. Pair it with parsing and validation when untrusted input must meet a runtime schema.
