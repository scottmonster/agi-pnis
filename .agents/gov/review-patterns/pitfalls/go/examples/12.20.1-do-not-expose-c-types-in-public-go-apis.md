# Do not expose C types in public Go APIs

## 1. Catalog record

- **Catalog identifier:** 12.20.1
- **Impact:** medium
- **Consensus:** high
- **Definition:** Translate C values into ordinary Go types before exposing them across package boundaries.

## 2. Example

### 2.1 Scenario

A package wraps a native library's log-level setting for use by the rest of a Go service.

### 2.2 Preferred form

```go
package native

/*
#include <stdint.h>
static void set_log_level(int level) {
	(void)level;
}
*/
import "C"

import "fmt"

func SetLogLevel(level int) error {
	if level < 0 || level > 5 {
		return fmt.Errorf("log level %d is outside 0 through 5", level)
	}
	C.set_log_level(C.int(level))
	return nil
}
```

### 2.3 Hazardous form

```go
package native

/*
#include <stdint.h>
*/
import "C"

// SetLogLevel leaks the wrapper's cgo dependency into every caller.
func SetLogLevel(level C.int) C.int {
	return level
}
```

### 2.4 Why this difference matters

Public C types force callers to understand cgo details and couple them to the native library's ABI choices. Converting at the package boundary leaves the exported API portable and makes native implementation changes local.

## 3. Boundaries and distinctions

An internal cgo package may use `C.int`, `C.size_t`, and pointers while talking to C. The boundary to ordinary Go packages should expose Go values, errors, and domain types instead.
