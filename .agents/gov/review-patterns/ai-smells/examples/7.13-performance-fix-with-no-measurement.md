# Performance “fix” with no measurement

## 1. Catalog record

- **Catalog identifier:** 7.13
- **Evidence:** se
- **Definition:** Complexity increases without a benchmark demonstrating improvement.

## 2. Scenario

### 2.1 Context

An agent replaces a clear request-processing path with a cache and worker pool after assuming it will be faster.

### 2.2 Safer approach

It records a representative baseline, identifies the bottleneck, and compares the changed implementation against the same benchmark before keeping it.

### 2.3 Failure mode

It lands the extra cache and concurrency controls without measuring latency, throughput, or resource use.

### 2.4 Why this difference matters

The system gains operational complexity without evidence that the change improves the relevant performance.

## 3. Boundaries and distinctions

Measurement need not be a production-scale benchmark for every small change, but a claimed performance fix should be evaluated against a representative, relevant measure.
