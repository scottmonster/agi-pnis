# Specify endianness explicitly with DataView

## 1. Catalog record

- **Catalog identifier:** 4.1.9
- **Impact:** medium
- **Consensus:** high
- **Definition:** When reading or writing externally defined binary formats, use `DataView` and specify the expected byte order rather than relying on the platform's native typed-array representation.

## 2. Example

### 2.1 Scenario

A client reads a 16-bit length field from a protocol defined as little-endian.

### 2.2 Preferred form

```javascript
const packet = new Uint8Array([0x34, 0x12]).buffer;
const view = new DataView(packet);
const length = view.getUint16(0, true);

console.log(length);
```

### 2.3 Hazardous form

```javascript
const packet = new Uint8Array([0x34, 0x12]).buffer;
const view = new DataView(packet);
const length = view.getUint16(0);

console.log(length);
```

### 2.4 Why this difference matters

Omitting the second argument makes `DataView` read big-endian, so the hazardous form reads the protocol field as a different number.

## 3. Boundaries and distinctions

Use the byte order defined by the binary format. `DataView` is especially useful at protocol boundaries because its endianness choice is explicit.
