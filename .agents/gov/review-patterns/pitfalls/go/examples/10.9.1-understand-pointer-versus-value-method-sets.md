# Understand pointer versus value method sets

## 1. Catalog record

- **Catalog identifier:** 10.9.1
- **Impact:** medium
- **Consensus:** high
- **Definition:** A method defined only on `*T` does not make `T` satisfy an interface requiring that method, although `*T` also has methods defined on `T`.

## 2. Example

### 2.1 Scenario

A counter has a mutating method and is passed to an interface-based batch processor.

### 2.2 Preferred form

```go
package example

type Incrementer interface {
	Increment()
}

type Counter struct{ value int }

func (c *Counter) Increment() { c.value++ }

func run(c Incrementer) { c.Increment() }

func example() int {
	counter := Counter{}
	run(&counter)
	return counter.value
}
```

### 2.3 Hazardous form

```go
package example

type Incrementer interface {
	Increment()
}

type Counter struct{ value int }

func (c *Counter) Increment() { c.value++ }

func run(c Incrementer) { c.Increment() }

func example() {
	counter := Counter{}
	// run(counter) // Counter does not implement Incrementer
	_ = counter
}
```

### 2.4 Why this difference matters

The method set of `Counter` excludes methods declared only on `*Counter`. Passing a value where the interface requires `Increment` produces a compile-time failure.

## 3. Boundaries and distinctions

Methods with value receivers belong to both `T` and `*T` method sets. Prefer pointer receivers for mutable or large types, then consistently pass pointers where the interface is required.
