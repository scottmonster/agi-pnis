# `exec` replaces the shell on success

## 1. Catalog record

- **Catalog identifier:** 8.7.1
- **Impact:** medium
- **Consensus:** high
- **Definition:** `exec command` does not launch a child and then resume the script; on success, the current shell process becomes the target program.

## 2. Example

### 2.1 Scenario

A container entrypoint should transfer control to the service after writing its setup log.

### 2.2 Preferred form

```bash
#!/usr/bin/env bash
printf 'starting service\n' >&2
exec ./service --port 8080
```

### 2.3 Hazardous form

```bash
#!/usr/bin/env bash
exec ./service --port 8080
printf 'service stopped\n' >&2
```

### 2.4 Why this difference matters

When `exec` succeeds, the service replaces the shell and the later message is unreachable. Place required work before `exec`, or launch a child without `exec` when the script must continue.

## 3. Boundaries and distinctions

If `exec` fails, the shell continues and returns a failure status unless the script handles it. Replacing the shell is useful for process supervision and signal delivery in entrypoints.
