# Use URL instead of hand-parsing URLs

## 1. Catalog record

- **Catalog identifier:** 10.1.7
- **Impact:** medium
- **Consensus:** high
- **Definition:** Parse and construct URLs and query parameters with URL and URLSearchParams.

## 2. Example

### 2.1 Scenario

A search page builds a link from a user query and an optional page number.

### 2.2 Preferred form

```javascript
function searchUrl(query, page) {
  const url = new URL("https://app.example/search");
  url.searchParams.set("q", query);
  url.searchParams.set("page", String(page));
  return url.toString();
}

console.log(searchUrl("red & blue", 2));
```

### 2.3 Hazardous form

```javascript
function searchUrl(query, page) {
  return `https://app.example/search?q=${query}&page=${page}`;
}

console.log(searchUrl("red & blue", 2));
```

### 2.4 Why this difference matters

The hand-built URL lets the ampersand in the query become a structural separator, changing which query parameters the server receives.

## 3. Boundaries and distinctions

String concatenation is safe only when every component is already fixed and correctly encoded. `URL` also makes relative URL resolution explicit when a base is supplied.
