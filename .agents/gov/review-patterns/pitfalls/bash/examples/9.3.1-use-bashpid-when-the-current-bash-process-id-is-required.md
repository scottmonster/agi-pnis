# Use `BASHPID` when the current Bash process ID is required

## 1. Catalog record

- **Catalog identifier:** 9.3.1
- **Impact:** medium
- **Consensus:** high
- **Definition:** Use `BASHPID` for the current Bash process because `$$` can retain the invoking shell PID in subshells.

## 2. Example

### 2.1 Scenario

A script creates a distinct diagnostic log name from inside a subshell.

### 2.2 Preferred form

```bash
#!/usr/bin/env bash
set -euo pipefail

(
  log_file="/tmp/worker-${BASHPID}.log"
  printf 'subshell log: %s\n' "$log_file"
)
```

### 2.3 Hazardous form

```bash
#!/usr/bin/env bash
set -euo pipefail

(
  log_file="/tmp/worker-$$.log"
  printf 'subshell log: %s\n' "$log_file"
)
```

### 2.4 Why this difference matters

The hazardous form can label the subshell output with the parent shell PID, making process-specific coordination and diagnostics ambiguous.

## 3. Boundaries and distinctions

`$$` is appropriate when the invoking shell PID is specifically what the program needs rather than the current subshell's PID.
