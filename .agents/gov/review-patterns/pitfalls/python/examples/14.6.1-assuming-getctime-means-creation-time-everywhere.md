# Assuming `getctime()` means creation time everywhere

## 1. Catalog record

- **Catalog identifier:** 14.6.1
- **Impact:** medium
- **Consensus:** high
- **Definition:** Do not treat `os.path.getctime()` as a portable file-creation timestamp.

## 2. Example

### 2.1 Scenario

A cross-platform archive tool reports when a file was first created. Its report must not label a metadata-change timestamp as a creation timestamp.

### 2.2 Preferred form

```python
from pathlib import Path
import sys


def creation_time(path: Path) -> float:
    if sys.platform != "win32":
        raise NotImplementedError("portable creation time is unavailable")
    return path.stat().st_ctime
```

### 2.3 Hazardous form

```python
import os


def creation_time(filename: str) -> float:
    return os.path.getctime(filename)
```

### 2.4 Why this difference matters

On Unix, `getctime()` represents the most recent metadata change, while on Windows it represents creation time. The hazardous report silently changes meaning across platforms.

## 3. Boundaries and distinctions

Use `getctime()` when its platform-specific meaning is intentional. A portable application may need to omit creation time or obtain it from platform-specific metadata.
