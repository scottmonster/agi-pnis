# Run `go vet`, but do not treat silence as correctness proof

## 1. Catalog record

- **Catalog identifier:** 11.13.1
- **Impact:** medium
- **Consensus:** high
- **Definition:** Include vet in normal validation while understanding that its checks are deliberately heuristic and incomplete.

## 2. Example

### 2.1 Scenario

A service validates user-supplied amount strings before crediting an account. The code is syntactically normal and may receive no vet diagnostic.

### 2.2 Preferred form

```go
package example

import (
	"fmt"
	"strconv"
)

func creditAmount(input string) (int64, error) {
	amount, err := strconv.ParseInt(input, 10, 64)
	if err != nil || amount < 0 {
		return 0, fmt.Errorf("invalid credit amount")
	}
	return amount, nil
}
```

### 2.3 Hazardous form

```go
package example

import "strconv"

func creditAmount(input string) (int64, error) {
	amount, err := strconv.ParseInt(input, 10, 64)
	if err != nil {
		return 0, err
	}
	return amount, nil // negative credits are a domain bug that vet cannot infer
}
```

### 2.4 Why this difference matters

Vet catches useful but intentionally limited classes of mistakes. Its silence cannot prove application invariants, security requirements, or every concurrency property.

## 3. Boundaries and distinctions

Run `go vet` as a normal validation step and investigate diagnostics in context. Complement it with tests, reviews, static tools suited to the project, and reasoning about the actual contract.
