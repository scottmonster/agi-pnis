# Do not `source` untrusted configuration files

## 1. Catalog record

- **Catalog identifier:** 3.8.1
- **Impact:** high
- **Consensus:** high
- **Definition:** Parse untrusted configuration as data instead of sourcing it as code in the current shell.

## 2. Example

### 2.1 Scenario

A tool reads a user-provided configuration file that contains a service endpoint.

### 2.2 Preferred form

```bash
config_file='user.conf'
endpoint=$(sed -n 's/^endpoint=//p' "$config_file")
printf 'connecting to %s\n' "$endpoint"
```

### 2.3 Hazardous form

```bash
config_file='user.conf'
source "$config_file"
printf 'connecting to %s\n' "$endpoint"
```

### 2.4 Why this difference matters

Sourcing executes every shell construct in the file, allowing untrusted input to run commands or alter the calling shell.

## 3. Boundaries and distinctions

Sourcing can be suitable for a reviewed, trusted shell library that is deliberately executable, not for untrusted data.
