# Every successfully started subprocess must be waited for

## 1. Catalog record

- **Catalog identifier:** 12.1.1
- **Impact:** medium
- **Consensus:** high
- **Definition:** After a successful `cmd.Start`, call `cmd.Wait`. Prefer `Run` when no asynchronous interaction is needed.

## 2. Example

### 2.1 Scenario

An administrative service runs `git --version` and only needs to know whether the command succeeded.

### 2.2 Preferred form

```go
package example

import "os/exec"

func checkGit() error {
	return exec.Command("git", "--version").Run()
}
```

### 2.3 Hazardous form

```go
package example

import "os/exec"

func checkGit() error {
	cmd := exec.Command("git", "--version")
	return cmd.Start()
}
```

### 2.4 Why this difference matters

`Run` starts the child and waits for it. The hazardous form returns after a successful start, leaving the child unreaped and losing its exit status.

## 3. Boundaries and distinctions

Use `Start` when the parent must interact with a running child, but arrange for exactly one later `Wait` after that interaction finishes.
