# Synchronize SharedArrayBuffer access with Atomics

## 1. Catalog record

- **Catalog identifier:** 4.1.11
- **Impact:** high
- **Consensus:** high
- **Definition:** When multiple agents or workers coordinate through shared memory, use `Atomics` and an appropriate synchronization design instead of assuming ordinary reads and writes provide safe inter-thread coordination.

## 2. Example

### 2.1 Scenario

Two workers use a shared flag to signal that a value has been published.

### 2.2 Preferred form

```javascript
const memory = new SharedArrayBuffer(Int32Array.BYTES_PER_ELEMENT * 2);
const state = new Int32Array(memory);

Atomics.store(state, 1, 42);
Atomics.store(state, 0, 1);

if (Atomics.load(state, 0) === 1) {
  console.log(Atomics.load(state, 1));
}
```

### 2.3 Hazardous form

```javascript
const memory = new SharedArrayBuffer(Int32Array.BYTES_PER_ELEMENT * 2);
const state = new Int32Array(memory);

state[1] = 42;
state[0] = 1;

if (state[0] === 1) {
  console.log(state[1]);
}
```

### 2.4 Why this difference matters

Ordinary shared-memory reads and writes do not establish the synchronization protocol that concurrent workers need, so a consumer can observe an inconsistent state.

## 3. Boundaries and distinctions

`Atomics` is needed only for shared-memory concurrency. Ordinary `ArrayBuffer` data owned by one execution context does not introduce this coordination problem.
