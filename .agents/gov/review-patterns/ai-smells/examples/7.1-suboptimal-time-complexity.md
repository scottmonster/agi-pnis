# Suboptimal time complexity

## 1. Catalog record

- **Catalog identifier:** 7.1
- **Evidence:** e
- **Definition:** Runtime grows faster than necessary for input size, often because of avoidable repeated scans or nested work.

## 2. Scenario

### 2.1 Context

An agent implements duplicate detection for a large list of account IDs in a service endpoint.

### 2.2 Safer approach

It uses a set while scanning once, then tests the implementation with both small and large representative inputs.

### 2.3 Failure mode

It compares every ID with every other ID in nested loops, turning a linear membership problem into quadratic work.

### 2.4 Why this difference matters

The endpoint becomes disproportionately slow as the input grows.

## 3. Boundaries and distinctions

Nested loops are not inherently wrong when the required algorithm needs pairwise comparisons; this failure is avoidable repeated or nested work for the actual result.
