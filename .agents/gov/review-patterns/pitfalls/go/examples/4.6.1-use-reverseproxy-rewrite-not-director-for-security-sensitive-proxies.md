# Use `ReverseProxy.Rewrite`, not `Director`, for security-sensitive proxies

## 1. Catalog record

- **Catalog identifier:** 4.6.1
- **Impact:** high
- **Consensus:** high
- **Definition:** `httputil.ReverseProxy.Director` is deprecated and explicitly documented as insecure. Use `Rewrite` and reconstruct trusted forwarding headers deliberately.

## 2. Example

### 2.1 Scenario

An edge proxy forwards requests to one trusted upstream and must control the forwarded request headers.

### 2.2 Preferred form

```go
package example

import (
	"net/http/httputil"
	"net/url"
)

func proxyTo(target *url.URL) *httputil.ReverseProxy {
	return &httputil.ReverseProxy{
		Rewrite: func(pr *httputil.ProxyRequest) {
			pr.SetURL(target)
			pr.Out.Header.Del("X-Forwarded-For")
			pr.SetXForwarded()
		},
	}
}
```

### 2.3 Hazardous form

```go
package example

import (
	"net/http"
	"net/http/httputil"
	"net/url"
)

func proxyTo(target *url.URL) *httputil.ReverseProxy {
	return &httputil.ReverseProxy{
		Director: func(r *http.Request) {
			r.URL.Scheme = target.Scheme
			r.URL.Host = target.Host
		},
	}
}
```

### 2.4 Why this difference matters

`Rewrite` makes the outgoing request and forwarding headers an explicit policy. A `Director` callback preserves client-supplied forwarding headers unless it carefully removes them, which lets an attacker influence headers trusted by the upstream.

## 3. Boundaries and distinctions

Set forwarding headers only from the network information your proxy has authenticated. A proxy may need additional policy for paths, hosts, hop-by-hop headers, and response rewriting.
