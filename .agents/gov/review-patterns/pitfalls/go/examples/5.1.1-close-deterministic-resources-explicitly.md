# Close deterministic resources explicitly

## 1. Catalog record

- **Catalog identifier:** 5.1.1
- **Impact:** high
- **Consensus:** high
- **Definition:** Do not rely on finalizers, `runtime.AddCleanup`, or weak references to close files, flush buffers, commit data, unlock resources, or perform other required cleanup.

## 2. Example

### 2.1 Scenario

A service writes an audit record whose file descriptor must be released before the request is acknowledged.

### 2.2 Preferred form

```go
package example

import "os"

func writeAudit(path string, record []byte) (err error) {
	f, err := os.Create(path)
	if err != nil {
		return err
	}
	defer func() {
		if closeErr := f.Close(); err == nil {
			err = closeErr
		}
	}()
	_, err = f.Write(record)
	return err
}
```

### 2.3 Hazardous form

```go
package example

import "os"

func writeAudit(path string, record []byte) error {
	f, err := os.Create(path)
	if err != nil {
		return err
	}
	_, err = f.Write(record)
	return err // f is left to nondeterministic finalization.
}
```

### 2.4 Why this difference matters

The preferred form closes the file predictably on every return path. Finalization is not a delivery or cleanup guarantee.

## 3. Boundaries and distinctions

This is for cleanup whose completion is required. GC cleanup can still be suitable as a nonessential last-resort safety net.
