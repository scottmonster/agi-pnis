# JSON.stringify silently transforms or removes some values

## 1. Catalog record

- **Catalog identifier:** 9.1.3
- **Impact:** medium
- **Consensus:** high
- **Definition:** Do not assume undefined, functions, or symbols round-trip through JSON.stringify.

## 2. Example

### 2.1 Scenario

An application sends an optional retry delay over a JSON API and needs the receiver to distinguish an omitted value from a configured empty value.

### 2.2 Preferred form

```javascript
function serializeJob(job) {
  return JSON.stringify({
    name: job.name,
    retryAfterSeconds: job.retryAfterSeconds ?? null,
  });
}

console.log(serializeJob({ name: "backup", retryAfterSeconds: undefined }));
// {"name":"backup","retryAfterSeconds":null}
```

### 2.3 Hazardous form

```javascript
const job = {
  name: "backup",
  retryAfterSeconds: undefined,
  onComplete() {},
  internalId: Symbol("job"),
};

console.log(JSON.stringify(job)); // {"name":"backup"}
```

### 2.4 Why this difference matters

Object properties whose values are `undefined`, functions, or symbols disappear, so the receiver cannot tell that the sender supplied them.

## 3. Boundaries and distinctions

JSON is appropriate for data already constrained to JSON-compatible types. Define a wire representation for every value whose absence or type has special meaning.
