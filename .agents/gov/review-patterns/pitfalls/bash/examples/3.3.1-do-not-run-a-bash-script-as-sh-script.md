# Do not run a Bash script as sh script

## 1. Catalog record

- **Catalog identifier:** 3.3.1
- **Impact:** high
- **Consensus:** high
- **Definition:** Run a Bash-declared script directly or with `bash`, rather than explicitly invoking it with `sh`.

## 2. Example

### 2.1 Scenario

The executable script `collect.sh` declares Bash because it uses an array.

### 2.2 Preferred form

```bash
chmod +x ./collect.sh
./collect.sh

# Or, when execute permission is unavailable:
bash ./collect.sh
```

### 2.3 Hazardous form

```bash
#!/usr/bin/env bash
files=(one two)
printf '%s\n' "${files[@]}"

# Later, a caller runs: sh ./collect.sh
```

### 2.4 Why this difference matters

Calling `sh` bypasses the shebang and selects `sh` semantics, so Bash-specific syntax and assumptions can fail or behave differently.

## 3. Boundaries and distinctions

Running `sh script` is appropriate only when the script was intentionally written and tested as POSIX shell code.
