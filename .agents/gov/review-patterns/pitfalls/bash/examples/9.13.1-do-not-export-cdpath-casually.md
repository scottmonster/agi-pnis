# Do not export `CDPATH` casually

## 1. Catalog record

- **Catalog identifier:** 9.13.1
- **Impact:** medium
- **Consensus:** high
- **Definition:** Avoid surprising inherited or exported `CDPATH` when scripts require deterministic relative-directory resolution.

## 2. Example

### 2.1 Scenario

A release script changes into a project-relative directory before packaging an artifact.

### 2.2 Preferred form

```bash
#!/usr/bin/env bash
set -euo pipefail

unset CDPATH
cd -- "./build"
printf 'packaging from %s\n' "$PWD"
```

### 2.3 Hazardous form

```bash
#!/usr/bin/env bash
set -euo pipefail

export CDPATH="/srv/shared-projects"
cd build
printf 'packaging from %s\n' "$PWD"
```

### 2.4 Why this difference matters

An ambient `CDPATH` can redirect a relative `cd` to another directory and print unexpected output during a successful directory change.

## 3. Boundaries and distinctions

`CDPATH` can be useful interactively or in a tightly controlled environment where its resolution behavior is intentional.
