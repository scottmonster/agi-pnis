# Handle unmatched globs explicitly

## 1. Catalog record

- **Catalog identifier:** 5.10.1
- **Impact:** medium
- **Consensus:** high
- **Definition:** By default, an unmatched Bash glob normally remains unchanged as literal text. Decide explicitly whether zero matches should produce no arguments, an error, or literal text.

## 2. Example

### 2.1 Scenario

A cleanup job should remove temporary files if any exist, and otherwise quietly do nothing.

### 2.2 Preferred form

```bash
work_dir=${1:?provide a work directory}

(
  shopt -s nullglob
  temporary_files=("$work_dir"/*.tmp)
  ((${#temporary_files[@]})) || exit 0
  rm -- "${temporary_files[@]}"
)
```

### 2.3 Hazardous form

```bash
work_dir=${1:?provide a work directory}

rm -- "$work_dir"/*.tmp
```

### 2.4 Why this difference matters

If no files match, the hazardous glob is passed literally to `rm`. The command then fails against a pathname containing `*`, rather than implementing the intended empty-match behavior.

## 3. Boundaries and distinctions

`nullglob` is appropriate when zero matches means no arguments. Use `failglob` or an explicit check instead when a missing match should stop the operation.
