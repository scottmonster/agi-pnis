# Format Go code with `gofmt`

## 1. Catalog record

- **Catalog identifier:** 13.1.1
- **Impact:** low
- **Consensus:** high
- **Definition:** Use `gofmt`, or `goimports` when import management is also desired, instead of maintaining a project-specific formatting style.

## 2. Example

### 2.1 Scenario

A team shares a package that will be edited by several developers and reviewed in many small changes.

### 2.2 Preferred form

```go
package example

import "fmt"

func greeting(name string) string {
	return fmt.Sprintf("hello, %s", name)
}
```

### 2.3 Hazardous form

```go
package example
import "fmt"
func greeting(name string)string{ return fmt.Sprintf("hello, %s",name) }
```

### 2.4 Why this difference matters

The first form has Go's standard layout, so tooling and reviewers can focus on behavior. The second is valid Go, but a local formatting style creates noisy diffs and needless disagreements.

## 3. Boundaries and distinctions

Use `gofmt` for Go source. Use `goimports` when automatically adding, removing, and grouping imports is also wanted.
