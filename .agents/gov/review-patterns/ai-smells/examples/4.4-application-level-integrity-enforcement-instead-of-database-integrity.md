# Application-level integrity enforcement instead of database integrity

## 1. Catalog record

- **Catalog identifier:** 4.4
- **Evidence:** se
- **Definition:** Race-prone “check then insert” logic replaces unique/foreign-key/check constraints.

## 2. Scenario

### 2.1 Context

An agent must ensure that each workspace has only one member record for a given user.

### 2.2 Safer approach

It creates a database unique constraint on `(workspace_id, user_id)` and handles the resulting conflict as an already-existing membership.

### 2.3 Failure mode

It first queries for a membership and inserts only when the query returns no row. Two simultaneous requests can both see no row and insert duplicates.

### 2.4 Why this difference matters

The database is the shared concurrency boundary, so its constraint preserves integrity under races that application checks cannot prevent.

## 3. Boundaries and distinctions

Application checks may improve error messages or avoid unnecessary work, but they do not replace database integrity constraints for persistent invariants.
