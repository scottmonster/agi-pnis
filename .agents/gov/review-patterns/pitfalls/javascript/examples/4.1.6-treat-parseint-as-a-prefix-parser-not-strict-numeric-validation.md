# Treat parseInt as a prefix parser, not strict numeric validation

## 1. Catalog record

- **Catalog identifier:** 4.1.6
- **Impact:** medium
- **Consensus:** high
- **Definition:** Use `parseInt()` when parsing an integer prefix is actually intended, specify the radix when appropriate, and validate the whole string separately when strict syntax is required.

## 2. Example

### 2.1 Scenario

An endpoint accepts a page number and must reject input that contains any non-digit characters.

### 2.2 Preferred form

```javascript
function parsePageNumber(text) {
  if (!/^(?:0|[1-9]\d*)$/.test(text)) {
    throw new TypeError("Page number must contain only decimal digits");
  }
  return Number(text);
}

console.log(parsePageNumber("12"));
```

### 2.3 Hazardous form

```javascript
function parsePageNumber(text) {
  return parseInt(text, 10);
}

console.log(parsePageNumber("12pages"));
```

### 2.4 Why this difference matters

`parseInt()` stops at the first invalid character, so the hazardous form accepts malformed input as page 12.

## 3. Boundaries and distinctions

`parseInt()` is useful when an integer prefix is genuinely part of the format. Strict validation needs a full-input check, and callers should specify a radix when using `parseInt()`.
