# `Client.Timeout` covers body reading too

## 1. Catalog record

- **Catalog identifier:** 9.6.1
- **Impact:** medium
- **Consensus:** high
- **Definition:** Set `Client.Timeout` with awareness that it spans connection setup, redirects, and reading the response body, not merely waiting for headers.

## 2. Example

### 2.1 Scenario

A client downloads a report whose body may take most of the request's deadline to arrive.

### 2.2 Preferred form

```go
package example

import (
	"io"
	"net/http"
	"time"
)

func download(url string) error {
	client := &http.Client{Timeout: 30 * time.Second}
	resp, err := client.Get(url)
	if err != nil { return err }
	defer resp.Body.Close()
	_, err = io.Copy(io.Discard, resp.Body)
	return err
}
```

### 2.3 Hazardous form

```go
package example

import (
	"io"
	"net/http"
	"time"
)

func download(url string) error {
	client := &http.Client{Timeout: 100 * time.Millisecond}
	resp, err := client.Get(url) // Headers can arrive before the deadline.
	if err != nil { return err }
	defer resp.Body.Close()
	time.Sleep(time.Second) // Later body reads will fail due to Client.Timeout.
	_, err = io.ReadAll(resp.Body)
	return err
}
```

### 2.4 Why this difference matters

The timeout remains active until the response body is fully read or closed. Treating it as a header-only limit causes surprising mid-download failures.

## 3. Boundaries and distinctions

Use request contexts and transport-specific timeouts when a single whole-request timeout is too coarse. The appropriate budget depends on expected body size and throughput.
