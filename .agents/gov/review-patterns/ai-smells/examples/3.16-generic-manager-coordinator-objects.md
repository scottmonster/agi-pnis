# Generic manager/coordinator objects

## 1. Catalog record

- **Catalog identifier:** 3.16
- **Evidence:** se
- **Definition:** Responsibilities migrate into vague `Manager`, `Handler`, `Processor`, or `Coordinator` classes instead of meaningful domain boundaries.

## 2. Scenario

### 2.1 Context

Order cancellation needs to validate status, release stock, and notify a customer.

### 2.2 Safer approach

Place the operation in a named order service with collaborators that reflect their domain roles.

### 2.3 Failure mode

Create a catch-all `OrderManager` and continue adding unrelated workflow and infrastructure duties to it.

### 2.4 Why this difference matters

Vague ownership makes responsibilities accumulate and prevents readers from locating domain decisions.

## 3. Boundaries and distinctions

Coordination can be a real responsibility, but the name and boundary should communicate what is being coordinated and why.
