# Unnecessary conditional blocks

## 1. Catalog record

- **Catalog identifier:** 5.11
- **Evidence:** e
- **Definition:** Conditions exist where a direct return/expression would suffice.

## 2. Scenario

### 2.1 Context

A formatter returns either `name` or the same `name` after an `if` condition that changes neither value nor behavior.

### 2.2 Safer approach

Replace the redundant branch with the direct expression and retain conditions only where they affect behavior.

### 2.3 Failure mode

Add a second no-op conditional around the same return to make an imagined special case explicit.

### 2.4 Why this difference matters

Redundant branches add reading and testing burden while hiding the actual decision points.

## 3. Boundaries and distinctions

Conditions that protect a distinct result, side effect, or precondition are necessary. Only behaviorless conditional blocks are unnecessary.
