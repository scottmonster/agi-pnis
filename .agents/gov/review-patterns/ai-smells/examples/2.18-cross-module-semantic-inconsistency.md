# Cross-module semantic inconsistency

## 1. Catalog record

- **Catalog identifier:** 2.18
- **Evidence:** e/a
- **Definition:** Different modules end up implementing incompatible interpretations of the same concept.

## 2. Scenario

### 2.1 Context

The billing module and reporting module both classify an invoice as overdue based on its due date.

### 2.2 Safer approach

The agent identifies the shared definition, reuses or centralizes it, and verifies both modules around the same date boundary.

### 2.3 Failure mode

It changes billing to mark invoices overdue at midnight UTC while reporting continues to use midnight in the account's local time zone.

### 2.4 Why this difference matters

The same invoice can be overdue in one part of the product and current in another, producing contradictory actions and reports.

## 3. Boundaries and distinctions

Independent concepts may legitimately use different rules; this failure arises when modules claim to represent the same business concept.
