# Silent truncation with `zip()`

## 1. Catalog record

- **Catalog identifier:** 5.3.1
- **Impact:** high
- **Consensus:** high
- **Definition:** When corresponding iterables are required to have the same length, use `zip(..., strict=True)` instead of ordinary `zip()`.

## 2. Example

### 2.1 Scenario

An importer pairs every account identifier with a required balance from a separate column.

### 2.2 Preferred form

```python
account_ids = ["a-100", "a-200"]
balances = [25, 50]

records = dict(zip(account_ids, balances, strict=True))
assert records == {"a-100": 25, "a-200": 50}
```

### 2.3 Hazardous form

```python
account_ids = ["a-100", "a-200"]
balances = [25]

records = dict(zip(account_ids, balances))
assert records == {"a-100": 25}
```

### 2.4 Why this difference matters

Ordinary `zip()` stops at the shorter input without an error. `strict=True` exposes a malformed parallel data set instead of dropping a record.

## 3. Boundaries and distinctions

Ordinary `zip()` is appropriate when shortest-input truncation is intentional, such as deliberately limiting output to available pairs.
