# Missing security-relevant input validation

## 1. Catalog record

- **Catalog identifier:** 10.18
- **Evidence:** e
- **Definition:** Fails to constrain untrusted values before they reach a security-sensitive operation or trust boundary.

## 2. Scenario

### 2.1 Context

A document-conversion service accepts an output format and source document from a request.

### 2.2 Safer approach

Validate the format against supported values, limit size and type, and apply the checks before passing data to the conversion boundary.

### 2.3 Failure mode

The agent forwards all request fields to the converter because the converter can reject unsupported options.

### 2.4 Why this difference matters

Dangerous or malformed input can reach a sensitive component before the application enforces its own trust boundary.

## 3. Boundaries and distinctions

Validation should be specific to the receiving operation. Generic cleanup is not a substitute for constraints that reflect the actual security-sensitive use.
