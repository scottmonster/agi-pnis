# Quote variables used with `[ ... ]`

## 1. Catalog record

- **Catalog identifier:** 4.7.1
- **Impact:** medium
- **Consensus:** high
- **Definition:** Quote variable operands in `test` and `[ ... ]` to preserve their intended argument structure.

## 2. Example

### 2.1 Scenario

A script must determine whether an optional search term was provided, even when it is empty or contains whitespace.

### 2.2 Preferred form

```bash
#!/usr/bin/env bash

term=${1-}
if [ -n "$term" ]; then
  printf 'searching for: %s\n' "$term"
fi
```

### 2.3 Hazardous form

```bash
#!/usr/bin/env bash

term=${1-}
if [ -n $term ]; then
  printf 'searching for: %s\n' "$term"
fi
```

### 2.4 Why this difference matters

Traditional `test` parses its final argument list. An empty value, whitespace, or pathname expansion can alter that list and change the condition's meaning.

## 3. Boundaries and distinctions

Quote variable operands with `[` and `test`. In Bash-only code, `[[ ... ]]` has safer operand handling, but portability may require `[ ... ]`.
