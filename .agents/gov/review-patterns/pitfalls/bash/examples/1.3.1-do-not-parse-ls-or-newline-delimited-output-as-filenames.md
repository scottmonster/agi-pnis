# Do not parse `ls` or newline-delimited output as filenames

## 1. Catalog record

- **Catalog identifier:** 1.3.1
- **Impact:** high
- **Consensus:** high
- **Definition:** Do not use constructs such as `for f in $(ls ...)` or otherwise assume filenames are separated by whitespace or newlines. Use shell globs, `find -exec`, or NUL-delimited interfaces.

## 2. Example

### 2.1 Scenario

A cleanup script scans an input directory whose files may have spaces or newlines in their names. It must pass each pathname to a command unchanged.

### 2.2 Preferred form

```bash
input_dir=${1:?usage: process-files DIRECTORY}

shopt -s nullglob
for path in "$input_dir"/*; do
    printf 'Processing: %s\n' "$path"
done
```

### 2.3 Hazardous form

```bash
input_dir=${1:?usage: process-files DIRECTORY}

for name in $(ls -- "$input_dir"); do
    printf 'Processing: %s\n' "$input_dir/$name"
done
```

### 2.4 Why this difference matters

`ls` produces presentation-oriented text, and command substitution then applies word splitting and pathname expansion. A filename with whitespace or a newline can become multiple incorrect names before the loop receives it.

## 3. Boundaries and distinctions

Shell globs are appropriate when the required traversal is non-recursive and their matching rules fit the task. For recursive or cross-process traversal, use pathname-aware `find -exec` or a NUL-delimited interface instead.
