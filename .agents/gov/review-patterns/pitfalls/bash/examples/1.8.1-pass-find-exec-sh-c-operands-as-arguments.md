# Pass `find -exec sh -c` operands as arguments

## 1. Catalog record

- **Catalog identifier:** 1.8.1
- **Impact:** high
- **Consensus:** high
- **Definition:** Do not interpolate `{}` directly into the shell program supplied to `find -exec sh -c`. Pass filenames after the script and access them through positional parameters, such as `sh -c 'for f do ...; done' sh {} +`.

## 2. Example

### 2.1 Scenario

A cleanup job finds old report files and prints the paths it will remove. Report names can originate outside the script and may contain shell metacharacters.

### 2.2 Preferred form

```bash
#!/usr/bin/env bash

report_dir=${1:?Usage: "$0" REPORT_DIR}

find "$report_dir" -type f -name '*.old' -exec sh -c '
  for path do
    printf "Would remove: %s\n" "$path"
  done
' sh {} +
```

### 2.3 Hazardous form

```bash
#!/usr/bin/env bash

report_dir=${1:?Usage: "$0" REPORT_DIR}

find "$report_dir" -type f -name '*.old' -exec sh -c '
  printf "Would remove: %s\n" {}
' \;
```

### 2.4 Why this difference matters

In the hazardous form, `find` substitutes the pathname into shell source before `sh -c` parses it. A quote, command substitution, or separator in a filename can therefore change the program. In the preferred form, each pathname is an argument, so `"$path"` remains data.

## 3. Boundaries and distinctions

`sh -c` is unnecessary when the required command can be passed directly to `find -exec`. When a shell program is genuinely needed, supply a placeholder value for `$0` and pass every pathname after it.
