# Bash `=~` uses extended regular expressions, not PCRE

## 1. Catalog record

- **Catalog identifier:** 10.2.1
- **Impact:** medium
- **Consensus:** high
- **Definition:** Patterns in `[[ value =~ regex ]]` use Bash's POSIX extended-regular-expression interface, not PCRE or Perl semantics.

## 2. Example

### 2.1 Scenario

A release script accepts only dates written as `YYYY-MM-DD`.

### 2.2 Preferred form

```bash
release_date='2026-09-04'

if [[ $release_date =~ ^[0-9]{4}-[0-9]{2}-[0-9]{2}$ ]]; then
  printf 'valid date: %s\n' "$release_date"
fi
```

### 2.3 Hazardous form

```bash
release_date='2026-09-04'

if [[ $release_date =~ ^\d{4}-\d{2}-\d{2}$ ]]; then
  printf 'valid date: %s\n' "$release_date"
fi
```

### 2.4 Why this difference matters

The PCRE-style `\d` is not a portable Bash ERE digit class, so a pattern copied from another regex dialect can reject valid input or match different text.

## 3. Boundaries and distinctions

Use an external regex engine only when its required dialect and behavior are deliberately part of the script's contract. Bash ERE is sufficient for many simple validations.
