# stopPropagation does not prevent the default action

## 1. Catalog record

- **Catalog identifier:** 11.1.6
- **Impact:** medium
- **Consensus:** high
- **Definition:** Use preventDefault, not stopPropagation, to cancel a browser default action.

## 2. Example

### 2.1 Scenario

A single-page application handles a settings link without a full page navigation. The click handler needs to stop the link's normal navigation after showing the settings panel.

### 2.2 Preferred form

```javascript
const settingsLink = document.querySelector("#settings-link");
const settingsPanel = document.querySelector("#settings-panel");

settingsLink.addEventListener("click", (event) => {
  event.preventDefault();
  settingsPanel.hidden = false;
});
```

### 2.3 Hazardous form

```javascript
const settingsLink = document.querySelector("#settings-link");
const settingsPanel = document.querySelector("#settings-panel");

settingsLink.addEventListener("click", (event) => {
  event.stopPropagation();
  settingsPanel.hidden = false;
});
```

### 2.4 Why this difference matters

`stopPropagation()` prevents the event from reaching other listeners but does not cancel the link's built-in navigation. The hazardous handler may briefly reveal the panel before the browser leaves the page.

## 3. Boundaries and distinctions

Use `stopPropagation()` when suppressing ancestor listeners is the intended behavior. `preventDefault()` works only for cancelable events and does not prevent other listeners from running.
