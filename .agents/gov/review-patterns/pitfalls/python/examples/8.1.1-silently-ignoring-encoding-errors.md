# Silently ignoring encoding errors

## 1. Catalog record

- **Catalog identifier:** 8.1.1
- **Impact:** medium
- **Consensus:** high
- **Definition:** Avoid `errors="ignore"` unless deliberate irreversible data loss is acceptable. Prefer strict handling or an error strategy such as `surrogateescape` when round-tripping arbitrary bytes is required.

## 2. Example

### 2.1 Scenario

A file-processing service must preserve every input byte while it temporarily handles text-like data.

### 2.2 Preferred form

```python
payload = b"name=Ren\xffe\n"
text = payload.decode("utf-8", errors="surrogateescape")
round_tripped = text.encode("utf-8", errors="surrogateescape")

assert round_tripped == payload
```

### 2.3 Hazardous form

```python
payload = b"name=Ren\xffe\n"
text = payload.decode("utf-8", errors="ignore")

assert text == "name=Rene\n"  # The invalid byte was silently discarded.
```

### 2.4 Why this difference matters

Ignoring errors silently changes data, which can corrupt identifiers, logs, or files before the application notices a problem.

## 3. Boundaries and distinctions

Ignoring errors can be acceptable for intentionally lossy display-only output. Use strict decoding when invalid input must be rejected.
