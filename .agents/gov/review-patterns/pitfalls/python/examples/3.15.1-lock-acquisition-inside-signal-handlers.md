# Lock acquisition inside signal handlers

## 1. Catalog record

- **Catalog identifier:** 3.15.1
- **Impact:** high
- **Consensus:** high
- **Definition:** Do not use ordinary synchronization locks from Python signal handlers. Also remember that Python signal handlers execute in the main Python thread.

## 2. Example

### 2.1 Scenario

An application receives SIGTERM and needs its main processing loop to begin a graceful shutdown.

### 2.2 Preferred form

```python
import signal


shutdown_requested = False


def request_shutdown(signum: int, frame: object) -> None:
    global shutdown_requested
    shutdown_requested = True


signal.signal(signal.SIGTERM, request_shutdown)
```

### 2.3 Hazardous form

```python
import signal
import threading


shutdown_lock = threading.Lock()


def request_shutdown(signum: int, frame: object) -> None:
    with shutdown_lock:
        print("shutting down")


signal.signal(signal.SIGTERM, request_shutdown)
```

### 2.4 Why this difference matters

A signal can interrupt the main thread while it already holds the lock. Acquiring that ordinary lock again in the handler can deadlock the process instead of initiating shutdown.

## 3. Boundaries and distinctions

Handlers should do the smallest safe amount of work and defer cleanup to ordinary control flow. Python signal handlers run in the main Python thread, not at an arbitrary worker thread.
