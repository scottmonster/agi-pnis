# Close channels only when no future send is possible

## 1. Catalog record

- **Catalog identifier:** 1.10.1
- **Impact:** high
- **Consensus:** high
- **Definition:** Coordinate channel closure with all producers. Sending on a closed channel panics, as does closing an already closed channel; closing a nil channel also panics.

## 2. Example

### 2.1 Scenario

Several producers send jobs to one consumer channel.

### 2.2 Preferred form

```go
package main

import "sync"

func produceAll(out chan<- int, inputs []int) {
	var producers sync.WaitGroup
	for _, input := range inputs {
		producers.Go(func() { out <- input })
	}
	go func() {
		producers.Wait()
		close(out)
	}()
}
```

### 2.3 Hazardous form

```go
package main

func produceAll(out chan<- int, inputs []int) {
	for _, input := range inputs {
		go func() { out <- input }()
	}
	close(out)
}
```

### 2.4 Why this difference matters

The hazardous function closes the channel while producer goroutines may still send, causing a panic. The coordinating goroutine closes only after all sends finish.

## 3. Boundaries and distinctions

The sole sender can close its own channel directly after its final send. Receivers generally should not close a channel they do not exclusively own.
