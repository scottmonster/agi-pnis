# Use `declare` for type-only inherited field refinement

## 1. Catalog record

- **Catalog identifier:** 9.5.1
- **Impact:** medium
- **Consensus:** high
- **Definition:** When narrowing the type of an inherited class field without changing its runtime value, write `declare field: NarrowerType` instead of redeclaring a normal field.

## 2. Example

### 2.1 Scenario

A specialized house narrows an inherited resident field but must retain the value initialized by its base constructor.

### 2.2 Preferred form

```typescript
class Animal {}
class Dog extends Animal {
  bark(): void {}
}

class House {
  resident: Animal;

  constructor(resident: Animal) {
    this.resident = resident;
  }
}

class DogHouse extends House {
  declare resident: Dog;

  makeNoise(): void {
    this.resident.bark();
  }
}

new DogHouse(new Dog()).makeNoise();
```

### 2.3 Hazardous form

```typescript
class Animal {}
class Dog extends Animal {
  bark(): void {}
}

class House {
  resident: Animal;

  constructor(resident: Animal) {
    this.resident = resident;
  }
}

class DogHouse extends House {
  resident!: Dog;
}

const house = new DogHouse(new Dog());
house.resident.bark(); // can fail: the emitted field may overwrite resident with undefined
```

### 2.4 Why this difference matters

Under standard class-field semantics, a derived field declaration can run after `super()` and overwrite the value initialized by the base class.

## 3. Boundaries and distinctions

Apply this guidance in the conditions described by the catalog record. Deliberate exceptions need a documented runtime guarantee, compatible toolchain behavior, or an explicit local unsafe boundary.
