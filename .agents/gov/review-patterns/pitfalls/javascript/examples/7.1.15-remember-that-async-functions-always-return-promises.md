# Remember that async functions always return promises

## 1. Catalog record

- **Catalog identifier:** 7.1.15
- **Impact:** low
- **Consensus:** high
- **Definition:** Calling an `async` function always produces a promise, even when the function directly returns a non-promise value.

## 2. Example

### 2.1 Scenario

A caller obtains a display name from a helper that is declared async.

### 2.2 Preferred form

```javascript
async function displayName() {
  return "Morgan";
}

async function showName() {
  console.log(await displayName());
}

showName().catch(console.error);
```

### 2.3 Hazardous form

```javascript
async function displayName() {
  return "Morgan";
}

const name = displayName();
console.log(name.toUpperCase());
```

### 2.4 Why this difference matters

The call returns a Promise rather than a string, so treating it as the direct value causes a type error.

## 3. Boundaries and distinctions

An async function may return a promise-like value internally, but callers still receive one promise and must use promise-aware handling.
