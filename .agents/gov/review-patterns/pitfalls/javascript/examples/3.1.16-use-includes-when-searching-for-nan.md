# Use includes when searching for NaN

## 1. Catalog record

- **Catalog identifier:** 3.1.16
- **Impact:** medium
- **Consensus:** high
- **Definition:** `Array.prototype.includes()` uses SameValueZero equality and can find `NaN`; `indexOf()` cannot.

## 2. Example

### 2.1 Scenario

A data-quality check must detect an invalid numeric reading stored as `NaN`.

### 2.2 Preferred form

```javascript
const readings = [12, NaN, 18];

console.log(readings.includes(NaN)); // true
```

### 2.3 Hazardous form

```javascript
const readings = [12, NaN, 18];

console.log(readings.indexOf(NaN)); // -1
```

### 2.4 Why this difference matters

`NaN` is not strictly equal to itself, so `indexOf` cannot find it. `includes` uses SameValueZero equality and can.

## 3. Boundaries and distinctions

`indexOf` remains useful when an index is required for values it can compare. Use `includes` for Boolean membership checks involving possible `NaN`.
