# Non-deterministic resource cleanup

## 1. Catalog record

- **Catalog identifier:** 1.5.1
- **Impact:** high
- **Consensus:** high
- **Definition:** Use context managers or explicit `close()` operations for files, sockets, locks, database resources, and similar objects rather than relying on garbage collection or `__del__`.

## 2. Example

### 2.1 Scenario

A report writer appends a line to a file and must release the file descriptor reliably.

### 2.2 Preferred form

```python
from pathlib import Path


def write_report(path: Path) -> None:
    with path.open("a", encoding="utf-8") as report:
        report.write("completed\\n")


write_report(Path("report.txt"))
```

### 2.3 Hazardous form

```python
from pathlib import Path


def write_report(path: Path) -> None:
    report = path.open("a", encoding="utf-8")
    report.write("completed\\n")


write_report(Path("report.txt"))
```

### 2.4 Why this difference matters

The hazardous code leaves closure timing to garbage collection, which can exhaust descriptors or keep data buffered after an exception or on another implementation.

## 3. Boundaries and distinctions

Explicit `close()` is valid when a context manager does not fit, but it must be reached reliably, commonly through `try` and `finally`.
