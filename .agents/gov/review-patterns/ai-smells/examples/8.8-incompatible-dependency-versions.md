# Incompatible dependency versions

## 1. Catalog record

- **Catalog identifier:** 8.8
- **Evidence:** e
- **Definition:** Selects versions whose requirements or APIs cannot work together.

## 2. Scenario

### 2.1 Context

A React application adds a plugin that declares React 18 as its peer requirement while the application remains on React 17.

### 2.2 Safer approach

Inspect peer dependencies and choose a plugin release compatible with the installed framework, or plan a tested framework upgrade.

```json
{
  "dependencies": {
    "react": "^17.0.2",
    "acme-react-plugin": "^2.4.0"
  }
}
```

### 2.3 Failure mode

The agent installs the plugin's newest release and overrides the peer-dependency warning.

```json
{
  "dependencies": {
    "react": "^17.0.2",
    "acme-react-plugin": "^4.0.0"
  }
}
```

### 2.4 Why this difference matters

The resulting tree can install with warnings but fail at runtime because the plugin calls framework APIs that React 17 does not provide.

## 3. Boundaries and distinctions

Version differences are not automatically incompatible. This failure concerns versions with conflicting declared requirements or APIs, not an intentional upgrade that is accompanied by a compatible dependency set and verification.
