# Use `command -v` for shell-aware command discovery

## 1. Catalog record

- **Catalog identifier:** 9.9.1
- **Impact:** medium
- **Consensus:** high
- **Definition:** Use `command -v` to discover how the shell resolves a command instead of relying on external `which`.

## 2. Example

### 2.1 Scenario

A setup script must verify that its `deploy` command can be resolved by the current shell.

### 2.2 Preferred form

```bash
#!/usr/bin/env bash
set -euo pipefail

if ! command -v deploy >/dev/null 2>&1; then
  printf 'deploy is unavailable\n' >&2
  exit 1
fi

deploy
```

### 2.3 Hazardous form

```bash
#!/usr/bin/env bash
set -euo pipefail

if ! which deploy >/dev/null 2>&1; then
  printf 'deploy is unavailable\n' >&2
  exit 1
fi

deploy
```

### 2.4 Why this difference matters

`which` is an external utility that cannot reliably represent aliases, functions, builtins, and the shell's actual command-resolution rules.

## 3. Boundaries and distinctions

Use a different check when the requirement is specifically an executable file at a known path rather than a shell-resolvable command.
