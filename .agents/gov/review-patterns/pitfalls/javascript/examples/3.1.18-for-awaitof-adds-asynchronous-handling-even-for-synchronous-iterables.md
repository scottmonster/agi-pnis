# for await...of adds asynchronous handling even for synchronous iterables

## 1. Catalog record

- **Catalog identifier:** 3.1.18
- **Impact:** low
- **Consensus:** high
- **Definition:** Use ordinary `for...of` for synchronous iterables unless asynchronous unwrapping or a unified async interface is actually needed.

## 2. Example

### 2.1 Scenario

A calculation processes an in-memory list of completed order totals.

### 2.2 Preferred form

```javascript
function totalOrders(amounts) {
  let total = 0;
  for (const amount of amounts) {
    total += amount;
  }
  return total;
}

console.log(totalOrders([12, 18])); // 30
```

### 2.3 Hazardous form

```javascript
async function totalOrders(amounts) {
  let total = 0;
  for await (const amount of amounts) {
    total += amount;
  }
  return total;
}

void totalOrders([12, 18]).then(console.log); // 30
```

### 2.4 Why this difference matters

`for await...of` wraps synchronous iteration in asynchronous handling and awaits each iteration, adding scheduling overhead and changing the function's asynchronous contract.

## 3. Boundaries and distinctions

Use `for await...of` for async iterables, promised values that need unwrapping, or a deliberately unified async iteration interface.
