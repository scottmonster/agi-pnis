# Avoid `-a` and `-o` inside `test` expressions

## 1. Catalog record

- **Catalog identifier:** 5.1.1
- **Impact:** medium
- **Consensus:** high
- **Definition:** Instead of complex `[ ... -a ... ]` or `[ ... -o ... ]` expressions, combine separate tests with shell `&&` and `||`, or use `[[ ... ]]` in Bash.

## 2. Example

### 2.1 Scenario

A deployment script must permit a production release only for an approved operator with an enabled account.

### 2.2 Preferred form

```bash
operator=${1:-}
account_state=${2:-}

if [[ $operator == "release-manager" && $account_state == "enabled" ]]; then
  printf 'deployment permitted\n'
else
  printf 'deployment denied\n' >&2
fi
```

### 2.3 Hazardous form

```bash
operator=${1:-}
account_state=${2:-}

if [ "$operator" = "release-manager" -a "$account_state" = "enabled" ]; then
  printf 'deployment permitted\n'
else
  printf 'deployment denied\n' >&2
fi
```

### 2.4 Why this difference matters

The `test` utility's multi-argument grammar has historical ambiguities, making compound `-a` and `-o` expressions harder to review and maintain. `[[ ... && ... ]]` makes the shell-level boolean structure explicit.

## 3. Boundaries and distinctions

Simple single-condition `[ ... ]` tests remain useful, particularly in POSIX shell code. This guidance targets compound conditions inside `test`.
