# Persisting built-in string hashes

## 1. Catalog record

- **Catalog identifier:** 16.11.1
- **Impact:** low
- **Consensus:** high
- **Definition:** Do not persist `hash(str_value)` or `hash(bytes_value)` when a stable cross-process digest is required. Use an explicit stable hash function instead.

## 2. Example

### 2.1 Scenario

A build cache stores a key for a source filename that must match when a later Python process reads it.

### 2.2 Preferred form

```python
import hashlib


def cache_key(filename: str) -> str:
    return hashlib.sha256(filename.encode("utf-8")).hexdigest()


print(cache_key("report.csv"))
```

### 2.3 Hazardous form

```python
def cache_key(filename: str) -> int:
    return hash(filename)


print(cache_key("report.csv"))
```

### 2.4 Why this difference matters

Python salts string and bytes hashes with process-specific randomness, so the hazardous key can differ across processes and invalidate persisted lookup data.

## 3. Boundaries and distinctions

Built-in `hash()` is suitable for in-memory hash tables during one process. Choose a cryptographic digest only when its security properties, not merely stable output, are needed.
