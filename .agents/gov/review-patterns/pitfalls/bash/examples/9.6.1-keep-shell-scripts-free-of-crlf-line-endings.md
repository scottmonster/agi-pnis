# Keep shell scripts free of CRLF line endings

## 1. Catalog record

- **Catalog identifier:** 9.6.1
- **Impact:** medium
- **Consensus:** high
- **Definition:** Use LF line endings in Unix shell scripts so carriage returns do not become part of interpreter paths or tokens.

## 2. Example

### 2.1 Scenario

A release script is edited on another platform and then committed for execution on Linux hosts.

### 2.2 Preferred form

```bash
#!/usr/bin/env bash
set -euo pipefail

printf 'release started\n'
```

### 2.3 Hazardous form

```bash
#!/usr/bin/env bash\r
set -euo pipefail\r

printf 'release started\n'\r
```

### 2.4 Why this difference matters

CRLF can leave a carriage return in the interpreter pathname or command tokens, causing misleading command-not-found errors.

## 3. Boundaries and distinctions

Line-ending conversion is harmless only when a deployment step reliably converts the script back to LF before Unix execution.
