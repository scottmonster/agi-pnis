# Separate assignment and export when tilde portability matters

## 1. Catalog record

- **Catalog identifier:** 10.10.1
- **Impact:** low
- **Consensus:** high
- **Definition:** Shells have differed over tilde handling in declaration assignments such as `export var=~/dir`; assign with `$HOME` and export separately for clarity.

## 2. Example

### 2.1 Scenario

A startup script exports a configuration directory that should work across target shells.

### 2.2 Preferred form

```bash
config_dir="$HOME/.config/example"
export config_dir
printf '%s\n' "$config_dir"
```

### 2.3 Hazardous form

```bash
export config_dir=~/.config/example
printf '%s\n' "$config_dir"
```

### 2.4 Why this difference matters

The compact declaration depends on shell-specific assignment-context parsing, while the two-step form makes the intended home-directory expansion unambiguous.

## 3. Boundaries and distinctions

This is mainly a portability concern. In Bash the compact form can be understood as intended, but shared shell code benefits from the explicit form.
