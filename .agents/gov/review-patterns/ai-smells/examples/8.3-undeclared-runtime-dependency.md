# Undeclared runtime dependency

## 1. Catalog record

- **Catalog identifier:** 8.3
- **Evidence:** e
- **Definition:** Requires a library or service at execution time without declaring it in the project’s dependency metadata.

## 2. Scenario

### 2.1 Context

An agent adds image conversion to a Python web worker and tests it in a development container that already has the needed package installed.

### 2.2 Safer approach

It adds the verified package and compatible version to the project's runtime dependency manifest, refreshes the lockfile when applicable, and starts the worker from a clean environment to confirm installation and execution.

### 2.3 Failure mode

It imports the converter library and commits only the source change. Production installs from the manifest, so the worker crashes on its first conversion request because the library was never declared.

### 2.4 Why this difference matters

The change passes on the author's machine but cannot be reliably deployed or reproduced by CI and runtime environments.

## 3. Boundaries and distinctions

Runtime dependencies must be declared where the deployed program needs them. A test-only tool may belong in development metadata, while a package that is declared but unavailable globally is a different dependency problem.
