# Do not leave promises floating

## 1. Catalog record

- **Catalog identifier:** 7.1.1
- **Impact:** high
- **Consensus:** high
- **Definition:** Await, return, or deliberately handle each promise whose completion matters. In promise chains, do not start asynchronous work and then discard its promise unintentionally.

## 2. Example

### 2.1 Scenario

A checkout handler must save an order before it reports that checkout has finished.

### 2.2 Preferred form

```javascript
async function saveOrder(order) {
  await Promise.resolve(order);
  console.log(`saved ${order.id}`);
}

async function checkout(order) {
  await saveOrder(order);
  console.log("checkout complete");
}

checkout({ id: "A-17" }).catch(console.error);
```

### 2.3 Hazardous form

```javascript
async function saveOrder(order) {
  await Promise.resolve(order);
  console.log(`saved ${order.id}`);
}

async function checkout(order) {
  saveOrder(order);
  console.log("checkout complete");
}

checkout({ id: "A-17" }).catch(console.error);
```

### 2.4 Why this difference matters

The hazardous handler continues before the save completes, and a save rejection is detached from the checkout operation.

## 3. Boundaries and distinctions

Fire-and-forget work can be intentional, but it should be explicitly handled with a documented error-reporting policy.
