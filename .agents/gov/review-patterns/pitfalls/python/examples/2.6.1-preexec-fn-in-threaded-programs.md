# `preexec_fn` in threaded programs

## 1. Catalog record

- **Catalog identifier:** 2.6.1
- **Impact:** high
- **Consensus:** high
- **Definition:** Do not use `Popen(preexec_fn=...)` in a process containing threads. Prefer dedicated `Popen` parameters such as `env`, `start_new_session`, and `process_group`.

## 2. Example

### 2.1 Scenario

A threaded service starts a maintenance process in a new session.

### 2.2 Preferred form

```python
import subprocess


def start_maintenance() -> subprocess.Popen[str]:
    return subprocess.Popen(
        ["python", "-c", "print('maintenance')"],
        start_new_session=True,
        text=True,
    )


process = start_maintenance()
process.wait()
```

### 2.3 Hazardous form

```python
import os
import subprocess


def start_maintenance() -> subprocess.Popen[str]:
    return subprocess.Popen(
        ["python", "-c", "print('maintenance')"],
        preexec_fn=os.setsid,
        text=True,
    )


process = start_maintenance()
process.wait()
```

### 2.4 Why this difference matters

After a fork in a threaded process, `preexec_fn` can run while inherited locks are held, leaving the child deadlocked before it executes the new program.

## 3. Boundaries and distinctions

`preexec_fn` is not safe in a threaded parent. Prefer documented `Popen` arguments that express the needed child configuration.
