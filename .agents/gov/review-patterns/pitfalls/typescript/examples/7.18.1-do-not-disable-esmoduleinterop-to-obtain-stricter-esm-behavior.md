# Do not disable `esModuleInterop` to obtain stricter ESM behavior

## 1. Catalog record

- **Catalog identifier:** 7.18.1
- **Impact:** medium
- **Consensus:** high
- **Definition:** For modern projects, use current interop behavior and `verbatimModuleSyntax` when you need less transformation rather than turning `esModuleInterop` off.

## 2. Example

### 2.1 Scenario

A modern Node project imports a CommonJS dependency while preserving the import syntax that its runtime will execute.

### 2.2 Preferred form

```typescript
// tsconfig.json
// {
//   "compilerOptions": {
//     "module": "NodeNext",
//     "moduleResolution": "NodeNext",
//     "esModuleInterop": true,
//     "verbatimModuleSyntax": true
//   }
// }

// src/server.ts
import legacyLogger from 'legacy-logger';
import type { LogRecord } from 'legacy-logger';

const record: LogRecord = { message: 'started' };
legacyLogger.info(record);
```

### 2.3 Hazardous form

```typescript
// tsconfig.json
// {
//   "compilerOptions": {
//     "module": "commonjs",
//     "esModuleInterop": false,
//     "allowSyntheticDefaultImports": true
//   }
// }

// src/server.ts
import legacyLogger from 'legacy-logger';

legacyLogger.info({ message: 'started' });

// Type checking accepts the synthetic default import, while CommonJS output
// can read require('legacy-logger').default, which the package may not provide.
```

### 2.4 Why this difference matters

`esModuleInterop` supplies consistent compatibility behavior for CommonJS imports. Turning it off does not make a project more ESM-correct, and combining it with synthetic default imports can create a type-checked program whose emitted CommonJS code reads a missing `.default`. `verbatimModuleSyntax` is the focused option for making TypeScript preserve import and export syntax and requiring type-only imports to be explicit.

## 3. Boundaries and distinctions

An existing CommonJS-only project may need legacy settings during migration. In that case, use an import form that matches the package's actual export shape and test the emitted code in its target runtime. This guidance does not replace selecting `module` and `moduleResolution` values that match the deployment environment.
