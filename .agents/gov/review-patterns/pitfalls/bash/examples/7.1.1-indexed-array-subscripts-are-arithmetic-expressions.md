# Indexed-array subscripts are arithmetic expressions

## 1. Catalog record

- **Catalog identifier:** 7.1.1
- **Impact:** medium
- **Consensus:** high
- **Definition:** `array[index]` does not require `index` to be a simple decimal literal. Indexed-array subscripts are evaluated arithmetically. Validate externally supplied index values rather than assuming they are inert strings.

## 2. Example

### 2.1 Scenario

A script selects a deployment target by an index supplied on its command line. The input should identify only an existing numeric position.

### 2.2 Preferred form

```bash
targets=(development staging production)
index=${1:-}

if [[ $index =~ ^[0-9]+$ ]] && (( 10#$index < ${#targets[@]} )); then
  printf 'Deploying to %s\n' "${targets[10#$index]}"
else
  printf 'Choose an index from 0 through %d\n' "$(( ${#targets[@]} - 1 ))" >&2
  exit 2
fi
```

### 2.3 Hazardous form

```bash
targets=(development staging production)
index=${1:-'1 + 1'}

printf 'Deploying to %s\n' "${targets[index]}"
```

### 2.4 Why this difference matters

The hazardous subscript evaluates `1 + 1` as arithmetic and selects `production`, even though the input was not a simple index. Validation constrains external input to the representation the script expects.

## 3. Boundaries and distinctions

Arithmetic subscripts are useful for trusted calculations in the script. The validation is important when an index crosses a trust boundary or when only literal decimal positions are valid.
