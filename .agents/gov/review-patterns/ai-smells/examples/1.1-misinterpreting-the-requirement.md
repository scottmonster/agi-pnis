# Misinterpreting the requirement

## 1. Catalog record

- **Catalog identifier:** 1.1
- **Evidence:** e
- **Definition:** Implements a plausible neighboring problem instead of what was actually requested.

## 2. Scenario

### 2.1 Context

A maintainer asks for a CSV export button to include only active customers. The repository already has an `isActive` field and an existing export endpoint.

### 2.2 Safer approach

Inspect the endpoint, model, and tests, then add the `isActive` filter to the export query and verify that inactive customers are excluded.

### 2.3 Failure mode

The agent interprets "active" as customers with recent orders and filters by `lastOrderAt` instead, despite no such requirement.

### 2.4 Why this difference matters

The export appears plausible but has the wrong business meaning, so it omits valid customers and includes inactive ones.

## 3. Boundaries and distinctions

This differs from partially satisfying the requirement: the requested behavior is misunderstood here, rather than correctly understood but incompletely implemented.
