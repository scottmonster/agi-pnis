# Preserve the distinction between unset and empty `IFS`

## 1. Catalog record

- **Catalog identifier:** 6.8.1
- **Impact:** medium
- **Consensus:** high
- **Definition:** Saving `IFS` as `oldIFS=$IFS` cannot record whether it was originally unset rather than merely empty. Prefer `local IFS` in a function or a subshell when temporarily changing it.

## 2. Example

### 2.1 Scenario

A function reads a colon-separated account record without changing caller state.

### 2.2 Preferred form

```bash
#!/usr/bin/env bash
print_account() {
  local IFS=:
  local user group
  read -r user group <<< "$1"
  echo "$user: $group"
}
print_account 'alix:ops'
```

### 2.3 Hazardous form

```bash
#!/usr/bin/env bash
print_account() {
  local oldIFS=$IFS
  IFS=:
  local user group
  read -r user group <<< "$1"
  IFS=$oldIFS
  echo "$user: $group"
}
print_account 'alix:ops'
```

### 2.4 Why this difference matters

Saving the value cannot distinguish unset `IFS` from an empty `IFS`, so restoration can change shell semantics.

## 3. Boundaries and distinctions

Value restoration is adequate only if the unset state is irrelevant. `local IFS` confines the temporary change.
