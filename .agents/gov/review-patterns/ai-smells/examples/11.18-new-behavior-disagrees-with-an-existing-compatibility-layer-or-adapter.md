# New behavior disagrees with an existing compatibility layer or adapter

## 1. Catalog record

- **Catalog identifier:** 11.18
- **Evidence:** se
- **Definition:** Introduces a contract that conflicts with the translation or legacy behavior at a system boundary.

## 2. Scenario

### 2.1 Context

A service adds a new `archived` order state while an adapter maps current states for an older partner API.

### 2.2 Safer approach

The agent inspects the adapter, decides how `archived` maps for the partner contract, and tests the boundary translation.

### 2.3 Failure mode

The agent emits `archived` directly from the new service path while the adapter only recognizes `open` and `closed`.

### 2.4 Why this difference matters

The system works locally but fails or communicates a contradictory contract at the legacy boundary.

## 3. Boundaries and distinctions

New behavior can intentionally retire a compatibility layer when consumers have migrated; otherwise the boundary translation must remain coherent.
