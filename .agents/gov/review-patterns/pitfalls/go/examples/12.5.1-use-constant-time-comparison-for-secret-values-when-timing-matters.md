# Use constant-time comparison for secret values when timing matters

## 1. Catalog record

- **Catalog identifier:** 12.5.1
- **Impact:** medium
- **Consensus:** high
- **Definition:** Use appropriate `crypto/subtle` operations for authentication tags and other secret comparisons whose timing could expose information.

## 2. Example

### 2.1 Scenario

An HTTP endpoint verifies a fixed-length HMAC tag supplied by a remote client.

### 2.2 Preferred form

```go
package example

import "crypto/subtle"

func validTag(expected, received []byte) bool {
	if len(expected) != 32 || len(received) != 32 {
		return false
	}
	return subtle.ConstantTimeCompare(expected, received) == 1
}
```

### 2.3 Hazardous form

```go
package example

import "bytes"

func validTag(expected, received []byte) bool {
	return bytes.Equal(expected, received)
}
```

### 2.4 Why this difference matters

`bytes.Equal` may stop at the first mismatch, allowing an attacker who can make many precise timing observations to learn information about a secret tag. `ConstantTimeCompare` examines fixed-length values without that early mismatch behavior.

## 3. Boundaries and distinctions

This is for secrets exposed to an attacker who may observe timing. Ordinary public identifiers and non-secret data do not usually need constant-time comparison; fixed lengths should be checked separately when length itself is not secret.
