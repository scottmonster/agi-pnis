# Do not spread values into objects merely because TypeScript permits it

## 1. Catalog record

- **Catalog identifier:** 9.1.1
- **Impact:** medium
- **Consensus:** high
- **Definition:** Be cautious spreading arrays, Promises, functions, class instances, Maps, Sets, and other non-record values into object literals.

## 2. Example

### 2.1 Scenario

A request needs a plain object made from a map of headers.

### 2.2 Preferred form

```typescript
const headers = new Map([['accept', 'application/json']]);
const requestHeaders = Object.fromEntries(headers);

console.log(requestHeaders.accept);
```

### 2.3 Hazardous form

```typescript
const headers = new Map([['accept', 'application/json']]);
const requestHeaders = { ...headers };

console.log(requestHeaders); // {}, not { accept: 'application/json' }
```

### 2.4 Why this difference matters

Object spread copies enumerable own properties, which often has little relationship to the conceptual value being spread and can silently discard important state.

## 3. Boundaries and distinctions

Apply this guidance in the conditions described by the catalog record. Deliberate exceptions need a documented runtime guarantee, compatible toolchain behavior, or an explicit local unsafe boundary.
