# Dependency to avoid understanding a small problem

## 1. Catalog record

- **Catalog identifier:** 4.8
- **Evidence:** se
- **Definition:** Imports a heavyweight package for a simple transformation or algorithm.

## 2. Scenario

### 2.1 Context

An agent must convert a list of API records into a lookup keyed by each record's identifier.

### 2.2 Safer approach

It confirms the input shape, uses a short native reduction or loop, and adds tests for duplicate-key behavior.

### 2.3 Failure mode

It imports a large data-processing package without examining the transformation, solely to call a helper that makes the simple mapping opaque.

### 2.4 Why this difference matters

The dependency obscures a small problem the team should understand and adds weight and maintenance for a basic operation.

## 3. Boundaries and distinctions

Use a package when the problem is genuinely complex or its correctness depends on specialized expertise. This failure is importing heavyweight code to avoid understanding a simple transformation or algorithm.
