# BigInt is not supported by default JSON serialization

## 1. Catalog record

- **Catalog identifier:** 9.1.5
- **Impact:** medium
- **Consensus:** high
- **Definition:** Convert BigInt to an explicit serializable representation before JSON.stringify.

## 2. Example

### 2.1 Scenario

A billing API sends an invoice identifier that must remain an exact integer.

### 2.2 Preferred form

```javascript
const invoice = { id: 9007199254740993n, totalCents: 1250 };
const payload = JSON.stringify({ ...invoice, id: invoice.id.toString() });
const received = JSON.parse(payload);

console.log(BigInt(received.id) === invoice.id); // true
```

### 2.3 Hazardous form

```javascript
const invoice = { id: 9007199254740993n, totalCents: 1250 };

console.log(JSON.stringify(invoice));
```

### 2.4 Why this difference matters

The hazardous form throws a `TypeError`, so the request cannot be serialized at all.

## 3. Boundaries and distinctions

Use strings only when the receiving schema documents that representation. A replacer and reviver can centralize a tagged BigInt convention for a controlled protocol.
