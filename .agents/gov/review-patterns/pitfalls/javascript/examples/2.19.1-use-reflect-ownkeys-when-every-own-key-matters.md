# Use Reflect.ownKeys when every own key matters

## 1. Catalog record

- **Catalog identifier:** 2.19.1
- **Impact:** low
- **Consensus:** high
- **Definition:** Use `Reflect.ownKeys()` when every own string and symbol key matters.

## 2. Example

### 2.1 Scenario

A diagnostic tool reports all own property names on an object.

### 2.2 Preferred form

```javascript
const trace = Symbol("trace");
const event = { name: "saved", [trace]: "abc" };
Object.defineProperty(event, "internalId", { value: 7 });

console.log(Reflect.ownKeys(event));
```

### 2.3 Hazardous form

```javascript
const trace = Symbol("trace");
const event = { name: "saved", [trace]: "abc" };
Object.defineProperty(event, "internalId", { value: 7 });

console.log(Object.getOwnPropertyNames(event));
```

### 2.4 Why this difference matters

`Object.getOwnPropertyNames()` includes non-enumerable string keys but omits symbols, while `Reflect.ownKeys()` includes both.

## 3. Boundaries and distinctions

Use narrower reflection APIs when their exact omissions are desired, such as `Object.keys()` for enumerable strings only.
