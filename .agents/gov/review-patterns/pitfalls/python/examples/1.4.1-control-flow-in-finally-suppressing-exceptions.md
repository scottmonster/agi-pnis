# Control flow in `finally` suppressing exceptions

## 1. Catalog record

- **Catalog identifier:** 1.4.1
- **Impact:** high
- **Consensus:** high
- **Definition:** Avoid `return`, `break`, or `continue` that exits a `finally` block while an exception is active. Python 3.14 warns about such constructs.

## 2. Example

### 2.1 Scenario

A service validates an order and must report invalid totals to its caller.

### 2.2 Preferred form

```python
def validate_total(total: int) -> str:
    try:
        if total < 0:
            raise ValueError("total cannot be negative")
        return "accepted"
    finally:
        print("validation finished")


print(validate_total(10))
```

### 2.3 Hazardous form

```python
def validate_total(total: int) -> str:
    try:
        if total < 0:
            raise ValueError("total cannot be negative")
        return "accepted"
    finally:
        return "finished"


print(validate_total(-1))
```

### 2.4 Why this difference matters

The `return` in `finally` replaces the active `ValueError`, so the caller receives a misleading success-like result.

## 3. Boundaries and distinctions

Use `finally` for unconditional cleanup that completes normally. Return only after the cleanup boundary when no exception must propagate.
