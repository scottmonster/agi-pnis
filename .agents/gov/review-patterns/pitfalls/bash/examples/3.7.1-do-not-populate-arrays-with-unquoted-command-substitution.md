# Do not populate arrays with unquoted command substitution

## 1. Catalog record

- **Catalog identifier:** 3.7.1
- **Impact:** high
- **Consensus:** high
- **Definition:** Read command output as records with `mapfile` or a delimiter-aware reader instead of unquoted command substitution.

## 2. Example

### 2.1 Scenario

A report command emits one filename per line, and filenames can contain spaces.

### 2.2 Preferred form

```bash
list_reports() {
  printf '%s\n' 'April report.csv' 'May report.csv'
}

mapfile -t reports < <(list_reports)
printf '<%s>\n' "${reports[@]}"
```

### 2.3 Hazardous form

```bash
list_reports() {
  printf '%s\n' 'April report.csv' 'May report.csv'
}

reports=( $(list_reports) )
printf '<%s>\n' "${reports[@]}"
```

### 2.4 Why this difference matters

Unquoted command substitution applies word splitting and pathname expansion, turning line records into unrelated words or matched pathnames.

## 3. Boundaries and distinctions

`mapfile -t` is appropriate for newline-delimited records; use an explicit reader for a different delimiter or data format.
