# Name repeatedly evaluated complex types

## 1. Catalog record

- **Catalog identifier:** 11.1.2
- **Impact:** low
- **Consensus:** high
- **Definition:** Extract heavily reused conditional, mapped, or other complex anonymous types into named aliases when type-checking performance becomes material.

## 2. Example

### 2.1 Scenario

A schema library derives the serializable shape of models in several public APIs.

### 2.2 Preferred form

```typescript
type SerializableShape<T> = {
  [K in keyof T as T[K] extends Function ? never : K]:
    T[K] extends readonly (infer Item)[]
      ? SerializableShape<Item>[]
      : T[K] extends object
        ? SerializableShape<T[K]>
        : T[K];
};

interface User {
  id: string;
  profile: { displayName: string };
  refresh(): void;
}

function save(value: SerializableShape<User>): void {}
function send(value: SerializableShape<User>): void {}
```

### 2.3 Hazardous form

```typescript
interface User {
  id: string;
  profile: { displayName: string };
  refresh(): void;
}

function save(value: {
  [K in keyof User as User[K] extends Function ? never : K]:
    User[K] extends readonly (infer Item)[]
      ? { [P in keyof Item]: Item[P] }[]
      : User[K] extends object
        ? { [P in keyof User[K]]: User[K][P] }
        : User[K];
}): void {}

function send(value: {
  [K in keyof User as User[K] extends Function ? never : K]:
    User[K] extends readonly (infer Item)[]
      ? { [P in keyof Item]: Item[P] }[]
      : User[K] extends object
        ? { [P in keyof User[K]]: User[K][P] }
        : User[K];
}): void {}
```

### 2.4 Why this difference matters

Named types give the compiler opportunities to reuse cached results instead of repeatedly evaluating the same complex expression.

## 3. Boundaries and distinctions

Apply this guidance in the conditions described by the catalog record. Deliberate exceptions need a documented runtime guarantee, compatible toolchain behavior, or an explicit local unsafe boundary.
