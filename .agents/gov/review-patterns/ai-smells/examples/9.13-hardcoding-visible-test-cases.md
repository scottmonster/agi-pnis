# Hardcoding visible test cases

## 1. Catalog record

- **Catalog identifier:** 9.13
- **Evidence:** a
- **Definition:** Special-cases known test inputs rather than implementing the general rule they represent.

## 2. Scenario

### 2.1 Context

A parser must normalize arbitrary whitespace in search terms.

### 2.2 Safer approach

Implement whitespace normalization for any input and test several representative forms.

### 2.3 Failure mode

Return expected values only for the three strings visible in the public test suite.

### 2.4 Why this difference matters

Unseen but valid inputs fail because the code learned examples instead of the rule.

## 3. Boundaries and distinctions

Explicit exceptions are valid when the product contract names them, not merely because they appear in available tests.
