# Do not use truthiness when valid data can be falsy

## 1. Catalog record

- **Catalog identifier:** 6.3.1
- **Impact:** medium
- **Consensus:** high
- **Definition:** Prefer explicit nullish or domain-specific checks when `0`, `""`, `false`, or `NaN` are legitimate values.

## 2. Example

### 2.1 Scenario

A report may legitimately contain a zero-item count.

### 2.2 Preferred form

```typescript
function formatCount(count: number | undefined): string {
  return count === undefined ? 'Not reported' : `${count} items`;
}

```

### 2.3 Hazardous form

```typescript
function formatCount(count: number | undefined): string {
  return count ? `${count} items` : 'Not reported';
}
```

### 2.4 Why this difference matters

Truthiness narrowing removes all falsy values, not merely `null` and `undefined`.

## 3. Boundaries and distinctions

Apply this guidance in the conditions described by the catalog record. Deliberate exceptions need a documented runtime guarantee, compatible toolchain behavior, or an explicit local unsafe boundary.
