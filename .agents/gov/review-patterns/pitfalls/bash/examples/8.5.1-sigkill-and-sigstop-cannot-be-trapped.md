# SIGKILL and SIGSTOP cannot be trapped

## 1. Catalog record

- **Catalog identifier:** 8.5.1
- **Impact:** medium
- **Consensus:** high
- **Definition:** Do not design mandatory cleanup or data-integrity guarantees around traps for `KILL` or `STOP`, because those signals cannot be caught by the shell.

## 2. Example

### 2.1 Scenario

A deployment script wants to remove a temporary file if it is interrupted.

### 2.2 Preferred form

```bash
tmp_file=$(mktemp)
trap 'rm -f -- "$tmp_file"' EXIT INT TERM

printf 'staged data\n' >"$tmp_file"
mv -- "$tmp_file" ./release-data
trap - EXIT INT TERM
```

### 2.3 Hazardous form

```bash
tmp_file=$(mktemp)
trap 'rm -f -- "$tmp_file"' KILL STOP

printf 'staged data\n' >"$tmp_file"
mv -- "$tmp_file" ./release-data
```

### 2.4 Why this difference matters

Bash cannot install handlers for KILL or STOP, so required cleanup cannot depend on those events. The preferred form uses catchable signals and makes the final update an atomic rename.

## 3. Boundaries and distinctions

EXIT, INT, and TERM improve normal interruption handling but remain best effort. Design important data changes so they remain recoverable even after an uncatchable termination.
