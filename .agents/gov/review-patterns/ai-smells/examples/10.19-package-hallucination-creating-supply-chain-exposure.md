# Package hallucination creating supply-chain exposure

## 1. Catalog record

- **Catalog identifier:** 10.19
- **Evidence:** e
- **Definition:** Names a nonexistent package that an attacker can publish and have downstream users install.

## 2. Scenario

### 2.1 Context

An agent needs a library helper while updating a project dependency file.

### 2.2 Safer approach

Check the project’s existing dependencies and the package registry or official documentation before adding a verified package with an appropriate version.

### 2.3 Failure mode

The agent invents a plausible package name and adds it to the install instructions without confirming it exists or is the intended project.

### 2.4 Why this difference matters

An attacker can publish the invented name and cause downstream installs to execute untrusted supply-chain code.

## 3. Boundaries and distinctions

An unfamiliar but verified package is not a hallucination. The failure is relying on an unverified, nonexistent or wrongly identified dependency name.
