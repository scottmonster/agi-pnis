# Avoid top-level var in classic browser scripts

## 1. Catalog record

- **Catalog identifier:** 8.1.6
- **Impact:** medium
- **Consensus:** high
- **Definition:** Avoid top-level var in classic browser scripts unless a global property is intentional.

## 2. Example

### 2.1 Scenario

A classic browser script stores private configuration for its own initialization code.

### 2.2 Preferred form

```javascript
// Loaded by a classic <script> element.
const retryLimit = 3;

function configureRetries() {
  return retryLimit;
}

console.log(window.retryLimit); // undefined
console.log(configureRetries()); // 3
```

### 2.3 Hazardous form

```javascript
// Loaded by a classic <script> element.
var retryLimit = 3;

function configureRetries() {
  return retryLimit;
}

console.log(window.retryLimit); // 3
console.log(configureRetries()); // 3
```

### 2.4 Why this difference matters

At the top level of a classic browser script, `var` creates a property on `window`, increasing collision and accidental-coupling risk.

## 3. Boundaries and distinctions

This behavior is specific to classic browser scripts. Creating a global property can be intentional for a documented legacy integration point.
