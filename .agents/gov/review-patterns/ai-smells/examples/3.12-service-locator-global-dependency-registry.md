# Service locator / global dependency registry

## 1. Catalog record

- **Catalog identifier:** 3.12
- **Evidence:** se
- **Definition:** Introduces indirection while making dependency relationships less visible.

## 2. Scenario

### 2.1 Context

An invoice service needs a mail sender.

### 2.2 Safer approach

Pass the mail sender into the service constructor so the dependency is explicit.

### 2.3 Failure mode

Have the service retrieve a mail sender from a process-global registry at send time.

### 2.4 Why this difference matters

Hidden dependencies complicate tests, lifecycle reasoning, and understanding of required collaborators.

## 3. Boundaries and distinctions

This concerns lookup that conceals dependencies, not ordinary explicit dependency injection.
