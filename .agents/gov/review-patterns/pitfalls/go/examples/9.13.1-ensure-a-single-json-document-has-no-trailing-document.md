# Ensure a single JSON document has no trailing document

## 1. Catalog record

- **Catalog identifier:** 9.13.1
- **Impact:** medium
- **Consensus:** high
- **Definition:** When using `Decoder.Decode` for a single payload, verify that the next decode reaches EOF, or use `json.Unmarshal` on bounded input.

## 2. Example

### 2.1 Scenario

An API accepts exactly one JSON configuration document from a bounded request body.

### 2.2 Preferred form

```go
package example

import (
	"encoding/json"
	"fmt"
	"io"
)

type Config struct { Name string `json:"name"` }

func decodeOne(r io.Reader) (Config, error) {
	decoder := json.NewDecoder(r)
	var config Config
	if err := decoder.Decode(&config); err != nil { return Config{}, err }
	var extra any
	if err := decoder.Decode(&extra); err != io.EOF {
		if err == nil { return Config{}, fmt.Errorf("expected one JSON value") }
		return Config{}, err
	}
	return config, nil
}
```

### 2.3 Hazardous form

```go
package example

import (
	"encoding/json"
	"io"
)

type Config struct { Name string `json:"name"` }

func decodeOne(r io.Reader) (Config, error) {
	var config Config
	err := json.NewDecoder(r).Decode(&config) // Accepts {"name":"a"}{"name":"b"}.
	return config, err
}
```

### 2.4 Why this difference matters

A successful first decode does not prove the stream contained only one document. Checking for EOF rejects payload smuggling and malformed concatenated input.

## 3. Boundaries and distinctions

JSON streams intentionally containing multiple values should decode them in a documented loop. For a single bounded byte slice, `json.Unmarshal` already rejects trailing non-whitespace data.
