# Adding before understanding

## 1. Catalog record

- **Catalog identifier:** 14.1
- **Evidence:** a
- **Definition:** New code, abstractions, dependencies, and configuration appear before the existing solution space is inspected.

## 2. Scenario

### 2.1 Context

An agent is asked to add CSV export to an established TypeScript service. The repository may already expose an export utility and a response streaming convention.

### 2.2 Safer approach

The agent inspects nearby endpoints, dependency manifests, and existing export helpers before proposing the smallest compatible change.

### 2.3 Failure mode

It immediately adds a CSV package, a generic export layer, a new configuration flag, and a separate route without looking for existing support.

### 2.4 Why this difference matters

The change can duplicate capabilities, diverge from repository conventions, and create maintenance work unrelated to CSV export.

## 3. Boundaries and distinctions

Exploration should fit the task. This does not prohibit a new dependency or abstraction after inspection shows that the existing solution space lacks a suitable option.
