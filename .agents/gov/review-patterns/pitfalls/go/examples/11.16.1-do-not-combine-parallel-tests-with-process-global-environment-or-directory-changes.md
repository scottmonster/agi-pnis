# Do not combine parallel tests with process-global environment or directory changes

## 1. Catalog record

- **Catalog identifier:** 11.16.1
- **Impact:** medium
- **Consensus:** high
- **Definition:** Tests using `T.Setenv` or `T.Chdir` cannot safely run in parallel with tests sharing the process state.

## 2. Example

### 2.1 Scenario

A configuration test needs a temporary environment variable and an unrelated test may run concurrently.

### 2.2 Preferred form

```go
package example

import (
	"os"
	"testing"
)

func TestConfiguration(t *testing.T) {
	t.Setenv("SERVICE_MODE", "test")
	if got := os.Getenv("SERVICE_MODE"); got != "test" {
		t.Fatalf("SERVICE_MODE = %q", got)
	}
}
```

### 2.3 Hazardous form

```go
package example

import "testing"

func TestConfiguration(t *testing.T) {
	t.Parallel()
	t.Setenv("SERVICE_MODE", "test") // process-global mutation races with peers
}
```

### 2.4 Why this difference matters

The environment and working directory belong to the process, not one test. Parallel tests can observe or overwrite each other's state, producing flaky results.

## 3. Boundaries and distinctions

Use parallelism for tests with isolated state. Tests that call `T.Setenv` or `T.Chdir` must stay non-parallel, including with parallel ancestors or descendants that could share the mutation.
