# Treat loop capture rules as version and declaration sensitive

## 1. Catalog record

- **Catalog identifier:** 1.12.1
- **Impact:** high
- **Consensus:** high
- **Definition:** Go 1.22+ gives variables declared by a range clause with `:=` a new variable per iteration. Older language versions retain the old capture behavior, and current loops assigning into predeclared variables with `=` still reuse those variables.

## 2. Example

### 2.1 Scenario

A program starts callbacks that must retain each input name.

### 2.2 Preferred form

```go
package main

import "fmt"

func callbacks(names []string) []func() {
	callbacks := make([]func(), 0, len(names))
	for _, name := range names {
		name := name
		callbacks = append(callbacks, func() { fmt.Println(name) })
	}
	return callbacks
}
```

### 2.3 Hazardous form

```go
package main

import "fmt"

func callbacks(names []string) []func() {
	callbacks := make([]func(), 0, len(names))
	var name string
	for _, name = range names {
		callbacks = append(callbacks, func() { fmt.Println(name) })
	}
	return callbacks
}
```

### 2.4 Why this difference matters

The hazardous loop assigns into one predeclared variable, so every closure observes its final value. Shadowing creates a distinct captured value for each callback.

## 3. Boundaries and distinctions

Go 1.22 and later give `:=` range variables per-iteration semantics, but explicitly shadowing remains portable and makes intent clear. Verify the module language version when supporting older Go versions.
