# Remember that output redirection truncates before command execution

## 1. Catalog record

- **Catalog identifier:** 2.1.2
- **Impact:** high
- **Consensus:** high
- **Definition:** `command > file` causes Bash to open and normally truncate `file` as part of setting up the command. For important transformations, write to another file and replace the target only after success.

## 2. Example

### 2.1 Scenario

A deployment script regenerates a checked-in manifest with a generator that might be missing or fail. It must not destroy the current manifest first.

### 2.2 Preferred form

```bash
#!/usr/bin/env bash
set -euo pipefail

manifest='manifest.txt'
temporary_file=$(mktemp "${manifest}.XXXXXX")
trap 'rm -f -- "$temporary_file"' EXIT

generate_manifest > "$temporary_file"
mv -- "$temporary_file" "$manifest"
trap - EXIT
```

### 2.3 Hazardous form

```bash
#!/usr/bin/env bash
set -euo pipefail

manifest='manifest.txt'
generate_manifest > "$manifest"
```

### 2.4 Why this difference matters

The hazardous form opens and truncates `manifest.txt` before Bash starts `generate_manifest`. If the command is absent or fails immediately, the previously valid manifest is already gone.

## 3. Boundaries and distinctions

Truncation is intentional when replacing a disposable output is safe. Use a temporary file when preserving the prior file through command setup and execution matters.
