# Coding before grounding

## 1. Catalog record

- **Catalog identifier:** 14.8
- **Evidence:** a
- **Definition:** The model starts implementation before understanding repository-specific facts.

## 2. Scenario

### 2.1 Context

An issue requests a field on an existing API response. The repository has generated types, a versioned schema, and a compatibility policy.

### 2.2 Safer approach

The agent reads the endpoint, schema-generation workflow, related tests, and contribution guidance before editing the authoritative source.

### 2.3 Failure mode

It changes a hand-written response type in one file and opens a patch before learning that generated artifacts and versioning rules control the API.

### 2.4 Why this difference matters

The patch can be overwritten, fail integration, or violate local conventions despite appearing correct in isolation.

## 3. Boundaries and distinctions

Grounding need not mean reading the entire repository. It means establishing the repository-specific facts material to the requested change before implementation.
