# Preserve listener identity when removing event listeners

## 1. Catalog record

- **Catalog identifier:** 11.1.7
- **Impact:** medium
- **Consensus:** high
- **Definition:** Reuse listener identity and capture semantics when removing a listener, or use AbortSignal lifecycle management.

## 2. Example

### 2.1 Scenario

A dialog registers an Escape-key handler while it is open and must remove it when the dialog closes.

### 2.2 Preferred form

```javascript
const controller = new AbortController();

function closeOnEscape(event) {
  if (event.key === "Escape") document.querySelector("dialog").close();
}

document.addEventListener("keydown", closeOnEscape, { signal: controller.signal });
controller.abort();
```

### 2.3 Hazardous form

```javascript
document.addEventListener("keydown", (event) => {
  if (event.key === "Escape") document.querySelector("dialog").close();
});

document.removeEventListener("keydown", (event) => {
  if (event.key === "Escape") document.querySelector("dialog").close();
});
```

### 2.4 Why this difference matters

Each anonymous function is a different object, so the removal call does not remove the original handler and the closed dialog can remain referenced by an active listener.

## 3. Boundaries and distinctions

`removeEventListener()` can also use a named handler directly, provided its listener identity and capture setting match the registration.
