# Assuming imports are passive declarations

## 1. Catalog record

- **Catalog identifier:** 9.3.1
- **Impact:** medium
- **Consensus:** high
- **Definition:** Keep unavoidable import-time side effects controlled and remember that ordinary module top-level code executes on the first import in an interpreter.

## 2. Example

### 2.1 Scenario

An application needs to start a background worker only after its runtime configuration has been loaded.

### 2.2 Preferred form

```python
# worker.py
def start_worker() -> None:
    print("worker started")

# app.py
import worker

worker.start_worker()
```

### 2.3 Hazardous form

```python
# worker.py
print("worker started")

# app.py
import worker
```

### 2.4 Why this difference matters

The hazardous module starts work merely because it is imported, making ordering, tests, and reuse unexpectedly dependent on import behavior.

## 3. Boundaries and distinctions

Some modules must register declarations during import, but those effects should be minimal, predictable, and safe to perform once.
