# Plain-object keys are strings or symbols

## 1. Catalog record

- **Catalog identifier:** 2.8.1
- **Impact:** medium
- **Consensus:** high
- **Definition:** Use `Map` or another identity-preserving structure for arbitrary object keys.

## 2. Example

### 2.1 Scenario

A cache associates a result with each request object.

### 2.2 Preferred form

```javascript
const cache = new Map();
const firstRequest = { path: "/users" };
const secondRequest = { path: "/users" };

cache.set(firstRequest, "first");
cache.set(secondRequest, "second");
console.log(cache.size);
```

### 2.3 Hazardous form

```javascript
const cache = {};
const firstRequest = { path: "/users" };
const secondRequest = { path: "/users" };

cache[firstRequest] = "first";
cache[secondRequest] = "second";
console.log(Object.keys(cache).length);
```

### 2.4 Why this difference matters

Plain object keys coerce both request objects to the same string, so the second assignment overwrites the first.

## 3. Boundaries and distinctions

Plain objects are appropriate for known string or symbol keys. Use `Map` when key identity or non-string keys matter.
