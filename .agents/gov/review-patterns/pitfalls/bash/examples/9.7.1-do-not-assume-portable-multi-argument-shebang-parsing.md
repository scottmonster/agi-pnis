# Do not assume portable multi-argument shebang parsing

## 1. Catalog record

- **Catalog identifier:** 9.7.1
- **Impact:** medium
- **Consensus:** high
- **Definition:** Keep shebang invocation simple unless every deployment platform's interpreter-argument behavior is controlled.

## 2. Example

### 2.1 Scenario

A script must run on several Unix-like deployment systems with strict Bash options.

### 2.2 Preferred form

```bash
#!/usr/bin/env bash
set -euo pipefail

printf 'validated input: %s\n' "${1:?an input is required}"
```

### 2.3 Hazardous form

```bash
#!/usr/bin/env bash -euo pipefail

printf 'validated input: %s\n' "${1:?an input is required}"
```

### 2.4 Why this difference matters

Kernels can tokenize or reject multiple shebang arguments differently, so the hazardous script may not start Bash with the intended options.

## 3. Boundaries and distinctions

Multi-argument forms can be acceptable when the supported operating systems and features such as `env -S` are explicitly controlled and tested.
