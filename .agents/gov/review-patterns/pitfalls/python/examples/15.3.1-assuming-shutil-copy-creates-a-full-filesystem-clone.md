# Assuming `shutil.copy*` creates a full filesystem clone

## 1. Catalog record

- **Catalog identifier:** 15.3.1
- **Impact:** medium
- **Consensus:** high
- **Definition:** Do not assume ordinary `shutil` copy operations preserve all ownership, ACL, resource-fork, alternate-stream, and extended metadata.

## 2. Example

### 2.1 Scenario

An administrator copies a file into a protected location where its ownership and access-control list are part of the security policy.

### 2.2 Preferred form

```python
from pathlib import Path
import shutil


def copy_content_for_review(source: Path, destination: Path) -> None:
    shutil.copy2(source, destination)
    print("Review ownership, ACLs, and platform metadata separately.")
```

### 2.3 Hazardous form

```python
from pathlib import Path
import shutil


def clone_secure_file(source: Path, destination: Path) -> None:
    shutil.copy2(source, destination)
    print("The destination has identical security metadata.")
```

### 2.4 Why this difference matters

`copy2()` preserves more metadata than `copy()`, but it is not a full filesystem clone. Ownership, ACLs, and platform-specific metadata can be absent or different.

## 3. Boundaries and distinctions

`shutil` is suitable for ordinary content copies and best-effort metadata preservation. Use platform-specific tools and verification when exact metadata fidelity is required.
