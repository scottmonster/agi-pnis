# Make getters return a value on every intended path

## 1. Catalog record

- **Catalog identifier:** 2.4.1
- **Impact:** medium
- **Consensus:** high
- **Definition:** Return the intended value from every reachable getter path.

## 2. Example

### 2.1 Scenario

A task exposes a label for both complete and pending states.

### 2.2 Preferred form

```javascript
class Task {
  constructor(done) {
    this.done = done;
  }

  get label() {
    return this.done ? "complete" : "pending";
  }
}
```

### 2.3 Hazardous form

```javascript
class Task {
  constructor(done) {
    this.done = done;
  }

  get label() {
    if (this.done) return "complete";
  }
}
```

### 2.4 Why this difference matters

The hazardous getter returns `undefined` for pending tasks, which can silently reach display or decision logic.

## 3. Boundaries and distinctions

Returning `undefined` is valid when it is a documented, intentional result rather than an unhandled path.
