# Assigning a lambda to a name

## 1. Catalog record

- **Catalog identifier:** 16.4.1
- **Impact:** low
- **Consensus:** high
- **Definition:** When a callable needs a durable name, prefer `def` over assigning a `lambda` expression.

## 2. Example

### 2.1 Scenario

A billing module exposes a named function that formats a customer identifier.

### 2.2 Preferred form

```python
def format_customer_id(customer_id: int) -> str:
    return f"customer-{customer_id:06d}"
```

### 2.3 Hazardous form

```python
format_customer_id = lambda customer_id: f"customer-{customer_id:06d}"
```

### 2.4 Why this difference matters

A `def` gives the callable a meaningful name for tracebacks, introspection, and documentation. A named lambda still reports itself as `<lambda>`.

## 3. Boundaries and distinctions

Lambdas are useful for small inline callbacks where no durable name is needed. Use `def` for public, reusable, or nontrivial functions.
