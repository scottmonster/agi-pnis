# Prefer function-property signatures where callback variance must be sound

## 1. Catalog record

- **Catalog identifier:** 5.1.1
- **Impact:** high
- **Consensus:** medium
- **Definition:** Under `strictFunctionTypes`, prefer properties such as `handler: (x: T) => void` for callback contracts where contravariant checking matters; method syntax retains bivariant parameter behavior for compatibility.

## 2. Example

### 2.1 Scenario

A dispatcher calls handlers with any event in its declared event union.

### 2.2 Preferred form

```typescript
type Event = { type: 'created' } | { type: 'deleted'; id: string };

interface Listener {
  handle: (event: Event) => void;
}

const listener: Listener = { handle: (event) => console.log(event.type) };
```

### 2.3 Hazardous form

```typescript
type Event = { type: 'created' } | { type: 'deleted'; id: string };

interface Listener {
  handle(event: Event): void; // Method parameters are bivariant.
}

const listener: Listener = {
  handle(event: { type: 'deleted'; id: string }) { console.log(event.id); },
};
```

### 2.4 Why this difference matters

Method bivariance can accept a callback that handles a narrower input than the caller may actually provide.

## 3. Boundaries and distinctions

Apply this guidance in the conditions described by the catalog record. Deliberate exceptions need a documented runtime guarantee, compatible toolchain behavior, or an explicit local unsafe boundary.
