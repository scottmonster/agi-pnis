# Assuming `sys.exit()` from a worker thread exits the process

## 1. Catalog record

- **Catalog identifier:** 3.17.1
- **Impact:** high
- **Consensus:** high
- **Definition:** Do not use `sys.exit()` in a worker thread as a process-wide shutdown mechanism. Coordinate shutdown with the main thread instead.

## 2. Example

### 2.1 Scenario

A background worker detects a fatal condition and must ask the application to stop cleanly.

### 2.2 Preferred form

```python
import threading


shutdown_requested = threading.Event()


def worker() -> None:
    shutdown_requested.set()


thread = threading.Thread(target=worker)
thread.start()
thread.join()

if shutdown_requested.is_set():
    raise SystemExit("worker requested shutdown")
```

### 2.3 Hazardous form

```python
import sys
import threading


def worker() -> None:
    sys.exit("stop the whole application")


thread = threading.Thread(target=worker)
thread.start()
thread.join()
print("the main thread is still running")
```

### 2.4 Why this difference matters

`sys.exit()` raises `SystemExit`; in a worker it normally ends only that worker. A signal to the main thread permits coordinated cleanup and a process-wide decision.

## 3. Boundaries and distinctions

Calling `sys.exit()` from the main thread is an appropriate normal termination mechanism when that thread owns application shutdown.
