# API misuse

## 1. Catalog record

- **Catalog identifier:** 2.7
- **Evidence:** e
- **Definition:** The API exists but arguments, preconditions, lifecycle, or exception semantics are wrong.

## 2. Scenario

### 2.1 Context

A worker uses a real database transaction API to save an order and its payment record.

### 2.2 Safer approach

It begins the transaction, performs both writes through the transaction handle, and rolls back on failure before committing.

### 2.3 Failure mode

It creates a transaction but performs one write through the global database client, outside that transaction.

### 2.4 Why this difference matters

The API is real, yet a payment failure can leave an order committed without its corresponding payment record.

## 3. Boundaries and distinctions

Verification must cover API semantics, not merely whether method names and types are valid.
