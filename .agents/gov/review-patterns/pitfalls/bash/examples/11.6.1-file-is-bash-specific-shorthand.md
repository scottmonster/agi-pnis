# `$(<file)` is Bash-specific shorthand

## 1. Catalog record

- **Catalog identifier:** 11.6.1
- **Impact:** low
- **Consensus:** high
- **Definition:** Bash supports `$(<file)` as an optimized way to read a file through command substitution. Do not use it in code that must run under shells that do not implement the extension.

## 2. Example

### 2.1 Scenario

A script reads a single release identifier from a file and is declared as portable `sh`.

### 2.2 Preferred form

```bash
#!/bin/sh

release_id=$(cat ./release-id.txt)
echo "release: $release_id"
```

### 2.3 Hazardous form

```bash
#!/bin/sh

release_id=$(<./release-id.txt)
echo "release: $release_id"
```

### 2.4 Why this difference matters

The shorthand is accepted by Bash but is not POSIX shell syntax, so a portable script can fail when `/bin/sh` is another shell.

## 3. Boundaries and distinctions

`$(<file)` is appropriate when the interpreter contract is Bash. Use a portable alternative when the script must run under POSIX `sh` implementations.
