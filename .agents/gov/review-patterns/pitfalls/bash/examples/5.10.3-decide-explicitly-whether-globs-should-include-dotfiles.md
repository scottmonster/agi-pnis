# Decide explicitly whether globs should include dotfiles

## 1. Catalog record

- **Catalog identifier:** 5.10.3
- **Impact:** medium
- **Consensus:** high
- **Definition:** Ordinary `*` does not match leading-dot names. Use `dotglob` or another deliberate technique when hidden entries must be included.

## 2. Example

### 2.1 Scenario

A backup task must copy an application directory, including hidden configuration such as `.settings`.

### 2.2 Preferred form

```bash
source_dir=${1:?provide a source directory}
backup_dir=${2:?provide a backup directory}

mkdir -p -- "$backup_dir"
cp -a -- "$source_dir"/. "$backup_dir"/
```

### 2.3 Hazardous form

```bash
source_dir=${1:?provide a source directory}
backup_dir=${2:?provide a backup directory}

mkdir -p -- "$backup_dir"
cp -a -- "$source_dir"/* "$backup_dir"/
```

### 2.4 Why this difference matters

The hazardous `*` omits names beginning with a dot, so a backup can appear successful while silently excluding configuration and other hidden files.

## 3. Boundaries and distinctions

Excluding dotfiles is often correct for a deliberately visible-only operation. Choose that behavior explicitly rather than relying on the default glob rule.
