# Avoid exact-byte tests for outputs whose representation is not contractual

## 1. Catalog record

- **Catalog identifier:** 13.14.1
- **Impact:** low
- **Consensus:** high
- **Definition:** Compare decoded meaning or promised properties instead of exact serialized bytes when the encoding API does not promise canonical output.

## 2. Example

### 2.1 Scenario

A cache persists a value with `encoding/gob`, whose output bytes are an implementation detail rather than its public contract.

### 2.2 Preferred form

```go
package example

import (
	"bytes"
	"encoding/gob"
	"testing"
)

type record struct{ Name string }

func TestGobRoundTrip(t *testing.T) {
	var buf bytes.Buffer
	want := record{Name: "ada"}
	if err := gob.NewEncoder(&buf).Encode(want); err != nil { t.Fatal(err) }
	var got record
	if err := gob.NewDecoder(&buf).Decode(&got); err != nil { t.Fatal(err) }
	if got != want { t.Fatalf("got %#v, want %#v", got, want) }
}
```

### 2.3 Hazardous form

```go
package example

import (
	"bytes"
	"encoding/gob"
	"testing"
)

type record struct{ Name string }

func TestGobBytes(t *testing.T) {
	var buf bytes.Buffer
	if err := gob.NewEncoder(&buf).Encode(record{Name: "ada"}); err != nil { t.Fatal(err) }
	want := []byte{29, 127, 3, 1, 1, 6, 114, 101, 99, 111, 114, 100}
	if !bytes.Equal(buf.Bytes(), want) { t.Fatalf("gob bytes changed: %x", buf.Bytes()) }
}
```

### 2.4 Why this difference matters

The round-trip test verifies the value the cache needs to preserve. The byte test freezes a representation that the encoding package does not promise to keep stable.

## 3. Boundaries and distinctions

Use exact bytes when a format, protocol, or documented canonical encoder makes byte identity part of the contract.
