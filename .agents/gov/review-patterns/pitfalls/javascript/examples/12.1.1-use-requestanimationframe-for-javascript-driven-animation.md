# Use requestAnimationFrame for JavaScript-driven animation

## 1. Catalog record

- **Catalog identifier:** 12.1.1
- **Impact:** medium
- **Consensus:** high
- **Definition:** Use requestAnimationFrame rather than fixed timer loops for JavaScript-driven visual animation.

## 2. Example

### 2.1 Scenario

A browser application moves a notification dot across an on-screen progress track.

### 2.2 Preferred form

```javascript
const dot = document.querySelector(".progress-dot");
let position = 0;

function renderFrame() {
  position = (position + 1) % 101;
  dot.style.transform = `translateX(${position}px)`;
  requestAnimationFrame(renderFrame);
}

requestAnimationFrame(renderFrame);
```

### 2.3 Hazardous form

```javascript
const dot = document.querySelector(".progress-dot");
let position = 0;

setInterval(() => {
  position = (position + 1) % 101;
  dot.style.transform = `translateX(${position}px)`;
}, 16);
```

### 2.4 Why this difference matters

`requestAnimationFrame()` lets the browser coordinate visual updates with repaint scheduling, while a fixed timer can run at poorly aligned times and continue attempting work when rendering is not useful.

## 3. Boundaries and distinctions

Use timers for work that is not visual animation, such as a delayed retry. An animation loop still needs explicit cancellation when the associated UI is removed.
