# Do not compare calculated floating-point values with naive exact equality

## 1. Catalog record

- **Catalog identifier:** 4.1.5
- **Impact:** medium
- **Consensus:** high
- **Definition:** When calculations can introduce rounding error, compare using a tolerance appropriate to the magnitude and domain rather than assuming exact decimal arithmetic.

## 2. Example

### 2.1 Scenario

A checkout calculation verifies that three decimal prices add up to an expected total.

### 2.2 Preferred form

```javascript
function approximatelyEqual(left, right, tolerance = Number.EPSILON * 10) {
  return Math.abs(left - right) <= tolerance;
}

const total = 0.1 + 0.2;
console.log(approximatelyEqual(total, 0.3));
```

### 2.3 Hazardous form

```javascript
const total = 0.1 + 0.2;

console.log(total === 0.3);
```

### 2.4 Why this difference matters

Binary floating-point cannot represent many decimal fractions exactly, so an exact comparison can reject a mathematically equivalent result.

## 3. Boundaries and distinctions

The tolerance must suit the value magnitude and domain. For money, integer minor units or a decimal representation is often a better model than an arbitrary floating-point tolerance.
