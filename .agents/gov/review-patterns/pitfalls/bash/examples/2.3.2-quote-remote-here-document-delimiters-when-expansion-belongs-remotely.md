# Quote remote here-document delimiters when expansion belongs remotely

## 1. Catalog record

- **Catalog identifier:** 2.3.2
- **Impact:** high
- **Consensus:** high
- **Definition:** When feeding a script to `ssh` with a here-document, quote the local delimiter if variables and command substitutions should remain intact until the remote shell receives them.

## 2. Example

### 2.1 Scenario

A deployment script sends a remote shell program that should write the remote machine's hostname to a file.

### 2.2 Preferred form

```bash
#!/usr/bin/env bash
set -euo pipefail

remote_host='app.example.test'
ssh -- "$remote_host" 'bash -s' <<'REMOTE_SCRIPT'
printf '%s\n' "$HOSTNAME" > /var/tmp/host-status
REMOTE_SCRIPT
```

### 2.3 Hazardous form

```bash
#!/usr/bin/env bash
set -euo pipefail

remote_host='app.example.test'
ssh -- "$remote_host" 'bash -s' <<REMOTE_SCRIPT
printf '%s\n' "$HOSTNAME" > /var/tmp/host-status
REMOTE_SCRIPT
```

### 2.4 Why this difference matters

The unquoted delimiter makes the local shell expand `$HOSTNAME` before transmitting the body. The remote program then receives the local hostname rather than evaluating its own value.

## 3. Boundaries and distinctions

Leave the delimiter unquoted only when local interpolation into the transmitted body is intentional and every interpolated value is controlled for the remote context.
