# Treat `noclobber` as a guardrail, not a complete write strategy

## 1. Catalog record

- **Catalog identifier:** 10.4.1
- **Impact:** medium
- **Consensus:** medium
- **Definition:** `set -C` prevents ordinary `>` redirection from replacing an existing regular file, but it can be overridden and is not a transactional or atomic-write strategy.

## 2. Example

### 2.1 Scenario

A report generator must avoid publishing a partially written report after a failed generation.

### 2.2 Preferred form

```bash
destination='report.txt'
temporary=$(mktemp "${destination}.tmp.XXXXXX") || exit 1
trap 'rm -f -- "$temporary"' EXIT

printf 'report contents\n' >"$temporary" || exit 1
mv -- "$temporary" "$destination"
trap - EXIT
```

### 2.3 Hazardous form

```bash
set -C
destination='report.txt'

printf 'report contents\n' >"$destination"
```

### 2.4 Why this difference matters

`noclobber` may catch an accidental ordinary overwrite, but it does not provide a complete publication protocol or protect against all data-integrity failures.

## 3. Boundaries and distinctions

Atomic replacement and no-overwrite behavior are separate policies. Choose the required collision and durability guarantees for the destination filesystem.
