# Unnecessary `else`

## 1. Catalog record

- **Catalog identifier:** 5.12
- **Evidence:** e
- **Definition:** Adds indentation after a branch that already returns, throws, or breaks.

## 2. Scenario

### 2.1 Context

A request handler returns an error for an invalid token, then places its normal path inside `else`.

### 2.2 Safer approach

Use the early return and keep the normal path at the outer indentation level.

### 2.3 Failure mode

Nest another `else` after each guard even though the guard already exits the function.

### 2.4 Why this difference matters

Avoidable indentation makes the main path harder to scan and compounds nesting over time.

## 3. Boundaries and distinctions

An `else` is useful when both branches remain part of one decision. It is unnecessary after control has already left the function or loop.
