# State-machine violation

## 1. Catalog record

- **Catalog identifier:** 6.25
- **Evidence:** se
- **Definition:** Allows impossible transitions or bypasses required lifecycle stages.

## 2. Scenario

### 2.1 Context

An invoice may be paid only after it has been issued.

### 2.2 Safer approach

The agent checks the current invoice state and permits the documented transition from `issued` to `paid`.

### 2.3 Failure mode

It accepts a `pay` action for an invoice still in `draft` state.

### 2.4 Why this difference matters

Downstream accounting and notification logic encounter records that skipped required lifecycle steps.

## 3. Boundaries and distinctions

This applies where lifecycle states and legal transitions exist; it is not a reason to invent a state framework for a simple stateless action.
