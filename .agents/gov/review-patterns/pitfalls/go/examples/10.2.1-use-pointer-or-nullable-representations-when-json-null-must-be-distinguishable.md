# Use pointer or nullable representations when JSON null must be distinguishable

## 1. Catalog record

- **Catalog identifier:** 10.2.1
- **Impact:** medium
- **Consensus:** high
- **Definition:** Do not decode into an ordinary scalar when `null`, missing, and the scalar zero value have different meanings.

## 2. Example

### 2.1 Scenario

An account update accepts an optional quota. A zero quota means disable access, while JSON `null` means clear the custom quota.

### 2.2 Preferred form

```go
package example

type Update struct {
	Quota *int `json:"quota"`
}

func quotaMeaning(update Update) string {
	if update.Quota == nil {
		return "clear custom quota"
	}
	if *update.Quota == 0 {
		return "disable access"
	}
	return "set quota"
}
```

### 2.3 Hazardous form

```go
package example

import "encoding/json"

type Update struct {
	Quota int `json:"quota"`
}

func decodeClear() (Update, error) {
	var update Update
	err := json.Unmarshal([]byte(`{"quota":null}`), &update)
	return update, err // Quota is 0, indistinguishable from {"quota":0} or {}
}
```

### 2.4 Why this difference matters

An ordinary numeric field receives its zero value for both absent and null JSON. The handler can no longer decide whether the client cleared, omitted, or explicitly set the quota to zero.

## 3. Boundaries and distinctions

A scalar is simpler and correct when null, missing, and zero deliberately share one meaning. Use a custom nullable type when a pointer does not express all required states.
