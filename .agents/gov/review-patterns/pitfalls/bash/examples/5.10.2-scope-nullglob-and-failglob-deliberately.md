# Scope `nullglob` and `failglob` deliberately

## 1. Catalog record

- **Catalog identifier:** 5.10.2
- **Impact:** medium
- **Consensus:** high
- **Definition:** `nullglob` removes unmatched patterns, while `failglob` turns them into an expansion error. Enable such options only where their behavior is intended, often in a subshell or tightly scoped section.

## 2. Example

### 2.1 Scenario

A script wants an optional pass over report files while preserving the caller's default glob behavior for later commands.

### 2.2 Preferred form

```bash
report_dir=${1:?provide a report directory}

(
  shopt -s nullglob
  reports=("$report_dir"/*.report)
  for report in "${reports[@]}"; do
    printf 'archiving %s\n' "$report"
  done
)

printf 'report scan completed\n'
```

### 2.3 Hazardous form

```bash
report_dir=${1:?provide a report directory}

shopt -s nullglob
for report in "$report_dir"/*.report; do
  printf 'archiving %s\n' "$report"
done

printf 'report scan completed\n'
```

### 2.4 Why this difference matters

The hazardous form changes shell-wide option state. Code executed later in the same shell can silently receive zero words for an unmatched glob, even if it expected the default literal pattern.

## 3. Boundaries and distinctions

Global option changes are acceptable when they are an intentional script-wide policy and are documented. Otherwise use a subshell, a function with restoration, or a narrow section.
