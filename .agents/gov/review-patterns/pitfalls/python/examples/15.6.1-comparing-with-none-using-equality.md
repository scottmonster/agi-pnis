# Comparing with `None` using equality

## 1. Catalog record

- **Catalog identifier:** 15.6.1
- **Impact:** low
- **Consensus:** high
- **Definition:** Prefer `x is None` and `x is not None` rather than equality comparisons.

## 2. Example

### 2.1 Scenario

An API uses `None` to mean that a caller did not supply an optional timeout.

### 2.2 Preferred form

```python
def timeout_or_default(timeout: object) -> int:
    if timeout is None:
        return 30
    return int(timeout)
```

### 2.3 Hazardous form

```python
class PretendsToBeNone:
    def __eq__(self, other: object) -> bool:
        return other is None


def timeout_or_default(timeout: object) -> int:
    if timeout == None:
        return 30
    return int(timeout)
```

### 2.4 Why this difference matters

Equality can invoke user-defined comparison behavior. Identity states precisely that the singleton sentinel `None` was supplied.

## 3. Boundaries and distinctions

Use equality for value comparisons between ordinary values. Identity checks are appropriate for singleton sentinels such as `None`, `NotImplemented`, and a deliberately created sentinel object.
