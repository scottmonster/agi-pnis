# Distinguish live and static DOM collections

## 1. Catalog record

- **Catalog identifier:** 11.1.2
- **Impact:** medium
- **Consensus:** high
- **Definition:** Account for whether a DOM collection changes as the DOM is mutated.

## 2. Example

### 2.1 Scenario

A task board marks every pending row as processed. Changing a row's class mutates the same DOM state used to select the rows.

### 2.2 Preferred form

```javascript
const pendingRows = document.querySelectorAll(".task--pending");

for (const row of pendingRows) {
  row.classList.remove("task--pending");
  row.classList.add("task--processed");
}
```

### 2.3 Hazardous form

```javascript
const pendingRows = document.getElementsByClassName("task--pending");

for (let index = 0; index < pendingRows.length; index += 1) {
  const row = pendingRows[index];
  row.classList.remove("task--pending");
  row.classList.add("task--processed");
}
```

### 2.4 Why this difference matters

`querySelectorAll()` returns a static `NodeList`, so its membership stays stable for the loop. `getElementsByClassName()` returns a live collection that shrinks after each class removal, so incrementing the index can skip rows.

## 3. Boundaries and distinctions

Live collections are useful when code deliberately needs a current view of the document. When mutating nodes selected by a live collection, iterate safely, such as by repeatedly handling its first item or by first copying it to an array.
