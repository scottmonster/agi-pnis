# Avoid exporting a callable named then from dynamically imported modules

## 1. Catalog record

- **Catalog identifier:** 8.1.8
- **Impact:** low
- **Consensus:** high
- **Definition:** Do not export a callable named then from a module intended for dynamic import.

## 2. Example

### 2.1 Scenario

A plug-in loader dynamically imports a module and calls its initialization export.

### 2.2 Preferred form

```javascript
// plugin.js
export function initialize() {
  return "plug-in ready";
}

// loader.js
const plugin = await import("./plugin.js");
console.log(plugin.initialize());
```

### 2.3 Hazardous form

```javascript
// plugin.js
export function initialize() {
  return "plug-in ready";
}

export function then(resolve) {
  resolve("not a module namespace");
}

// loader.js
const plugin = await import("./plugin.js");
console.log(plugin.initialize());
```

### 2.4 Why this difference matters

Dynamic import resolves through promise machinery. A callable `then` export makes the module namespace thenable, so the loader can receive the value supplied to `resolve` instead of the namespace object.

## 3. Boundaries and distinctions

The restriction matters for modules consumed with `import()`. A non-callable export named `then` does not trigger thenable assimilation, but a different name is clearer.
