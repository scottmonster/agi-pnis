# Give CJS and ESM entrypoints separate declarations

## 1. Catalog record

- **Catalog identifier:** 3.4.1
- **Impact:** high
- **Consensus:** high
- **Definition:** A package exposing both CommonJS and ESM entrypoints should provide declaration files whose detected module formats correspond to each JavaScript entrypoint.

## 2. Example

### 2.1 Scenario

A package offers separate import and require entrypoints.

### 2.2 Preferred form

```typescript
// package.json
// { "exports": { ".": {
//   "import": { "types": "./dist/index.d.mts", "default": "./dist/index.mjs" },
//   "require": { "types": "./dist/index.d.cts", "default": "./dist/index.cjs" }
// } } }
```

### 2.3 Hazardous form

```typescript
// package.json
// { "exports": { ".": {
//   "types": "./dist/index.d.ts",
//   "import": "./dist/index.mjs",
//   "require": "./dist/index.cjs"
// } } }
// One declaration module kind cannot accurately describe both entrypoints.
```

### 2.4 Why this difference matters

A single declaration file cannot correctly represent both module identities and can cause consumers to see missing or incompatible exports.

## 3. Boundaries and distinctions

Apply this guidance in the conditions described by the catalog record. Deliberate exceptions need a documented runtime guarantee, compatible toolchain behavior, or an explicit local unsafe boundary.
