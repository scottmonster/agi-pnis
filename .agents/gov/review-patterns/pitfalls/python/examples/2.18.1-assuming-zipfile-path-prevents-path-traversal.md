# Assuming `zipfile.Path` prevents path traversal

## 1. Catalog record

- **Catalog identifier:** 2.18.1
- **Impact:** high
- **Consensus:** high
- **Definition:** When using `zipfile.Path` on untrusted archives, validate filenames and destination paths yourself.

## 2. Example

### 2.1 Scenario

A tool reads a named member from an archive uploaded by an untrusted user.

### 2.2 Preferred form

```python
from pathlib import PurePosixPath
import zipfile


def read_member(archive_path: str, member_name: str) -> bytes:
    member_path = PurePosixPath(member_name)
    if member_path.is_absolute() or ".." in member_path.parts:
        raise ValueError("unsafe archive member name")
    with zipfile.ZipFile(archive_path) as archive:
        return archive.read(member_name)
```

### 2.3 Hazardous form

```python
import zipfile


def read_member(archive_path: str, member_name: str) -> bytes:
    with zipfile.ZipFile(archive_path) as archive:
        return zipfile.Path(archive, member_name).read_bytes()
```

### 2.4 Why this difference matters

`zipfile.Path` does not sanitize untrusted names for traversal. Validate member names and any destination path before using archive content.

## 3. Boundaries and distinctions

`ZipFile.extract()` and `extractall()` apply some filename sanitization, but untrusted archives still need a threat-model review.
