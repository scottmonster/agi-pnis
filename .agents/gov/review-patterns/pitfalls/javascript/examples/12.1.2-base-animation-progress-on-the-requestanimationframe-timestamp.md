# Base animation progress on the requestAnimationFrame timestamp

## 1. Catalog record

- **Catalog identifier:** 12.1.2
- **Impact:** medium
- **Consensus:** high
- **Definition:** Calculate animation progress from elapsed time or the supplied frame timestamp, not a fixed frame duration.

## 2. Example

### 2.1 Scenario

A browser animation must move an element 300 pixels over one second on displays with different refresh rates.

### 2.2 Preferred form

```javascript
const dot = document.querySelector(".progress-dot");
const durationMs = 1_000;
const distancePx = 300;
let startTime;

function animate(timestamp) {
  startTime ??= timestamp;
  const progress = Math.min((timestamp - startTime) / durationMs, 1);
  dot.style.transform = `translateX(${progress * distancePx}px)`;
  if (progress < 1) requestAnimationFrame(animate);
}

requestAnimationFrame(animate);
```

### 2.3 Hazardous form

```javascript
const dot = document.querySelector(".progress-dot");
const distancePerFrame = 5;
let position = 0;

function animate() {
  position += distancePerFrame;
  dot.style.transform = `translateX(${position}px)`;
  if (position < 300) requestAnimationFrame(animate);
}

requestAnimationFrame(animate);
```

### 2.4 Why this difference matters

The hazardous version travels farther on a high-refresh display and takes longer after dropped frames because it equates frame count with elapsed time.

## 3. Boundaries and distinctions

Frame-based movement can be appropriate for deliberately frame-stepped effects. Time-based progress is needed when the animation duration or physical speed must remain stable across varying frame delivery.
