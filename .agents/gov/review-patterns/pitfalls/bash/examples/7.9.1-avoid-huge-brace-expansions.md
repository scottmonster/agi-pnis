# Avoid huge brace expansions

## 1. Catalog record

- **Catalog identifier:** 7.9.1
- **Impact:** medium
- **Consensus:** high
- **Definition:** Brace expansion creates the expanded words before executing the command. For large numeric ranges, use an arithmetic loop or streaming mechanism instead.

## 2. Example

### 2.1 Scenario

A cleanup report must process a very large sequence of archived batch numbers. Each batch can be handled independently.

### 2.2 Preferred form

```bash
for ((batch = 1; batch <= 10000000; batch++)); do
  printf 'processing batch %d\n' "$batch" > /dev/null
done
```

### 2.3 Hazardous form

```bash
printf 'processing batch %s\n' {1..10000000} > /dev/null
```

### 2.4 Why this difference matters

The hazardous command constructs millions of words before `printf` starts, consuming shell memory and creating a huge argument list. The loop emits and handles one batch at a time.

## 3. Boundaries and distinctions

Brace expansion is reasonable for small, fixed sets where the resulting argument list is comfortably bounded. A loop still runs every iteration, so select a streaming design appropriate to the work being performed.
