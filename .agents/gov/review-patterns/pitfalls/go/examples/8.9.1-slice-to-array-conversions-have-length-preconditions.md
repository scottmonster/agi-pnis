# Slice-to-array conversions have length preconditions

## 1. Catalog record

- **Catalog identifier:** 8.9.1
- **Impact:** medium
- **Consensus:** high
- **Definition:** Check slice length before converting a slice to an array or pointer-to-array type unless sufficient length is already guaranteed.

## 2. Example

### 2.1 Scenario

A binary parser needs the first four bytes of an input buffer as a fixed-size header.

### 2.2 Preferred form

```go
package parser

import "fmt"

func header(input []byte) ([4]byte, error) {
	if len(input) < 4 {
		return [4]byte{}, fmt.Errorf("header needs 4 bytes, got %d", len(input))
	}
	return [4]byte(input[:4]), nil
}
```

### 2.3 Hazardous form

```go
package parser

func header(input []byte) [4]byte {
	return [4]byte(input)
}
```

### 2.4 Why this difference matters

Converting a shorter slice to an array panics at runtime. Checking the length at the parser boundary gives malformed input an ordinary error path instead.

## 3. Boundaries and distinctions

The check is unnecessary only when an immediately preceding operation already guarantees the required length, such as a successful fixed-size read. A pointer-to-array conversion has the same length requirement.
