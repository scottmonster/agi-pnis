# Hallucinated package/dependency

## 1. Catalog record

- **Catalog identifier:** 8.1
- **Evidence:** e
- **Definition:** Recommends or imports a package that does not exist.

## 2. Scenario

### 2.1 Context

An agent is adding request retries to a Node service and needs a library that fits the repository's supported package manager and runtime.

### 2.2 Safer approach

It inspects the existing manifest and lockfile, searches the configured registry for the proposed package, and confirms its documented import path before adding it. If the package is unavailable, it uses an existing dependency or proposes a verified alternative.

### 2.3 Failure mode

It adds `import { retry } from "fetch-retry-plus"` and updates the implementation without checking whether that package exists in the configured registry. The install step then fails because the named package is fabricated.

### 2.4 Why this difference matters

The failed recommendation blocks builds and sends reviewers toward debugging an implementation that can never be installed.

## 3. Boundaries and distinctions

This concerns a nonexistent recommendation or import. A real package that is missing from project metadata is an undeclared runtime dependency, while a real but unsuitable package raises compatibility or maintenance concerns instead.
