# Reloading modules after `from ... import ...`

## 1. Catalog record

- **Catalog identifier:** 9.2.1
- **Impact:** medium
- **Consensus:** high
- **Definition:** Do not expect `importlib.reload(module)` to update names previously copied into another namespace with `from module import name`. Use module-qualified references or re-execute the import.

## 2. Example

### 2.1 Scenario

A development tool reloads a configuration module after its source file changes.

### 2.2 Preferred form

```python
import importlib
import settings

importlib.reload(settings)
print(settings.TIMEOUT_SECONDS)
```

### 2.3 Hazardous form

```python
import importlib
import settings
from settings import TIMEOUT_SECONDS

importlib.reload(settings)
print(TIMEOUT_SECONDS)
```

### 2.4 Why this difference matters

Reloading updates attributes on `settings`, but the imported `TIMEOUT_SECONDS` binding still points to the value copied before the reload.

## 3. Boundaries and distinctions

Reloading is itself difficult to make reliable when modules keep state or instances. Restarting the process is often preferable outside tightly controlled development tooling.
