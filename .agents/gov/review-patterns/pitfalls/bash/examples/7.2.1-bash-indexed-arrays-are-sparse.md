# Bash indexed arrays are sparse

## 1. Catalog record

- **Catalog identifier:** 7.2.1
- **Impact:** medium
- **Consensus:** high
- **Definition:** `${#array[@]}` is the number of assigned elements, not necessarily one more than the largest index. Iterate `"${!array[@]}"` when actual indices matter.

## 2. Example

### 2.1 Scenario

A job keeps retry settings at selected priority levels. Some levels are intentionally absent.

### 2.2 Preferred form

```bash
declare -a retries
retries[0]=1
retries[3]=5

for priority in "${!retries[@]}"; do
  printf 'priority %s retries %s\n' "$priority" "${retries[$priority]}"
done
```

### 2.3 Hazardous form

```bash
declare -a retries
retries[0]=1
retries[3]=5

for ((priority = 0; priority < ${#retries[@]}; priority++)); do
  printf 'priority %s retries %s\n' "$priority" "${retries[$priority]}"
done
```

### 2.4 Why this difference matters

There are two assigned elements, but the hazardous loop visits indices zero and one, missing the value at index three. Iterating assigned indices preserves the array's actual shape.

## 3. Boundaries and distinctions

A counter loop is appropriate when the script itself maintains a dense array with consecutive indexes. Do not infer density from the element count after deletions or explicit high indexes.
