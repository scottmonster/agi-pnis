# Platform-specific build/shell assumption presented as portable

## 1. Catalog record

- **Catalog identifier:** 8.16
- **Evidence:** se
- **Definition:** Relies on an OS, shell, filesystem, or tool behavior that other supported environments do not share.

## 2. Scenario

### 2.1 Context

An agent adds a `prepare-assets` script to a Node project that must run in Linux CI and on developers' macOS and Windows workstations.

### 2.2 Safer approach

It checks the supported platforms and existing scripts, then uses a cross-platform Node script with path utilities. It runs the command in the project’s supported CI environment and on the affected local platforms when available.

### 2.3 Failure mode

It adds `rm -rf dist && cp -R assets dist/assets` to `package.json` and describes the command as portable, even though Windows developers use a shell that does not provide those commands or their semantics.

### 2.4 Why this difference matters

The feature can pass Linux CI while blocking supported contributors or producing different output on another platform, making the build unreliable outside the author’s setup.

## 3. Boundaries and distinctions

Platform-specific commands are appropriate when the project explicitly supports only that platform or when guarded behind a platform-specific target. This failure concerns presenting an unsupported assumption as portable, not deliberately scoped platform integration.
