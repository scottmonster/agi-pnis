# Reset or localize `OPTIND` before reparsing options

## 1. Catalog record

- **Catalog identifier:** 8.1.1
- **Impact:** medium
- **Consensus:** high
- **Definition:** `getopts` uses `OPTIND` to track parser position, so functions or repeated parsing passes should initialize or localize it deliberately.

## 2. Example

### 2.1 Scenario

A helper parses its own options after the main script has already called `getopts`.

### 2.2 Preferred form

```bash
parse_flags() {
  local OPTIND=1 option
  while getopts ':v' option; do
    [[ $option == v ]] && printf 'verbose\n'
  done
}

parse_flags -v
parse_flags -v
```

### 2.3 Hazardous form

```bash
parse_flags() {
  local option
  while getopts ':v' option; do
    [[ $option == v ]] && printf 'verbose\n'
  done
}

parse_flags -v
parse_flags -v
```

### 2.4 Why this difference matters

The second hazardous call can begin at the parser position left by the first call and skip its option. A local reset makes each invocation independent.

## 3. Boundaries and distinctions

Use a deliberate shared `OPTIND` only when parsing one argument list across coordinated code. Resetting it is needed before a new parsing pass.
