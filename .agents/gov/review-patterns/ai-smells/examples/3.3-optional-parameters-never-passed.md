# Optional parameters never passed

## 1. Catalog record

- **Catalog identifier:** 3.3
- **Evidence:** se
- **Definition:** Function signatures advertise retries, modes, loggers, strategies, or toggles that all callers leave at defaults.

## 2. Scenario

### 2.1 Context

All callers invoke `sendReceipt(order)` with the same delivery behavior.

### 2.2 Safer approach

Use the small required signature and add a parameter only when a caller has a supported different need.

### 2.3 Failure mode

Change it to `sendReceipt(order, retries = 3, logger = null, mode = "standard")` although no caller supplies those values.

### 2.4 Why this difference matters

Unused parameters obscure the real contract and invite untested combinations.

## 3. Boundaries and distinctions

An optional parameter is justified by current variation at a call site; it is not justified solely by imagined flexibility.
