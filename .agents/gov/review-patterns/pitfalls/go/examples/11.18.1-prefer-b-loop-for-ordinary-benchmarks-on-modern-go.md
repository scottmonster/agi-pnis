# Prefer `B.Loop` for ordinary benchmarks on modern Go

## 1. Catalog record

- **Catalog identifier:** 11.18.1
- **Impact:** medium
- **Consensus:** high
- **Definition:** For new benchmarks, use `for b.Loop() { ... }` unless lower-level benchmark control is required.

## 2. Example

### 2.1 Scenario

A benchmark measures the cost of serializing a fixed request payload.

### 2.2 Preferred form

```go
package example

import "testing"

func serialize(input string) []byte { return []byte(input) }

func BenchmarkSerialize(b *testing.B) {
	input := "request"
	for b.Loop() {
		_ = serialize(input)
	}
}
```

### 2.3 Hazardous form

```go
package example

import "testing"

func serialize(input string) []byte { return []byte(input) }

func BenchmarkSerialize(b *testing.B) {
	input := "request"
	for range b.N {
		_ = serialize(input)
	}
}
```

### 2.4 Why this difference matters

`B.Loop` manages setup timing and compiler-optimization concerns more robustly for ordinary new benchmarks than manually arranging a `b.N` loop.

## 3. Boundaries and distinctions

Use lower-level benchmark controls when a benchmark truly needs them, such as custom timer boundaries. `B.Loop` is the default for new ordinary benchmarks on Go versions that support it.
