# Prefer `WalkDir` over `Walk` when file metadata is unnecessary

## 1. Catalog record

- **Catalog identifier:** 13.19.1
- **Impact:** low
- **Consensus:** high
- **Definition:** For new recursive filesystem traversal, use `filepath.WalkDir` when its `DirEntry` API provides everything needed.

## 2. Example

### 2.1 Scenario

A cleanup tool recursively prints ordinary file paths and does not inspect file metadata.

### 2.2 Preferred form

```go
package example

import (
	"io/fs"
	"path/filepath"
)

func list(root string) error {
	return filepath.WalkDir(root, func(path string, entry fs.DirEntry, err error) error {
		if err != nil { return err }
		if !entry.IsDir() { println(path) }
		return nil
	})
}
```

### 2.3 Hazardous form

```go
package example

import (
	"os"
	"path/filepath"
)

func list(root string) error {
	return filepath.Walk(root, func(path string, info os.FileInfo, err error) error {
		if err != nil { return err }
		if !info.IsDir() { println(path) }
		return nil
	})
}
```

### 2.4 Why this difference matters

`WalkDir` supplies lightweight directory entries and can avoid retrieving full file metadata. `Walk` obtains `FileInfo` for every path even though this traversal only needs to distinguish directories.

## 3. Boundaries and distinctions

Use `Walk` or call `DirEntry.Info` when metadata such as file mode, size, or modification time is actually required.
