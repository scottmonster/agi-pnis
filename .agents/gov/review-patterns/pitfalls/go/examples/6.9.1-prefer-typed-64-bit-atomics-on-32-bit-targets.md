# Prefer typed 64-bit atomics on 32-bit targets

## 1. Catalog record

- **Catalog identifier:** 6.9.1
- **Impact:** medium
- **Consensus:** high
- **Definition:** Prefer `atomic.Int64` and `atomic.Uint64` over primitive 64-bit atomic functions when portability to 32-bit platforms matters.

## 2. Example

### 2.1 Scenario

A portable metrics type counts requests.

### 2.2 Preferred form

```go
package main

import "sync/atomic"

type metrics struct { requests atomic.Uint64 }
func (m *metrics) record() { m.requests.Add(1) }
func (m *metrics) total() uint64 { return m.requests.Load() }
```

### 2.3 Hazardous form

```go
package main

import "sync/atomic"

type metrics struct { name byte; requests uint64 }
func (m *metrics) record() { atomic.AddUint64(&m.requests, 1) }
```

### 2.4 Why this difference matters

On 32-bit systems, the manual `uint64` might not be aligned for primitive atomic operations. Typed atomics arrange their own alignment.

## 3. Boundaries and distinctions

Primitive atomics work when alignment is guaranteed and an address is required. Do not copy atomic values after first use.
