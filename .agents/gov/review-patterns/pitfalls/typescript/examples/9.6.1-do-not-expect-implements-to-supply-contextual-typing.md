# Do not expect `implements` to supply contextual typing

## 1. Catalog record

- **Catalog identifier:** 9.6.1
- **Impact:** medium
- **Consensus:** high
- **Definition:** Explicitly type class members as needed even when the class has an `implements Interface` clause.

## 2. Example

### 2.1 Scenario

A class implements a handler contract, but its method still needs its own parameter annotation.

### 2.2 Preferred form

```typescript
interface Handler {
  handle(message: string): void;
}

class ConsoleHandler implements Handler {
  handle(message: string): void {
    console.log(message.toUpperCase());
  }
}

new ConsoleHandler().handle('connected');
```

### 2.3 Hazardous form

```typescript
interface Handler {
  handle(message: string): void;
}

class ConsoleHandler implements Handler {
  handle(message) {
    console.log(message.toUpperCase());
  }
}

// Error with noImplicitAny: parameter 'message' is implicitly any.
```

### 2.4 Why this difference matters

`implements` checks compatibility after the member's own type has been determined; it does not automatically infer or rewrite that member's parameter types.

## 3. Boundaries and distinctions

Apply this guidance in the conditions described by the catalog record. Deliberate exceptions need a documented runtime guarantee, compatible toolchain behavior, or an explicit local unsafe boundary.
