# Installing project dependencies into the system Python

## 1. Catalog record

- **Catalog identifier:** 4.3.1
- **Impact:** high
- **Consensus:** high
- **Definition:** Use virtual environments for project-specific third-party dependencies and respect externally managed Python installations rather than routinely forcing pip modifications into the system interpreter.

## 2. Example

### 2.1 Scenario

A developer needs an application dependency without changing packages owned by the operating system.

### 2.2 Preferred form

```python
import venv


venv.EnvBuilder(with_pip=True).create(".venv")
```

### 2.3 Hazardous form

```python
import subprocess
import sys


subprocess.run(
    [sys.executable, "-m", "pip", "install", "httpx"],
    check=True,
)
```

### 2.4 Why this difference matters

Mixing application dependencies into a system interpreter can conflict with OS-managed packages and other projects. An isolated environment has clear dependency ownership.

## 3. Boundaries and distinctions

Container images and deliberately managed application runtimes can install globally within that isolated runtime when it is not an OS-managed interpreter.
