# Prefer the nil slice as the ordinary empty zero value

## 1. Catalog record

- **Catalog identifier:** 13.3.1
- **Impact:** low
- **Consensus:** high
- **Definition:** Prefer `var s []T` over `s := []T{}` when there is no semantic need for a non-nil empty slice. Preserve the distinction only where protocols such as JSON require it.

## 2. Example

### 2.1 Scenario

A collector starts empty and only grows if a scan finds matching files.

### 2.2 Preferred form

```go
package example

func matches(names []string) []string {
	var found []string
	for _, name := range names {
		if name == "config.yaml" {
			found = append(found, name)
		}
	}
	return found
}
```

### 2.3 Hazardous form

```go
package example

func matches(names []string) []string {
	found := []string{}
	for _, name := range names {
		if name == "config.yaml" {
			found = append(found, name)
		}
	}
	return found
}
```

### 2.4 Why this difference matters

Both forms support `len`, `range`, and `append`, but the nil slice is the useful zero value and avoids an unnecessary allocation or initialization convention.

## 3. Boundaries and distinctions

Keep a non-nil empty slice when an external contract distinguishes it, for example when JSON must encode `[]` instead of `null`.
