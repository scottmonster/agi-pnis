# Use Map.has when undefined is a valid Map value

## 1. Catalog record

- **Catalog identifier:** 2.16.1
- **Impact:** medium
- **Consensus:** high
- **Definition:** Use `Map.has()` rather than a retrieved value to distinguish absence from an undefined value.

## 2. Example

### 2.1 Scenario

A feature map uses `undefined` to record an explicitly unset feature.

### 2.2 Preferred form

```javascript
const features = new Map([["beta", undefined]]);

if (features.has("beta")) {
  console.log("beta was configured");
}
```

### 2.3 Hazardous form

```javascript
const features = new Map([["beta", undefined]]);

if (features.get("beta") !== undefined) {
  console.log("beta was configured");
}
```

### 2.4 Why this difference matters

`Map.get()` returns `undefined` for both a missing entry and an entry whose stored value is `undefined`.

## 3. Boundaries and distinctions

Testing `get()` is fine only when `undefined` is impossible as a stored value or is deliberately treated as absence.
