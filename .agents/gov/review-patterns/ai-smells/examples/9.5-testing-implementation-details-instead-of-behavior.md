# Testing implementation details instead of behavior

## 1. Catalog record

- **Catalog identifier:** 9.5
- **Evidence:** se
- **Definition:** Asserts private calls, structure, or incidental sequencing rather than the result a consumer can observe.

## 2. Scenario

### 2.1 Context

A notification service sends a receipt after an order is placed.

### 2.2 Safer approach

Use the public order flow and assert that the recipient receives a receipt with the required order details.

### 2.3 Failure mode

Spy on a private formatter and require it to be called before an internal queue helper.

### 2.4 Why this difference matters

A harmless refactor breaks the test, while an incorrect receipt can still satisfy the private-call assertions.

## 3. Boundaries and distinctions

Interactions at a real public boundary can be appropriate to test when that interaction is itself the contract.
