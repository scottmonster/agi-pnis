# Stop repeating pre-Go-1.23 timer GC advice unconditionally

## 1. Catalog record

- **Catalog identifier:** 6.17.1
- **Impact:** medium
- **Consensus:** high
- **Definition:** For Go 1.23+ semantics, unreachable timers and tickers can be garbage collected even when unstopped. Stop them when you need to prevent future events, not merely because old advice said GC requires it.

## 2. Example

### 2.1 Scenario

A request races successful completion against a timeout.

### 2.2 Preferred form

```go
package main

import "time"

func wait(done <-chan struct{}) bool {
	timer := time.NewTimer(time.Second); defer timer.Stop()
	select { case <-done: return true; case <-timer.C: return false }
}
```

### 2.3 Hazardous form

```go
package main

import "time"

func armTimeout() <-chan time.Time { return time.After(time.Hour) }
```

### 2.4 Why this difference matters

For Go 1.23 and later, discarding `time.After` does not require stopping solely for garbage collection. Stop a timer when early completion must prevent its future event.

## 3. Boundaries and distinctions

Older Go versions differ, so module and runtime versions matter. Stop timers to control lifecycle, not as a ritual.
