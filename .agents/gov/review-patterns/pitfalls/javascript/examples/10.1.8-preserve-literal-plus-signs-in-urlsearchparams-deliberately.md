# Preserve literal plus signs in URLSearchParams deliberately

## 1. Catalog record

- **Catalog identifier:** 10.1.8
- **Impact:** medium
- **Consensus:** high
- **Definition:** Do not interpolate raw plus-containing values into URLSearchParams string input when plus must remain literal.

## 2. Example

### 2.1 Scenario

An application puts an opaque access token containing a plus sign into a query parameter.

### 2.2 Preferred form

```javascript
function tokenQuery(token) {
  const parameters = new URLSearchParams();
  parameters.set("token", token);
  return parameters.toString();
}

console.log(tokenQuery("a+b")); // token=a%2Bb
```

### 2.3 Hazardous form

```javascript
function tokenQuery(token) {
  const parameters = new URLSearchParams(`token=${token}`);
  return parameters.get("token");
}

console.log(tokenQuery("a+b")); // a b
```

### 2.4 Why this difference matters

The string constructor parses form-style input, where an unescaped plus sign represents a space, corrupting opaque token data.

## 3. Boundaries and distinctions

Passing a complete, correctly percent-encoded query string to `URLSearchParams` is valid. Use `set()` or an object initializer for raw application values.
