# Hardcoded build paths/URLs

## 1. Catalog record

- **Catalog identifier:** 8.13
- **Evidence:** e
- **Definition:** Embeds machine-, network-, or environment-specific locations that fail outside the author’s setup.

## 2. Scenario

### 2.1 Context

An agent configures a release build to fetch a generated API specification used during packaging.

### 2.2 Safer approach

It reads the repository's environment configuration, accepts the endpoint through the established build setting, and supplies a documented development default where appropriate.

### 2.3 Failure mode

It writes `https://staging.internal.example/api/openapi.json` directly into the build script because that URL works on its current network.

### 2.4 Why this difference matters

Developers, CI runners, and production builds can lack access to that host or require another endpoint, so the build becomes tied to one environment.

## 3. Boundaries and distinctions

A stable public endpoint can be intentionally fixed when the supported contract requires it. This failure concerns locations that encode one machine, network, or environment while being treated as generally usable.
