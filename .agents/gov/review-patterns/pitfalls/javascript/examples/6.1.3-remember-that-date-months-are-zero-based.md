# Remember that Date months are zero-based

## 1. Catalog record

- **Catalog identifier:** 6.1.3
- **Impact:** medium
- **Consensus:** high
- **Definition:** Numeric month values in legacy `Date` constructors and methods such as `getMonth()` are zero-based.

## 2. Example

### 2.1 Scenario

A reporting job creates a UTC date for January 15, 2026 from numeric components.

### 2.2 Preferred form

```javascript
const january = 0;
const reportDate = new Date(Date.UTC(2026, january, 15));

console.log(reportDate.toISOString()); // 2026-01-15T00:00:00.000Z
```

### 2.3 Hazardous form

```javascript
const january = 1;
const reportDate = new Date(Date.UTC(2026, january, 15));

console.log(reportDate.toISOString()); // 2026-02-15T00:00:00.000Z
```

### 2.4 Why this difference matters

Treating January as month 1 creates an off-by-one error that silently moves the result to February.

## 3. Boundaries and distinctions

Only legacy `Date` numeric APIs use zero-based months. ISO date strings and many domain-level month values conventionally use one-based numbering.
