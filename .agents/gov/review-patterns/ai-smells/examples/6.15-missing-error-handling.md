# Missing error handling

## 1. Catalog record

- **Catalog identifier:** 6.15
- **Evidence:** e
- **Definition:** Expected operational failures escape incorrectly.

## 2. Scenario

### 2.1 Context

An API sends a receipt through a mail provider that can reject or time out.

### 2.2 Safer approach

The agent handles the provider's expected failure, records the actionable context, and returns the service's documented response.

### 2.3 Failure mode

It awaits the provider call with no handling, allowing a provider exception to become an unstructured server failure.

### 2.4 Why this difference matters

Users receive an incorrect response and operators lose the intended recovery or diagnosis path.

## 3. Boundaries and distinctions

Handling should match expected operational failures; catching every exception and pretending success is broad exception swallowing.
