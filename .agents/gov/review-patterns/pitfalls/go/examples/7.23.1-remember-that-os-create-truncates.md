# Remember that `os.Create` truncates

## 1. Catalog record

- **Catalog identifier:** 7.23.1
- **Impact:** medium
- **Consensus:** high
- **Definition:** Do not use `os.Create` when existing contents must be preserved. Select `os.OpenFile` flags that express the desired append, create, exclusive, or truncate behavior.

## 2. Example

### 2.1 Scenario

A service appends audit events to a log file without losing existing events.

### 2.2 Preferred form

```go
package audit

import "os"

func openLog(path string) (*os.File, error) {
	return os.OpenFile(path, os.O_WRONLY|os.O_CREATE|os.O_APPEND, 0o600)
}
```

### 2.3 Hazardous form

```go
package audit

import "os"

func openLog(path string) (*os.File, error) {
	return os.Create(path) // Truncates an existing log.
}
```

### 2.4 Why this difference matters

`os.Create` uses truncate behavior for an existing file, so opening the audit log can erase prior events.

## 3. Boundaries and distinctions

Use `os.Create` when replacement is intentional. Choose `OpenFile` flags explicitly for append-only, exclusive creation, or deliberate truncation semantics.
