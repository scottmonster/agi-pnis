# Regular expressions without raw strings

## 1. Catalog record

- **Catalog identifier:** 8.8.1
- **Impact:** medium
- **Consensus:** high
- **Definition:** Prefer raw string literals such as `r"\d+\."` for regular-expression patterns containing backslashes.

## 2. Example

### 2.1 Scenario

A validator accepts an identifier that starts with one or more digits followed by a period.

### 2.2 Preferred form

```python
import re

pattern = re.compile(r"\d+\.")

assert pattern.fullmatch("12.") is not None
```

### 2.3 Hazardous form

```python
import re

pattern = re.compile("\bitem")

assert pattern.search("item") is None  # "\b" became a backspace character.
```

### 2.4 Why this difference matters

Normal string parsing can consume a backslash before the regular-expression engine sees it, producing a different pattern.

## 3. Boundaries and distinctions

Ordinary string literals are fine for patterns with no backslashes or when the necessary escaping is intentional and clear.
