# Prefer `[[ ... ]]` for Bash-native string tests

## 1. Catalog record

- **Catalog identifier:** 4.7.2
- **Impact:** medium
- **Consensus:** high
- **Definition:** In Bash-specific code, use `[[ ... ]]` to avoid ordinary operand splitting and pathname expansion.

## 2. Example

### 2.1 Scenario

A Bash-only log processor accepts a filename that may contain spaces or glob characters.

### 2.2 Preferred form

```bash
#!/usr/bin/env bash

path=${1:?provide a path}
if [[ -n $path && $path == *.log ]]; then
  printf 'processing %s\n' "$path"
fi
```

### 2.3 Hazardous form

```bash
#!/usr/bin/env bash

path=${1:?provide a path}
if [ -n $path ] && [ $path = *.log ]; then
  printf 'processing %s\n' "$path"
fi
```

### 2.4 Why this difference matters

Within `[[ ... ]]`, ordinary operands are not subject to word splitting or pathname expansion. The traditional test form can be distorted by the supplied path or files in the current directory.

## 3. Boundaries and distinctions

Use `[[ ... ]]` for Bash-specific scripts. Use carefully quoted `[ ... ]` forms when the script must run in a POSIX shell.
