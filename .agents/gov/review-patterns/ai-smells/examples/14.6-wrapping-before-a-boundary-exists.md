# Wrapping before a boundary exists

## 1. Catalog record

- **Catalog identifier:** 14.6
- **Evidence:** a
- **Definition:** Interfaces/adapters are introduced around components with no current substitution, isolation, or ownership requirement.

## 2. Scenario

### 2.1 Context

A command handler uses one local date-formatting helper owned by the same package.

### 2.2 Safer approach

The agent calls the helper directly and keeps it focused, adding a boundary only if substitution, isolation, or separate ownership becomes necessary.

### 2.3 Failure mode

It creates a formatter interface, adapter implementation, dependency-injection registration, and factory even though no alternate formatter or independent boundary exists.

### 2.4 Why this difference matters

The wrapper obscures straightforward behavior and increases indirection without protecting a meaningful seam.

## 3. Boundaries and distinctions

An external system, a separately owned module, or a real test-isolation need can establish a boundary. This is distinct from merely preferring layered code.
