# Waiting on subprocesses with unread pipes

## 1. Catalog record

- **Catalog identifier:** 2.5.1
- **Impact:** high
- **Consensus:** high
- **Definition:** Do not call `Popen.wait()` while a child may fill `stdout=PIPE` or `stderr=PIPE`. Use `communicate()` or otherwise continuously drain the pipes.

## 2. Example

### 2.1 Scenario

A build runner captures a compiler's output before determining its exit status.

### 2.2 Preferred form

```python
import subprocess


def run_build() -> str:
    process = subprocess.Popen(
        ["python", "-c", "print('build output')"],
        stdout=subprocess.PIPE,
        text=True,
    )
    output, _ = process.communicate()
    return output


print(run_build())
```

### 2.3 Hazardous form

```python
import subprocess


def run_build() -> str:
    process = subprocess.Popen(
        ["python", "-c", "print('build output')"],
        stdout=subprocess.PIPE,
        text=True,
    )
    process.wait()
    return process.stdout.read() if process.stdout is not None else ""


print(run_build())
```

### 2.4 Why this difference matters

If the child fills its pipe buffer, it blocks waiting for a reader while the parent blocks in `wait()`, causing a deadlock.

## 3. Boundaries and distinctions

Calling `wait()` is fine when output is not piped or when another mechanism continuously drains every captured pipe.
