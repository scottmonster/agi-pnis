# Distinguish unset from empty in parameter defaults

## 1. Catalog record

- **Catalog identifier:** 5.7.1
- **Impact:** medium
- **Consensus:** high
- **Definition:** `${var:-word}` substitutes `word` when `var` is unset or empty, while `${var-word}` substitutes only when it is unset. The same colon distinction applies to related parameter operators.

## 2. Example

### 2.1 Scenario

A configuration variable may be unset to request a default endpoint, while an explicitly empty value means to disable remote publishing.

### 2.2 Preferred form

```bash
endpoint=${PUBLISH_ENDPOINT-default-publisher}

if [[ -z $endpoint ]]; then
  printf 'remote publishing disabled\n'
else
  printf 'publishing to %s\n' "$endpoint"
fi
```

### 2.3 Hazardous form

```bash
endpoint=${PUBLISH_ENDPOINT:-default-publisher}

if [[ -z $endpoint ]]; then
  printf 'remote publishing disabled\n'
else
  printf 'publishing to %s\n' "$endpoint"
fi
```

### 2.4 Why this difference matters

With the colon form, `PUBLISH_ENDPOINT=''` is replaced by the default endpoint. The caller cannot express the intentional empty setting that disables publishing.

## 3. Boundaries and distinctions

Use the colon form when unset and empty should have identical meaning. The non-colon form matters only when an empty value is distinct from an absent one.
