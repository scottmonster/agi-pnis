# A pointer to a range value is not a pointer to the collection element

## 1. Catalog record

- **Catalog identifier:** 7.12.1
- **Impact:** medium
- **Consensus:** high
- **Definition:** Even with Go 1.22's per-iteration variables, `&v` where `v` is a range value points to that iteration variable, not to `slice[i]`.

## 2. Example

### 2.1 Scenario

An API needs pointers to the actual records held in a slice.

### 2.2 Preferred form

```go
package records

type Record struct{ ID string }

func pointers(items []Record) []*Record {
	result := make([]*Record, 0, len(items))
	for index := range items { result = append(result, &items[index]) }
	return result
}
```

### 2.3 Hazardous form

```go
package records

type Record struct{ ID string }

func pointers(items []Record) []*Record {
	result := make([]*Record, 0, len(items))
	for _, item := range items { result = append(result, &item) }
	return result
}
```

### 2.4 Why this difference matters

Each hazardous pointer refers to a range variable copy, not the corresponding element of `items`.

## 3. Boundaries and distinctions

Go 1.22 gives each iteration its own variable, avoiding one older capture bug, but it does not make the variable an element alias.
