# Do not store Go pointers in `uintptr`

## 1. Catalog record

- **Catalog identifier:** 4.10.1
- **Impact:** high
- **Consensus:** high
- **Definition:** Treat `uintptr` as an integer, not a GC-visible pointer. Follow only the conversion patterns explicitly permitted by `unsafe`.

## 2. Example

### 2.1 Scenario

A cache needs to retain a reference to a Go value for later use.

### 2.2 Preferred form

```go
package example

type cache struct {
	pointer *int
}

func (c *cache) remember(n *int) {
	c.pointer = n
}
```

### 2.3 Hazardous form

```go
package example

import "unsafe"

type cache struct {
	address uintptr
}

func (c *cache) remember(n *int) {
	c.address = uintptr(unsafe.Pointer(n))
}
```

### 2.4 Why this difference matters

A Go pointer keeps its referent visible to the garbage collector. A `uintptr` is only an integer, so retaining an address this way can leave the referent collectible or make a later conversion back to a pointer invalid.

## 3. Boundaries and distinctions

`unsafe` permits a small set of tightly constrained conversions, including pointer arithmetic performed within one expression. Follow the documented patterns exactly, and prefer a normal pointer or a safe package API whenever one expresses the intent.
