# Separate declaration from status-sensitive command substitution

## 1. Catalog record

- **Catalog identifier:** 2.8.1
- **Impact:** high
- **Consensus:** high
- **Definition:** Avoid `local x=$(command)`, `export x=$(command)`, and similar constructs when `command` status matters. Declare first, then assign: `local x; x=$(command)`.

## 2. Example

### 2.1 Scenario

A function reads a required release version and must stop when the lookup command fails.

### 2.2 Preferred form

```bash
#!/usr/bin/env bash
set -euo pipefail

read_release_version() {
  local version
  version=$(git describe --tags --exact-match HEAD) || return
  printf '%s\n' "$version"
}

read_release_version
```

### 2.3 Hazardous form

```bash
#!/usr/bin/env bash
set -euo pipefail

read_release_version() {
  local version=$(git describe --tags --exact-match HEAD)
  printf '%s\n' "$version"
}

read_release_version
```

### 2.4 Why this difference matters

`local` can return success even when the command substitution fails, masking a missing release tag. Separating declaration from assignment leaves the assignment status available for explicit handling.

## 3. Boundaries and distinctions

Combining declaration and assignment is acceptable only when the substitution's status is intentionally irrelevant. The same masking concern applies to builtins such as `export`, `declare`, and `readonly`.
