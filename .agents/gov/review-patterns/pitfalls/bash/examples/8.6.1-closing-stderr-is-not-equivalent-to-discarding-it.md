# Closing stderr is not equivalent to discarding it

## 1. Catalog record

- **Catalog identifier:** 8.6.1
- **Impact:** medium
- **Consensus:** high
- **Definition:** `2>&-` closes file descriptor 2, whereas `2>/dev/null` leaves it open and directs output to a sink; use `/dev/null` when the goal is only to suppress output.

## 2. Example

### 2.1 Scenario

A script runs a noisy command and wants to hide its diagnostics without changing the command's file-descriptor environment.

### 2.2 Preferred form

```bash
report_status() {
  printf 'details\n' >&2
}

report_status 2>/dev/null
```

### 2.3 Hazardous form

```bash
report_status() {
  printf 'details\n' >&2
}

report_status 2>&-
```

### 2.4 Why this difference matters

Redirecting stderr to `/dev/null` silently consumes diagnostics. Closing it can instead cause writes to fail or let programs detect that descriptor 2 is unavailable.

## 3. Boundaries and distinctions

Close stderr only when its absence is intentional and acceptable to the called program. Redirect it to a file when diagnostics must be retained rather than discarded.
