# Changing process locale in concurrent code

## 1. Catalog record

- **Catalog identifier:** 10.3.1
- **Impact:** medium
- **Consensus:** high
- **Definition:** Avoid repeated `locale.setlocale()` changes in multithreaded code and prefer designs that do not mutate the process-wide locale during normal operation.

## 2. Example

### 2.1 Scenario

A server formats monetary values for requests from users in different regions.

### 2.2 Preferred form

```python
def format_usd(cents: int) -> str:
    dollars, remainder = divmod(cents, 100)
    return f"${dollars:,}.{remainder:02d}"

print(format_usd(123456))
```

### 2.3 Hazardous form

```python
import locale

def format_usd(cents: int) -> str:
    locale.setlocale(locale.LC_ALL, "en_US.UTF-8")
    return locale.currency(cents / 100, grouping=True)

print(format_usd(123456))
```

### 2.4 Why this difference matters

`setlocale()` changes process-wide state and is not thread-safe on most systems, so another request can observe the wrong locale or race with the change.

## 3. Boundaries and distinctions

Setting a stable locale once during single-threaded process initialization can be appropriate. Per-request localization needs a locale-aware library or formatting approach that does not mutate global state.
