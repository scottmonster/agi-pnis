# Use `regexp.Compile` for runtime patterns

## 1. Catalog record

- **Catalog identifier:** 8.3.1
- **Impact:** medium
- **Consensus:** high
- **Definition:** Reserve `regexp.MustCompile` for patterns that are effectively program constants and should make initialization fail if invalid. Use `Compile` for user or runtime input.

## 2. Example

### 2.1 Scenario

An API accepts a search pattern from a request and uses it to filter names.

### 2.2 Preferred form

```go
package search

import "regexp"

func matches(pattern, name string) (bool, error) {
	re, err := regexp.Compile(pattern)
	if err != nil {
		return false, err
	}
	return re.MatchString(name), nil
}
```

### 2.3 Hazardous form

```go
package search

import "regexp"

func matches(pattern, name string) bool {
	re := regexp.MustCompile(pattern)
	return re.MatchString(name)
}
```

### 2.4 Why this difference matters

An invalid request pattern causes `MustCompile` to panic, which can terminate a request or process. `Compile` turns invalid input into an ordinary error that the API can report.

## 3. Boundaries and distinctions

`MustCompile` is useful for a package-level literal whose validity is controlled by the program and whose failure should prevent initialization. Cache compiled runtime patterns when reuse justifies it.
