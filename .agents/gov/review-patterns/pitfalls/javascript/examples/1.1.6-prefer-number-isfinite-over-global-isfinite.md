# Prefer Number.isFinite over global isFinite

## 1. Catalog record

- **Catalog identifier:** 1.1.6
- **Impact:** medium
- **Consensus:** high
- **Definition:** Use `Number.isFinite()` when only finite numeric values should pass. Global `isFinite()` converts non-number arguments first.

## 2. Example

### 2.1 Scenario

A billing calculation accepts only finite numeric amounts.

### 2.2 Preferred form

```javascript
function acceptsAmount(value) {
  return Number.isFinite(value);
}

console.log(acceptsAmount("42"));
```

### 2.3 Hazardous form

```javascript
function acceptsAmount(value) {
  return isFinite(value);
}

console.log(acceptsAmount("42"));
```

### 2.4 Why this difference matters

Global `isFinite()` accepts a numeric string after coercion, allowing input that has not satisfied the numeric type requirement.

## 3. Boundaries and distinctions

Parse text separately when text input is supported, then use `Number.isFinite()` on the parsed value.
