# Insufficient repository exploration

## 1. Catalog record

- **Catalog identifier:** 2.1
- **Evidence:** a
- **Definition:** Starts editing before locating the relevant implementation, callers, tests, and conventions.

## 2. Scenario

### 2.1 Context

An agent is asked to add a `timeout` option to the checkout client in an unfamiliar repository.

### 2.2 Safer approach

It searches for the client definition, its construction sites, integration tests, and nearby option names before changing the implementation and callers.

### 2.3 Failure mode

It immediately edits the first file named `client.ts`, without checking whether it is the checkout client or whether the option is forwarded elsewhere.

### 2.4 Why this difference matters

The patch can miss required callers, violate local conventions, or change an unrelated component.

## 3. Boundaries and distinctions

Exploration should be proportionate to the task, but must locate the relevant implementation and its material dependencies before editing.
