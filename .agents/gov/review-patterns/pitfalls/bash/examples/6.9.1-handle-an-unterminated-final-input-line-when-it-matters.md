# Handle an unterminated final input line when it matters

## 1. Catalog record

- **Catalog identifier:** 6.9.1
- **Impact:** medium
- **Consensus:** high
- **Definition:** `read` can assign the final partial line and still return failure if it lacks a terminating newline. When such input is valid, use a loop condition that also processes a nonempty final value.

## 2. Example

### 2.1 Scenario

A script processes every item in a manifest, including an accepted final line without a newline.

### 2.2 Preferred form

```bash
#!/usr/bin/env bash
while IFS= read -r item || [[ -n $item ]]; do echo "deploying $item"; done < "$1"
```

### 2.3 Hazardous form

```bash
#!/usr/bin/env bash
while IFS= read -r item; do echo "deploying $item"; done < "$1"
```

### 2.4 Why this difference matters

For an unterminated final line, `read` assigns the value but returns failure, causing the simple loop to skip it.

## 3. Boundaries and distinctions

If the format requires newline-terminated records, rejecting an incomplete final line can be preferable.
