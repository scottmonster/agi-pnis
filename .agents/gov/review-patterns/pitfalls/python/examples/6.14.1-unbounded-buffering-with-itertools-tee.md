# Unbounded buffering with `itertools.tee()`

## 1. Catalog record

- **Catalog identifier:** 6.14.1
- **Impact:** medium
- **Consensus:** high
- **Definition:** Do not assume `tee()` duplicates an iterator for free. If one branch may advance far ahead of another, materializing the data may be more appropriate.

## 2. Example

### 2.1 Scenario

One consumer needs a complete event batch while another processes the same batch promptly.

### 2.2 Preferred form

```python
events = list(range(1_000))
first_consumer = iter(events)
second_consumer = iter(events)
print(next(first_consumer), next(second_consumer))  # 0 0
```

### 2.3 Hazardous form

```python
from itertools import tee

source = (number for number in range(1_000_000))
fast, slow = tee(source)
sum(fast)  # tee buffers nearly all values until slow consumes them.
print(next(slow))
```

### 2.4 Why this difference matters

`tee()` retains elements unseen by the lagging branch, so a large gap can consume substantial hidden memory.

## 3. Boundaries and distinctions

`tee()` is useful for short streams whose branches remain close together. It is also not thread-safe.
