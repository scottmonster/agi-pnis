# Prevent commands inside `while read` from stealing loop input

## 1. Catalog record

- **Catalog identifier:** 2.11.1
- **Impact:** high
- **Consensus:** high
- **Definition:** Commands such as `ssh` that read standard input can consume data intended for the surrounding `while read` loop. Redirect their input, use options such as `ssh -n`, or dedicate another file descriptor to the loop.

## 2. Example

### 2.1 Scenario

A deployment script reads server names from a file and runs one remote command for every server.

### 2.2 Preferred form

```bash
#!/usr/bin/env bash
set -euo pipefail

while IFS= read -r server; do
  ssh -n -- "$server" 'systemctl reload example-service'
done < servers.txt
```

### 2.3 Hazardous form

```bash
#!/usr/bin/env bash
set -euo pipefail

while IFS= read -r server; do
  ssh -- "$server" 'systemctl reload example-service'
done < servers.txt
```

### 2.4 Why this difference matters

Without `-n`, `ssh` can read from the loop's standard input and consume subsequent server names. That leaves the loop incomplete or produces behavior that varies with the remote command.

## 3. Boundaries and distinctions

Redirecting a nested command from `/dev/null` is appropriate only when it does not need interactive input. If it needs a separate input stream, use another file descriptor or pass that stream explicitly.
