# Testing only editable installs

## 1. Catalog record

- **Catalog identifier:** 11.2.1
- **Impact:** medium
- **Consensus:** high
- **Definition:** Do not rely solely on editable installation behavior when validating a distributable project. Also test a normal built and installed distribution.

## 2. Example

### 2.1 Scenario

A release pipeline verifies that a package can be used after distribution.

### 2.2 Preferred form

```python
# CI commands:
# python -m build
# python -m venv .test-venv
# .test-venv/bin/python -m pip install dist/invoice_tools-1.0.0-py3-none-any.whl

installed_artifact = "dist/invoice_tools-1.0.0-py3-none-any.whl"
print(installed_artifact)
```

### 2.3 Hazardous form

```python
# CI command:
# python -m pip install -e .

install_mode = "editable"
print(install_mode)
```

### 2.4 Why this difference matters

An editable install exposes the source tree and can succeed even when the built wheel is missing package data or behaves differently after ordinary installation.

## 3. Boundaries and distinctions

Editable-install tests are valuable for development feedback. They complement, rather than replace, testing a built artifact in a clean environment.
