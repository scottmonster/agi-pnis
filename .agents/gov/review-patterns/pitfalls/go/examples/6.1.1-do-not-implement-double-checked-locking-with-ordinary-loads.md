# Do not implement double-checked locking with ordinary loads

## 1. Catalog record

- **Catalog identifier:** 6.1.1
- **Impact:** medium
- **Consensus:** high
- **Definition:** Use `sync.Once`, `OnceValue`, or proper synchronization instead of checking a shared initialization flag before acquiring a lock.

## 2. Example

### 2.1 Scenario

A service lazily creates one shared configuration.

### 2.2 Preferred form

```go
package main

import "sync"

type config struct{ endpoint string }
var loadConfig = sync.OnceValue(func() *config { return &config{"https://api.example"} })
func currentConfig() *config { return loadConfig() }
```

### 2.3 Hazardous form

```go
package main

import "sync"

var (
	mu sync.Mutex
	loaded bool
	shared *config
)
type config struct{ endpoint string }
func currentConfig() *config {
	if !loaded { mu.Lock(); if !loaded { shared = &config{}; loaded = true }; mu.Unlock() }
	return shared
}
```

### 2.4 Why this difference matters

The ordinary read of `loaded` races with its write and does not safely publish `shared`. `OnceValue` supplies the needed synchronization.

## 3. Boundaries and distinctions

Use a mutex when initialization must be reset. Do not recursively call the same `Once` operation.
