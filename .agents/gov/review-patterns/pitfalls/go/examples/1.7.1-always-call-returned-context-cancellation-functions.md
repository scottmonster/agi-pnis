# Always call returned context cancellation functions

## 1. Catalog record

- **Catalog identifier:** 1.7.1
- **Impact:** high
- **Consensus:** high
- **Definition:** When `WithCancel`, `WithTimeout`, or `WithDeadline` returns a `CancelFunc`, arrange to call it, normally with `defer cancel()`.

## 2. Example

### 2.1 Scenario

A request helper imposes a deadline on an outbound operation.

### 2.2 Preferred form

```go
package main

import (
	"context"
	"time"
)

func fetch(parent context.Context) error {
	ctx, cancel := context.WithTimeout(parent, time.Second)
	defer cancel()
	return callRemote(ctx)
}

func callRemote(context.Context) error { return nil }
```

### 2.3 Hazardous form

```go
package main

import (
	"context"
	"time"
)

func fetch(parent context.Context) error {
	ctx, _ := context.WithTimeout(parent, time.Second)
	return callRemote(ctx)
}

func callRemote(context.Context) error { return nil }
```

### 2.4 Why this difference matters

Without cancellation, timeout-related resources can remain live until the deadline expires even after the operation returns. Calling `cancel` releases them promptly and signals derived work.

## 3. Boundaries and distinctions

Call cancellation functions even after a deadline fires because cleanup is still explicit. A cancel function does not cancel the parent context.
