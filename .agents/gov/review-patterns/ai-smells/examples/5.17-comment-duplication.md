# Comment duplication

## 1. Catalog record

- **Catalog identifier:** 5.17
- **Evidence:** e
- **Definition:** Generated comments repeat themselves across closely related blocks.

## 2. Scenario

### 2.1 Context

Five branches each carry a comment saying “Validate the input before processing it,” with no branch-specific explanation.

### 2.2 Safer approach

Keep one useful comment where it explains a shared invariant, or rely on clear code when no extra explanation is needed.

### 2.3 Failure mode

Paste the same generic comment above every new validation block.

### 2.4 Why this difference matters

Repeated commentary adds noise and can become stale while providing no new information.

## 3. Boundaries and distinctions

Repeated code may need locally specific rationale. This concerns duplicated comments that repeat the same information across related blocks.
