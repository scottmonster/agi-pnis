# `weakref.finalize()` callback retaining its object

## 1. Catalog record

- **Catalog identifier:** 14.1.1
- **Impact:** medium
- **Consensus:** high
- **Definition:** Ensure a `weakref.finalize()` callback does not directly or indirectly retain the object being finalized, especially through a bound method.

## 2. Example

### 2.1 Scenario

A session owns an operating-system handle and registers best-effort cleanup for it.

### 2.2 Preferred form

```python
import weakref


def close_handle(handle: int) -> None:
    print(f"closing handle {handle}")


class Session:
    def __init__(self, handle: int) -> None:
        self.handle = handle
        self.finalizer = weakref.finalize(self, close_handle, handle)


session = Session(10)
del session
```

### 2.3 Hazardous form

```python
import weakref


class Session:
    def close(self) -> None:
        print("closing handle")

    def __init__(self) -> None:
        self.finalizer = weakref.finalize(self, self.close)


session = Session()
del session
```

### 2.4 Why this difference matters

A bound method retains its instance. Registering `self.close` as the finalizer callback can keep `self` alive, defeating the finalizer's purpose.

## 3. Boundaries and distinctions

Use a standalone callback or pass only independent data needed for cleanup. A finalizer remains best-effort cleanup, not a replacement for explicit resource ownership.
