# Minimal Version Selection does not mean latest

## 1. Catalog record

- **Catalog identifier:** 11.6.1
- **Impact:** medium
- **Consensus:** high
- **Definition:** Do not assume a build automatically selects the newest released dependency. Inspect and upgrade dependencies deliberately.

## 2. Example

### 2.1 Scenario

A service needs a bug fix released in `example.com/parse` v1.5.0, while its current module graph only requires v1.2.0.

### 2.2 Preferred form

```go
package example

import "os/exec"

func upgradeParser() error {
	return exec.Command("go", "get", "example.com/parse@v1.5.0").Run()
}
```

### 2.3 Hazardous form

```go
package example

import "example.com/parse"

func hazardous(input string) error {
	// Importing the package does not request its newest upstream release.
	return parse.Validate(input)
}
```

### 2.4 Why this difference matters

Minimal Version Selection chooses the highest version required by the module graph, not the newest version available upstream.

## 3. Boundaries and distinctions

MVS provides reproducible version selection from declared requirements. It does not remove the need to audit, upgrade, and test dependencies deliberately.
