# Remember that sort mutates the original array

## 1. Catalog record

- **Catalog identifier:** 3.1.8
- **Impact:** medium
- **Consensus:** high
- **Definition:** `sort()` rearranges the array in place. Use `toSorted()` or an explicit copy when callers expect the original ordering to remain unchanged.

## 2. Example

### 2.1 Scenario

A UI needs a sorted display order while another view still relies on arrival order.

### 2.2 Preferred form

```javascript
const arrivals = ["Mina", "Ari", "Zoe"];
const displayOrder = [...arrivals].sort();

console.log(arrivals); // ["Mina", "Ari", "Zoe"]
console.log(displayOrder); // ["Ari", "Mina", "Zoe"]
```

### 2.3 Hazardous form

```javascript
const arrivals = ["Mina", "Ari", "Zoe"];
const displayOrder = arrivals.sort();

console.log(arrivals); // ["Ari", "Mina", "Zoe"]
console.log(displayOrder === arrivals); // true
```

### 2.4 Why this difference matters

The hazardous form changes shared `arrivals`, so code expecting arrival order later observes the sorted order instead.

## 3. Boundaries and distinctions

In-place sorting is efficient and appropriate when the receiver is owned and its new order is intentional. `toSorted()` is also an option where supported.
