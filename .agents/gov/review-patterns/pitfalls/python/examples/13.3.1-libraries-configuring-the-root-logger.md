# Libraries configuring the root logger

## 1. Catalog record

- **Catalog identifier:** 13.3.1
- **Impact:** medium
- **Consensus:** high
- **Definition:** Library code should log through named loggers, normally based on `__name__`, and should not configure the root logger or install application handlers behind the user's back.

## 2. Example

### 2.1 Scenario

A reusable library reports retry activity while allowing its host application to choose handlers and log levels.

### 2.2 Preferred form

```python
import logging


logger = logging.getLogger(__name__)


def retrying_request(url: str) -> None:
    logger.info("retrying request to %s", url)
```

### 2.3 Hazardous form

```python
import logging


logging.basicConfig(level=logging.DEBUG)


def retrying_request(url: str) -> None:
    logging.info("retrying request to %s", url)
```

### 2.4 Why this difference matters

Configuring the root logger changes process-wide behavior, potentially duplicating output, exposing sensitive logs, or overriding an application's logging policy.

## 3. Boundaries and distinctions

An executable application owns root logging configuration and handlers. A library may use a named logger, but should leave configuration to its caller.
