# Return promises from then callbacks

## 1. Catalog record

- **Catalog identifier:** 7.1.2
- **Impact:** high
- **Consensus:** high
- **Definition:** When a `.then()` callback starts asynchronous work that the next step depends on, return that promise instead of starting it without returning it.

## 2. Example

### 2.1 Scenario

A profile is loaded, then its audit event must be stored before a confirmation is displayed.

### 2.2 Preferred form

```javascript
function loadProfile() {
  return Promise.resolve({ id: "u-9" });
}

function writeAudit(profile) {
  return Promise.resolve(`audited ${profile.id}`);
}

loadProfile()
  .then((profile) => writeAudit(profile))
  .then((message) => console.log(message))
  .catch(console.error);
```

### 2.3 Hazardous form

```javascript
function loadProfile() {
  return Promise.resolve({ id: "u-9" });
}

function writeAudit(profile) {
  return Promise.resolve(`audited ${profile.id}`);
}

loadProfile()
  .then((profile) => {
    writeAudit(profile);
    return "profile handled";
  })
  .then((message) => console.log(message))
  .catch(console.error);
```

### 2.4 Why this difference matters

Without the return, the second callback waits only for its predecessor and not for the audit operation or its failure.

## 3. Boundaries and distinctions

Do not return a promise only when the later chain deliberately has no dependency on that work and its errors are handled separately.
