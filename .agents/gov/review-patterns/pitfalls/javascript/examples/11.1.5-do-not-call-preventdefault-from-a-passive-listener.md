# Do not call preventDefault from a passive listener

## 1. Catalog record

- **Catalog identifier:** 11.1.5
- **Impact:** medium
- **Consensus:** high
- **Definition:** Register a non-passive listener when it must cancel default behavior.

## 2. Example

### 2.1 Scenario

A canvas viewer temporarily blocks wheel scrolling while a user holds a modifier key to zoom. Its wheel handler must cancel the browser's normal scroll action in that case.

### 2.2 Preferred form

```javascript
const viewer = document.querySelector("#image-viewer");

viewer.addEventListener("wheel", (event) => {
  if (!event.ctrlKey) return;

  event.preventDefault();
  viewer.style.scale = String(1 + event.deltaY / -1000);
}, { passive: false });
```

### 2.3 Hazardous form

```javascript
const viewer = document.querySelector("#image-viewer");

viewer.addEventListener("wheel", (event) => {
  if (!event.ctrlKey) return;

  event.preventDefault();
  viewer.style.scale = String(1 + event.deltaY / -1000);
}, { passive: true });
```

### 2.4 Why this difference matters

A passive listener promises not to cancel the event, so `preventDefault()` has no effect in the hazardous form. The browser can scroll or zoom while application code also changes the viewer, producing conflicting behavior.

## 3. Boundaries and distinctions

Keep listeners passive when they never need to cancel an event because that lets the browser optimize scrolling and touch handling. Only opt out of passivity for listeners that actually need cancellation, and scope them narrowly.
