# Missing early termination

## 1. Catalog record

- **Catalog identifier:** 7.7
- **Evidence:** e
- **Definition:** Continues processing after a decisive result, error, or match is already known.

## 2. Scenario

### 2.1 Context

An agent validates an upload and needs to reject it when any row has an invalid required field.

### 2.2 Safer approach

It returns a validation error as soon as it finds the first invalid row, including that row's location.

### 2.3 Failure mode

It keeps parsing and validating the remaining million rows after the rejection condition is known.

### 2.4 Why this difference matters

The user waits longer and the system spends resources after the outcome is already decisive.

## 3. Boundaries and distinctions

Full processing is appropriate when all errors must be reported or required cleanup remains; early termination applies only after the result, error, or match is sufficient for the contract.
