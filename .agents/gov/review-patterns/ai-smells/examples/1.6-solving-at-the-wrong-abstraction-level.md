# Solving at the wrong abstraction level

## 1. Catalog record

- **Catalog identifier:** 1.6
- **Evidence:** se
- **Definition:** Re-architects a subsystem when a local conditional or data change would solve the task.

## 2. Scenario

### 2.1 Context

A checkout form should hide the company-name input for individual buyers. The form already receives a buyer type from the server.

### 2.2 Safer approach

Use the existing buyer type to conditionally render the input and add a focused UI test for each buyer type.

### 2.3 Failure mode

The agent introduces a new form-schema service, field plugin registry, and client-side rules engine for this single visibility condition.

### 2.4 Why this difference matters

The simple requirement gains new concepts, dependencies, and failure paths that make maintenance harder than the original conditional.

## 3. Boundaries and distinctions

A broader architecture can be justified when multiple stable requirements need independent form rules. One local condition alone does not establish that need.
