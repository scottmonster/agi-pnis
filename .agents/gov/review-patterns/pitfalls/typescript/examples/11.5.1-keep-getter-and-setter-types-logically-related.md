# Keep getter and setter types logically related

## 1. Catalog record

- **Catalog identifier:** 11.5.1
- **Impact:** low
- **Consensus:** medium
- **Definition:** TypeScript permits explicitly annotated getter and setter types that are completely unrelated, but prefer a getter type assignable to its corresponding setter type unless the unusual asymmetry is intentional.

## 2. Example

### 2.1 Scenario

A settings object accepts an optional input but always exposes a normalized value.

### 2.2 Preferred form

```typescript
class Settings {
  #theme = 'system';

  get theme(): string {
    return this.#theme;
  }

  set theme(value: string | undefined) {
    this.#theme = value ?? 'system';
  }
}

const settings = new Settings();
settings.theme = settings.theme;
```

### 2.3 Hazardous form

```typescript
class Settings {
  #theme = 'system';

  get theme(): number {
    return this.#theme.length;
  }

  set theme(value: string) {
    this.#theme = value;
  }
}

const settings = new Settings();
settings.theme = settings.theme; // Error: number is not assignable to string.
```

### 2.4 Why this difference matters

Unrelated types make ordinary reasoning such as `obj.value = obj.value` fail and can make property APIs surprisingly difficult to use.

## 3. Boundaries and distinctions

Apply this guidance in the conditions described by the catalog record. Deliberate exceptions need a documented runtime guarantee, compatible toolchain behavior, or an explicit local unsafe boundary.
