# Bundle declarations when bundling library JavaScript

## 1. Catalog record

- **Catalog identifier:** 4.6.1
- **Impact:** high
- **Consensus:** high
- **Definition:** If a library bundles internal JavaScript modules, ensure its declaration output represents that bundled module structure rather than blindly publishing the unbundled declaration graph.

## 2. Example

### 2.1 Scenario

A library bundles its JavaScript into one public entrypoint.

### 2.2 Preferred form

```typescript
// dist/index.d.ts mirrors the JavaScript bundle's public surface.
export interface ClientOptions { endpoint: string }
export declare function createClient(options: ClientOptions): { get(path: string): Promise<string> };
```

### 2.3 Hazardous form

```typescript
// dist/index.d.ts still references an internal declaration not shipped with the bundle.
export { createClient } from './internal/client.js';
```

### 2.4 Why this difference matters

Declaration imports valid under bundler resolution can remain invalid for consumers running Node-style resolution.

## 3. Boundaries and distinctions

Apply this guidance in the conditions described by the catalog record. Deliberate exceptions need a documented runtime guarantee, compatible toolchain behavior, or an explicit local unsafe boundary.
