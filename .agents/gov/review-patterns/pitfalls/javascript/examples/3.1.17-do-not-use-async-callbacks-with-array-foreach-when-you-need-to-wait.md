# Do not use async callbacks with Array.forEach when you need to wait

## 1. Catalog record

- **Catalog identifier:** 3.1.17
- **Impact:** high
- **Consensus:** high
- **Definition:** `forEach()` does not await promises returned by its callback. Use `for...of` with `await` for sequential work or construct promises and use `Promise.all()` for concurrent work.

## 2. Example

### 2.1 Scenario

An import must finish saving every record before it reports completion.

### 2.2 Preferred form

```javascript
async function save(record) {
  await Promise.resolve();
  console.log(`Saved ${record}`);
}

async function importRecords(records) {
  for (const record of records) {
    await save(record);
  }
  console.log("Import complete");
}

void importRecords(["a", "b"]);
```

### 2.3 Hazardous form

```javascript
async function save(record) {
  await Promise.resolve();
  console.log(`Saved ${record}`);
}

async function importRecords(records) {
  await records.forEach(async (record) => {
    await save(record);
  });
  console.log("Import complete");
}

void importRecords(["a", "b"]);
```

### 2.4 Why this difference matters

`forEach` returns `undefined`, so awaiting it does not wait for its asynchronous callbacks. Completion can be reported before saves and their failures settle.

## 3. Boundaries and distinctions

Use `Promise.all(records.map(save))` when saves are independent and should run concurrently. Use `for...of` when sequencing is required.
