# Repeating a failed approach

## 1. Catalog record

- **Catalog identifier:** 13.6
- **Evidence:** a
- **Definition:** Error evidence changes but the strategy does not.

## 2. Scenario

### 2.1 Context

A migration fails first on a missing column, then on a foreign-key constraint after the column is added.

### 2.2 Safer approach

The agent treats the new constraint error as evidence, inspects the migration order and existing data, then adjusts the migration plan.

### 2.3 Failure mode

The agent keeps adding nullable columns because that fixed the first error, despite the new failure identifying invalid references.

### 2.4 Why this difference matters

The patch drifts further from the actual cause and can damage data or conceal the constraint violation.

## 3. Boundaries and distinctions

Persisting with a strategy can be justified while evidence continues to support it. Repetition becomes a failure when changed diagnostics invalidate the original hypothesis.
