# Trivial factory class

## 1. Catalog record

- **Catalog identifier:** 3.6
- **Evidence:** se
- **Definition:** `UserFactory.create(x)` merely calls `User(x)`.

## 2. Scenario

### 2.1 Context

A request handler creates a small `User` value from validated input.

### 2.2 Safer approach

Construct `User(input.name)` at the clear creation point.

### 2.3 Failure mode

Add a `UserFactory` whose only method forwards its argument to the constructor.

### 2.4 Why this difference matters

Readers must trace another name and file without gaining policy or construction logic.

## 3. Boundaries and distinctions

A factory is useful when construction selects variants, validates complex state, or hides meaningful setup; simple forwarding is not that case.
