# Remember arrays copy by value

## 1. Catalog record

- **Catalog identifier:** 8.8.1
- **Impact:** medium
- **Consensus:** high
- **Definition:** Passing or assigning an array copies the entire array. Prefer slices for ordinary sequence APIs unless value-array semantics are specifically wanted.

## 2. Example

### 2.1 Scenario

A decoder fills a caller-provided sequence of bytes.

### 2.2 Preferred form

```go
package decoder

func markHeader(b []byte) {
	b[0] = 0xA5
}

func decode() byte {
	b := []byte{0, 0}
	markHeader(b)
	return b[0]
}
```

### 2.3 Hazardous form

```go
package decoder

func markHeader(b [2]byte) {
	b[0] = 0xA5
}

func decode() byte {
	b := [2]byte{}
	markHeader(b)
	return b[0]
}
```

### 2.4 Why this difference matters

The array argument is copied when `markHeader` is called, so the assignment changes only the callee's copy and `decode` returns zero. A slice carries a descriptor that refers to the caller's elements.

## 3. Boundaries and distinctions

Arrays are useful when fixed size and value-copy semantics are part of the design, for example a fixed digest value. Use an array pointer when mutation of a fixed-size array is explicitly intended.
