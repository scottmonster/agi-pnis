# Avoid unnecessary import renaming

## 1. Catalog record

- **Catalog identifier:** 13.7.1
- **Impact:** low
- **Consensus:** high
- **Definition:** Use a package's natural name unless a collision or similar concrete reason requires an alias.

## 2. Example

### 2.1 Scenario

A handler encodes a response with the standard JSON package and has no naming collision.

### 2.2 Preferred form

```go
package example

import "encoding/json"

func encode(v any) ([]byte, error) {
	return json.Marshal(v)
}
```

### 2.3 Hazardous form

```go
package example

import jsonpkg "encoding/json"

func encode(v any) ([]byte, error) {
	return jsonpkg.Marshal(v)
}
```

### 2.4 Why this difference matters

The natural `json` name is immediately recognizable. An arbitrary alias adds a name readers must translate without resolving a collision.

## 3. Boundaries and distinctions

Use an alias when two imported packages collide or when it communicates a necessary local distinction.
