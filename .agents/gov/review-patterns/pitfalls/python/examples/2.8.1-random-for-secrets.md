# `random` for secrets

## 1. Catalog record

- **Catalog identifier:** 2.8.1
- **Impact:** high
- **Consensus:** high
- **Definition:** Use `secrets`, not the default `random` module, for authentication tokens, password-reset URLs, passwords, or other security-sensitive randomness.

## 2. Example

### 2.1 Scenario

A service creates password-reset links that an attacker must not be able to guess.

### 2.2 Preferred form

```python
import secrets


def make_reset_token() -> str:
    return secrets.token_urlsafe(32)
```

### 2.3 Hazardous form

```python
import random


def make_reset_token() -> str:
    return str(random.getrandbits(256))
```

### 2.4 Why this difference matters

`random` is designed for simulation, not cryptographic unpredictability. A predictable reset token can let an attacker take over an account.

## 3. Boundaries and distinctions

The `random` module remains suitable for non-security work such as simulations, games, and randomized tests.
