# General-purpose hashes for passwords

## 1. Catalog record

- **Catalog identifier:** 2.9.1
- **Impact:** high
- **Consensus:** high
- **Definition:** Do not store passwords using a direct fast hash such as `sha256(password)`. Use a password-oriented, salted, deliberately expensive derivation mechanism.

## 2. Example

### 2.1 Scenario

An application needs to store credentials for later password verification.

### 2.2 Preferred form

```python
import hashlib
import os


def hash_password(password: str) -> tuple[bytes, bytes]:
    salt = os.urandom(16)
    digest = hashlib.scrypt(password.encode(), salt=salt, n=2**14, r=8, p=1)
    return salt, digest
```

### 2.3 Hazardous form

```python
import hashlib


def hash_password(password: str) -> str:
    return hashlib.sha256(password.encode()).hexdigest()
```

### 2.4 Why this difference matters

A fast unsalted hash makes large-scale offline guessing cheap after a database leak. A salted, expensive derivation increases that cost.

## 3. Boundaries and distinctions

Use a reviewed password-hashing library or platform service when one is available, and choose parameters appropriate to the deployment's resources.
