# Fail-open behavior on authorization/configuration errors

## 1. Catalog record

- **Catalog identifier:** 10.22
- **Evidence:** se
- **Definition:** Grants access or proceeds with an unsafe default when a required security decision cannot be made.

## 2. Scenario

### 2.1 Context

An API consults a policy service before allowing access to billing records.

### 2.2 Safer approach

If the policy service is unavailable or its response is invalid, deny the protected operation, record a safe diagnostic, and provide a controlled recovery path.

### 2.3 Failure mode

The agent catches policy lookup errors and allows the request so a transient outage does not affect users.

### 2.4 Why this difference matters

An attacker or outage can turn uncertainty in a required security decision into unauthorized access.

## 3. Boundaries and distinctions

Availability-oriented defaults can be appropriate for non-security features. Authorization and similarly required security decisions need an explicit safe failure policy.
