# Missing multiprocessing main guard

## 1. Catalog record

- **Catalog identifier:** 3.4.1
- **Impact:** high
- **Consensus:** high
- **Definition:** Protect process-creating entry points with `if __name__ == "__main__":`, particularly when spawn or forkserver is used.

## 2. Example

### 2.1 Scenario

A command-line program starts a worker process. It must work on platforms that use the spawn start method.

### 2.2 Preferred form

```python
from multiprocessing import Process


def generate_report() -> None:
    print("report generated")


def main() -> None:
    process = Process(target=generate_report)
    process.start()
    process.join()


if __name__ == "__main__":
    main()
```

### 2.3 Hazardous form

```python
from multiprocessing import Process


def generate_report() -> None:
    print("report generated")


process = Process(target=generate_report)
process.start()
process.join()
```

### 2.4 Why this difference matters

With spawn, the child imports the main module. Top-level process creation runs again during that import and can recursively create children or fail before useful work begins.

## 3. Boundaries and distinctions

Imports may still define functions, classes, and constants at module scope. The guard is specifically for entry-point behavior that creates processes or performs other run-only actions.
