# Missing import/include

## 1. Catalog record

- **Catalog identifier:** 8.2
- **Evidence:** e
- **Definition:** Uses an external symbol without bringing its defining module, header, or package into the build.

## 2. Scenario

### 2.1 Context

A TypeScript service adds a UUID to an audit event using a library already listed in `package.json`.

### 2.2 Safer approach

The agent checks the library's installed API and adds the corresponding import alongside the changed code. It runs the repository type check or build so the compilation unit verifies its complete set of imports.

### 2.3 Failure mode

It writes `const eventId = v4()` in the handler but omits the import from the UUID module. The code reads plausibly in review but fails during type checking with an unresolved symbol.

### 2.4 Why this difference matters

An incomplete compilation unit turns an otherwise small change into a broken build and delays integration until the missing dependency reference is found.

## 3. Boundaries and distinctions

This is about failing to bring an existing external symbol into the relevant build unit. It is distinct from declaring no dependency metadata at all, and from intentionally using a project-local symbol that needs no external import.
