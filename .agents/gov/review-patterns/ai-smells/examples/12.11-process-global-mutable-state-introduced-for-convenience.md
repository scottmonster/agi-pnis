# Process-global mutable state introduced for convenience

## 1. Catalog record

- **Catalog identifier:** 12.11
- **Evidence:** se
- **Definition:** Stores changing application state globally, making lifecycle, isolation, concurrency, and tests harder to reason about.

## 2. Scenario

### 2.1 Context

A request handler writes the current tenant into a module-level variable so downstream functions need not accept a context parameter.

### 2.2 Safer approach

Pass request-scoped context through the relevant interfaces or use an established scoped mechanism with explicit lifecycle and isolation behavior.

### 2.3 Failure mode

Store the active tenant in a mutable module global and assume concurrent requests will not overlap.

### 2.4 Why this difference matters

Concurrent requests can read the wrong tenant, while tests become order-dependent and lifecycle ownership is unclear.

## 3. Boundaries and distinctions

Immutable process-wide configuration is not the same problem. This failure concerns changing application state whose scope, concurrency, or test isolation matters.
