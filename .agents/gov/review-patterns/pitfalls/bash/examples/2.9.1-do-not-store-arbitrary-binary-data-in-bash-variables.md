# Do not store arbitrary binary data in Bash variables

## 1. Catalog record

- **Catalog identifier:** 2.9.1
- **Impact:** high
- **Consensus:** high
- **Definition:** Bash variables cannot represent embedded NUL bytes. Keep arbitrary binary data in files, pipes, or other byte-oriented tools rather than shell variables.

## 2. Example

### 2.1 Scenario

A script receives a binary record that may contain NUL bytes and must preserve its exact contents for another program.

### 2.2 Preferred form

```bash
#!/usr/bin/env bash
set -euo pipefail

binary_file=$(mktemp)
trap 'rm -f -- "$binary_file"' EXIT

receive_binary_record > "$binary_file"
consume_binary_record < "$binary_file"
```

### 2.3 Hazardous form

```bash
#!/usr/bin/env bash
set -euo pipefail

binary_record=$(receive_binary_record)
printf '%s' "$binary_record" | consume_binary_record
```

### 2.4 Why this difference matters

Command substitution stores the result in a Bash variable, which cannot retain embedded NUL bytes. The hazardous form irreversibly changes binary data before the consumer sees it.

## 3. Boundaries and distinctions

Bash variables are suitable for text whose encoding and content exclude NUL. For arbitrary bytes, use files, pipes, or tools designed for byte-oriented data.
