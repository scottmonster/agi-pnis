# Cancel pipelines when downstream stops early

## 1. Catalog record

- **Catalog identifier:** 1.4.1
- **Impact:** high
- **Consensus:** high
- **Definition:** Pipeline stages must stop sending when downstream consumers return early. Propagate cancellation rather than leaving upstream goroutines blocked on sends.

## 2. Example

### 2.1 Scenario

A caller needs only the first generated value from a producer.

### 2.2 Preferred form

```go
package main

import "context"

func produce(ctx context.Context, out chan<- int) {
	defer close(out)
	for i := 0; ; i++ {
		select {
		case out <- i:
		case <-ctx.Done():
			return
		}
	}
}

func main() {
	ctx, cancel := context.WithCancel(context.Background())
	defer cancel()
	values := make(chan int)
	go produce(ctx, values)
	<-values
}
```

### 2.3 Hazardous form

```go
package main

func produce(out chan<- int) {
	for i := 0; ; i++ {
		out <- i
	}
}

func main() {
	values := make(chan int)
	go produce(values)
	<-values
}
```

### 2.4 Why this difference matters

After the consumer returns, the hazardous producer blocks forever on its next send. Cancellation gives every stage a way to stop.

## 3. Boundaries and distinctions

Closing a channel can signal completion when ownership is clear. Context cancellation is especially useful when several stages or external operations must stop together.
