# Repository abstraction over trivial persistence

## 1. Catalog record

- **Catalog identifier:** 3.15
- **Evidence:** se
- **Definition:** Adds repository interfaces/mappers around a framework already providing a sufficient persistence abstraction.

## 2. Scenario

### 2.1 Context

The ORM already provides a typed model API for simple account CRUD.

### 2.2 Safer approach

Use the framework persistence API in the domain operation and keep any real query policy nearby.

### 2.3 Failure mode

Add repository interfaces and row mappers that only repeat the ORM's CRUD operations.

### 2.4 Why this difference matters

Duplicated persistence abstractions add translation code and can drift from the framework behavior.

## 3. Boundaries and distinctions

A repository can be valuable for genuine cross-store policy or a domain boundary; trivial wrapping of an adequate framework is the failure.
