# Interface equality can panic

## 1. Catalog record

- **Catalog identifier:** 2.2.1
- **Impact:** high
- **Consensus:** high
- **Definition:** Do not assume every pair of interface values can safely be compared with `==`. Comparison panics when the dynamic value is not comparable, such as a slice or map.

## 2. Example

### 2.1 Scenario

A configuration validator receives arbitrary decoded values as `any` and needs to recognize a missing value without panicking on slices or maps.

### 2.2 Preferred form

```go
package example

import "reflect"

func isNil(value any) bool {
	if value == nil {
		return true
	}
	v := reflect.ValueOf(value)
	switch v.Kind() {
	case reflect.Chan, reflect.Func, reflect.Interface, reflect.Map, reflect.Pointer, reflect.Slice:
		return v.IsNil()
	default:
		return false
	}
}
```

### 2.3 Hazardous form

```go
package example

func hasSameValue(left, right any) bool {
	return left == right // panics if both hold []string or map values
}

func example() bool {
	return hasSameValue([]string{"admin"}, []string{"admin"})
}
```

### 2.4 Why this difference matters

An interface comparison compares its dynamic values. Slices and maps are not comparable, so a generic equality helper can turn ordinary input into a runtime panic.

## 3. Boundaries and distinctions

Direct interface equality is safe when both dynamic values are comparable. Use an explicit domain comparison, or a tool such as `reflect.DeepEqual` only when its semantics fit the data.
