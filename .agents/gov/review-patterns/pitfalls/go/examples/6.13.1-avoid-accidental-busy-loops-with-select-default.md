# Avoid accidental busy loops with `select default`

## 1. Catalog record

- **Catalog identifier:** 6.13.1
- **Impact:** medium
- **Consensus:** high
- **Definition:** A `default` case makes `select` nonblocking. Do not put such a `select` in an unrestricted loop unless active polling is intentional and controlled.

## 2. Example

### 2.1 Scenario

A worker waits for a job or shutdown.

### 2.2 Preferred form

```go
package main

func work(stop <-chan struct{}, jobs <-chan string) {
	for {
		select {
		case <-stop:
			return
		case job := <-jobs:
			_ = job
		}
	}
}
```

### 2.3 Hazardous form

```go
package main

func work(stop <-chan struct{}, jobs <-chan string) {
	for {
		select {
		case <-stop:
			return
		case job := <-jobs:
			_ = job
		default:
		}
	}
}
```

### 2.4 Why this difference matters

When no channel is ready, `default` makes the hazardous loop spin and consume CPU. The preferred select blocks.

## 3. Boundaries and distinctions

One nonblocking check can be useful. Rate-limit intentional polling and document its CPU and latency cost.
