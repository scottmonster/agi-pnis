# Prefer higher-level synchronization to hand-written atomics

## 1. Catalog record

- **Catalog identifier:** 6.8.1
- **Impact:** medium
- **Consensus:** high
- **Definition:** Use channels, mutexes, or other `sync` facilities unless an atomic algorithm is genuinely needed.

## 2. Example

### 2.1 Scenario

A producer hands complete work items to a consumer.

### 2.2 Preferred form

```go
package main

type job struct { id string; body []byte }
func submit(queue chan<- job, value job) { queue <- value }
```

### 2.3 Hazardous form

```go
package main

import "sync/atomic"

type queue struct { head atomic.Uint64; tail atomic.Uint64; data [128]string }
func (q *queue) submit(value string) {
	position := q.tail.Add(1) - 1
	q.data[position%128] = value
	q.head.Store(position + 1)
}
```

### 2.4 Why this difference matters

The hand-written queue has subtle publication, overwrite, and full-queue requirements that these atomics do not solve. A channel expresses ownership transfer.

## 3. Boundaries and distinctions

Atomics can be appropriate in measured hot paths with a proven algorithm. Document memory-order assumptions and test concurrent behavior.
