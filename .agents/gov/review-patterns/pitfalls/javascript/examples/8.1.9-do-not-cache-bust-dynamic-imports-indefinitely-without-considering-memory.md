# Do not cache-bust dynamic imports indefinitely without considering memory

## 1. Catalog record

- **Catalog identifier:** 8.1.9
- **Impact:** low
- **Consensus:** high
- **Definition:** Do not create unbounded unique dynamic import URLs solely to bypass module caching.

## 2. Example

### 2.1 Scenario

A development dashboard periodically reloads a rules module while it remains open.

### 2.2 Preferred form

```javascript
async function loadRules() {
  const module = await import("./rules.js");
  return module.rules;
}

loadRules().then(console.log, console.error);
```

### 2.3 Hazardous form

```javascript
async function loadRules() {
  const module = await import(`./rules.js?reload=${Date.now()}`);
  return module.rules;
}

setInterval(() => {
  loadRules().then(console.log, console.error);
}, 5_000);
```

### 2.4 Why this difference matters

Every distinct specifier can create another module record. The hazardous polling loop keeps producing unique URLs and can grow module-related memory for the lifetime of the page or process.

## 3. Boundaries and distinctions

A bounded versioned URL can be suitable for a controlled deployment or explicit refresh workflow. Define a retention and restart strategy before repeatedly bypassing module caching.
