# Capture `$?` before running anything else

## 1. Catalog record

- **Catalog identifier:** 5.4.1
- **Impact:** medium
- **Consensus:** high
- **Definition:** If `$?` must be inspected, save it immediately after the relevant command. Prefer testing the command directly when possible.

## 2. Example

### 2.1 Scenario

A cleanup script needs to log a failed removal before returning the removal status to its caller.

### 2.2 Preferred form

```bash
remove_archive() {
  local archive=$1

  rm -- "$archive"
  local status=$?
  printf 'attempted removal of %s\n' "$archive" >&2
  return "$status"
}

remove_archive "${1:?provide an archive path}"
```

### 2.3 Hazardous form

```bash
remove_archive() {
  local archive=$1

  rm -- "$archive"
  printf 'attempted removal of %s\n' "$archive" >&2
  return "$?"
}

remove_archive "${1:?provide an archive path}"
```

### 2.4 Why this difference matters

The `printf` succeeds in the usual case and replaces the failed `rm` status. The hazardous function can therefore report success even when the archive was not removed.

## 3. Boundaries and distinctions

When no intervening command is needed, test the command directly in `if`. Save the status only when it must survive later work.
