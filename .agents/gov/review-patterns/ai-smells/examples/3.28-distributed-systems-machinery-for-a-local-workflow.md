# Distributed-systems machinery for a local workflow

## 1. Catalog record

- **Catalog identifier:** 3.28
- **Evidence:** se
- **Definition:** Sagas, distributed locks, leases, consensus-like coordination, or idempotency infrastructure precede any distributed need.

## 2. Scenario

### 2.1 Context

A single process updates one local database transaction during account setup.

### 2.2 Safer approach

Use the database transaction and local validation required by the actual workflow.

### 2.3 Failure mode

Add leases, a saga coordinator, and distributed locking although no remote participant exists.

### 2.4 Why this difference matters

Distributed coordination increases failure handling and operational complexity while solving no current distributed problem.

## 3. Boundaries and distinctions

Such machinery may be needed with real distributed participants and failure modes; a local transactional workflow is not that condition.
