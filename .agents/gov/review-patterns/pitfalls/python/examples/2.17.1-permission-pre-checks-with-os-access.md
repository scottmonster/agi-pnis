# Permission pre-checks with `os.access()`

## 1. Catalog record

- **Catalog identifier:** 2.17.1
- **Impact:** high
- **Consensus:** high
- **Definition:** Do not normally check access with `os.access()` and then separately open the file. Attempt the operation and handle failure instead.

## 2. Example

### 2.1 Scenario

A command reads a configuration file that another process might replace or change permissions on.

### 2.2 Preferred form

```python
from pathlib import Path


def read_config(path: Path) -> str:
    try:
        return path.read_text(encoding="utf-8")
    except OSError as error:
        raise RuntimeError(f"cannot read configuration: {path}") from error
```

### 2.3 Hazardous form

```python
import os
from pathlib import Path


def read_config(path: Path) -> str:
    if not os.access(path, os.R_OK):
        raise RuntimeError(f"cannot read configuration: {path}")
    return path.read_text(encoding="utf-8")
```

### 2.4 Why this difference matters

The filesystem can change after the pre-check but before the read. Performing the operation directly handles the actual state at use time.

## 3. Boundaries and distinctions

`os.access()` can be useful for a user-facing advisory check, but it must not be used to authorize a later security-sensitive operation.
