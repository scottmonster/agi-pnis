# Mutable class variables used as per-instance state

## 1. Catalog record

- **Catalog identifier:** 6.3.1
- **Impact:** medium
- **Consensus:** high
- **Definition:** Put mutable data intended to belong to each instance on `self` during initialization rather than defining one mutable object as a class variable.

## 2. Example

### 2.1 Scenario

Each order must maintain its own editable list of line items.

### 2.2 Preferred form

```python
class Order:
    def __init__(self) -> None:
        self.items: list[str] = []


first = Order()
second = Order()
first.items.append("book")
assert second.items == []
```

### 2.3 Hazardous form

```python
class Order:
    items: list[str] = []


first = Order()
second = Order()
first.items.append("book")
assert second.items == ["book"]
```

### 2.4 Why this difference matters

The class attribute is one list shared by every instance that has not replaced it. A mutation for one order appears in another order.

## 3. Boundaries and distinctions

Immutable class attributes and mutable state intentionally shared by all instances are valid class variables when that sharing is explicit.
