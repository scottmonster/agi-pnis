# Failing to resolve material ambiguity

## 1. Catalog record

- **Catalog identifier:** 1.8
- **Evidence:** a
- **Definition:** Makes a consequential assumption when repository inspection or a clarification was needed.

## 2. Scenario

### 2.1 Context

A request says to "archive" an organization. The repository has both a soft-delete `archivedAt` field and a permanent deletion job, but no task detail identifies which is intended.

### 2.2 Safer approach

Inspect callers, UI wording, and tests for the established meaning. If they do not resolve the difference, ask whether archiving should be reversible before changing data.

### 2.3 Failure mode

The agent assumes archive means permanent deletion and removes the organization and its related records.

### 2.4 Why this difference matters

An unresolved interpretation causes irreversible data loss where a reversible state change may have been intended.

## 3. Boundaries and distinctions

Routine details can be inferred from strong local conventions. Clarification is needed when plausible interpretations have materially different behavior, risk, or compatibility effects.
