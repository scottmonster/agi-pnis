# Unsafe deserialization or dynamic evaluation

## 1. Catalog record

- **Catalog identifier:** 10.11
- **Evidence:** e
- **Definition:** Reconstructs objects or evaluates code-like input from untrusted data, enabling unintended behavior or code execution.

## 2. Scenario

### 2.1 Context

An API accepts a saved filter definition from a browser client.

### 2.2 Safer approach

Parse a data-only format, validate it against a strict schema, and map the permitted fields to supported filter operations.

### 2.3 Failure mode

The agent evaluates the submitted filter text as an expression or deserializes it with a format that can instantiate arbitrary objects.

### 2.4 Why this difference matters

Input intended as a filter can run unintended behavior under the application’s authority.

## 3. Boundaries and distinctions

Dynamic evaluation may be acceptable only for code from a tightly controlled, authenticated build path. Untrusted request data requires a non-executable representation.
