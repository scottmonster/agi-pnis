# Public API/schema break without migration or versioning

## 1. Catalog record

- **Catalog identifier:** 11.11
- **Evidence:** se
- **Definition:** Removes or changes a published contract without a compatible transition path for consumers or stored data.

## 2. Scenario

### 2.1 Context

A public orders API returns a `status` string consumed by mobile clients and partner integrations.

### 2.2 Safer approach

The agent introduces the revised field through a versioned endpoint or compatible alias, documents the transition, and schedules consumer migration.

### 2.3 Failure mode

The agent replaces `status` with an integer `state_code` in place and deploys without a migration path.

### 2.4 Why this difference matters

Consumers and stored integrations fail at the system boundary, often outside the repository's immediate test coverage.

## 3. Boundaries and distinctions

Private, fully controlled contracts may allow coordinated changes; published APIs and stored schemas need a compatible transition or explicit versioning.
