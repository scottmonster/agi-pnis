# Environment conflict

## 1. Catalog record

- **Catalog identifier:** 2.9
- **Evidence:** e
- **Definition:** Assumes a different language, framework, compiler, runtime, OS, driver, or tool version.

## 2. Scenario

### 2.1 Context

An agent updates a Node service whose package configuration specifies Node 18.

### 2.2 Safer approach

It checks the engine and CI configuration, then writes syntax and APIs supported by Node 18.

### 2.3 Failure mode

It uses a runtime feature that requires Node 22 because it assumes the newest local runtime is the deployment target.

### 2.4 Why this difference matters

The change can pass locally but fail in CI or production under the repository's actual environment.

## 3. Boundaries and distinctions

This concerns the execution environment itself, not a missing project dependency within an otherwise matching environment.
