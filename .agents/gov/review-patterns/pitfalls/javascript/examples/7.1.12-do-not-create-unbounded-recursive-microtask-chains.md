# Do not create unbounded recursive microtask chains

## 1. Catalog record

- **Catalog identifier:** 7.1.12
- **Impact:** medium
- **Consensus:** high
- **Definition:** Use `queueMicrotask()` and promise continuations carefully when callbacks can continually enqueue more microtasks. Yield to tasks when other event-loop work must make progress.

## 2. Example

### 2.1 Scenario

A browser job processes items in batches without preventing timers, input, and rendering from running.

### 2.2 Preferred form

```javascript
function processBatches(items) {
  let index = 0;
  function nextBatch() {
    items.slice(index, index + 100).forEach((item) => console.log(item));
    index += 100;
    if (index < items.length) setTimeout(nextBatch, 0);
  }
  nextBatch();
}

processBatches(["a", "b", "c"]);
```

### 2.3 Hazardous form

```javascript
function keepWorking() {
  queueMicrotask(keepWorking);
}

setTimeout(() => console.log("timer ran"), 0);
keepWorking();
```

### 2.4 Why this difference matters

Each hazardous microtask schedules another before the event loop can advance to the timer, so other task work can starve indefinitely.

## 3. Boundaries and distinctions

A finite microtask sequence is useful for prompt follow-up work; yield to a task only when repeated scheduling could block other event-loop work.
