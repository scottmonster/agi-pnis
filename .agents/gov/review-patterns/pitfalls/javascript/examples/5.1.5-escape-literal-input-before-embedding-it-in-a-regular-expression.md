# Escape literal input before embedding it in a regular expression

## 1. Catalog record

- **Catalog identifier:** 5.1.5
- **Impact:** high
- **Consensus:** high
- **Definition:** When externally supplied text should be matched literally inside a dynamically constructed regular expression, use `RegExp.escape()` where supported rather than hand-written escaping.

## 2. Example

### 2.1 Scenario

A log viewer highlights an operator-provided literal search term.

### 2.2 Preferred form

```javascript
function hasLiteralTerm(logLine, term) {
  const pattern = new RegExp(RegExp.escape(term), "u");
  return pattern.test(logLine);
}

console.log(hasLiteralTerm("build version 1.2.3", "1.2.3")); // true
```

### 2.3 Hazardous form

```javascript
function hasLiteralTerm(logLine, term) {
  const pattern = new RegExp(term, "u");
  return pattern.test(logLine);
}

console.log(hasLiteralTerm("build version 1x2y3", "1.2.3")); // true, but unintended
```

### 2.4 Why this difference matters

The hazardous form gives characters such as `.` regular-expression meaning, so a literal search can match unrelated text.

## 3. Boundaries and distinctions

`RegExp.escape()` is for literal fragments embedded in a dynamic pattern, not for a complete pattern whose regular-expression syntax is deliberately authored. Confirm runtime support when targeting older environments.
