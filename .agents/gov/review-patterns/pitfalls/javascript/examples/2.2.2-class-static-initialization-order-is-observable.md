# Class static initialization order is observable

## 1. Catalog record

- **Catalog identifier:** 2.2.2
- **Impact:** low
- **Consensus:** high
- **Definition:** Respect declaration order when static initialization reads class fields.

## 2. Example

### 2.1 Scenario

A class derives a display label from a static prefix.

### 2.2 Preferred form

```javascript
class Metrics {
  static prefix = "metrics";
  static label = `${this.prefix}:requests`;
}

console.log(Metrics.label);
```

### 2.3 Hazardous form

```javascript
class Metrics {
  static label = `${this.prefix}:requests`;
  static prefix = "metrics";
}

console.log(Metrics.label);
```

### 2.4 Why this difference matters

Static fields run in source order, so the hazardous `label` reads `undefined` before `prefix` is initialized.

## 3. Boundaries and distinctions

Use a static method or a later initialization step when a value must be computed after several fields are established.
