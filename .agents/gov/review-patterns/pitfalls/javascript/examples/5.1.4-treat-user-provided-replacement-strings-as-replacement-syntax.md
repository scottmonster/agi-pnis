# Treat user-provided replacement strings as replacement syntax

## 1. Catalog record

- **Catalog identifier:** 5.1.4
- **Impact:** medium
- **Consensus:** high
- **Definition:** If arbitrary text must be inserted literally through `String.prototype.replace()`, remember that replacement strings interpret tokens such as `$&`, `$1`, and `$<name>`. A replacer function can return literal text without applying these replacement patterns.

## 2. Example

### 2.1 Scenario

A moderation tool replaces a selected word with an administrator-supplied label.

### 2.2 Preferred form

```javascript
function replaceLabel(message, label) {
  return message.replace("[label]", () => label);
}

console.log(replaceLabel("Status: [label]", "$& approved"));
// Status: $& approved
```

### 2.3 Hazardous form

```javascript
function replaceLabel(message, label) {
  return message.replace("[label]", label);
}

console.log(replaceLabel("Status: [label]", "$& approved"));
// Status: [label] approved
```

### 2.4 Why this difference matters

The hazardous form interprets replacement metasyntax, changing administrator or user data instead of inserting it literally.

## 3. Boundaries and distinctions

Replacement-string tokens are useful when substitution syntax is intentional. Use a string replacement only when its `$` semantics are part of the expected result.
