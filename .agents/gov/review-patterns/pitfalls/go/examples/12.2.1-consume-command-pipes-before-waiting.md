# Consume command pipes before waiting

## 1. Catalog record

- **Catalog identifier:** 12.2.1
- **Impact:** medium
- **Consensus:** high
- **Definition:** With `StdoutPipe` or `StderrPipe`, read the pipe to completion before calling `Wait`; do not call `Run` while separately trying to consume those pipe APIs.

## 2. Example

### 2.1 Scenario

A tool captures all output from a child process that can write more than an operating-system pipe buffer.

### 2.2 Preferred form

```go
package example

import (
	"io"
	"os/exec"
)

func listFiles() ([]byte, error) {
	cmd := exec.Command("find", ".", "-type", "f")
	stdout, err := cmd.StdoutPipe()
	if err != nil {
		return nil, err
	}
	if err := cmd.Start(); err != nil {
		return nil, err
	}

	output, readErr := io.ReadAll(stdout)
	waitErr := cmd.Wait()
	if readErr != nil {
		return nil, readErr
	}
	return output, waitErr
}
```

### 2.3 Hazardous form

```go
package example

import (
	"io"
	"os/exec"
)

func listFiles() ([]byte, error) {
	cmd := exec.Command("find", ".", "-type", "f")
	stdout, err := cmd.StdoutPipe()
	if err != nil {
		return nil, err
	}
	if err := cmd.Start(); err != nil {
		return nil, err
	}
	if err := cmd.Wait(); err != nil {
		return nil, err
	}
	return io.ReadAll(stdout)
}
```

### 2.4 Why this difference matters

If the child fills its stdout pipe, it blocks until the parent reads. Waiting first can therefore deadlock the parent and child, and `Wait` may close the pipe before later reads complete.

## 3. Boundaries and distinctions

This ordering applies to pipes returned by `StdoutPipe` and `StderrPipe`. Assigning `cmd.Stdout` to an ordinary writer uses a different ownership model.
