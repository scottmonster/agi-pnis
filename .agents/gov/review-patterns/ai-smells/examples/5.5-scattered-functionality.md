# Scattered functionality

## 1. Catalog record

- **Catalog identifier:** 5.5
- **Evidence:** e
- **Definition:** A single concern is fragmented across unrelated locations.

## 2. Scenario

### 2.1 Context

Timezone conversion rules are partly in an API route, a report formatter, a database helper, and a client utility.

### 2.2 Safer approach

Locate the common policy and give it one clearly owned implementation, with callers using that behavior.

### 2.3 Failure mode

Update daylight-saving handling in only the report formatter after searching there first.

### 2.4 Why this difference matters

The product can show contradictory times depending on which path a user takes.

## 3. Boundaries and distinctions

Concern-specific integration points can remain local. Scattering is the problem when one policy is split across unrelated places without a clear owner.
