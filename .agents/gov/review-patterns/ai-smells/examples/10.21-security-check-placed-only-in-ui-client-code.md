# Security check placed only in UI/client code

## 1. Catalog record

- **Catalog identifier:** 10.21
- **Evidence:** se
- **Definition:** Relies on a bypassable client-side control instead of enforcing the rule at the trusted server-side boundary.

## 2. Scenario

### 2.1 Context

The UI hides the Delete button from users without the administrator role.

### 2.2 Safer approach

Keep the UI control for usability, but enforce the administrator permission in the server endpoint that performs deletion.

### 2.3 Failure mode

The agent treats the hidden button as the authorization mechanism and leaves the delete endpoint callable by any signed-in user.

### 2.4 Why this difference matters

Users can bypass the interface and call the server endpoint directly.

## 3. Boundaries and distinctions

Client-side checks can improve user experience, but they are not a trusted boundary and cannot replace server-side authorization.
