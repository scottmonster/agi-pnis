# Remember that nil channels block forever

## 1. Catalog record

- **Catalog identifier:** 1.9.1
- **Impact:** high
- **Consensus:** high
- **Definition:** Sending to or receiving from a nil channel blocks forever. Deliberately use nil channels only when disabling a `select` case is intended.

## 2. Example

### 2.1 Scenario

A worker must send its result to a caller.

### 2.2 Preferred form

```go
package main

func result() <-chan int {
	out := make(chan int, 1)
	out <- 42
	close(out)
	return out
}
```

### 2.3 Hazardous form

```go
package main

func result() <-chan int {
	var out chan int
	go func() { out <- 42 }()
	return out
}
```

### 2.4 Why this difference matters

The hazardous send and any caller receive block forever because `out` is nil. Initializing the channel gives the operation a real synchronization path.

## 3. Boundaries and distinctions

Assigning a select case's channel to nil is a useful deliberate way to disable that case. It should not be an accidental zero-value channel used for communication.
