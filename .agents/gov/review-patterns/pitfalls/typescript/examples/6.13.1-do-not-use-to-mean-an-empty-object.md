# Do not use `{}` to mean an empty object

## 1. Catalog record

- **Catalog identifier:** 6.13.1
- **Impact:** medium
- **Consensus:** high
- **Definition:** `{}` means essentially any non-nullish value, including primitives; use a precise object shape, `object`, `unknown`, or another type matching the actual intent.

## 2. Example

### 2.1 Scenario

A report job has one optional, documented setting.

### 2.2 Preferred form

```typescript
type ReportOptions = { dryRun?: boolean };

function runReport(options: ReportOptions): string {
  return options.dryRun ? 'preview created' : 'report sent';
}

console.log(runReport({ dryRun: true }));
```

### 2.3 Hazardous form

```typescript
function runReport(options: {}): string {
  return 'report sent';
}

console.log(runReport('send immediately'));
// `{}` accepts non-nullish primitives, not just objects with no properties.
```

### 2.4 Why this difference matters

Treating `{}` as "object with no properties" creates unexpectedly broad APIs and constraints.

## 3. Boundaries and distinctions

Apply this guidance in the conditions described by the catalog record. Deliberate exceptions need a documented runtime guarantee, compatible toolchain behavior, or an explicit local unsafe boundary.
