# Premature interface/protocol

## 1. Catalog record

- **Catalog identifier:** 3.5
- **Evidence:** se
- **Definition:** Defines `FooRepository` plus exactly one `SqlFooRepository` without a genuine substitution boundary.

## 2. Scenario

### 2.1 Context

An application reads accounts from its only PostgreSQL database.

### 2.2 Safer approach

Inject the concrete account store where needed and test its observable behavior.

### 2.3 Failure mode

Create an `AccountRepository` protocol and one `PostgresAccountRepository` implementation solely for future swapping.

### 2.4 Why this difference matters

The extra contract adds indirection without an active alternative or ownership boundary.

## 3. Boundaries and distinctions

An interface helps when multiple real implementations or an isolation boundary exist; a hypothetical replacement does not require one.
