# Use defer or modules instead of parser-blocking classic scripts when appropriate

## 1. Catalog record

- **Catalog identifier:** 8.1.4
- **Impact:** medium
- **Consensus:** high
- **Definition:** Use defer or modules when a classic script need not block HTML parsing at its location.

## 2. Example

### 2.1 Scenario

A page script initializes an application element that appears later in the document.

### 2.2 Preferred form

```javascript
// index.html: <script defer src="app.js"></script>
// app.js
const app = document.querySelector("#app");
app.textContent = "Ready";
```

### 2.3 Hazardous form

```javascript
// index.html: <script src="app.js"></script>
// app.js
const app = document.querySelector("#app");
app.textContent = "Ready";
```

### 2.4 Why this difference matters

Without `defer`, a classic script in the document head blocks parsing and can run before the later `#app` element exists, producing a null access failure.

## 3. Boundaries and distinctions

A parser-blocking script can be intentional when later parsing must wait for it. Module scripts are deferred by default, subject to their own loading and evaluation behavior.
