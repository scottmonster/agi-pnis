# Large speculative patch before the first verification step

## 1. Catalog record

- **Catalog identifier:** 13.14
- **Evidence:** a
- **Definition:** Accumulates many unvalidated changes based on assumptions rather than testing the smallest plausible approach.

## 2. Scenario

### 2.1 Context

A flaky test suggests a date formatting mismatch between a service and its client.

### 2.2 Safer approach

The agent reproduces the failing case, identifies the serialization boundary, makes one focused formatting correction, and reruns the relevant test.

### 2.3 Failure mode

The agent rewrites date utilities, response types, fixtures, and several endpoints before running any test.

### 2.4 Why this difference matters

When the initial assumption is false, a large unvalidated patch obscures the cause and multiplies rollback work.

## 3. Boundaries and distinctions

Some changes necessarily span several files, but their key assumptions should be tested as early as practical rather than accumulated unchecked.
