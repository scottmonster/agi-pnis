# Feature implemented in one duplicated code path but not the others

## 1. Catalog record

- **Catalog identifier:** 11.17
- **Evidence:** se
- **Definition:** Updates only one equivalent implementation, causing behavior to vary by entry point or environment.

## 2. Scenario

### 2.1 Context

The web application and command-line importer each contain similar customer-address validation.

### 2.2 Safer approach

The agent locates both paths, updates both consistently, and adds coverage for web and import workflows or consolidates the shared behavior.

### 2.3 Failure mode

The agent adds postal-code validation only to the web form, leaving the importer to accept invalid addresses.

### 2.4 Why this difference matters

Equivalent workflows produce different data quality and users encounter inconsistent behavior by entry point.

## 3. Boundaries and distinctions

Separate paths may intentionally have different contracts; confirm that distinction before treating them as duplicated behavior requiring coordinated updates.
