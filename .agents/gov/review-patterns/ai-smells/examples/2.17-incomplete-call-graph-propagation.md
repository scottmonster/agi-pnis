# Incomplete call-graph propagation

## 1. Catalog record

- **Catalog identifier:** 2.17
- **Evidence:** e/a
- **Definition:** Changes a signature or contract without updating all consumers.

## 2. Scenario

### 2.1 Context

An agent changes `createInvoice(order)` so it now requires the requesting `actor` for auditing.

### 2.2 Safer approach

It finds every production caller, test helper, and adapter, then passes or derives the actor consistently and verifies the call graph.

### 2.3 Failure mode

It updates only the HTTP controller and leaves the scheduled billing job calling the old signature.

### 2.4 Why this difference matters

Some entry points fail or silently bypass the new contract, making system behavior depend on how the invoice was created.

## 3. Boundaries and distinctions

This applies to materially consumed contracts; private local changes with no other consumers do not require broader propagation.
