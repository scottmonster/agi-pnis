# Boolean and numeric keys colliding

## 1. Catalog record

- **Catalog identifier:** 6.19.1
- **Impact:** medium
- **Consensus:** high
- **Definition:** Do not use values such as `True`, `1`, and `1.0` as supposedly distinct dict or set keys when their semantic distinction matters.

## 2. Example

### 2.1 Scenario

A cache needs distinct identifiers for a boolean flag and a numeric account number.

### 2.2 Preferred form

```python
cache = {("enabled", True): "flag", ("account", 1): "account"}
print(len(cache))  # 2
```

### 2.3 Hazardous form

```python
cache = {True: "flag", 1: "account", 1.0: "decimal account"}
print(cache)  # {True: 'decimal account'}
```

### 2.4 Why this difference matters

`True`, `1`, and `1.0` compare equal and have compatible hashes, so hashed collections treat them as the same key.

## 3. Boundaries and distinctions

This behavior is useful when numeric equivalence is intended. Use tagged keys or separate mappings when the types carry different meanings.
