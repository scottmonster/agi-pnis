# Attacker-controlled second argument to `urljoin()`

## 1. Catalog record

- **Catalog identifier:** 2.14.1
- **Impact:** high
- **Consensus:** high
- **Definition:** Do not use `urljoin(base, attacker_value)` and assume the result remains under `base`. Validate or constrain the second value first.

## 2. Example

### 2.1 Scenario

An application builds a profile link under its own site from a user-supplied path segment.

### 2.2 Preferred form

```python
from urllib.parse import urljoin, urlsplit


def profile_url(user_path: str) -> str:
    parts = urlsplit(user_path)
    if parts.scheme or parts.netloc or user_path.startswith("/"):
        raise ValueError("profile path must be relative")
    return urljoin("https://example.test/profiles/", user_path)
```

### 2.3 Hazardous form

```python
from urllib.parse import urljoin


def profile_url(user_path: str) -> str:
    return urljoin("https://example.test/profiles/", user_path)
```

### 2.4 Why this difference matters

An absolute second argument can replace the base scheme and host, turning an internal-looking link into an attacker-controlled destination.

## 3. Boundaries and distinctions

`urljoin()` is correct when replacement by an absolute reference is intended. Validate input only when the result must remain under a trusted base.
