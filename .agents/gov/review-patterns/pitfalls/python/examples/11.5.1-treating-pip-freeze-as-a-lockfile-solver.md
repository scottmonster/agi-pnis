# Treating `pip freeze` as a lockfile solver

## 1. Catalog record

- **Catalog identifier:** 11.5.1
- **Impact:** medium
- **Consensus:** high
- **Definition:** Use `pip freeze` as a report of an environment's installed state, not as proof that a dependency set was independently solved or securely locked.

## 2. Example

### 2.1 Scenario

A team wants a repeatable dependency set for a production deployment.

### 2.2 Preferred form

```python
# Keep declared inputs and a resolver-produced, reviewed lock artifact.
declared_dependency = "httpx>=0.27"
resolved_dependency = "httpx==0.27.2"

print(declared_dependency, resolved_dependency)
```

### 2.3 Hazardous form

```python
# pip freeze > requirements.txt
environment_report = "httpx==0.27.2"

print(environment_report)
```

### 2.4 Why this difference matters

`pip freeze` reports what happened to be installed in one environment. It does not independently resolve a declared dependency graph or establish the security properties of a reviewed lock.

## 3. Boundaries and distinctions

Freeze output can be useful for diagnostics, reproducing a known environment, or auditing. Treat it as an observation, not as a dependency solver result.
