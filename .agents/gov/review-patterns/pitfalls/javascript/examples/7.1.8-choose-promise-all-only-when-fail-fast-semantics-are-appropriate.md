# Choose Promise.all only when fail-fast semantics are appropriate

## 1. Catalog record

- **Catalog identifier:** 7.1.8
- **Impact:** medium
- **Consensus:** high
- **Definition:** Use `Promise.all()` when all operations must succeed and an early rejection should reject the aggregate. Use `Promise.allSettled()` when every outcome must be observed.

## 2. Example

### 2.1 Scenario

A diagnostics screen needs to show the outcome from each independent health check.

### 2.2 Preferred form

```javascript
function check(name, succeeds) {
  return succeeds ? Promise.resolve(`${name}: ok`) : Promise.reject(new Error(`${name}: down`));
}

async function collectHealth() {
  const results = await Promise.allSettled([check("api", true), check("mail", false)]);
  return results.map((result) => result.status);
}

collectHealth().then(console.log, console.error);
```

### 2.3 Hazardous form

```javascript
function check(name, succeeds) {
  return succeeds ? Promise.resolve(`${name}: ok`) : Promise.reject(new Error(`${name}: down`));
}

async function collectHealth() {
  const results = await Promise.all([check("api", true), check("mail", false)]);
  return results.map((result) => result);
}

collectHealth().then(console.log, console.error);
```

### 2.4 Why this difference matters

Promise.all rejects as soon as one check fails, so the hazardous form does not provide a complete set of observed outcomes.

## 3. Boundaries and distinctions

Use Promise.all when every operation is required and one failure should make the aggregate unusable.
