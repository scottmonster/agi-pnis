# Do not use instanceof for cross-realm Array detection

## 1. Catalog record

- **Catalog identifier:** 2.15.1
- **Impact:** medium
- **Consensus:** high
- **Definition:** Use `Array.isArray()` when arrays can originate in another realm.

## 2. Example

### 2.1 Scenario

A browser receives an array from an iframe.

### 2.2 Preferred form

```javascript
function acceptsArray(value) {
  return Array.isArray(value);
}

const frame = document.createElement("iframe");
document.body.append(frame);
const foreignArray = frame.contentWindow.Array.of("item");
console.log(acceptsArray(foreignArray));
```

### 2.3 Hazardous form

```javascript
function acceptsArray(value) {
  return value instanceof Array;
}

const frame = document.createElement("iframe");
document.body.append(frame);
const foreignArray = frame.contentWindow.Array.of("item");
console.log(acceptsArray(foreignArray));
```

### 2.4 Why this difference matters

An iframe has its own `Array` constructor, so its arrays can fail an `instanceof Array` test in the parent realm.

## 3. Boundaries and distinctions

`instanceof` remains useful for realm-local class instances when testing a particular constructor relationship is the goal.
