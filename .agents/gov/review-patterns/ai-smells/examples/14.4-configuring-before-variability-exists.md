# Configuring before variability exists

## 1. Catalog record

- **Catalog identifier:** 14.4
- **Evidence:** a
- **Definition:** Flags/options exist before there are real alternative behaviors.

## 2. Scenario

### 2.1 Context

A notification job has one approved delivery behavior: send a daily summary at 09:00 UTC.

### 2.2 Safer approach

The agent encodes the approved behavior plainly and introduces configuration only when a supported alternative is identified.

### 2.3 Failure mode

It adds environment variables for schedule, timezone, batching, retry policy, channel selection, and template mode, although no consumer needs alternatives.

### 2.4 Why this difference matters

Unused options expand testing and documentation obligations, imply unsupported contracts, and make behavior less predictable.

## 3. Boundaries and distinctions

Configuration is appropriate when deployments or users genuinely require supported variation. A possible future preference alone does not establish that variability.
