# Naive UTC datetimes

## 1. Catalog record

- **Catalog identifier:** 7.4.1
- **Impact:** medium
- **Consensus:** high
- **Definition:** Prefer timezone-aware UTC values such as `datetime.now(UTC)` and `datetime.fromtimestamp(ts, UTC)` rather than `utcnow()` or `utcfromtimestamp()`.

## 2. Example

### 2.1 Scenario

An event timestamp is emitted for exchange between systems.

### 2.2 Preferred form

```python
from datetime import UTC, datetime

created_at = datetime.now(UTC)
print(created_at.isoformat())
```

### 2.3 Hazardous form

```python
from datetime import datetime

created_at = datetime.utcnow()
print(created_at.isoformat())
```

### 2.4 Why this difference matters

The hazardous value is naive, so later code can misinterpret it as local time or combine it incorrectly with aware timestamps.

## 3. Boundaries and distinctions

Naive datetimes may be suitable for deliberately timezone-free civil times. Use aware values for instants and cross-system timestamps.
