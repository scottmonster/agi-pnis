# Assuming an import name identifies the package to install

## 1. Catalog record

- **Catalog identifier:** 5.2.1
- **Impact:** high
- **Consensus:** high
- **Definition:** Do not automatically derive `pip install <name>` from an unknown `import <name>`. Verify the intended distribution package.

## 2. Example

### 2.1 Scenario

A dependency is documented as `import yaml`, and a developer must add the correct distribution to project metadata.

### 2.2 Preferred form

```python
distribution_name = "PyYAML"
import_name = "yaml"

assert distribution_name != import_name
```

### 2.3 Hazardous form

```python
missing_import = "yaml"
suggested_requirement = missing_import

print(f"pip install {suggested_requirement}")
```

### 2.4 Why this difference matters

Distribution names and import names are separate namespaces. Guessing from an import can select the wrong project or introduce a supply-chain risk.

## 3. Boundaries and distinctions

Some projects intentionally use identical names, but dependency declarations should still come from verified project documentation or trusted package metadata.
