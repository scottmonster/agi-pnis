# Use `os.Root` for untrusted paths inside a trusted directory

## 1. Catalog record

- **Catalog identifier:** 4.4.1
- **Impact:** high
- **Consensus:** high
- **Definition:** When an external filename must remain below a fixed directory, prefer `os.Root` or `os.OpenInRoot` to validating a joined path and opening it later.

## 2. Example

### 2.1 Scenario

A download endpoint opens a file selected by a request path, but files must remain under its upload directory.

### 2.2 Preferred form

```go
package example

import "os"

func openUpload(uploadDir, requestName string) (*os.File, error) {
	root, err := os.OpenRoot(uploadDir)
	if err != nil {
		return nil, err
	}
	defer root.Close()
	return root.Open(requestName)
}
```

### 2.3 Hazardous form

```go
package example

import (
	"os"
	"path/filepath"
)

func openUpload(uploadDir, requestName string) (*os.File, error) {
	path := filepath.Join(uploadDir, requestName)
	return os.Open(path)
}
```

### 2.4 Why this difference matters

`os.Root` resolves the untrusted name relative to the trusted directory while enforcing containment. Joining a path before opening it can permit traversal or symlink races that escape the intended directory.

## 3. Boundaries and distinctions

`os.Root` is for a trusted root plus an untrusted relative path. For a path that is entirely application-controlled, ordinary filesystem operations may be clearer; availability depends on the Go version supported by the program.
