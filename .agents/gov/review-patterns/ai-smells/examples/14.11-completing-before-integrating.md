# Completing before integrating

## 1. Catalog record

- **Catalog identifier:** 14.11
- **Evidence:** a
- **Definition:** A local implementation is declared finished without checking callers, tests, schemas, docs, dependencies, and compatibility.

## 2. Scenario

### 2.1 Context

An agent renames a configuration property in the service implementation and the local unit test for that class passes.

### 2.2 Safer approach

It searches callers and configuration samples, updates the schema and documentation as needed, checks compatibility, and runs affected integration tests.

### 2.3 Failure mode

It stops after the local test passes and declares completion without checking deployment manifests, callers, generated schema, or public configuration guidance.

### 2.4 Why this difference matters

The isolated edit can break consumers or operational setup even though its immediate code path appears complete.

## 3. Boundaries and distinctions

The integration surface depends on the change. A private implementation detail may need a small check, while a public contract may require broad compatibility review.
