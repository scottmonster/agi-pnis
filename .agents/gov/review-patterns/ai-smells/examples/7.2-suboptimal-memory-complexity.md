# Suboptimal memory complexity

## 1. Catalog record

- **Catalog identifier:** 7.2
- **Evidence:** e
- **Definition:** Retains more data than necessary, causing memory use to grow unnecessarily with the input.

## 2. Scenario

### 2.1 Context

An agent adds an import job that computes the count of valid rows in a large CSV upload.

### 2.2 Safer approach

It reads rows incrementally and keeps only the running count and the state needed for validation.

### 2.3 Failure mode

It parses every row into an in-memory array before counting the valid ones.

### 2.4 Why this difference matters

Large uploads can exhaust memory even though the final result is only a count.

## 3. Boundaries and distinctions

Retaining the full dataset can be justified when later processing genuinely requires random access; the issue is retaining data that the task does not need.
