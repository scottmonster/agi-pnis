# Generating before verifying

## 1. Catalog record

- **Catalog identifier:** 14.10
- **Evidence:** a
- **Definition:** Plausibility is mistaken for correctness.

## 2. Scenario

### 2.1 Context

An agent changes a database migration and produces SQL that looks consistent with nearby migrations.

### 2.2 Safer approach

It reviews the generated SQL, applies it to an appropriate disposable database, and verifies the resulting schema and rollback behavior where applicable.

### 2.3 Failure mode

It treats the generated migration as correct because the syntax looks familiar and reports the task complete without executing or inspecting it.

### 2.4 Why this difference matters

Plausible output can contain incorrect identifiers, unsafe transformations, or incompatible assumptions that only verification exposes.

## 3. Boundaries and distinctions

Verification should match the change and environment. It can be static inspection, targeted tests, or a controlled execution, but generated output alone is not proof.
