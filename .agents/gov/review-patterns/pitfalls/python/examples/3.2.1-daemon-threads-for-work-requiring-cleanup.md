# Daemon threads for work requiring cleanup

## 1. Catalog record

- **Catalog identifier:** 3.2.1
- **Impact:** high
- **Consensus:** high
- **Definition:** Do not put essential cleanup, transactional, or persistent work exclusively in daemon threads. Prefer non-daemon threads with an explicit shutdown signal and join.

## 2. Example

### 2.1 Scenario

A background writer persists audit records before the process exits. Every accepted record must be flushed deliberately.

### 2.2 Preferred form

```python
from queue import Empty, Queue
from threading import Event, Thread


def write_records(records: Queue[str], stop: Event) -> None:
    with open("audit.log", "a", encoding="utf-8") as log:
        while not stop.is_set() or not records.empty():
            try:
                record = records.get(timeout=0.1)
            except Empty:
                continue
            log.write(record + "\n")
            records.task_done()


records: Queue[str] = Queue()
stop = Event()
writer = Thread(target=write_records, args=(records, stop), daemon=False)
writer.start()
records.put("account-created")
records.join()
stop.set()
writer.join()
```

### 2.3 Hazardous form

```python
from queue import Queue
from threading import Thread


def write_records(records: Queue[str]) -> None:
    with open("audit.log", "a", encoding="utf-8") as log:
        while True:
            log.write(records.get() + "\n")


records: Queue[str] = Queue()
Thread(target=write_records, args=(records,), daemon=True).start()
records.put("account-created")
```

### 2.4 Why this difference matters

Daemon threads can be stopped abruptly during interpreter shutdown, so the hazardous form may lose buffered records or skip required cleanup.

## 3. Boundaries and distinctions

Daemon threads are reasonable for optional work that can safely disappear at exit. Essential work needs a defined shutdown and completion path.
