# Remember that `case` operands are patterns

## 1. Catalog record

- **Catalog identifier:** 5.9.1
- **Impact:** medium
- **Consensus:** high
- **Definition:** An expanded value in a `case` pattern position remains pattern syntax unless quoted appropriately. Quote an expansion when its content should be matched literally.

## 2. Example

### 2.1 Scenario

A command dispatcher accepts one configured command name, which may contain characters that are meaningful to shell patterns.

### 2.2 Preferred form

```bash
allowed_command='report*'
requested_command=${1:-report-private}

case $requested_command in
  "$allowed_command") printf 'running configured command\n' ;;
  *) printf 'command not allowed\n' >&2; exit 1 ;;
esac
```

### 2.3 Hazardous form

```bash
allowed_command='report*'
requested_command=${1:-report-private}

case $requested_command in
  $allowed_command) printf 'running configured command\n' ;;
  *) printf 'command not allowed\n' >&2; exit 1 ;;
esac
```

### 2.4 Why this difference matters

In the hazardous form, the configured `*` broadens the pattern and allows `report-private`, even though that string is not literally equal to `report*`.

## 3. Boundaries and distinctions

Unquoted `case` patterns are correct when wildcard matching is the intended feature. Quote variable expansions only when their contents are data to match exactly.
