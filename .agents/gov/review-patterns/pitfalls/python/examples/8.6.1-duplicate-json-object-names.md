# Duplicate JSON object names

## 1. Catalog record

- **Catalog identifier:** 8.6.1
- **Impact:** medium
- **Consensus:** high
- **Definition:** Do not assume the default JSON decoder rejects duplicate object member names. Use `object_pairs_hook` or external validation when duplicates must be detected.

## 2. Example

### 2.1 Scenario

An authorization payload must reject duplicate field names rather than silently accepting one value.

### 2.2 Preferred form

```python
import json

def reject_duplicates(pairs: list[tuple[str, object]]) -> dict[str, object]:
    result: dict[str, object] = {}
    for key, value in pairs:
        if key in result:
            raise ValueError(f"duplicate JSON name: {key}")
        result[key] = value
    return result

json.loads('{"role": "user", "role": "admin"}', object_pairs_hook=reject_duplicates)
```

### 2.3 Hazardous form

```python
import json

payload = json.loads('{"role": "user", "role": "admin"}')

assert payload == {"role": "admin"}
```

### 2.4 Why this difference matters

The default decoder retains the final occurrence, allowing ambiguous input to be interpreted differently by different systems.

## 3. Boundaries and distinctions

Duplicate detection is most important when duplicate names affect validation, authorization, signatures, or interoperability.
