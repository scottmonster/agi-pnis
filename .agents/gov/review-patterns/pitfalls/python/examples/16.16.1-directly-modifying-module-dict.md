# Directly modifying module `__dict__`

## 1. Catalog record

- **Catalog identifier:** 16.16.1
- **Impact:** low
- **Consensus:** high
- **Definition:** Prefer ordinary attribute assignment and supported APIs over direct mutation of a module's `__dict__` unless low-level introspection is intentionally required.

## 2. Example

### 2.1 Scenario

An application module records the version currently loaded by its startup routine.

### 2.2 Preferred form

```python
import sys


module = sys.modules[__name__]
module.loaded_version = "2.4"
print(module.loaded_version)
```

### 2.3 Hazardous form

```python
import sys


module = sys.modules[__name__]
module.__dict__["loaded_version"] = "2.4"
print(module.__dict__["loaded_version"])
```

### 2.4 Why this difference matters

Direct symbol-table mutation is a low-level mechanism that obscures ordinary attribute updates and can make tooling and maintenance harder to reason about.

## 3. Boundaries and distinctions

Intentional framework or introspection code may need a module dictionary. Ordinary program state should use normal names, attributes, or a dedicated configuration object.
