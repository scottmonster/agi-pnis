# Quote trap bodies for the intended expansion time

## 1. Catalog record

- **Catalog identifier:** 8.3.1
- **Impact:** medium
- **Consensus:** high
- **Definition:** A double-quoted trap body can expand variables or substitutions when `trap` is installed, so single-quote it when expansion should occur at the signal or exit event.

## 2. Example

### 2.1 Scenario

A script creates a temporary file after installing its cleanup handler.

### 2.2 Preferred form

```bash
tmp_file=''
trap '[[ -n $tmp_file ]] && rm -f -- "$tmp_file"' EXIT

tmp_file=$(mktemp)
printf 'work\n' >"$tmp_file"
```

### 2.3 Hazardous form

```bash
tmp_file=''
trap "[[ -n $tmp_file ]] && rm -f -- \"$tmp_file\"" EXIT

tmp_file=$(mktemp)
printf 'work\n' >"$tmp_file"
```

### 2.4 Why this difference matters

The hazardous handler captures the empty value present at installation time, so it does not remove the file created later. Single quotes defer expansion until the EXIT trap runs.

## 3. Boundaries and distinctions

Double quotes are appropriate only when intentionally capturing a value at trap installation. Validate any later-expanded values before using them in cleanup commands.
