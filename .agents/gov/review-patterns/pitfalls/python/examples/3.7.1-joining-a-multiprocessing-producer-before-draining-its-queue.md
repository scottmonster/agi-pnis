# Joining a multiprocessing producer before draining its queue

## 1. Catalog record

- **Catalog identifier:** 3.7.1
- **Impact:** high
- **Consensus:** high
- **Definition:** Ensure queued data is consumed before joining a process that has written substantial data to a multiprocessing queue.

## 2. Example

### 2.1 Scenario

A worker sends a large report through a multiprocessing queue. The parent must read the report without creating a pipe-buffer deadlock.

### 2.2 Preferred form

```python
from multiprocessing import Process, Queue


def produce_report(results: Queue[str]) -> None:
    results.put("x" * 1_000_000)


if __name__ == "__main__":
    results: Queue[str] = Queue()
    process = Process(target=produce_report, args=(results,))
    process.start()
    report = results.get()
    process.join()
    print(len(report))
```

### 2.3 Hazardous form

```python
from multiprocessing import Process, Queue


def produce_report(results: Queue[str]) -> None:
    results.put("x" * 1_000_000)


if __name__ == "__main__":
    results: Queue[str] = Queue()
    process = Process(target=produce_report, args=(results,))
    process.start()
    process.join()
    report = results.get()
    print(len(report))
```

### 2.4 Why this difference matters

The producer can remain alive while its queue feeder waits for the parent to drain buffered data. Joining first can therefore wait forever.

## 3. Boundaries and distinctions

Small messages may not expose the problem because they fit in available buffers. Code that can send substantial data should establish the correct drain-before-join order.
