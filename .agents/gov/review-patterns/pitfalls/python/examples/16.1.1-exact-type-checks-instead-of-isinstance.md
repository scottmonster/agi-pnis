# Exact type checks instead of `isinstance()`

## 1. Catalog record

- **Catalog identifier:** 16.1.1
- **Impact:** low
- **Consensus:** high
- **Definition:** Prefer `isinstance(obj, Type)` to `type(obj) is Type` when subclasses should satisfy the interface.

## 2. Example

### 2.1 Scenario

A formatter accepts text strings, including a custom string subclass that carries source metadata.

### 2.2 Preferred form

```python
class TaggedText(str):
    pass


def format_label(value: object) -> str:
    if isinstance(value, str):
        return value.upper()
    raise TypeError("expected text")
```

### 2.3 Hazardous form

```python
class TaggedText(str):
    pass


def format_label(value: object) -> str:
    if type(value) is str:
        return value.upper()
    raise TypeError("expected text")
```

### 2.4 Why this difference matters

The exact check rejects `TaggedText` even though it has the string interface the formatter needs. `isinstance()` honors normal subtype substitution.

## 3. Boundaries and distinctions

Use an exact type check when behavior genuinely depends on excluding subclasses. Prefer protocols or duck typing when an interface, rather than inheritance, is the actual contract.
