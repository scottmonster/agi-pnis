# Remember that `((i++))` can return failure

## 1. Catalog record

- **Catalog identifier:** 5.6.1
- **Impact:** medium
- **Consensus:** high
- **Definition:** Arithmetic commands return success when the resulting expression value is nonzero. Consequently `((i++))` returns status 1 when `i` was initially zero. Use a form such as `((++i))` when that status distinction matters, or otherwise neutralize the status deliberately.

## 2. Example

### 2.1 Scenario

A strict-mode script increments a completed-job counter before it records progress.

### 2.2 Preferred form

```bash
set -e

completed=0
((++completed))
printf 'completed jobs: %d\n' "$completed"
```

### 2.3 Hazardous form

```bash
set -e

completed=0
((completed++))
printf 'completed jobs: %d\n' "$completed"
```

### 2.4 Why this difference matters

The post-increment expression evaluates to the old value, zero, and therefore returns status 1. Under `set -e`, Bash exits before printing the progress message even though the counter was incremented.

## 3. Boundaries and distinctions

`((i++))` is fine where its status is ignored or deliberately handled. The risk arises when command status drives error handling or control flow.
