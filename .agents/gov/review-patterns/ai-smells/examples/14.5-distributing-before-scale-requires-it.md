# Distributing before scale requires it

## 1. Catalog record

- **Catalog identifier:** 14.5
- **Evidence:** a
- **Definition:** Async, queues, workers, microservices, caches, and coordination precede actual load or operational constraints.

## 2. Scenario

### 2.1 Context

An internal report takes two seconds and is requested a few times each day by a single team.

### 2.2 Safer approach

The agent keeps report generation in the application request path, records its runtime, and defines a threshold for revisiting the design.

### 2.3 Failure mode

It adds a queue, worker deployment, status polling endpoint, Redis coordination, and result cache without evidence that the current path exceeds a load or operational limit.

### 2.4 Why this difference matters

The distributed design creates failure modes involving jobs, retries, state, and observability that the modest workload did not require.

## 3. Boundaries and distinctions

Long-running work, service-level requirements, or known concurrency limits may require distribution immediately. The failure is applying it before such constraints are present.
