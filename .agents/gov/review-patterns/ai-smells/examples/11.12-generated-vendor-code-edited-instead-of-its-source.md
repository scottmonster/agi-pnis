# Generated/vendor code edited instead of its source

## 1. Catalog record

- **Catalog identifier:** 11.12
- **Evidence:** se
- **Definition:** Modifies derived or third-party files that will be overwritten or cannot be maintained through the owning source.

## 2. Scenario

### 2.1 Context

A generated API client mishandles a response field after its OpenAPI specification changes.

### 2.2 Safer approach

The agent updates the specification or generator configuration, regenerates the client, and records the generated output according to repository practice.

### 2.3 Failure mode

The agent edits the generated client method directly without changing the specification.

### 2.4 Why this difference matters

The next regeneration discards the fix, and future maintainers cannot identify the true source of behavior.

## 3. Boundaries and distinctions

Direct modification may be appropriate for deliberately maintained forks with documented ownership; ordinarily, derived output must be changed through its source.
