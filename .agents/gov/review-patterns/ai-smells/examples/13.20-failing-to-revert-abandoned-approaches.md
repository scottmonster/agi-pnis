# Failing to revert abandoned approaches

## 1. Catalog record

- **Catalog identifier:** 13.20
- **Evidence:** a
- **Definition:** Leaves superseded patches, flags, helpers, or configuration after changing course.

## 2. Scenario

### 2.1 Context

An agent first adds a feature flag for a cache, then learns the issue is a missing database index and switches to the index fix.

### 2.2 Safer approach

The agent removes the unused cache flag, helper, and configuration before delivering the focused migration.

### 2.3 Failure mode

The agent ships the index migration together with the now-unused cache setting and dead helper code.

### 2.4 Why this difference matters

Abandoned paths become maintenance debt and suggest behavior or support obligations that do not exist.

## 3. Boundaries and distinctions

Retaining an alternate path can be intentional during a planned migration. It should have a current purpose, ownership, and explicit transition plan.
