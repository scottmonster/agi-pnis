# Assuming mutable generic containers are covariant

## 1. Catalog record

- **Catalog identifier:** 11.6.1
- **Impact:** medium
- **Consensus:** high
- **Definition:** Do not treat `list[Derived]` as `list[Base]`. Use a read-only abstraction such as `Sequence[Base]` where covariance is actually safe.

## 2. Example

### 2.1 Scenario

A function reads labels from specialized report objects without needing to modify the caller's collection.

### 2.2 Preferred form

```python
from collections.abc import Sequence

class Report:
    def label(self) -> str:
        return "report"

class SalesReport(Report):
    pass

def labels(reports: Sequence[Report]) -> list[str]:
    return [report.label() for report in reports]

print(labels([SalesReport()]))
```

### 2.3 Hazardous form

```python
class Report:
    def label(self) -> str:
        return "report"

class SalesReport(Report):
    pass

def append_generic_report(reports: list[Report]) -> None:
    reports.append(Report())

sales_reports: list[SalesReport] = [SalesReport()]
append_generic_report(sales_reports)
```

### 2.4 Why this difference matters

If `list[SalesReport]` were accepted as `list[Report]`, the function could insert a plain `Report`, violating the caller's narrower collection type.

## 3. Boundaries and distinctions

Covariance is safe for read-only interfaces such as `Sequence`. Use invariant mutable containers when code can add, replace, or remove values.
