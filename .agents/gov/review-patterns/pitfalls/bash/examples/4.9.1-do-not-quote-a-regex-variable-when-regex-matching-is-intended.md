# Do not quote a regex variable when regex matching is intended

## 1. Catalog record

- **Catalog identifier:** 4.9.1
- **Impact:** medium
- **Consensus:** high
- **Definition:** Use a deliberately defined regex variable unquoted with `=~`; quoting it makes it literal.

## 2. Example

### 2.1 Scenario

A validator accepts dates in `YYYY-MM` format using a deliberately defined regular expression.

### 2.2 Preferred form

```bash
#!/usr/bin/env bash

date_value=${1:?provide a date}
pattern='^[0-9]{4}-[0-9]{2}$'
if [[ $date_value =~ $pattern ]]; then
  printf 'valid date\n'
fi
```

### 2.3 Hazardous form

```bash
#!/usr/bin/env bash

date_value=${1:?provide a date}
pattern='^[0-9]{4}-[0-9]{2}$'
if [[ $date_value =~ "$pattern" ]]; then
  printf 'valid date\n'
fi
```

### 2.4 Why this difference matters

Quoting the regex expansion makes the quoted expression literal. A valid date then fails to match because Bash looks for the punctuation characters of the pattern itself.

## 3. Boundaries and distinctions

Use an unquoted regex variable only when it is intentionally an extended regular expression. Treat untrusted pattern text as a separate validation concern.
