# Command/visitor/state pattern without corresponding complexity

## 1. Catalog record

- **Catalog identifier:** 3.10
- **Evidence:** se
- **Definition:** Pattern ceremony exceeds the problem being represented.

## 2. Scenario

### 2.1 Context

A document can be either draft or published and has two allowed actions.

### 2.2 Safer approach

Represent the state directly and use explicit transition checks.

### 2.3 Failure mode

Introduce commands, visitors, state objects, and dispatch infrastructure for the two transitions.

### 2.4 Why this difference matters

The pattern vocabulary and files dominate a problem that readers could otherwise understand at a glance.

## 3. Boundaries and distinctions

These patterns can clarify rich, changing behavior; the failure occurs when their ceremony has no corresponding complexity to manage.
