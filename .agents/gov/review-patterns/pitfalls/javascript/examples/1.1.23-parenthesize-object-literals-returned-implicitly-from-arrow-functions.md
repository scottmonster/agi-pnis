# Parenthesize object literals returned implicitly from arrow functions

## 1. Catalog record

- **Catalog identifier:** 1.1.23
- **Impact:** low
- **Consensus:** high
- **Definition:** Write `x => ({ value: x })`, not `x => { value: x }`, when an expression-bodied arrow should return an object literal.

## 2. Example

### 2.1 Scenario

A mapper creates a product summary object for each numeric identifier.

### 2.2 Preferred form

```javascript
const toSummary = (id) => ({ id, label: `product-${id}` });

console.log(toSummary(7));
```

### 2.3 Hazardous form

```javascript
const toSummary = (id) => { id: id };

console.log(toSummary(7));
```

### 2.4 Why this difference matters

The braces in the hazardous form create a function body, not an object literal. The apparent properties are parsed as statements and the function returns `undefined`.

## 3. Boundaries and distinctions

Use a block body with an explicit `return` when the arrow needs multiple statements. Parentheses are needed only for an implicit object return.
