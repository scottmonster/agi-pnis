# Preserve conventional initialism capitalization

## 1. Catalog record

- **Catalog identifier:** 13.8.1
- **Impact:** low
- **Consensus:** high
- **Definition:** Write conventional initialisms consistently, such as `URL`, `HTTP`, and `ID`, rather than forms such as `Url`, `Http`, and `Id`.

## 2. Example

### 2.1 Scenario

A client type exposes a URL and an account ID as part of its public API.

### 2.2 Preferred form

```go
package example

type Client struct {
	BaseURL string
	AccountID string
}
```

### 2.3 Hazardous form

```go
package example

type Client struct {
	BaseUrl string
	AccountId string
}
```

### 2.4 Why this difference matters

The conventional spelling makes exported identifiers predictable to Go readers and keeps related APIs searchable. Mixed capitalization creates needless inconsistency in documentation and call sites.

## 3. Boundaries and distinctions

Preserve an established public API spelling for compatibility. Apply conventional capitalization to new identifiers and coordinated breaking-change releases.
