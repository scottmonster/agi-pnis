# Depending on set iteration order

## 1. Catalog record

- **Catalog identifier:** 16.8.1
- **Impact:** low
- **Consensus:** high
- **Definition:** Explicitly sort or otherwise impose order when deterministic set traversal is part of a contract.

## 2. Example

### 2.1 Scenario

A reporting function emits enabled feature names for an audit file. The file must be reproducible across program runs.

### 2.2 Preferred form

```python
def render_features(features: set[str]) -> str:
    return ",".join(sorted(features))


print(render_features({"export", "search", "billing"}))
```

### 2.3 Hazardous form

```python
def render_features(features: set[str]) -> str:
    return ",".join(features)


print(render_features({"export", "search", "billing"}))
```

### 2.4 Why this difference matters

Set traversal order is not a stable cross-run contract, so the hazardous version can change audit output and create noisy diffs.

## 3. Boundaries and distinctions

Sorting is needed only when order is observable or contractual. A set remains appropriate when membership and uniqueness, rather than presentation order, are the concern.
