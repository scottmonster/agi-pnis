# Persisting or interpreting `id()` as a permanent object identifier

## 1. Catalog record

- **Catalog identifier:** 16.10.1
- **Impact:** low
- **Consensus:** high
- **Definition:** Use `id()` only for identity during an object's lifetime, not as a durable or globally unique identifier.

## 2. Example

### 2.1 Scenario

A service needs an identifier to store a customer record and retrieve it in a later process.

### 2.2 Preferred form

```python
from dataclasses import dataclass
from uuid import UUID, uuid4


@dataclass
class Customer:
    customer_id: UUID
    name: str


customer = Customer(customer_id=uuid4(), name="Mina")
stored_key = str(customer.customer_id)
print(stored_key)
```

### 2.3 Hazardous form

```python
from dataclasses import dataclass


@dataclass
class Customer:
    name: str


customer = Customer(name="Mina")
stored_key = id(customer)
print(stored_key)
```

### 2.4 Why this difference matters

An object ID identifies an object only while it exists. After destruction, Python can reuse that numeric value, and another process has unrelated IDs.

## 3. Boundaries and distinctions

`id()` is useful for short-lived in-process identity diagnostics. It is not a database key, network identifier, or persistent reference.
