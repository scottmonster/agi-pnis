# Avoid accidental duplicate enum values

## 1. Catalog record

- **Catalog identifier:** 10.7.2
- **Impact:** low
- **Consensus:** high
- **Definition:** Give different enum members different values unless aliases are intentional and documented.

## 2. Example

### 2.1 Scenario

A connection monitor chooses a message for each lifecycle event.

### 2.2 Preferred form

```typescript
enum ConnectionEvent {
  Connected = "connected",
  Reconnected = "reconnected",
  Disconnected = "disconnected",
}

function messageFor(event: ConnectionEvent): string {
  return event === ConnectionEvent.Reconnected ? "Connection restored" : "Connection changed";
}
```

### 2.3 Hazardous form

```typescript
enum ConnectionEvent {
  Connected = "connected",
  Reconnected = "connected",
  Disconnected = "disconnected",
}

function messageFor(event: ConnectionEvent): string {
  return event === ConnectionEvent.Connected ? "First connection" : "Connection changed";
}

messageFor(ConnectionEvent.Reconnected); // "First connection"
```

### 2.4 Why this difference matters

Equality cannot distinguish members that share a value. That can silently route a reconnect through first-connection behavior and makes reverse interpretation ambiguous.

## 3. Boundaries and distinctions

An alias is valid when two names deliberately mean the same protocol value. Make the alias explicit in documentation and avoid giving it distinct behavior.
