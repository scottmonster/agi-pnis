# Abstract lifecycle framework

## 1. Catalog record

- **Catalog identifier:** 3.20
- **Evidence:** se
- **Definition:** Defines overridable startup/shutdown/pre/post hooks when one concrete lifecycle exists.

## 2. Scenario

### 2.1 Context

One worker starts, processes its configured job, and shuts down.

### 2.2 Safer approach

Write the concrete startup and shutdown sequence in the worker.

### 2.3 Failure mode

Build a base lifecycle class with overridable pre-start, post-start, pre-stop, and post-stop methods for the one worker.

### 2.4 Why this difference matters

Inheritance points imply variations that do not exist and make the actual lifecycle indirect.

## 3. Boundaries and distinctions

An abstract lifecycle can support multiple genuine implementations; one known concrete sequence should remain direct.
