# God class

## 1. Catalog record

- **Catalog identifier:** 5.2
- **Evidence:** e
- **Definition:** One class accumulates routing, business logic, persistence, validation, formatting, and coordination.

## 2. Scenario

### 2.1 Context

`AccountController` handles HTTP routes, validates forms, hashes passwords, queries the database, renders emails, and schedules background work.

### 2.2 Safer approach

Let the controller coordinate request handling while dedicated domain and infrastructure components own their respective responsibilities.

### 2.3 Failure mode

Place a new account-export workflow and its database queries in `AccountController` because it already knows every account detail.

### 2.4 Why this difference matters

Unrelated changes converge on one class, increasing coupling, merge conflicts, and regression risk.

## 3. Boundaries and distinctions

A coordinating class can be appropriate. It becomes a God class when it owns several responsibilities that change independently.
