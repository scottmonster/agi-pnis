# Use `tool` directives for project-pinned Go tools

## 1. Catalog record

- **Catalog identifier:** 11.9.1
- **Impact:** medium
- **Consensus:** high
- **Definition:** On Go 1.24+, declare project tools with `tool` and manage them through the module rather than relying on the old dummy-import `tools.go` workaround.

## 2. Example

### 2.1 Scenario

A project needs a reproducible version of a generator for contributors and CI.

### 2.2 Preferred form

```go
package example

import "os/exec"

func generate() error {
	// go.mod contains: tool example.com/acme/cmd/schema
	return exec.Command("go", "tool", "schema", "-package", "example").Run()
}
```

### 2.3 Hazardous form

```go
//go:build tools

package example

import _ "example.com/acme/cmd/schema" // legacy dummy import only retains the tool
```

### 2.4 Why this difference matters

The `tool` directive makes a project tool an explicit module-managed dependency instead of hiding it behind a build-tagged source file.

## 3. Boundaries and distinctions

Use this form on Go 1.24 and later. Older supported toolchains may require a compatible legacy arrangement until the project's minimum version changes.
