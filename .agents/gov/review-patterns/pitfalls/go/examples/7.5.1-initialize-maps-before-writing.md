# Initialize maps before writing

## 1. Catalog record

- **Catalog identifier:** 7.5.1
- **Impact:** medium
- **Consensus:** high
- **Definition:** Reading a nil map is valid, but writing to one panics. Allocate it with `make` or a literal before the first write.

## 2. Example

### 2.1 Scenario

A counter is populated lazily while processing input.

### 2.2 Preferred form

```go
package counters

func add(counts map[string]int, name string) map[string]int {
	if counts == nil { counts = make(map[string]int) }
	counts[name]++
	return counts
}
```

### 2.3 Hazardous form

```go
package counters

func add(name string) {
	var counts map[string]int
	counts[name]++ // panic: assignment to entry in nil map
}
```

### 2.4 Why this difference matters

The nil map can be read safely, which can conceal the fact that its first assignment will panic.

## 3. Boundaries and distinctions

Leaving a map nil is appropriate for a read-only optional value. Initialize only when a write is required.
