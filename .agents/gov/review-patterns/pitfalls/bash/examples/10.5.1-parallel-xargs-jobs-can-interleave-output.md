# Parallel `xargs` jobs can interleave output

## 1. Catalog record

- **Catalog identifier:** 10.5.1
- **Impact:** medium
- **Consensus:** medium
- **Definition:** With `xargs -P`, concurrent workers should not write arbitrary multi-part records to shared stdout without coordination; buffer per-job output or serialize publication.

## 2. Example

### 2.1 Scenario

A batch job processes several files concurrently and produces one status record per file.

### 2.2 Preferred form

```bash
work_dir=$(mktemp -d) || exit 1
trap 'rm -rf -- "$work_dir"' EXIT
export work_dir

printf '%s\0' alpha beta gamma |
  xargs -0 -n 1 -P 3 bash -c '
    input=$1
    printf "start %s\nend %s\n" "$input" "$input" >"$work_dir/$input.result"
  ' bash

cat "$work_dir"/*.result
```

### 2.3 Hazardous form

```bash
printf '%s\0' alpha beta gamma |
  xargs -0 -n 1 -P 3 bash -c '
    input=$1
    printf "start %s\n" "$input"
    sleep 1
    printf "end %s\n" "$input"
  ' bash
```

### 2.4 Why this difference matters

Each worker emits a record in two writes, so concurrent output can mingle and no longer represent intact per-file records.

## 3. Boundaries and distinctions

Single atomic writes may be adequate for simple logs on a known destination, but record integrity needs an explicit design when output has multiple parts.
