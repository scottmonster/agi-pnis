# One-shot generator context-manager instances

## 1. Catalog record

- **Catalog identifier:** 16.17.1
- **Impact:** low
- **Consensus:** high
- **Definition:** Do not attempt to enter the same context-manager object returned by `@contextmanager` repeatedly. Call the decorated function again to create a new instance.

## 2. Example

### 2.1 Scenario

A test helper temporarily enables tracing around two independent operations.

### 2.2 Preferred form

```python
from contextlib import contextmanager


@contextmanager
def tracing():
    print("trace on")
    try:
        yield
    finally:
        print("trace off")


with tracing():
    print("first operation")
with tracing():
    print("second operation")
```

### 2.3 Hazardous form

```python
from contextlib import contextmanager


@contextmanager
def tracing():
    print("trace on")
    try:
        yield
    finally:
        print("trace off")


trace = tracing()
with trace:
    print("first operation")
with trace:
    print("second operation")
```

### 2.4 Why this difference matters

The generator behind a context-manager instance is consumed after its first use. Re-entering the same instance fails instead of starting a second tracing scope.

## 3. Boundaries and distinctions

A class-based context manager can define reuse semantics deliberately. The restriction applies specifically to one generator-backed instance returned by `@contextmanager`.
