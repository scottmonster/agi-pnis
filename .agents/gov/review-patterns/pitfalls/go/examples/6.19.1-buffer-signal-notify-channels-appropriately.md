# Buffer `signal.Notify` channels appropriately

## 1. Catalog record

- **Catalog identifier:** 6.19.1
- **Impact:** medium
- **Consensus:** high
- **Definition:** Provide enough buffering for signals you cannot afford to miss and unregister notifications when they are no longer needed. For `NotifyContext`, call its returned stop function.

## 2. Example

### 2.1 Scenario

A command starts graceful shutdown after an interrupt.

### 2.2 Preferred form

```go
package main

import (
	"os"
	"os/signal"
)

func waitForInterrupt() {
	signals := make(chan os.Signal, 1)
	signal.Notify(signals, os.Interrupt)
	defer signal.Stop(signals)
	<-signals
}
```

### 2.3 Hazardous form

```go
package main

import (
	"os"
	"os/signal"
)

func interrupts() <-chan os.Signal {
	signals := make(chan os.Signal)
	signal.Notify(signals, os.Interrupt)
	return signals
}
```

### 2.4 Why this difference matters

An unbuffered notification channel can miss a signal when no receiver is ready, and the registration remains active indefinitely.

## 3. Boundaries and distinctions

For a one-signal shutdown path, a buffer of one is often enough. Call the returned `NotifyContext` stop function when registration ends.
