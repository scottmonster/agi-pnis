# Negative indexed-array subscripts count from the end

## 1. Catalog record

- **Catalog identifier:** 11.5.1
- **Impact:** low
- **Consensus:** high
- **Definition:** Bash accepts negative indexed-array subscripts in relevant contexts, interpreting them relative to one greater than the maximum assigned index. Do not assume a negative subscript is automatically an error.

## 2. Example

### 2.1 Scenario

A script retrieves the most recently recorded deployment environment from an indexed array.

### 2.2 Preferred form

```bash
#!/usr/bin/env bash

environments=(development staging production)
last_index=$((${#environments[@]} - 1))
echo "latest environment: ${environments[last_index]}"
```

### 2.3 Hazardous form

```bash
#!/usr/bin/env bash

environments=(development staging production)
echo "expected an error: ${environments[-1]}"
```

### 2.4 Why this difference matters

The negative subscript is valid in Bash and returns `production`, so code that expects validation to reject it can silently select an unintended array element.

## 3. Boundaries and distinctions

Negative indexed-array subscripts are Bash semantics in relevant contexts. Do not transfer this behavior blindly to associative arrays or other languages and shells.
