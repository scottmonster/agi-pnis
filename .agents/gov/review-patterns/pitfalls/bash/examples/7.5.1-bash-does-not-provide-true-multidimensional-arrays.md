# Bash does not provide true multidimensional arrays

## 1. Catalog record

- **Catalog identifier:** 7.5.1
- **Impact:** medium
- **Consensus:** high
- **Definition:** Do not model substantial nested structures by assuming Bash arrays nest like arrays or maps in general-purpose languages. Bash array elements are strings, with one-dimensional indexed and associative collections.

## 2. Example

### 2.1 Scenario

A script records a small grid of deployment statuses by region and environment. Each cell must be retrieved without constructing shell code.

### 2.2 Preferred form

```bash
declare -A status
region=us-east
environment=staging

status["$region,$environment"]=ready
printf '%s\n' "${status["$region,$environment"]}"
```

### 2.3 Hazardous form

```bash
declare -a status_us_east=(ready pending)
region=us_east
environment_index=1

eval "cell=\${status_${region}[${environment_index}]}"
printf '%s\n' "$cell"
```

### 2.4 Why this difference matters

The hazardous form emulates nesting through dynamically constructed variable names and `eval`. That approach couples data access to shell parsing and becomes fragile as identifiers or data grow more complex.

## 3. Boundaries and distinctions

Composite keys can work for small, controlled tables. For substantial nested data or structured interchange, use a tool or language with a native data model instead of expanding indirect shell evaluation.
