# Know the limits of structured cloning

## 1. Catalog record

- **Catalog identifier:** 9.1.2
- **Impact:** medium
- **Consensus:** high
- **Definition:** Do not use structuredClone when unsupported values or semantics such as functions, DOM nodes, descriptors, or accessors must survive.

## 2. Example

### 2.1 Scenario

A job definition includes a callback that must remain callable after it is copied for a worker.

### 2.2 Preferred form

```javascript
function copyJob(job) {
  return {
    name: job.name,
    options: structuredClone(job.options),
    run: job.run,
  };
}

const originalJob = { name: "cleanup", options: { retries: 2 }, run: () => "done" };
const copiedJob = copyJob(originalJob);

console.log(copiedJob.run()); // done
```

### 2.3 Hazardous form

```javascript
const job = { name: "cleanup", options: { retries: 2 }, run: () => "done" };

const copiedJob = structuredClone(job);

console.log(copiedJob.run());
```

### 2.4 Why this difference matters

The hazardous form throws a `DataCloneError` because functions cannot be structured-cloned, preventing the worker configuration from being created.

## 3. Boundaries and distinctions

Use `structuredClone()` for its supported data types when a value copy is the intended semantic. Recreate unsupported values explicitly when their identity or behavior must survive.
