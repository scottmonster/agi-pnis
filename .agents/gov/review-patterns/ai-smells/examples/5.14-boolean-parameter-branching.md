# Boolean-parameter branching

## 1. Catalog record

- **Catalog identifier:** 5.14
- **Evidence:** se
- **Definition:** One function contains multiple behaviors selected by growing sets of flags.

## 2. Scenario

### 2.1 Context

`render_invoice(invoice, preview, include_tax, email_copy, legacy_format)` selects several workflows through boolean arguments.

### 2.2 Safer approach

Name genuinely distinct operations or use a small, explicit mode when it models a stable domain choice.

### 2.3 Failure mode

Add `skip_audit` and `force_currency` flags, then grow nested combinations inside the same function.

### 2.4 Why this difference matters

Call sites become unclear and flag combinations multiply paths that are difficult to validate.

## 3. Boundaries and distinctions

A single simple boolean can be readable. This failure concerns a growing flag set that bundles multiple behaviors into one function.
