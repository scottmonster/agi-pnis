# Do not accidentally execute command-substitution output

## 1. Catalog record

- **Catalog identifier:** 1.6.2
- **Impact:** high
- **Consensus:** high
- **Definition:** `$(command)` produces text. Placing that expansion where Bash expects a command, such as `$(get_command)`, causes the resulting text to be split and used as a command and arguments. Do this only when execution is explicitly intended.

## 2. Example

### 2.1 Scenario

A helper reports the name of the configured maintenance mode, and the script should display that value for an operator.

### 2.2 Preferred form

```bash
#!/usr/bin/env bash

get_mode() {
  printf '%s\n' 'maintenance mode is enabled'
}

mode=$(get_mode)
printf 'reported mode: %s\n' "$mode"
```

### 2.3 Hazardous form

```bash
#!/usr/bin/env bash

get_mode() {
  printf '%s\n' 'maintenance mode is enabled'
}

$(get_mode)
```

### 2.4 Why this difference matters

The preferred form captures the helper's output as text. In the hazardous form, Bash treats the substituted words as a command and its arguments, attempting to execute `maintenance` instead of reporting the mode.

## 3. Boundaries and distinctions

Command substitution is appropriate for collecting text from a command. Executing a computed command name is a separate design decision that should be explicit and constrained, rather than an incidental placement of `$(...)`.
