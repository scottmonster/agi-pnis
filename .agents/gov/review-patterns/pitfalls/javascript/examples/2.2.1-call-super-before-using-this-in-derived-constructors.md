# Call super before using this in derived constructors

## 1. Catalog record

- **Catalog identifier:** 2.2.1
- **Impact:** medium
- **Consensus:** high
- **Definition:** Call `super()` before accessing `this` in a derived constructor.

## 2. Example

### 2.1 Scenario

A specialized report adds a title to the base report state.

### 2.2 Preferred form

```javascript
class Report {
  constructor(id) {
    this.id = id;
  }
}

class SalesReport extends Report {
  constructor(id, title) {
    super(id);
    this.title = title;
  }
}
```

### 2.3 Hazardous form

```javascript
class Report {
  constructor(id) {
    this.id = id;
  }
}

class SalesReport extends Report {
  constructor(id, title) {
    this.title = title;
    super(id);
  }
}
```

### 2.4 Why this difference matters

Derived constructors have no initialized `this` until `super()` returns, so the hazardous form throws a `ReferenceError`.

## 3. Boundaries and distinctions

A class without `extends` does not need `super()`, but its constructor still must initialize any required state itself.
