# Do not design APIs that distinguish nil and empty slices without need

## 1. Catalog record

- **Catalog identifier:** 13.4.1
- **Impact:** low
- **Consensus:** high
- **Definition:** Treat nil and zero-length slices equivalently unless the distinction represents real domain information.

## 2. Example

### 2.1 Scenario

A search endpoint accepts optional tag filters from callers that may naturally have either nil or empty slices.

### 2.2 Preferred form

```go
package example

func hasFilters(tags []string) bool {
	return len(tags) > 0
}
```

### 2.3 Hazardous form

```go
package example

func hasFilters(tags []string) bool {
	if tags == nil {
		return false
	}
	return true
}
```

### 2.4 Why this difference matters

The preferred API recognizes that neither nil nor an empty slice contains a filter. The hazardous version reports that an empty slice has filters, forcing callers to care about an irrelevant representation detail.

## 3. Boundaries and distinctions

Distinguish nil from empty only when it conveys domain information, such as an omitted field versus an explicitly cleared collection.
