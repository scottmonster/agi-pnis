# Distinguish bytes, runes, and user-perceived characters

## 1. Catalog record

- **Catalog identifier:** 7.16.1
- **Impact:** medium
- **Consensus:** high
- **Definition:** `len(s)` and `s[i]` operate on bytes; range decodes UTF-8 runes and reports byte indexes. A rune still need not correspond to one grapheme visible to a user.

## 2. Example

### 2.1 Scenario

A UI limit allows a user name of at most ten Unicode code points.

### 2.2 Preferred form

```go
package names

import "unicode/utf8"

func valid(name string) bool {
	return utf8.RuneCountInString(name) <= 10
}
```

### 2.3 Hazardous form

```go
package names

func valid(name string) bool {
	return len(name) <= 10 // Counts UTF-8 bytes, not code points.
}
```

### 2.4 Why this difference matters

Many non-ASCII runes take multiple bytes, so byte counting rejects names that meet the intended rune limit.

## 3. Boundaries and distinctions

A rune count is not a user-visible grapheme count. Use grapheme segmentation when the product requirement is visible-character limits.
