# Preserve argument boundaries with `"$@"`

## 1. Catalog record

- **Catalog identifier:** 1.2.1
- **Impact:** high
- **Consensus:** high
- **Definition:** Forward arguments with `"$@"`, not unquoted `$@`, `$*`, or `"$*"`. Inside double quotes, `"$@"` expands each positional parameter as a separate word.

## 2. Example

### 2.1 Scenario

A wrapper passes every argument it received to a program and logs the resulting argument list. Callers may pass empty values and paths containing spaces.

### 2.2 Preferred form

```bash
run_with_logging() {
    local argument

    for argument in "$@"; do
        printf 'argument: <%s>\n' "$argument"
    done
}

run_with_logging 'draft report.txt' '' '*.csv'
```

### 2.3 Hazardous form

```bash
run_with_logging() {
    local argument

    for argument in $@; do
        printf 'argument: <%s>\n' "$argument"
    done
}

run_with_logging 'draft report.txt' '' '*.csv'
```

### 2.4 Why this difference matters

Unquoted `$@` splits arguments on shell word boundaries and expands glob patterns, while an empty argument can disappear entirely. A wrapper then invokes or logs something different from what its caller supplied.

## 3. Boundaries and distinctions

Use `"$@"` when forwarding positional parameters as distinct arguments. Use `"$*"` only when deliberately joining all parameters into one string with the first character of `IFS` as the separator.
