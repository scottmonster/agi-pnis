# Comments/docs that promise behavior not implemented

## 1. Catalog record

- **Catalog identifier:** 12.2
- **Evidence:** e/se
- **Definition:** Public or internal documentation advertises an API, guarantee, or workflow the system does not provide.

## 2. Scenario

### 2.1 Context

An SDK guide says that `client.publish()` retries transient failures automatically, but the method returns the first network error without retrying.

### 2.2 Safer approach

Either implement the documented retry guarantee with tests, or revise the guide to state that callers must choose and perform retries.

### 2.3 Failure mode

Publish the guide’s automatic-retry claim even though the client contains no retry logic.

### 2.4 Why this difference matters

Callers can rely on a guarantee that does not exist and lose work when transient failures occur instead of handling the error themselves.

## 3. Boundaries and distinctions

This is a promise absent from the implementation. It differs from a once-correct document that becomes stale after a later contract change.
