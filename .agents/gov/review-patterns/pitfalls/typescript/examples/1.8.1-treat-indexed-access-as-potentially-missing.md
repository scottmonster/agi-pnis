# Treat indexed access as potentially missing

## 1. Catalog record

- **Catalog identifier:** 1.8.1
- **Impact:** high
- **Consensus:** high
- **Definition:** Enable `noUncheckedIndexedAccess`, particularly for arrays, dictionaries, and index-signature-heavy code.

## 2. Example

### 2.1 Scenario

A queue may be empty when its next job is requested.

### 2.2 Preferred form

```typescript
// tsconfig.json: { "compilerOptions": { "noUncheckedIndexedAccess": true } }
function nextJobName(queue: readonly string[]): string {
  const job = queue[0];
  return job === undefined ? 'idle' : job;
}

```

### 2.3 Hazardous form

```typescript
function nextJobName(queue: string[]): string {
  // Without the option, this is typed as string even for an empty queue.
  return queue[0].toUpperCase();
}
```

### 2.4 Why this difference matters

Ordinary TypeScript indexed access can claim a value is present even when the key or array index does not exist.

## 3. Boundaries and distinctions

Apply this guidance in the conditions described by the catalog record. Deliberate exceptions need a documented runtime guarantee, compatible toolchain behavior, or an explicit local unsafe boundary.
