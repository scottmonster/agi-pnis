# `is` for value equality

## 1. Catalog record

- **Catalog identifier:** 6.18.1
- **Impact:** medium
- **Consensus:** high
- **Definition:** Use `==` for value equality and reserve `is` for identity checks such as `x is None`.

## 2. Example

### 2.1 Scenario

An API checks whether a user supplied the same textual status as the configured status.

### 2.2 Preferred form

```python
configured = "ready"
received = "".join(["rea", "dy"])
print(received == configured)  # True
```

### 2.3 Hazardous form

```python
configured = "ready"
received = "".join(["rea", "dy"])
print(received is configured)  # Usually False, despite equal text
```

### 2.4 Why this difference matters

Identity compares object instances, not their values. Interning can make `is` appear to work for some literals, but that is not a value-equality guarantee.

## 3. Boundaries and distinctions

Use `is` for singleton identity checks, most commonly `value is None`, and for deliberate object-identity semantics.
