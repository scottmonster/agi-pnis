# Failure to reproduce the bug before fixing it

## 1. Catalog record

- **Catalog identifier:** 9.18
- **Evidence:** se
- **Definition:** Changes code without a reliable demonstration of the reported failure, leaving cause and effectiveness uncertain.

## 2. Scenario

### 2.1 Context

A report says exporting a large account list sometimes omits the final page.

### 2.2 Safer approach

Capture the input size, paging state, and output discrepancy in a failing test or repeatable local command before changing pagination.

### 2.3 Failure mode

Guess at an off-by-one fix without ever observing the failure.

### 2.4 Why this difference matters

The patch may address the wrong cause, and there is no dependable evidence that the reported defect is gone.

## 3. Boundaries and distinctions

When reproduction depends on an unavailable production condition, document the evidence available and add the closest reliable regression check rather than pretending a reproduction exists.
