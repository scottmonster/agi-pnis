# Repeated anonymous event listeners are distinct registrations

## 1. Catalog record

- **Catalog identifier:** 11.1.8
- **Impact:** medium
- **Consensus:** high
- **Definition:** Do not repeatedly add newly created anonymous listeners when one reusable registration is intended.

## 2. Example

### 2.1 Scenario

A refreshable page component wires a Save button each time its data is rendered.

### 2.2 Preferred form

```javascript
const saveButton = document.querySelector("#save");

function saveDraft() {
  console.log("saved");
}

saveButton.addEventListener("click", saveDraft, { once: true });
```

### 2.3 Hazardous form

```javascript
const saveButton = document.querySelector("#save");

function render() {
  saveButton.addEventListener("click", () => {
    console.log("saved");
  });
}

render();
render();
```

### 2.4 Why this difference matters

Every render creates a distinct callback, so one click runs both registrations and can submit the same draft more than once.

## 3. Boundaries and distinctions

Anonymous listeners are appropriate for one-off registrations with a bounded lifetime, such as a listener registered with `{ once: true }`.
