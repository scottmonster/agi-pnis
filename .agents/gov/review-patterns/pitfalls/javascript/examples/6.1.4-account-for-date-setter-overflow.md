# Account for Date setter overflow

## 1. Catalog record

- **Catalog identifier:** 6.1.4
- **Impact:** medium
- **Consensus:** high
- **Definition:** Methods such as `setMonth()` normalize out-of-range component values rather than simply replacing one calendar field independently.

## 2. Example

### 2.1 Scenario

A billing system moves a monthly renewal date to the following month while keeping a valid calendar date.

### 2.2 Preferred form

```javascript
function moveToMonthClamped(date, targetMonth) {
  const result = new Date(date);
  const day = result.getUTCDate();
  result.setUTCDate(1);
  result.setUTCMonth(targetMonth);
  const lastDay = new Date(Date.UTC(result.getUTCFullYear(), targetMonth + 1, 0)).getUTCDate();
  result.setUTCDate(Math.min(day, lastDay));
  return result;
}

const january31 = new Date("2026-01-31T00:00:00Z");
console.log(moveToMonthClamped(january31, 1).toISOString()); // 2026-02-28T00:00:00.000Z
```

### 2.3 Hazardous form

```javascript
const january31 = new Date("2026-01-31T00:00:00Z");
january31.setUTCMonth(1);

console.log(january31.toISOString()); // 2026-03-03T00:00:00.000Z
```

### 2.4 Why this difference matters

Changing only the month while the date is the 31st normalizes the impossible February 31 into a day in March.

## 3. Boundaries and distinctions

Overflow normalization is useful when rollover is desired. When the domain requires clamping, rejection, or a separate recurrence policy, implement that policy explicitly.
