# Avoid recursive `String` formatting

## 1. Catalog record

- **Catalog identifier:** 13.17.1
- **Impact:** low
- **Consensus:** high
- **Definition:** Inside a `String` method, do not format the receiver in a way that invokes the same `String` method again. Convert to a representation that does not implement the method when needed.

## 2. Example

### 2.1 Scenario

A status type implements `fmt.Stringer` so it can appear in logs.

### 2.2 Preferred form

```go
package example

import "fmt"

type status int

func (s status) String() string {
	return fmt.Sprintf("status(%d)", int(s))
}
```

### 2.3 Hazardous form

```go
package example

import "fmt"

type status int

func (s status) String() string {
	return fmt.Sprintf("status(%v)", s)
}
```

### 2.4 Why this difference matters

Converting to `int` gives `fmt` a value that has no `String` method. Formatting `s` with `%v` calls `String` again, leading to unbounded recursion and eventual stack exhaustion.

## 3. Boundaries and distinctions

Formatting a different value is safe. The critical condition is avoiding a format operation that dispatches back to the receiver's own `String` method.
