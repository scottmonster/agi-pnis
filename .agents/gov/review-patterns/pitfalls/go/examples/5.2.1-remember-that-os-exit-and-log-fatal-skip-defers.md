# Remember that `os.Exit` and `log.Fatal` skip defers

## 1. Catalog record

- **Catalog identifier:** 5.2.1
- **Impact:** high
- **Consensus:** high
- **Definition:** Do not use `os.Exit` or `log.Fatal` from code that depends on deferred cleanup. Return an error to an outer level that can perform cleanup before exiting.

## 2. Example

### 2.1 Scenario

A command must flush a buffered report before returning a nonzero exit status.

### 2.2 Preferred form

```go
package example

import (
	"bufio"
	"fmt"
	"os"
)

func run() (err error) {
	w := bufio.NewWriter(os.Stdout)
	defer func() {
		if flushErr := w.Flush(); err == nil {
			err = flushErr
		}
	}()
	_, err = fmt.Fprintln(w, "report")
	return err
}
```

### 2.3 Hazardous form

```go
package example

import (
	"bufio"
	"fmt"
	"log"
	"os"
)

func run() {
	w := bufio.NewWriter(os.Stdout)
	defer w.Flush()
	_, _ = fmt.Fprintln(w, "report")
	log.Fatal("failed") // skips the deferred Flush.
}
```

### 2.4 Why this difference matters

`log.Fatal` calls `os.Exit`, so the deferred flush never runs and the report may be lost.

## 3. Boundaries and distinctions

Calling `os.Exit` is appropriate only after all required cleanup has completed or when immediate termination is intentional.
