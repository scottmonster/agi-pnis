# Do not construct Boolean wrapper objects

## 1. Catalog record

- **Catalog identifier:** 1.1.7
- **Impact:** medium
- **Consensus:** high
- **Definition:** Use Boolean primitives and `Boolean(value)` when explicit conversion is needed. Avoid `new Boolean(value)`.

## 2. Example

### 2.1 Scenario

A feature flag is converted to a Boolean before selecting a code path.

### 2.2 Preferred form

```javascript
const enabled = Boolean(false);

if (enabled) {
  console.log("feature enabled");
}
```

### 2.3 Hazardous form

```javascript
const enabled = new Boolean(false);

if (enabled) {
  console.log("feature enabled");
}
```

### 2.4 Why this difference matters

The wrapper object is truthy even though its wrapped primitive value is false, so the hazardous branch runs.

## 3. Boundaries and distinctions

Boolean objects exist for historical language behavior, but application conditions should use primitive Booleans.
