# Never rely on assignment to undeclared variables

## 1. Catalog record

- **Catalog identifier:** 1.1.2
- **Impact:** high
- **Consensus:** high
- **Definition:** Always declare bindings with `const`, `let`, or an intentional declaration rather than assigning to an unknown identifier. In sloppy scripts, undeclared assignment can create a global.

## 2. Example

### 2.1 Scenario

A formatter stores the result of a calculation before returning it.

### 2.2 Preferred form

```javascript
function formatTotal(cents) {
  const total = `$${(cents / 100).toFixed(2)}`;
  return total;
}

console.log(formatTotal(499));
```

### 2.3 Hazardous form

```javascript
function formatTotal(cents) {
  total = `$${(cents / 100).toFixed(2)}`;
  return total;
}

console.log(formatTotal(499));
```

### 2.4 Why this difference matters

In a sloppy classic script, `total` becomes shared global state. In strict code, the same bug becomes a `ReferenceError`.

## 3. Boundaries and distinctions

Declaring an intentional global is possible, but local values should be declared in the scope that owns them.
