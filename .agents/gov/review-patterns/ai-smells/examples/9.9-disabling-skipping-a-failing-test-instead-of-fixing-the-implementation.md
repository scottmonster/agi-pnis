# Disabling/skipping a failing test instead of fixing the implementation

## 1. Catalog record

- **Catalog identifier:** 9.9
- **Evidence:** a
- **Definition:** Removes the signal of a regression while leaving the defective behavior in place.

## 2. Scenario

### 2.1 Context

An authorization test fails because a non-owner can retrieve another user's invoice.

### 2.2 Safer approach

Trace the authorization path, enforce ownership, and retain the test as a regression check.

### 2.3 Failure mode

Mark the test skipped with a vague note so the build succeeds.

### 2.4 Why this difference matters

The defect remains reachable in production while continuous integration stops reporting it.

## 3. Boundaries and distinctions

A temporary skip can be justified for an independently broken test environment, but it needs a clear owner and restoration plan and must not conceal a product defect.
