# Ignoring local conventions

## 1. Catalog record

- **Catalog identifier:** 2.15
- **Evidence:** e/a
- **Definition:** Misses repository-specific helpers, framework patterns, naming, error semantics, directory placement, or test conventions.

## 2. Scenario

### 2.1 Context

The repository wraps HTTP errors through a shared `respondError` helper and tests handlers with a standard fixture builder.

### 2.2 Safer approach

The agent follows nearby handlers, uses `respondError`, and extends the matching fixture-based test.

### 2.3 Failure mode

It returns an ad hoc JSON error shape and creates an isolated test setup with different status semantics.

### 2.4 Why this difference matters

Users and maintainers encounter inconsistent behavior, while shared middleware and tests no longer cover the new path predictably.

## 3. Boundaries and distinctions

Conventions can be changed through a deliberate repository-wide decision; this failure is bypassing established local patterns in a focused change.
