# Do not use Math.random for security-sensitive randomness

## 1. Catalog record

- **Catalog identifier:** 4.1.3
- **Impact:** high
- **Consensus:** high
- **Definition:** Use Web Crypto facilities such as `crypto.getRandomValues()` or `crypto.randomUUID()` for tokens, secrets, identifiers requiring unpredictability, and other security-sensitive values.

## 2. Example

### 2.1 Scenario

A browser application creates a password-reset token that an attacker must not be able to predict.

### 2.2 Preferred form

```javascript
function createResetToken() {
  const bytes = new Uint8Array(32);
  crypto.getRandomValues(bytes);
  return Array.from(bytes, (byte) => byte.toString(16).padStart(2, "0")).join("");
}

console.log(createResetToken());
```

### 2.3 Hazardous form

```javascript
function createResetToken() {
  return Math.random().toString(36).slice(2);
}

console.log(createResetToken());
```

### 2.4 Why this difference matters

`Math.random()` does not provide cryptographic unpredictability, so a token derived from it is unsuitable for an attacker-facing secret.

## 3. Boundaries and distinctions

`Math.random()` can be reasonable for non-security uses such as a visual effect or randomized test data. Security-sensitive values need a cryptographic source.
