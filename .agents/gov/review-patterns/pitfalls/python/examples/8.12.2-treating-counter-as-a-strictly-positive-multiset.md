# Treating `Counter` as a strictly positive multiset

## 1. Catalog record

- **Catalog identifier:** 8.12.2
- **Impact:** medium
- **Consensus:** high
- **Definition:** Remember that `Counter` can retain zero and negative counts and that setting a count to zero does not remove the key. Delete entries or normalize when positive-only semantics are required.

## 2. Example

### 2.1 Scenario

An inventory counter must contain only items with positive quantities.

### 2.2 Preferred form

```python
from collections import Counter

inventory = Counter({"widget": 1})
inventory.subtract(["widget"])
inventory = +inventory

assert "widget" not in inventory
```

### 2.3 Hazardous form

```python
from collections import Counter

inventory = Counter({"widget": 1})
inventory.subtract(["widget"])

assert inventory == Counter({"widget": 0})
```

### 2.4 Why this difference matters

Zero and negative counts remain represented in a `Counter`, so membership and iteration can violate positive-only multiset assumptions.

## 3. Boundaries and distinctions

Retaining zero or negative counts is useful when a `Counter` represents deltas or debts rather than a strict multiset.
