# Depending before checking the platform

## 1. Catalog record

- **Catalog identifier:** 14.7
- **Evidence:** a
- **Definition:** New code/package is introduced before checking whether stdlib, framework, database, type system, or infrastructure already provides the feature.

## 2. Scenario

### 2.1 Context

An agent needs to validate an email-shaped field in a service that already uses a framework with declarative validation support.

### 2.2 Safer approach

It checks the language, framework, schema, and database capabilities before selecting the smallest supported solution.

### 2.3 Failure mode

It installs a validation package and writes custom middleware without checking the existing framework annotations and database constraints.

### 2.4 Why this difference matters

The new dependency or code can duplicate platform behavior, introduce version and security maintenance, and produce inconsistent validation semantics.

## 3. Boundaries and distinctions

A platform feature may be unsuitable because of its behavior, compatibility, or missing capability. Checking it first does not require using it when the comparison supports another choice.
