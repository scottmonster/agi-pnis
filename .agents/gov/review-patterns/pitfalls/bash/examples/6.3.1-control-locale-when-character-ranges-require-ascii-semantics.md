# Control locale when character ranges require ASCII semantics

## 1. Catalog record

- **Catalog identifier:** 6.3.1
- **Impact:** medium
- **Consensus:** high
- **Definition:** Bracket ranges and character classes can depend on locale. Use an appropriate locale such as `LC_ALL=C` when bytewise ASCII ordering is specifically required rather than assuming `[A-Z]` always has ASCII behavior.

## 2. Example

### 2.1 Scenario

A release script accepts exactly three ASCII uppercase letters.

### 2.2 Preferred form

```bash
#!/usr/bin/env bash
identifier=$1
if LC_ALL=C [[ $identifier == [A-Z][A-Z][A-Z] ]]; then echo "$identifier"; fi
```

### 2.3 Hazardous form

```bash
#!/usr/bin/env bash
identifier=$1
if [[ $identifier == [A-Z][A-Z][A-Z] ]]; then echo "$identifier"; fi
```

### 2.4 Why this difference matters

Bracket range results can differ between systems with different locale settings.

## 3. Boundaries and distinctions

Use the C locale only when bytewise ASCII semantics are the actual requirement, not for natural-language matching.
