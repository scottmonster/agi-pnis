# Heap entries without a tie-breaker

## 1. Catalog record

- **Catalog identifier:** 8.10.1
- **Impact:** medium
- **Consensus:** high
- **Definition:** When heap entries contain `(priority, task)` and equal priorities are possible, add a unique monotonic counter or comparable wrapper unless tasks themselves are safely orderable.

## 2. Example

### 2.1 Scenario

A scheduler queues distinct job objects with priorities that can be equal.

### 2.2 Preferred form

```python
import heapq
from itertools import count

jobs: list[tuple[int, int, object]] = []
sequence = count()
heapq.heappush(jobs, (10, next(sequence), object()))
heapq.heappush(jobs, (10, next(sequence), object()))

assert len(jobs) == 2
```

### 2.3 Hazardous form

```python
import heapq

jobs: list[tuple[int, object]] = []
heapq.heappush(jobs, (10, object()))
heapq.heappush(jobs, (10, object()))  # Equal priorities require object ordering.
```

### 2.4 Why this difference matters

When priorities tie, `heapq` compares the next tuple item. Unorderable task objects then raise `TypeError`.

## 3. Boundaries and distinctions

No tie-breaker is needed if tied task values are deliberately and safely comparable.
