# Do not use MD5 or SHA-1 for cryptographic security

## 1. Catalog record

- **Catalog identifier:** 12.4.1
- **Impact:** medium
- **Consensus:** high
- **Definition:** Reserve MD5 and SHA-1 for non-security compatibility uses where collision resistance is irrelevant. Use modern cryptographic hashes for security properties.

## 2. Example

### 2.1 Scenario

A service records a digest of a signed manifest so that tampering can be detected during verification.

### 2.2 Preferred form

```go
package example

import (
	"crypto/sha256"
	"encoding/hex"
)

func manifestDigest(manifest []byte) string {
	digest := sha256.Sum256(manifest)
	return hex.EncodeToString(digest[:])
}
```

### 2.3 Hazardous form

```go
package example

import (
	"crypto/md5"
	"encoding/hex"
)

func manifestDigest(manifest []byte) string {
	digest := md5.Sum(manifest)
	return hex.EncodeToString(digest[:])
}
```

### 2.4 Why this difference matters

MD5 has practical collision attacks, so an attacker can potentially substitute distinct data with the same digest. SHA-256 provides a modern collision-resistance margin for this security property.

## 3. Boundaries and distinctions

MD5 or SHA-1 may still be required to interoperate with a legacy, non-security format. Password storage needs a password-hashing scheme with salt and work factors, not a fast general-purpose hash.
