# Partial refactor

## 1. Catalog record

- **Catalog identifier:** 11.7
- **Evidence:** se
- **Definition:** New abstraction is introduced but the old path remains active.

## 2. Scenario

### 2.1 Context

The team replaces direct email sending with a notification service to centralize delivery rules.

### 2.2 Safer approach

The agent migrates each sender, verifies no direct-send call sites remain, and removes the obsolete path when compatible with the rollout.

### 2.3 Failure mode

The agent adds the notification service but leaves several production callers using the old direct-send helper.

### 2.4 Why this difference matters

Delivery behavior is split and later changes to the new abstraction do not affect all notifications.

## 3. Boundaries and distinctions

A deliberate staged migration can temporarily retain an old path when it has an explicit rollout plan and safeguards; accidental active remnants are the failure.
