# Data-schema conflict

## 1. Catalog record

- **Catalog identifier:** 2.12
- **Evidence:** e
- **Definition:** Assumes nonexistent columns, JSON properties, fields, types, encodings, or data formats.

## 2. Scenario

### 2.1 Context

An order endpoint returns JSON documented and tested with a `createdAt` timestamp field.

### 2.2 Safer approach

The agent reads the response type and fixtures, then formats `createdAt` using its actual timestamp representation.

### 2.3 Failure mode

It reads `order.created_at` as though the API returned database-style field names.

### 2.4 Why this difference matters

The feature receives `undefined` or fails at runtime because it is built against a data shape that does not exist.

## 3. Boundaries and distinctions

This differs from an incorrect parsing algorithm: the assumed field or representation is absent from the real schema.
