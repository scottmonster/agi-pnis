# Use `BASH_SOURCE` rather than `$0` for the currently sourced Bash file

## 1. Catalog record

- **Catalog identifier:** 9.2.1
- **Impact:** medium
- **Consensus:** high
- **Definition:** Use the `BASH_SOURCE` array to locate a sourced file because `$0` identifies the invoking shell or top-level script.

## 2. Example

### 2.1 Scenario

A reusable library needs to find a configuration file stored beside the library itself.

### 2.2 Preferred form

```bash
#!/usr/bin/env bash

library_dir() {
  local library_file=${BASH_SOURCE[0]}
  cd -- "$(dirname -- "$library_file")" && pwd -P
}

config_path="$(library_dir)/defaults.conf"
printf 'loading %s\n' "$config_path"
```

### 2.3 Hazardous form

```bash
#!/usr/bin/env bash

library_dir() {
  cd -- "$(dirname -- "$0")" && pwd -P
}

config_path="$(library_dir)/defaults.conf"
printf 'loading %s\n' "$config_path"
```

### 2.4 Why this difference matters

When this code is sourced, `$0` still refers to the caller, so the hazardous form can load a file beside the wrong script.

## 3. Boundaries and distinctions

For a standalone top-level script, `$0` can describe its invocation, but it is not a reliable library-file location.
