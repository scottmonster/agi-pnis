# Manual index loops over sequences

## 1. Catalog record

- **Catalog identifier:** 16.13.1
- **Impact:** low
- **Consensus:** high
- **Definition:** Prefer direct iteration or `enumerate(sequence)` over `for i in range(len(sequence))` when both the index and element are required.

## 2. Example

### 2.1 Scenario

A command-line report labels each error with its display number and message.

### 2.2 Preferred form

```python
def numbered_errors(errors: list[str]) -> list[str]:
    return [f"{number}: {message}" for number, message in enumerate(errors, start=1)]


print(numbered_errors(["missing file", "invalid header"]))
```

### 2.3 Hazardous form

```python
def numbered_errors(errors: list[str]) -> list[str]:
    lines = []
    for index in range(len(errors)):
        lines.append(f"{index + 1}: {errors[index]}")
    return lines


print(numbered_errors(["missing file", "invalid header"]))
```

### 2.4 Why this difference matters

The hazardous form repeats indexing and arithmetic that `enumerate()` expresses directly, making the loop more error-prone to modify.

## 3. Boundaries and distinctions

An index loop is reasonable when the index itself drives an algorithm, such as pairwise lookahead or indexed assignment. Use direct iteration when only values are needed.
