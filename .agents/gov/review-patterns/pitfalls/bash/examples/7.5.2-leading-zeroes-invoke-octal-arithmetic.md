# Leading zeroes invoke octal arithmetic

## 1. Catalog record

- **Catalog identifier:** 7.5.2
- **Impact:** medium
- **Consensus:** high
- **Definition:** Bash integer constants with a leading `0` are interpreted as octal. Validate decimal input or deliberately convert it before arithmetic when values such as `08` or `09` may occur.

## 2. Example

### 2.1 Scenario

A maintenance script receives a zero-padded day number from a date field. It needs to add one day as decimal arithmetic.

### 2.2 Preferred form

```bash
raw_day=08

if [[ $raw_day =~ ^[0-9]+$ ]]; then
  day=$((10#$raw_day))
  tomorrow=$((day + 1))
  printf 'Tomorrow is day %d\n' "$tomorrow"
else
  printf 'Invalid day: %s\n' "$raw_day" >&2
  exit 2
fi
```

### 2.3 Hazardous form

```bash
day=08
tomorrow=$((day + 1))
printf 'Tomorrow is day %d\n' "$tomorrow"
```

### 2.4 Why this difference matters

The hazardous arithmetic treats `08` as an octal constant, where eight is not a valid digit. Deliberate decimal conversion accepts the intended human-facing format.

## 3. Boundaries and distinctions

Leading zeroes are valid when the value is intentionally octal. Only force decimal interpretation for input that is specified as decimal.
