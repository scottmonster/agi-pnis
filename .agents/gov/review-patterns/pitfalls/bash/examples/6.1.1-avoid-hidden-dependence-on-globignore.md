# Avoid hidden dependence on `GLOBIGNORE`

## 1. Catalog record

- **Catalog identifier:** 6.1.1
- **Impact:** medium
- **Consensus:** high
- **Definition:** `GLOBIGNORE` changes filename expansion behavior and has interactions with dotfile matching. Scripts should set or neutralize such state deliberately when exact glob semantics matter.

## 2. Example

### 2.1 Scenario

A cleanup script must select visible log files regardless of caller state.

### 2.2 Preferred form

```bash
#!/usr/bin/env bash
log_dir=$1
( unset GLOBIGNORE; shopt -u dotglob; for file in "$log_dir"/*.log; do [[ -e $file ]] && echo "$file"; done )
```

### 2.3 Hazardous form

```bash
#!/usr/bin/env bash
log_dir=$1
for file in "$log_dir"/*.log; do [[ -e $file ]] && echo "$file"; done
```

### 2.4 Why this difference matters

An inherited `GLOBIGNORE` can change selected files without a change to the pattern.

## 3. Boundaries and distinctions

An interactive helper may honor caller glob state, but a script with exact matching requirements should establish it.
