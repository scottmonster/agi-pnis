# Use `sql.Tx`, not raw transaction statements

## 1. Catalog record

- **Catalog identifier:** 3.6.1
- **Impact:** high
- **Consensus:** high
- **Definition:** Use `DB.BeginTx`/`Tx` methods and perform transaction operations through the `Tx`. Do not issue raw `BEGIN`/`COMMIT`, and do not mix `DB` calls into the transaction.

## 2. Example

### 2.1 Scenario

A transfer records a debit and a credit that must either both persist or both roll back. Each statement must use the connection transaction selected by `database/sql`.

### 2.2 Preferred form

```go
package example

import (
	"context"
	"database/sql"
)

func transfer(ctx context.Context, db *sql.DB, fromID, toID int64, cents int64) error {
	tx, err := db.BeginTx(ctx, nil)
	if err != nil {
		return err
	}
	defer tx.Rollback()

	if _, err := tx.ExecContext(ctx, "UPDATE accounts SET balance = balance - $1 WHERE id = $2", cents, fromID); err != nil {
		return err
	}
	if _, err := tx.ExecContext(ctx, "UPDATE accounts SET balance = balance + $1 WHERE id = $2", cents, toID); err != nil {
		return err
	}
	return tx.Commit()
}
```

### 2.3 Hazardous form

```go
package example

import (
	"context"
	"database/sql"
)

func transfer(ctx context.Context, db *sql.DB, fromID, toID int64, cents int64) error {
	if _, err := db.ExecContext(ctx, "BEGIN"); err != nil {
		return err
	}
	if _, err := db.ExecContext(ctx, "UPDATE accounts SET balance = balance - $1 WHERE id = $2", cents, fromID); err != nil {
		return err
	}
	if _, err := db.ExecContext(ctx, "UPDATE accounts SET balance = balance + $1 WHERE id = $2", cents, toID); err != nil {
		return err
	}
	_, err := db.ExecContext(ctx, "COMMIT") // Calls can use different pooled connections.
	return err
}
```

### 2.4 Why this difference matters

`sql.Tx` binds transaction operations to the correct database connection and supplies structured commit and rollback behavior. Raw transaction statements through `DB` can be dispatched through a pool, breaking atomicity.

## 3. Boundaries and distinctions

Use `BeginTx` options when the isolation level or read-only mode is part of the operation's contract. A single independent statement does not need an explicit transaction, and some database-specific administrative operations may require documented exceptions.
