# Trusting its generated plan over contradictory repository evidence

## 1. Catalog record

- **Catalog identifier:** 13.9
- **Evidence:** a
- **Definition:** Continues following an initial hypothesis after source, configuration, tests, or errors show it is false.

## 2. Scenario

### 2.1 Context

An agent plans to add a REST route, but the repository configuration and tests show that this service exposes only GraphQL operations.

### 2.2 Safer approach

The agent revises its plan, studies the existing GraphQL resolver pattern, and implements the requested operation there.

### 2.3 Failure mode

The agent creates a new REST controller because it was in the original plan, despite no router registration or test convention supporting it.

### 2.4 Why this difference matters

An attractive plan cannot outweigh direct project facts; following it creates unreachable or inconsistent code.

## 3. Boundaries and distinctions

Plans are useful hypotheses, not evidence. Revising one after contradiction is normal engineering work.
