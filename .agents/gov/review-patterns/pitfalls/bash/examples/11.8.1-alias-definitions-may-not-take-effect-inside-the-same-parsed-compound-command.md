# Alias definitions may not take effect inside the same parsed compound command

## 1. Catalog record

- **Catalog identifier:** 11.8.1
- **Impact:** low
- **Consensus:** high
- **Definition:** Bash reads complete compound constructs before executing them, while alias expansion happens during parsing. An alias defined inside such a construct may therefore not affect later text in that already-parsed construct.

## 2. Example

### 2.1 Scenario

An interactive helper configures an alias and then tries to use it in the same function body.

### 2.2 Preferred form

```bash
#!/usr/bin/env bash

greet() {
  echo hello
}

configure_and_greet() {
  greet
}

configure_and_greet
```

### 2.3 Hazardous form

```bash
#!/usr/bin/env bash

shopt -s expand_aliases
configure_and_greet() {
  alias greet='echo hello'
  greet
}

configure_and_greet
```

### 2.4 Why this difference matters

Bash parses the complete function before running the alias definition, so `greet` is not expanded as the newly defined alias in that function body.

## 3. Boundaries and distinctions

Aliases are expanded while parsing and are usually an interactive convenience. A function is the appropriate reusable construct when definition and use must have normal execution order.
