# Weak or inappropriate cryptography

## 1. Catalog record

- **Catalog identifier:** 10.13
- **Evidence:** e
- **Definition:** Uses obsolete, misconfigured, homemade, or unsuitable algorithms, modes, keys, or key management for the protection required.

## 2. Scenario

### 2.1 Context

The application must store reset-token verifiers.

### 2.2 Safer approach

Use the organization’s approved cryptographic library and current password or token-verification construction with managed keys and documented parameters.

### 2.3 Failure mode

The agent writes a custom reversible transformation because it is simple to implement and does not require an added dependency.

### 2.4 Why this difference matters

Seemingly functional protection can be weak, misused, or impossible to manage safely, exposing security-sensitive data.

## 3. Boundaries and distinctions

The suitable construction depends on the goal, such as hashing a password versus encrypting recoverable data. Standard libraries still need correct configuration and key handling.
