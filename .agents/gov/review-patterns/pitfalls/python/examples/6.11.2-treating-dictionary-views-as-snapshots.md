# Treating dictionary views as snapshots

## 1. Catalog record

- **Catalog identifier:** 6.11.2
- **Impact:** medium
- **Consensus:** high
- **Definition:** Materialize `list(d.keys())`, `list(d.items())`, or similar when a snapshot is required rather than storing a view and assuming it is frozen.

## 2. Example

### 2.1 Scenario

An audit records the keys present at the beginning of a configuration update.

### 2.2 Preferred form

```python
config = {"region": "us"}
keys_at_start = list(config.keys())
config["retries"] = 3
print(keys_at_start)  # ['region']
```

### 2.3 Hazardous form

```python
config = {"region": "us"}
keys_at_start = config.keys()
config["retries"] = 3
print(list(keys_at_start))  # ['region', 'retries']
```

### 2.4 Why this difference matters

Dictionary views are live views, so later mutations change what a stored view exposes.

## 3. Boundaries and distinctions

Keep a view when live reflection of the mapping is desirable and consumers can tolerate its changing contents.
