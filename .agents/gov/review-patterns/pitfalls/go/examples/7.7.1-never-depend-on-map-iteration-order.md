# Never depend on map iteration order

## 1. Catalog record

- **Catalog identifier:** 7.7.1
- **Impact:** medium
- **Consensus:** high
- **Definition:** Sort keys or otherwise establish an order when deterministic output or processing is required.

## 2. Example

### 2.1 Scenario

A report must emit customer names in a stable order for users and tests.

### 2.2 Preferred form

```go
package report

import "sort"

func names(customers map[string]int) []string {
	result := make([]string, 0, len(customers))
	for name := range customers { result = append(result, name) }
	sort.Strings(result)
	return result
}
```

### 2.3 Hazardous form

```go
package report

func names(customers map[string]int) []string {
	result := make([]string, 0, len(customers))
	for name := range customers { result = append(result, name) }
	return result
}
```

### 2.4 Why this difference matters

Go deliberately leaves map iteration order unspecified, so the hazardous report can change order across runs.

## 3. Boundaries and distinctions

No sort is needed when order is irrelevant and consumers do not observe it.
