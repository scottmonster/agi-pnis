# Keep side-effect-only imports localized

## 1. Catalog record

- **Catalog identifier:** 13.6.1
- **Impact:** low
- **Consensus:** high
- **Definition:** Blank imports used solely for initialization side effects should generally live in `main` packages or tests that explicitly require them.

## 2. Example

### 2.1 Scenario

A profiling endpoint needs to be registered only by the executable that exposes its administrative server.

### 2.2 Preferred form

```go
package main

import (
	"net/http"
	_ "net/http/pprof"
)

func main() {
	_ = http.ListenAndServe("127.0.0.1:6060", nil)
}
```

### 2.3 Hazardous form

```go
package metrics

import _ "net/http/pprof"

func Enabled() bool { return true }
```

### 2.4 Why this difference matters

The executable makes the global registration explicit at the application boundary. A library blank import silently changes the process-wide default HTTP mux for every importer.

## 3. Boundaries and distinctions

Blank imports are correct when registration is the intended dependency. Put them as close as practical to the executable or test that relies on the side effect.
