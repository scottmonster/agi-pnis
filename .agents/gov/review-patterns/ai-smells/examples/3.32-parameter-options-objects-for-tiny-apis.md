# Parameter/options objects for tiny APIs

## 1. Catalog record

- **Catalog identifier:** 3.32
- **Evidence:** se
- **Definition:** A simple two-argument operation becomes an extensible configuration protocol.

## 2. Scenario

### 2.1 Context

The application archives a document with its path and retention date.

### 2.2 Safer approach

Expose `archive(path, retentionDate)` with clear parameter names.

### 2.3 Failure mode

Replace it with an `ArchiveOptions` protocol containing extensible nested fields that no caller needs.

### 2.4 Why this difference matters

The options object obscures a small operation and creates defaulting and compatibility obligations.

## 3. Boundaries and distinctions

An options object can help when many independently optional inputs are real and stable; a tiny readable API need not anticipate them.
