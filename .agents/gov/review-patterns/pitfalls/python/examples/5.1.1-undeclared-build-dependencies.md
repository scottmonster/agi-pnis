# Undeclared build dependencies

## 1. Catalog record

- **Catalog identifier:** 5.1.1
- **Impact:** high
- **Consensus:** high
- **Definition:** Declare the build backend and all required build-time dependencies in `[build-system]` rather than depending on packages that happen to exist in the developer's environment.

## 2. Example

### 2.1 Scenario

A project build imports a package that is required before its wheel can be built.

### 2.2 Preferred form

```python
pyproject_toml = """\
[build-system]
requires = ["setuptools>=68", "wheel"]
build-backend = "setuptools.build_meta"
"""

assert "requires" in pyproject_toml
```

### 2.3 Hazardous form

```python
def build_wheel() -> None:
    import wheel  # Present only in the developer's environment.

    print(wheel.__version__)


build_wheel()
```

### 2.4 Why this difference matters

Build frontends commonly use isolated environments. A package available on one developer machine is absent there unless it is declared as a build requirement.

## 3. Boundaries and distinctions

Only dependencies needed to build the project belong in `[build-system]`; ordinary runtime dependencies belong in the project's dependency metadata.
