# Redundant computation

## 1. Catalog record

- **Catalog identifier:** 7.3
- **Evidence:** e
- **Definition:** Repeats an expensive operation instead of retaining the result locally.

## 2. Scenario

### 2.1 Context

An agent formats a report with several fields derived from the same parsed configuration.

### 2.2 Safer approach

It parses the configuration once, stores the result in a local variable, and derives all fields from it.

### 2.3 Failure mode

It reparses the same configuration separately for every output field.

### 2.4 Why this difference matters

Repeated expensive work adds latency without changing the report.

## 3. Boundaries and distinctions

Recomputation may be appropriate if the value can change between uses or caching would make correctness unclear; this failure concerns a stable result that can safely be retained locally.
