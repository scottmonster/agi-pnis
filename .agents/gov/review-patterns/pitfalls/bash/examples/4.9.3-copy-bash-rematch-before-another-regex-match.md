# Copy `BASH_REMATCH` before another regex match

## 1. Catalog record

- **Catalog identifier:** 4.9.3
- **Impact:** medium
- **Consensus:** high
- **Definition:** Copy captures from `BASH_REMATCH` before another regex operation can overwrite them.

## 2. Example

### 2.1 Scenario

A parser extracts a key and value, then calls a helper that performs another regex match.

### 2.2 Preferred form

```bash
#!/usr/bin/env bash

validate_value() {
  [[ $1 =~ ^[a-z]+$ ]]
}

record=${1:?provide key:value}
if [[ $record =~ ^([^:]+):(.+)$ ]]; then
  key=${BASH_REMATCH[1]}
  value=${BASH_REMATCH[2]}
  validate_value "$value" || exit 1
  printf '%s = %s\n' "$key" "$value"
fi
```

### 2.3 Hazardous form

```bash
#!/usr/bin/env bash

validate_value() {
  [[ $1 =~ ^[a-z]+$ ]]
}

record=${1:?provide key:value}
if [[ $record =~ ^([^:]+):(.+)$ ]]; then
  validate_value "${BASH_REMATCH[2]}" || exit 1
  printf '%s\n' "${BASH_REMATCH[1]}"
fi
```

### 2.4 Why this difference matters

`BASH_REMATCH` is overwritten by later `=~` operations, including those in helpers. Copy the captures while they still describe the match you need.

## 3. Boundaries and distinctions

This is especially important across function calls. A subsequent match in the same scope can overwrite the array as well.
