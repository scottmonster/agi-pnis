# Object.assign invokes getters and setters and can partially mutate

## 1. Catalog record

- **Catalog identifier:** 2.12.1
- **Impact:** medium
- **Consensus:** high
- **Definition:** Do not treat `Object.assign()` as a side-effect-free copy when accessors or failures are possible.

## 2. Example

### 2.1 Scenario

A program copies a source object whose values may be computed by getters.

### 2.2 Preferred form

```javascript
const source = {
  get token() {
    return "generated";
  },
};

const descriptors = Object.getOwnPropertyDescriptors(source);
const copy = Object.defineProperties({}, descriptors);
```

### 2.3 Hazardous form

```javascript
const source = {
  get token() {
    console.log("getter ran");
    return "generated";
  },
};

const copy = Object.assign({}, source);
```

### 2.4 Why this difference matters

`Object.assign()` reads source values and writes target values, invoking getters and setters. If a later write fails, earlier target mutations remain.

## 3. Boundaries and distinctions

`Object.assign()` is useful for intentional value copying when accessor effects and non-atomic updates are acceptable.
