# Test placement/framework mismatch

## 1. Catalog record

- **Catalog identifier:** 9.20
- **Evidence:** a
- **Definition:** Adds tests in the wrong directory, runner, fixture style, or convention.

## 2. Scenario

### 2.1 Context

A repository uses its configured integration-test directory and shared database fixtures for API tests.

### 2.2 Safer approach

Inspect nearby tests and runner configuration, then add the API test in the recognized directory using the established fixture style.

### 2.3 Failure mode

Put a Jest-style test under an ignored source folder in a repository whose runner discovers only Python tests.

### 2.4 Why this difference matters

The test may never run, fail in continuous integration, or bypass the setup needed to establish the actual behavior.

## 3. Boundaries and distinctions

New test conventions can be introduced deliberately, but only together with the runner configuration and migration needed to make them authoritative.
