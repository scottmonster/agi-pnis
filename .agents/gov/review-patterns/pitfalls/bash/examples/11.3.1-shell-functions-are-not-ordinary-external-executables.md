# Shell functions are not ordinary external executables

## 1. Catalog record

- **Catalog identifier:** 11.3.1
- **Impact:** low
- **Consensus:** high
- **Definition:** A Bash function exists in shell state and cannot simply be invoked by an unrelated process as though it were a file in `PATH`. Use an executable script when behavior must naturally cross process or privilege boundaries.

## 2. Example

### 2.1 Scenario

A cleanup operation must run with elevated privileges through `sudo`.

### 2.2 Preferred form

```bash
#!/usr/bin/env bash

cleanup_script=/usr/local/libexec/project-cleanup
sudo "$cleanup_script" /var/tmp/project-cache
```

### 2.3 Hazardous form

```bash
#!/usr/bin/env bash

cleanup_cache() {
  rm -rf -- "$1"
}

sudo cleanup_cache /var/tmp/project-cache
```

### 2.4 Why this difference matters

`sudo` starts another process and resolves executable commands. It does not receive the calling shell's function table, so the function name is not an executable command.

## 3. Boundaries and distinctions

Functions work normally within the same Bash process. They can be exported for carefully controlled child Bash processes, but an executable script is usually clearer across privilege or process boundaries.
