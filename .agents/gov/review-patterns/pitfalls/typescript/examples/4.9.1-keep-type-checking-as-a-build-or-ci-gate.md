# Keep type checking as a build or CI gate

## 1. Catalog record

- **Catalog identifier:** 4.9.1
- **Impact:** high
- **Consensus:** high
- **Definition:** If a bundler, transpiler, `--noCheck`, or transpile-only workflow emits JavaScript despite type errors, run a separate required type-checking step.

## 2. Example

### 2.1 Scenario

A bundler emits JavaScript even when a source file violates its declared contract.

### 2.2 Preferred form

```typescript
// package.json: "typecheck": "tsc --noEmit"
export function formatTotal(total: number): string {
  return total.toFixed(2);
}

formatTotal(12.5); // The required typecheck step validates this call.
```

### 2.3 Hazardous form

```typescript
// A transpile-only bundler may still emit this JavaScript.
export function formatTotal(total: number): string {
  return total.toFixed(2);
}

formatTotal('12.50');
```

### 2.4 Why this difference matters

Successful JavaScript emission does not mean TypeScript validation occurred or passed.

## 3. Boundaries and distinctions

Apply this guidance in the conditions described by the catalog record. Deliberate exceptions need a documented runtime guarantee, compatible toolchain behavior, or an explicit local unsafe boundary.
