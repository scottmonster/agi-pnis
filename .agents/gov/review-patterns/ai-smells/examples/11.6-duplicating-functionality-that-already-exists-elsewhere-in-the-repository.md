# Duplicating functionality that already exists elsewhere in the repository

## 1. Catalog record

- **Catalog identifier:** 11.6
- **Evidence:** e/se
- **Definition:** Adds a second implementation rather than locating, reusing, or extending the existing authoritative behavior.

## 2. Scenario

### 2.1 Context

An API endpoint needs to normalize phone numbers before storing customer records.

### 2.2 Safer approach

The agent searches the repository, finds the existing phone-normalization utility, and uses or extends it with tests.

### 2.3 Failure mode

The agent writes a new endpoint-local regular expression that performs nearly the same normalization with slightly different rules.

### 2.4 Why this difference matters

Two implementations drift, so different entry points can store the same phone number in incompatible forms.

## 3. Boundaries and distinctions

New code is appropriate when the existing behavior has a genuinely different contract; first establish that reuse or extension cannot serve the requirement.
