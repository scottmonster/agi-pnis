# Browser bare module specifiers require resolution support

## 1. Catalog record

- **Catalog identifier:** 8.1.10
- **Impact:** low
- **Consensus:** high
- **Definition:** Use bare browser module specifiers only with an import map or supported resolver.

## 2. Example

### 2.1 Scenario

A browser module imports a formatter used by a product page.

### 2.2 Preferred form

```javascript
// app.js, resolved relative to this module
import { formatPrice } from "./format-price.js";

console.log(formatPrice(1999));

// format-price.js
export function formatPrice(cents) {
  return `$${(cents / 100).toFixed(2)}`;
}
```

### 2.3 Hazardous form

```javascript
// app.js, loaded directly by a browser without an import map
import { formatPrice } from "format-price";

console.log(formatPrice(1999));
```

### 2.4 Why this difference matters

Browsers do not infer package resolution for a bare specifier, so the hazardous import fails unless an import map, bundler output, or another resolver supplies a target URL.

## 3. Boundaries and distinctions

Bare specifiers are valid when the deployment provides resolution support. Relative and absolute URL specifiers work directly in native browser module loading.
