# Custom enum/result/record abstractions where the language provides them

## 1. Catalog record

- **Catalog identifier:** 4.6
- **Evidence:** se
- **Definition:** Replaces a built-in language construct with a local equivalent that adds maintenance without capability.

## 2. Scenario

### 2.1 Context

An agent needs to represent a successful or failed parsing outcome in a language that supports discriminated unions and records.

### 2.2 Safer approach

It uses the language's built-in union and record features, with a `kind` discriminator that callers can exhaustively handle.

### 2.3 Failure mode

It introduces a `ParseResultBase` hierarchy, factory methods, custom tags, and accessors that merely reproduce the language's type and value constructs.

### 2.4 Why this difference matters

The local abstraction adds APIs to learn and maintain while offering no capability that the built-in construct lacks.

## 3. Boundaries and distinctions

A domain abstraction can be justified when it encapsulates meaningful behavior or interoperability. The failure is a local equivalent whose only effect is to replace an available language construct.
