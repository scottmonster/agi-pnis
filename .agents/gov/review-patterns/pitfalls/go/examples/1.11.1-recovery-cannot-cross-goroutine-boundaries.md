# Recovery cannot cross goroutine boundaries

## 1. Catalog record

- **Catalog identifier:** 1.11.1
- **Impact:** high
- **Consensus:** high
- **Definition:** A panic must be recovered by a deferred function running in the same goroutine. A parent or supervisor goroutine cannot recover another goroutine's panic.

## 2. Example

### 2.1 Scenario

A service runs an isolated extension in a goroutine and needs to contain its panic.

### 2.2 Preferred form

```go
package main

func runExtension(fn func()) (panicked bool) {
	done := make(chan bool, 1)
	go func() {
		defer func() { done <- recover() != nil }()
		fn()
	}()
	return <-done
}
```

### 2.3 Hazardous form

```go
package main

func runExtension(fn func()) {
	defer func() { _ = recover() }()
	go fn()
}
```

### 2.4 Why this difference matters

The parent defer runs only in the parent goroutine, so it cannot recover a panic from `fn`. An unrecovered child panic terminates the process.

## 3. Boundaries and distinctions

Recover only where the application can establish a safe failure boundary and report or handle the fault. Recovery is not a substitute for avoiding ordinary panics.
