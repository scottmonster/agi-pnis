# Hidden dependency

## 1. Catalog record

- **Catalog identifier:** 8.4
- **Evidence:** e
- **Definition:** Code works only because something happens to be globally installed or supplied transitively.

## 2. Scenario

### 2.1 Context

An agent adds a formatting command to a repository's CI script after running it successfully on a workstation with many developer tools installed.

### 2.2 Safer approach

It identifies which executable provides the command, declares it directly in the relevant toolchain configuration, and verifies the script in a fresh CI-like environment with only declared dependencies available.

### 2.3 Failure mode

It commits a script that calls `prettier` without adding it to the project. The command works locally because another global installation is on the path, but a clean CI runner cannot find it.

### 2.4 Why this difference matters

An implicit machine or transitive dependency makes results vary by environment, producing avoidable CI failures and fragile maintenance.

## 3. Boundaries and distinctions

This is not a complaint about legitimate transitive dependencies managed by the package resolver. The failure occurs when project behavior relies on one without declaring or provisioning the required capability explicitly.
