# Use arrow functions only when lexical this is desired

## 1. Catalog record

- **Catalog identifier:** 1.1.14
- **Impact:** medium
- **Consensus:** high
- **Definition:** Arrow functions do not define their own `this`, `arguments`, or constructor behavior. Use an ordinary function when call-site `this` or construction is part of the contract.

## 2. Example

### 2.1 Scenario

A reusable formatter is invoked with a caller-provided prefix as its receiver.

### 2.2 Preferred form

```javascript
"use strict";

function format(value) {
  return `${this.prefix}${value}`;
}

console.log(format.call({ prefix: "ID-" }, 42));
```

### 2.3 Hazardous form

```javascript
"use strict";

const format = (value) => `${this.prefix}${value}`;

console.log(format.call({ prefix: "ID-" }, 42));
```

### 2.4 Why this difference matters

`call()` supplies a receiver to an ordinary function, but it cannot replace the lexical `this` captured by the arrow function.

## 3. Boundaries and distinctions

Arrow functions are useful for callbacks that should inherit the surrounding receiver. They are not suitable for methods or constructors that require dynamic `this`.
