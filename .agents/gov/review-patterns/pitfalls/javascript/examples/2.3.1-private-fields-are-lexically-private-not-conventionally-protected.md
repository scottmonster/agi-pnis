# Private fields are lexically private, not conventionally protected

## 1. Catalog record

- **Catalog identifier:** 2.3.1
- **Impact:** medium
- **Consensus:** high
- **Definition:** Do not expect a subclass to access a superclass private field.

## 2. Example

### 2.1 Scenario

A base account keeps its balance private while a subclass needs a public summary.

### 2.2 Preferred form

```javascript
class Account {
  #balance = 50;

  getBalance() {
    return this.#balance;
  }
}

class PremiumAccount extends Account {
  summary() {
    return `Balance: ${this.getBalance()}`;
  }
}
```

### 2.3 Hazardous form

```javascript
class Account {
  #balance = 50;
}

class PremiumAccount extends Account {
  summary() {
    return `Balance: ${this.#balance}`;
  }
}
```

### 2.4 Why this difference matters

The hazardous class fails to parse because `#balance` is declared only in the lexical body of `Account`.

## 3. Boundaries and distinctions

Private fields provide strong encapsulation. Expose an intentionally designed method or protected-by-convention API when subclasses need access.
