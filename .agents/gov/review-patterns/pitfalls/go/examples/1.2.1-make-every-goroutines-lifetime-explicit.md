# Make every goroutine's lifetime explicit

## 1. Catalog record

- **Catalog identifier:** 1.2.1
- **Impact:** high
- **Consensus:** high
- **Definition:** Every goroutine should have a clear condition under which it exits. Avoid goroutines that can remain indefinitely blocked after their work is no longer needed.

## 2. Example

### 2.1 Scenario

A background worker accepts jobs until the service shuts down.

### 2.2 Preferred form

```go
package main

import "context"

func runWorker(ctx context.Context, jobs <-chan string) {
	for {
		select {
		case job, ok := <-jobs:
			if !ok {
				return
			}
			_ = job
		case <-ctx.Done():
			return
		}
	}
}
```

### 2.3 Hazardous form

```go
package main

func runWorker(jobs <-chan string) {
	for {
		job := <-jobs
		_ = job
	}
}
```

### 2.4 Why this difference matters

The hazardous worker has no shutdown condition and can remain blocked forever if no more jobs arrive. The preferred form exits on cancellation or channel closure.

## 3. Boundaries and distinctions

An intentionally permanent goroutine still needs an owner and documented lifecycle. A closed channel alone is sufficient only when it is the worker's intended termination signal.
