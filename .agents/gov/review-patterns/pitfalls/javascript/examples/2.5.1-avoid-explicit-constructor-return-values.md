# Avoid explicit constructor return values

## 1. Catalog record

- **Catalog identifier:** 2.5.1
- **Impact:** medium
- **Consensus:** high
- **Definition:** Rely on the implicit instance return unless replacement-object semantics are intended.

## 2. Example

### 2.1 Scenario

A user class initializes a stable instance with an identifier.

### 2.2 Preferred form

```javascript
class User {
  constructor(id) {
    this.id = id;
  }
}

console.log(new User("u-42") instanceof User);
```

### 2.3 Hazardous form

```javascript
class User {
  constructor(id) {
    this.id = id;
    return { id };
  }
}

console.log(new User("u-42") instanceof User);
```

### 2.4 Why this difference matters

Returning an object replaces the constructed instance, so callers receive an object without `User` methods or its prototype.

## 3. Boundaries and distinctions

An explicit object return can implement a deliberate factory-like replacement, but it should be a conspicuous API decision.
