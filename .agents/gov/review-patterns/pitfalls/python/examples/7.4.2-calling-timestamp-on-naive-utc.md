# Calling `timestamp()` on naive UTC

## 1. Catalog record

- **Catalog identifier:** 7.4.2
- **Impact:** medium
- **Consensus:** high
- **Definition:** Attach or retain the correct timezone before converting a datetime to a timestamp rather than passing a naive UTC value to `.timestamp()`.

## 2. Example

### 2.1 Scenario

A UTC calendar value is converted to a Unix timestamp.

### 2.2 Preferred form

```python
from datetime import UTC, datetime

utc_value = datetime(2026, 1, 1, 12, 0, tzinfo=UTC)
print(utc_value.timestamp())
```

### 2.3 Hazardous form

```python
from datetime import datetime

utc_value = datetime(2026, 1, 1, 12, 0)
print(utc_value.timestamp())
```

### 2.4 Why this difference matters

`timestamp()` treats a naive datetime as local time, so the resulting instant can shift with the machine timezone.

## 3. Boundaries and distinctions

If a naive value really represents local time, attach the relevant local timezone intentionally before converting it.
