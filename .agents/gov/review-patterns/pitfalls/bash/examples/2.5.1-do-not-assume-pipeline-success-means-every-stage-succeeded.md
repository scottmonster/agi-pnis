# Do not assume pipeline success means every stage succeeded

## 1. Catalog record

- **Catalog identifier:** 2.5.1
- **Impact:** high
- **Consensus:** high
- **Definition:** Without `pipefail`, a pipeline's status is normally the status of its final command. Where upstream failure matters, inspect `PIPESTATUS`, use an appropriate `pipefail` scope, or redesign the operation to propagate status explicitly.

## 2. Example

### 2.1 Scenario

A backup script compresses database output and must fail if the dump command fails, even if the compressor accepts an empty stream.

### 2.2 Preferred form

```bash
#!/usr/bin/env bash
set -euo pipefail

dump_database | gzip -c > backup.sql.gz
```

### 2.3 Hazardous form

```bash
#!/usr/bin/env bash
set -eu

dump_database | gzip -c > backup.sql.gz
```

### 2.4 Why this difference matters

Without `pipefail`, Bash reports the status of `gzip`, which can succeed after receiving no useful data. The script can therefore accept an incomplete backup after `dump_database` fails.

## 3. Boundaries and distinctions

Use `pipefail` where every pipeline stage is required to succeed. If a stage is allowed to fail, handle its status deliberately rather than making a global assumption about all pipelines.
