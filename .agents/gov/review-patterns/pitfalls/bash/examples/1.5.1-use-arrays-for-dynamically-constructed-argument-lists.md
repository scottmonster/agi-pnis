# Use arrays for dynamically constructed argument lists

## 1. Catalog record

- **Catalog identifier:** 1.5.1
- **Impact:** high
- **Consensus:** high
- **Definition:** Store a command's arguments in an array and invoke it with `"${args[@]}"`. Do not build a single string containing shell quotes or escaped spaces and expect those characters to become shell syntax when the variable expands.

## 2. Example

### 2.1 Scenario

A deployment script optionally adds a destination directory whose name may contain spaces before invoking `rsync`.

### 2.2 Preferred form

```bash
#!/usr/bin/env bash

source_dir='build output/'
destination='/srv/releases/April build/'
args=(rsync -a -- "$source_dir")

if [[ -n $destination ]]; then
  args+=("$destination")
fi

"${args[@]}"
```

### 2.3 Hazardous form

```bash
#!/usr/bin/env bash

source_dir='build output/'
destination='/srv/releases/April build/'
command="rsync -a -- '$source_dir' '$destination'"

$command
```

### 2.4 Why this difference matters

The array keeps each argument as a separate value, including values with spaces. The string form does not make its embedded quotes active syntax, so expansion splits the paths into different arguments.

## 3. Boundaries and distinctions

An array is appropriate when Bash is invoking a command with dynamically assembled arguments. It does not serialize a command for a remote shell or another parser, which needs its own deliberate data-passing interface.
