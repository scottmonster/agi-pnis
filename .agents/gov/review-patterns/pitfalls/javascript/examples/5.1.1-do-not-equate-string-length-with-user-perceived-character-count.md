# Do not equate string length with user-perceived character count

## 1. Catalog record

- **Catalog identifier:** 5.1.1
- **Impact:** medium
- **Consensus:** high
- **Definition:** JavaScript strings are sequences of UTF-16 code units. `length`, indexing, and some slicing operations therefore do not necessarily correspond to Unicode code points or grapheme clusters.

## 2. Example

### 2.1 Scenario

A profile form limits a display name to three user-perceived characters.

### 2.2 Preferred form

```javascript
function countGraphemes(text, locale = "en") {
  const segmenter = new Intl.Segmenter(locale, { granularity: "grapheme" });
  return [...segmenter.segment(text)].length;
}

const displayName = "A🙂é";
console.log(countGraphemes(displayName) <= 3); // true
```

### 2.3 Hazardous form

```javascript
const displayName = "A🙂é";
console.log(displayName.length <= 3); // false: UTF-16 code units, not graphemes
```

### 2.4 Why this difference matters

The hazardous check rejects three visible characters because an emoji and a combining character occupy multiple UTF-16 code units.

## 3. Boundaries and distinctions

`String.length` is appropriate when an API explicitly measures UTF-16 code units. Grapheme segmentation is needed only when the product requirement is based on user-perceived characters.
