# Mutable values with `dict.fromkeys()`

## 1. Catalog record

- **Catalog identifier:** 6.9.1
- **Impact:** medium
- **Consensus:** high
- **Definition:** Do not use `dict.fromkeys(keys, mutable_object)` when each key needs independent mutable state. Use a comprehension.

## 2. Example

### 2.1 Scenario

A report groups messages by service and appends each message to that service's list.

### 2.2 Preferred form

```python
services = ["api", "worker"]
messages = {service: [] for service in services}
messages["api"].append("request received")
print(messages)  # {'api': ['request received'], 'worker': []}
```

### 2.3 Hazardous form

```python
services = ["api", "worker"]
messages = dict.fromkeys(services, [])
messages["api"].append("request received")
print(messages)  # Both keys refer to the same list.
```

### 2.4 Why this difference matters

`fromkeys()` stores the exact same list object for every key, so an update for one service appears under all services.

## 3. Boundaries and distinctions

`dict.fromkeys()` is fine with an immutable shared value, such as `None` or `0`, or when sharing one mutable object is intentional.
