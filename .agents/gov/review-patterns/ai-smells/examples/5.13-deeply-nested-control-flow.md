# Deeply nested control flow

## 1. Catalog record

- **Catalog identifier:** 5.13
- **Evidence:** se
- **Definition:** Layers of guards and conditionals make the actual path difficult to see.

## 2. Scenario

### 2.1 Context

An import loop nests account checks, row checks, permission checks, feature checks, and parsing checks before it finally saves a row.

### 2.2 Safer approach

Use clear guard clauses or focused helpers so the successful path and each rejection are visible.

### 2.3 Failure mode

Wrap a new validation rule in another `if` inside the deepest existing block.

### 2.4 Why this difference matters

The true execution path is obscured, making missing cases and incorrect side effects more likely.

## 3. Boundaries and distinctions

Some nesting reflects real dependent conditions. The concern is depth that hides the main path when equivalent structure can clarify it.
