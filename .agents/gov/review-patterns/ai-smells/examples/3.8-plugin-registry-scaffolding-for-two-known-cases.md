# Plugin/registry scaffolding for two known cases

## 1. Catalog record

- **Catalog identifier:** 3.8
- **Evidence:** se
- **Definition:** Registry, base interface, dynamic lookup, and subclasses replace a straightforward branch.

## 2. Scenario

### 2.1 Context

An export endpoint supports CSV and JSON, selected by a request field.

### 2.2 Safer approach

Use a clear branch that calls the two serializers and rejects other formats.

### 2.3 Failure mode

Build a plugin registry, formatter base type, dynamic imports, and subclasses for those two formats.

### 2.4 Why this difference matters

The moving parts conceal a tiny closed decision and introduce registration failure paths.

## 3. Boundaries and distinctions

A registry can fit independently supplied or frequently changing extensions; two owned fixed cases usually do not need it.
