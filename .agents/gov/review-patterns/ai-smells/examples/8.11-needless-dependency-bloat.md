# Needless dependency bloat

## 1. Catalog record

- **Catalog identifier:** 8.11
- **Evidence:** se
- **Definition:** Adds packages whose small benefit does not justify their maintenance, update, and supply-chain cost.

## 2. Scenario

### 2.1 Context

An agent needs to turn a kebab-case option name into a display label in a small command-line tool.

### 2.2 Safer approach

It uses a short local transformation with existing language features and adds a focused test for the displayed label.

### 2.3 Failure mode

It adds a large string-utility package solely to capitalize and replace hyphens in one label, even though no other project use needs that package.

### 2.4 Why this difference matters

The dependency adds updates, licensing review, vulnerability monitoring, and installation weight for negligible implementation benefit.

## 3. Boundaries and distinctions

Add a dependency when it supplies substantial, maintained behavior the project genuinely needs. This is not an argument against reusable libraries, only against packages whose small benefit cannot justify their ongoing cost.
