# Temporary feature flags/TODOs become permanent

## 1. Catalog record

- **Catalog identifier:** 11.16
- **Evidence:** se
- **Definition:** Leaves provisional controls or deferred work without ownership, expiry, or a plan to resolve them.

## 2. Scenario

### 2.1 Context

A new search ranking algorithm is rolled out behind a temporary configuration flag.

### 2.2 Safer approach

The agent assigns an owner and removal date, defines the rollout decision, and removes the flag after the evaluation concludes.

### 2.3 Failure mode

The agent adds `USE_NEW_RANKING` and a TODO but provides no owner, deadline, or criteria for deleting either path.

### 2.4 Why this difference matters

The old and new behavior remain indefinitely, increasing configuration complexity and test combinations.

## 3. Boundaries and distinctions

Temporary controls are appropriate for bounded rollout or risk mitigation when their lifecycle is explicit; unowned provisional code becomes permanent debt.
