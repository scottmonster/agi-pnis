# Use `crypto/rand` for security-sensitive randomness

## 1. Catalog record

- **Catalog identifier:** 4.2.1
- **Impact:** high
- **Consensus:** high
- **Definition:** Generate keys, tokens, nonces, session identifiers, and other secrets with `crypto/rand`, not `math/rand` or `math/rand/v2`.

## 2. Example

### 2.1 Scenario

An application issues an opaque session token that an attacker must not be able to predict.

### 2.2 Preferred form

```go
package example

import (
	"crypto/rand"
	"encoding/hex"
)

func newSessionToken() (string, error) {
	b := make([]byte, 32)
	if _, err := rand.Read(b); err != nil {
		return "", err
	}
	return hex.EncodeToString(b), nil
}
```

### 2.3 Hazardous form

```go
package example

import (
	"encoding/hex"
	"math/rand"
)

func newSessionToken() string {
	b := make([]byte, 32)
	for i := range b {
		b[i] = byte(rand.Intn(256))
	}
	return hex.EncodeToString(b)
}
```

### 2.4 Why this difference matters

`crypto/rand` obtains unpredictable bytes from the operating system. The `math/rand` generator is designed for simulation and can produce predictable values, allowing session takeover.

## 3. Boundaries and distinctions

`math/rand` remains suitable for non-security uses such as randomized tests, sampling, and simulations. Security-sensitive identifiers need cryptographic unpredictability, not merely uniqueness.
