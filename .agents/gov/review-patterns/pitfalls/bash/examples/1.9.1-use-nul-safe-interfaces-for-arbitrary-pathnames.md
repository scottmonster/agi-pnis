# Use NUL-safe interfaces for arbitrary pathnames

## 1. Catalog record

- **Catalog identifier:** 1.9.1
- **Impact:** high
- **Consensus:** high
- **Definition:** For pathname streams, prefer `find -exec ... {} +` or NUL-delimited pairs such as `find -print0` with `xargs -0` or `read -d ''`.

## 2. Example

### 2.1 Scenario

A backup script sends every regular file below a selected directory to a command one pathname at a time. The directory may contain spaces, newlines, and wildcard characters in names.

### 2.2 Preferred form

```bash
#!/usr/bin/env bash

source_dir=${1:?Usage: "$0" SOURCE_DIR}

while IFS= read -r -d '' path; do
  printf 'Backing up: %s\n' "$path"
done < <(find "$source_dir" -type f -print0)
```

### 2.3 Hazardous form

```bash
#!/usr/bin/env bash

source_dir=${1:?Usage: "$0" SOURCE_DIR}

for path in $(find "$source_dir" -type f); do
  printf 'Backing up: %s\n' "$path"
done
```

### 2.4 Why this difference matters

Command substitution turns the `find` output into text that Bash splits on `IFS` and then expands as path patterns. A single pathname with whitespace or a newline becomes several loop values, while a pathname containing `*` can be expanded again. NUL-delimited input preserves each original pathname.

## 3. Boundaries and distinctions

For a simple external command, `find -exec command {} +` avoids a pathname stream altogether and is often preferable. Newline-delimited text is acceptable only when the producer guarantees that values cannot contain newlines and consumers do not treat it as arbitrary pathnames.
