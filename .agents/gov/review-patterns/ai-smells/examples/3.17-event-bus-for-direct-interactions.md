# Event bus for direct interactions

## 1. Catalog record

- **Catalog identifier:** 3.17
- **Evidence:** se
- **Definition:** Publisher/subscriber infrastructure replaces a normal function call with no actual decoupling requirement.

## 2. Scenario

### 2.1 Context

Submitting an order must immediately reserve inventory.

### 2.2 Safer approach

Call the inventory reservation operation directly and handle its result.

### 2.3 Failure mode

Publish an `OrderSubmitted` event to a local bus with one synchronous subscriber solely to invoke reservation.

### 2.4 Why this difference matters

The event route hides sequencing and error handling while providing no independent consumer.

## 3. Boundaries and distinctions

Events can fit multiple independent consumers or asynchronous integration; a single direct dependency does not automatically need a bus.
