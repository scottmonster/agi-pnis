# High-cardinality/unbounded logging or metrics

## 1. Catalog record

- **Catalog identifier:** 12.9
- **Evidence:** se
- **Definition:** Uses unbounded values such as user IDs, URLs, or request bodies as metric dimensions or log fields, increasing cost and reducing query usefulness.

## 2. Scenario

### 2.1 Context

An HTTP latency metric labels every series with the complete request URL, including arbitrary search terms and generated identifiers.

### 2.2 Safer approach

Use a bounded route template such as `/search` as the metric dimension, and record carefully selected request detail only where operationally justified.

### 2.3 Failure mode

Emit a new metric label value for every raw URL to make later filtering seem more convenient.

### 2.4 Why this difference matters

The metric backend accumulates an unbounded number of series, increasing cost and making aggregate queries less useful.

## 3. Boundaries and distinctions

This targets uncontrolled values in telemetry dimensions or fields. It does not prohibit bounded identifiers or intentionally protected diagnostic records with retention controls.
