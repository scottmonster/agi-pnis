# Avoid repeatedly copying a growing reduce accumulator

## 1. Catalog record

- **Catalog identifier:** 3.1.13
- **Impact:** medium
- **Consensus:** high
- **Definition:** Be cautious with reducers that create a fresh object or array by spreading the entire accumulator on every iteration. Mutate a local accumulator or use a more suitable construction when immutability is not required at each intermediate step.

## 2. Example

### 2.1 Scenario

An import groups many records by status before saving a local result.

### 2.2 Preferred form

```javascript
const records = [{ status: "open" }, { status: "closed" }, { status: "open" }];
const counts = {};

for (const record of records) {
  counts[record.status] = (counts[record.status] ?? 0) + 1;
}

console.log(counts); // { open: 2, closed: 1 }
```

### 2.3 Hazardous form

```javascript
const records = [{ status: "open" }, { status: "closed" }, { status: "open" }];
const counts = records.reduce(
  (accumulator, record) => ({
    ...accumulator,
    [record.status]: (accumulator[record.status] ?? 0) + 1,
  }),
  {},
);

console.log(counts); // { open: 2, closed: 1 }
```

### 2.4 Why this difference matters

The hazardous reducer copies every accumulated property at each step, which can become quadratic work as the result grows.

## 3. Boundaries and distinctions

Repeated copies can be reasonable for small inputs or when immutable intermediate values are required. Prefer a local mutable accumulator when they are not.
