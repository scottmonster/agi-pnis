# Close dynamically allocated file descriptors when finished

## 1. Catalog record

- **Catalog identifier:** 8.6.2
- **Impact:** medium
- **Consensus:** high
- **Definition:** Redirections such as `exec {fd}>file` allocate a descriptor that can remain open beyond one command, so close persistent descriptors explicitly when their lifetime ends.

## 2. Example

### 2.1 Scenario

A script opens a log file for several related writes.

### 2.2 Preferred form

```bash
log_file=./build.log
exec {log_fd}>>"$log_file"
printf 'started\n' >&"$log_fd"
printf 'finished\n' >&"$log_fd"
exec {log_fd}>&-
```

### 2.3 Hazardous form

```bash
log_file=./build.log
exec {log_fd}>>"$log_file"
printf 'started\n' >&"$log_fd"
printf 'finished\n' >&"$log_fd"
# The descriptor remains open until the shell exits.
```

### 2.4 Why this difference matters

An open descriptor can keep a file, pipe, or socket alive longer than intended. In particular, a leaked pipe write end can prevent a reader from seeing EOF.

## 3. Boundaries and distinctions

Short-lived redirections attached to one command close automatically. Explicit closure is needed for a descriptor opened with `exec` for later reuse.
