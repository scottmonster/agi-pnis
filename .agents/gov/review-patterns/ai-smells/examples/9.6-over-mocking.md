# Over-mocking

## 1. Catalog record

- **Catalog identifier:** 9.6
- **Evidence:** se
- **Definition:** Mocks away the integration or behavior the test is supposed to establish.

## 2. Scenario

### 2.1 Context

An endpoint validates a request, saves a user, and maps a duplicate email to a conflict response.

### 2.2 Safer approach

Exercise the endpoint with a real test database or repository implementation that can produce the duplicate condition.

### 2.3 Failure mode

Mock validation, persistence, and error mapping so every dependency returns the expected success object.

### 2.4 Why this difference matters

The test can pass even when the real components disagree about data shape or error handling.

## 3. Boundaries and distinctions

Mocks remain useful for unavailable, slow, or hazardous external systems, provided the behavior they replace is covered at a suitable boundary elsewhere.
