# Separate a negative substring offset from `:`

## 1. Catalog record

- **Catalog identifier:** 11.4.1
- **Impact:** low
- **Consensus:** high
- **Definition:** Write forms such as `${value: -1}` when using a negative substring offset. Without separation, `:-` is parsed as the default-value parameter operator.

## 2. Example

### 2.1 Scenario

A script needs the final character of an optional version suffix.

### 2.2 Preferred form

```bash
#!/usr/bin/env bash

suffix='release-7'
last_character=${suffix: -1}
echo "last character: $last_character"
```

### 2.3 Hazardous form

```bash
#!/usr/bin/env bash

suffix='release-7'
last_character=${suffix:-1}
echo "last character: $last_character"
```

### 2.4 Why this difference matters

Without the space, Bash interprets `:-1` as a default-value expansion, so a nonempty suffix produces the entire suffix rather than its final character.

## 3. Boundaries and distinctions

The separating space is necessary for a negative offset. Positive offsets do not conflict with the `:-` default-value operator.
