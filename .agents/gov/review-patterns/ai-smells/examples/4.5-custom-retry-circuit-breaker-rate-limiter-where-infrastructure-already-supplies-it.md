# Custom retry/circuit-breaker/rate-limiter where infrastructure already supplies it

## 1. Catalog record

- **Catalog identifier:** 4.5
- **Evidence:** se
- **Definition:** Recreates resilience controls that the platform, gateway, or service mesh can apply more consistently.

## 2. Scenario

### 2.1 Context

An agent adds protection for a public API that is already routed through a gateway with configured rate limits and retry policies.

### 2.2 Safer approach

It verifies the gateway configuration, adjusts the shared policy where needed, and exposes application metrics that make the policy observable.

### 2.3 Failure mode

It adds per-process in-memory counters and retry loops in each service, producing inconsistent limits across replicas and retry behavior that ignores gateway policy.

### 2.4 Why this difference matters

Central infrastructure can enforce a consistent policy across services and instances, while local controls fragment behavior and operations.

## 3. Boundaries and distinctions

Implement application-level resilience behavior when infrastructure cannot see the needed business context or does not provide the control. This failure applies where the platform, gateway, or service mesh already supplies it.
