# Model variants as discriminated unions

## 1. Catalog record

- **Catalog identifier:** 1.9.1
- **Impact:** high
- **Consensus:** high
- **Definition:** Prefer separate union members with a literal discriminant over one large object containing many optional fields plus assertions.

## 2. Example

### 2.1 Scenario

A payment can be a card payment or a bank transfer with different required data.

### 2.2 Preferred form

```typescript
type Payment =
  | { kind: 'card'; lastFour: string }
  | { kind: 'bank'; iban: string };

function paymentLabel(payment: Payment): string {
  return payment.kind === 'card'
    ? `Card ending ${payment.lastFour}`
    : `Bank transfer to ${payment.iban}`;
}
```

### 2.3 Hazardous form

```typescript
type Payment = {
  kind: 'card' | 'bank';
  lastFour?: string;
  iban?: string;
};

function paymentLabel(payment: Payment): string {
  return `Card ending ${payment.lastFour!}`;
}
```

### 2.4 Why this difference matters

The union lets TypeScript encode which fields can coexist and narrow them together, preventing impossible or partially initialized states.
