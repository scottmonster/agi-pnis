# Treating “tests pass” as equivalent to “requirement satisfied.”

## 1. Catalog record

- **Catalog identifier:** 13.16
- **Evidence:** a
- **Definition:** Equates a limited test result with full compliance despite possible missing requirements, coverage, or integration checks.

## 2. Scenario

### 2.1 Context

A feature request requires an export to include timezone-aware timestamps and document the format. Existing tests check only that an export file is created.

### 2.2 Safer approach

The agent runs the tests, inspects the output contract, adds coverage for timezone formatting, and updates the relevant documentation.

### 2.3 Failure mode

The agent sees the existing file-creation test pass and declares the request complete while timestamps remain naive and docs unchanged.

### 2.4 Why this difference matters

Passing tests establish only what they exercise. Requirements can include behavior, compatibility, and integration outside that surface.

## 3. Boundaries and distinctions

Tests are strong verification evidence, but they must be evaluated against the full requested contract and the coverage they actually provide.
