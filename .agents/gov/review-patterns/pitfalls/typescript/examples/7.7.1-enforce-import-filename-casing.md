# Enforce import filename casing

## 1. Catalog record

- **Catalog identifier:** 7.7.1
- **Impact:** medium
- **Consensus:** high
- **Definition:** Keep `forceConsistentCasingInFileNames` enabled.

## 2. Example

### 2.1 Scenario

A cross-platform application imports a component whose source file is named `UserProfile.tsx`. Developers use both case-insensitive laptops and case-sensitive Linux CI runners.

### 2.2 Preferred form

```typescript
// tsconfig.json: { "compilerOptions": { "forceConsistentCasingInFileNames": true } }

// src/profile-page.ts
import { UserProfile } from './UserProfile.js';

export { UserProfile };
```

### 2.3 Hazardous form

```typescript
// The file on disk is src/UserProfile.tsx.
// src/profile-page.ts
import { UserProfile } from './userProfile.js';

// A case-insensitive filesystem may accept this; Linux does not.
```

### 2.4 Why this difference matters

Case-insensitive filesystems can resolve `./userProfile.js` to `UserProfile.tsx`, allowing a bad specifier into the codebase. Case-sensitive CI, containers, and production hosts resolve names exactly and fail to find it. The compiler option detects inconsistent casing early and prevents filesystem-dependent builds.

## 3. Boundaries and distinctions

Keep the actual filename, every import specifier, generated declaration, and source-control rename aligned. The option does not repair case-only Git renames that a case-insensitive working tree fails to record, so verify those renames with version control. Respect a package's published filename casing when importing its subpaths.
