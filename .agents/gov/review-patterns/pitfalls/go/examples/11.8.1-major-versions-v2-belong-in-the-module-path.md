# Major versions v2+ belong in the module path

## 1. Catalog record

- **Catalog identifier:** 11.8.1
- **Impact:** medium
- **Consensus:** high
- **Definition:** A module reaching v2 or higher must normally include `/v2`, `/v3`, and so on in its module and import paths.

## 2. Example

### 2.1 Scenario

An API introduces an incompatible v2 encoding format while a consumer still uses v1.

### 2.2 Preferred form

```go
package example

import api "example.com/encode/v2"

func preferred(input string) ([]byte, error) {
	return api.Encode(input)
}
```

### 2.3 Hazardous form

```go
package example

import "example.com/encode"

func hazardous(input string) ([]byte, error) {
	// Publishing incompatible v2 behavior at this v1 path breaks consumers.
	return encode.Encode(input)
}
```

### 2.4 Why this difference matters

The import path makes incompatible major versions distinct packages, allowing v1 and v2 to coexist in a build.

## 3. Boundaries and distinctions

This convention normally applies from v2 onward. A documented semantic-import-versioning exception can exist, but it should not be assumed for ordinary modules.
