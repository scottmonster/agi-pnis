# Prefer `$(...)` to backtick command substitution

## 1. Catalog record

- **Catalog identifier:** 10.8.1
- **Impact:** low
- **Consensus:** high
- **Definition:** Both command-substitution forms work, but `$(command)` nests directly and has clearer quoting and escaping rules than legacy backticks.

## 2. Example

### 2.1 Scenario

A script builds a dated output name using a nested command substitution.

### 2.2 Preferred form

```bash
directory='reports'
output="$directory/$(date +%Y)-$(printf '%s' summary).txt"
printf '%s\n' "$output"
```

### 2.3 Hazardous form

```bash
directory='reports'
output="$directory/`date +%Y`-`printf '%s' summary`.txt"
printf '%s\n' "$output"
```

### 2.4 Why this difference matters

The backtick form can work here, but it becomes difficult to read and escape correctly when substitutions themselves contain quotes, backslashes, or nesting.

## 3. Boundaries and distinctions

Existing code using backticks need not be rewritten solely for style. Prefer `$(...)` in new or modified code, especially when nesting is likely.
