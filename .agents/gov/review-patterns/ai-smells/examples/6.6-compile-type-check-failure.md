# Compile/type-check failure

## 1. Catalog record

- **Catalog identifier:** 6.6
- **Evidence:** e
- **Definition:** The source parses but violates compile-time or static type rules.

## 2. Scenario

### 2.1 Context

A typed function returns a user identifier as a string.

### 2.2 Safer approach

The agent checks the declared return type and returns `user.id.toString()`.

### 2.3 Failure mode

It returns the numeric `user.id` from a function declared to return `string`.

### 2.4 Why this difference matters

The code is syntactically valid but the project's compiler rejects the build.

## 3. Boundaries and distinctions

This requires a compile-time or static type rule; a runtime type mismatch can escape a non-static environment.
