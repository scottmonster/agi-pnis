# Do not enable `pipefail` blindly around early-exiting consumers

## 1. Catalog record

- **Catalog identifier:** 4.2.1
- **Impact:** high
- **Consensus:** medium
- **Definition:** Scope `pipefail` deliberately when a consumer may exit early and cause an upstream SIGPIPE.

## 2. Example

### 2.1 Scenario

A health check only needs to know whether a log file contains the word `ready`.

### 2.2 Preferred form

```bash
#!/usr/bin/env bash
set -euo pipefail

log_file=${1:?provide a log file}
if grep -q -- 'ready' "$log_file"; then
  printf 'service is ready\n'
fi
```

### 2.3 Hazardous form

```bash
#!/usr/bin/env bash
set -euo pipefail

producer_that_writes_many_lines() {
  local line
  for (( line = 0; line < 1000; line++ )); do
    printf 'ready\n'
  done
}

if producer_that_writes_many_lines | grep -q -- 'ready'; then
  printf 'service is ready\n'
fi
```

### 2.4 Why this difference matters

`grep -q` may exit as soon as it finds a match. The producer can then receive SIGPIPE, and `pipefail` can report the successful check as a failed pipeline.

## 3. Boundaries and distinctions

Use `pipefail` when every pipeline stage must finish successfully. For intentional early consumers, use a direct input source or handle the producer's expected SIGPIPE status deliberately.
