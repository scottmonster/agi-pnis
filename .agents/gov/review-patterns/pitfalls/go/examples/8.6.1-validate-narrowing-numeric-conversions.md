# Validate narrowing numeric conversions

## 1. Catalog record

- **Catalog identifier:** 8.6.1
- **Impact:** medium
- **Consensus:** high
- **Definition:** Check ranges before converting untrusted or unconstrained numeric values to narrower integer types or between signed and unsigned representations.

## 2. Example

### 2.1 Scenario

A network message provides an untrusted length that an encoder must store in a 16-bit field.

### 2.2 Preferred form

```go
package wire

import "fmt"

func uint16Length(n int) (uint16, error) {
	if n < 0 || n > 65535 {
		return 0, fmt.Errorf("length %d is outside uint16 range", n)
	}
	return uint16(n), nil
}
```

### 2.3 Hazardous form

```go
package wire

func uint16Length(n int) uint16 {
	return uint16(n)
}
```

### 2.4 Why this difference matters

Go conversions truncate or reinterpret out-of-range values without reporting an error. A negative or oversized input can therefore encode an incorrect length and desynchronize the protocol.

## 3. Boundaries and distinctions

An unchecked conversion is fine when a preceding invariant, type, or protocol validation proves the range. Keep that guarantee close enough to the conversion that maintenance cannot silently invalidate it.
