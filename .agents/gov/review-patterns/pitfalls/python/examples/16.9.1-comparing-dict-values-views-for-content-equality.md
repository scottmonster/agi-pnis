# Comparing `dict.values()` views for content equality

## 1. Catalog record

- **Catalog identifier:** 16.9.1
- **Impact:** low
- **Consensus:** high
- **Definition:** Convert or compare values using a representation appropriate to the desired semantics rather than relying on `d.values() == other.values()`.

## 2. Example

### 2.1 Scenario

A validator must decide whether two inventories contain the same quantities, independent of their item keys.

### 2.2 Preferred form

```python
def same_quantities(left: dict[str, int], right: dict[str, int]) -> bool:
    return sorted(left.values()) == sorted(right.values())


print(same_quantities({"apple": 2, "pear": 1}, {"chair": 1, "desk": 2}))
```

### 2.3 Hazardous form

```python
def same_quantities(left: dict[str, int], right: dict[str, int]) -> bool:
    return left.values() == right.values()


print(same_quantities({"apple": 2, "pear": 1}, {"chair": 1, "desk": 2}))
```

### 2.4 Why this difference matters

Dictionary values views do not provide content-based equality, so the hazardous comparison does not test the inventory values as intended.

## 3. Boundaries and distinctions

Sorting compares multiplicity while ignoring order. Use `set(values)` only when duplicate counts are irrelevant, or compare `items()` when keys must also match.
