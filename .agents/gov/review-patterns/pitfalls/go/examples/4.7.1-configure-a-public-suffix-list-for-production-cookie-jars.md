# Configure a public suffix list for production cookie jars

## 1. Catalog record

- **Catalog identifier:** 4.7.1
- **Impact:** high
- **Consensus:** high
- **Definition:** Do not use a nil `cookiejar.Options.PublicSuffixList` for a multi-domain production client. Use an appropriate public suffix implementation.

## 2. Example

### 2.1 Scenario

A production HTTP client follows requests across multiple registrable domains and retains cookies between them.

### 2.2 Preferred form

```go
package example

import (
	"net/http/cookiejar"

	"golang.org/x/net/publicsuffix"
)

func newJar() (*cookiejar.Jar, error) {
	return cookiejar.New(&cookiejar.Options{
		PublicSuffixList: publicsuffix.List,
	})
}
```

### 2.3 Hazardous form

```go
package example

import "net/http/cookiejar"

func newJar() (*cookiejar.Jar, error) {
	return cookiejar.New(nil)
}
```

### 2.4 Why this difference matters

The public suffix list prevents the jar from accepting cookies for public suffixes such as `com`. A nil list weakens domain isolation and is unsuitable for a client that handles unrelated sites.

## 3. Boundaries and distinctions

For a deliberately single-site client, a cookie jar may not be needed at all. Keep the suffix-list dependency current and choose a reviewed implementation if the standard public suffix list does not fit the deployment.
