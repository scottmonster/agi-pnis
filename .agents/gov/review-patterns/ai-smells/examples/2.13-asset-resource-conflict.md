# Asset/resource conflict

## 1. Catalog record

- **Catalog identifier:** 2.13
- **Evidence:** e
- **Definition:** Assumes files, templates, migrations, fixtures, static assets, certificates, or other resources that do not exist.

## 2. Scenario

### 2.1 Context

A service sends a password-reset email from templates stored in the repository.

### 2.2 Safer approach

The agent lists the template directory and adds the required template source and build registration together.

### 2.3 Failure mode

It changes the mailer to load `password-reset-v2.html`, assuming the asset is already bundled.

### 2.4 Why this difference matters

The path works in no clean deployment, so a user-facing flow fails when the resource is loaded.

## 3. Boundaries and distinctions

Creating a new resource is valid when included in the change; the failure is assuming an untracked or nonexistent resource is available.
