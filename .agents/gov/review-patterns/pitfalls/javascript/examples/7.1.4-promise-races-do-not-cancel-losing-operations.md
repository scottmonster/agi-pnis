# Promise races do not cancel losing operations

## 1. Catalog record

- **Catalog identifier:** 7.1.4
- **Impact:** high
- **Consensus:** high
- **Definition:** Do not implement a timeout with `Promise.race()` and assume the losing network request or other operation stopped. Cancel the underlying operation explicitly, commonly with `AbortController`.

## 2. Example

### 2.1 Scenario

A client gives an HTTP request a short deadline and must stop the request when the deadline expires.

### 2.2 Preferred form

```javascript
async function fetchWithTimeout(url, milliseconds) {
  const controller = new AbortController();
  const timer = setTimeout(() => controller.abort(), milliseconds);
  try {
    return await fetch(url, { signal: controller.signal });
  } finally {
    clearTimeout(timer);
  }
}

fetchWithTimeout("/api/report", 500).catch(console.error);
```

### 2.3 Hazardous form

```javascript
function fetchWithTimeout(url, milliseconds) {
  const timeout = new Promise((resolve) => {
    setTimeout(() => resolve("timed out"), milliseconds);
  });
  return Promise.race([fetch(url), timeout]);
}

fetchWithTimeout("/api/report", 500).then(console.log, console.error);
```

### 2.4 Why this difference matters

The race settles at the deadline, but the hazardous fetch continues and may still consume bandwidth or perform server-side work.

## 3. Boundaries and distinctions

AbortController works only when the underlying API honors its signal; use that operation's own cancellation mechanism when it differs.
