# Build artifacts/cache/generated output accidentally committed

## 1. Catalog record

- **Catalog identifier:** 11.13
- **Evidence:** se
- **Definition:** Adds machine-derived files that do not belong in version control and create noisy, stale, or platform-specific changes.

## 2. Scenario

### 2.1 Context

An agent runs the test suite while fixing a web route, producing coverage files and a local build cache.

### 2.2 Safer approach

The agent reviews version-control status, commits only source and intended test files, and updates ignore rules if an untracked artifact is recurring.

### 2.3 Failure mode

The agent stages all untracked files, including coverage output, compiled assets, and cache directories.

### 2.4 Why this difference matters

The repository gains noisy, stale, and potentially platform-specific files that burden review and future builds.

## 3. Boundaries and distinctions

Generated files belong in version control when the project explicitly treats them as required source artifacts; do not assume all generated output should be excluded.
