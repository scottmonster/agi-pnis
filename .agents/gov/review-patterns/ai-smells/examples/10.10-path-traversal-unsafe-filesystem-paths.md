# Path traversal / unsafe filesystem paths

## 1. Catalog record

- **Catalog identifier:** 10.10
- **Evidence:** e
- **Definition:** Accepts a path that can escape an intended directory or reach files outside the allowed location.

## 2. Scenario

### 2.1 Context

A download route serves reports stored beneath a tenant’s report directory.

### 2.2 Safer approach

Resolve the requested path against the approved base directory, reject paths that resolve outside it, and avoid treating raw user paths as filesystem authority.

### 2.3 Failure mode

The agent joins the base directory with the request filename and reads the result without containment validation.

### 2.4 Why this difference matters

Traversal segments or path tricks can expose files outside the report area.

## 3. Boundaries and distinctions

Filename validation helps but is not enough alone. Platform-specific normalization and symlink behavior must also preserve the intended boundary.
