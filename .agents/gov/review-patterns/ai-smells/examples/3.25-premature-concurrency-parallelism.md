# Premature concurrency/parallelism

## 1. Catalog record

- **Catalog identifier:** 3.25
- **Evidence:** se
- **Definition:** Threads, tasks, pools, locks, or worker processes appear before serial execution is a bottleneck.

## 2. Scenario

### 2.1 Context

A maintenance task processes ten records in under a second serially.

### 2.2 Safer approach

Keep serial execution and measure performance before changing the execution model.

### 2.3 Failure mode

Add a thread pool, locks, task partitioning, and synchronization for the tiny job.

### 2.4 Why this difference matters

Parallel code brings races, ordering concerns, and harder diagnosis without relieving a demonstrated bottleneck.

## 3. Boundaries and distinctions

Concurrency is appropriate when measurement and correctness constraints support it; serial execution is not inherently a defect.
