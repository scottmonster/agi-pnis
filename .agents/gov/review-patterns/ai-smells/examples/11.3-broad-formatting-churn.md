# Broad formatting churn

## 1. Catalog record

- **Catalog identifier:** 11.3
- **Evidence:** se
- **Definition:** Rewrites whitespace, line wrapping, or style across unrelated code, hiding material changes in noise.

## 2. Scenario

### 2.1 Context

A one-line fix changes the default retry delay in a service client.

### 2.2 Safer approach

The agent edits the delay and the targeted test, using the repository formatter only on changed files if required.

### 2.3 Failure mode

The agent runs a formatter over the entire repository and commits thousands of unrelated wrapping and whitespace changes with the delay fix.

### 2.4 Why this difference matters

The meaningful change is difficult to spot, review time grows, and merge conflicts become more likely.

## 3. Boundaries and distinctions

Repository-wide formatting is valid when deliberately requested or performed as an isolated migration; it should not be incidental to a focused fix.
