# Using `os._exit()` as an ordinary exit mechanism

## 1. Catalog record

- **Catalog identifier:** 3.16.1
- **Impact:** high
- **Consensus:** high
- **Definition:** Use `sys.exit()` for normal Python termination. Reserve `os._exit()` primarily for specialized post-fork child-process situations.

## 2. Example

### 2.1 Scenario

A command-line program has finished validation and needs to report a normal nonzero exit status.

### 2.2 Preferred form

```python
import sys


def main() -> int:
    return 2


raise SystemExit(main())
```

### 2.3 Hazardous form

```python
import os


def main() -> None:
    print("validation failed")
    os._exit(2)


main()
```

### 2.4 Why this difference matters

`os._exit()` bypasses normal cleanup handlers and does not flush standard I/O buffers. A normal `SystemExit` path permits normal interpreter shutdown behavior.

## 3. Boundaries and distinctions

`os._exit()` has specialized uses after `fork()` in a child process, where running ordinary interpreter cleanup may be unsafe. It is not the normal application exit API.
