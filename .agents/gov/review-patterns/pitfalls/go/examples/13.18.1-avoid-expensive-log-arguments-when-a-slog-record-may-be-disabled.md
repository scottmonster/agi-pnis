# Avoid expensive log arguments when a `slog` record may be disabled

## 1. Catalog record

- **Catalog identifier:** 13.18.1
- **Impact:** low
- **Consensus:** high
- **Definition:** Delay expensive computation or use lazy `LogValuer` behavior when constructing structured logging values that may be filtered out.

## 2. Example

### 2.1 Scenario

A service must only hash a payload when debug logging is enabled.

### 2.2 Preferred form

```go
package example

import (
	"context"
	"crypto/sha256"
	"fmt"
	"log/slog"
)

func digest(data []byte) string { return fmt.Sprintf("%x", sha256.Sum256(data)) }

func debugPayload(ctx context.Context, log *slog.Logger, data []byte) {
	if log.Enabled(ctx, slog.LevelDebug) {
		log.Debug("received payload", "sha256", digest(data))
	}
}
```

### 2.3 Hazardous form

```go
package example

import (
	"crypto/sha256"
	"fmt"
	"log/slog"
)

func digest(data []byte) string { return fmt.Sprintf("%x", sha256.Sum256(data)) }

func debugPayload(log *slog.Logger, data []byte) {
	log.Debug("received payload", "sha256", digest(data))
}
```

### 2.4 Why this difference matters

Arguments are evaluated before `Debug` decides whether to emit a record, so the hazardous form hashes every payload even when debug logging is disabled. The preferred form performs the work only when needed.

## 3. Boundaries and distinctions

For reusable structured values, a `slog.LogValuer` can defer computation. Do not add an enabled check when the argument is trivial or logging is known to be enabled.
