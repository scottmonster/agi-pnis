# Treat Promise rejection callback values as `unknown`

## 1. Catalog record

- **Catalog identifier:** 9.7.1
- **Impact:** medium
- **Consensus:** high
- **Definition:** Annotate `.catch((error: unknown) => ...)` or enforce the corresponding lint rule.

## 2. Example

### 2.1 Scenario

A request can reject with any JavaScript value, including a string rather than an `Error` object.

### 2.2 Preferred form

```typescript
Promise.reject('offline').catch((error: unknown) => {
  const message = error instanceof Error ? error.message : String(error);
  console.error(message.toUpperCase());
});
```

### 2.3 Hazardous form

```typescript
Promise.reject('offline').catch((error) => {
  console.error(error.message.toUpperCase()); // error is any and has no message
});
```

### 2.4 Why this difference matters

`useUnknownInCatchVariables` applies to language `catch` clauses but not to `Promise.prototype.catch`, whose callback parameter is otherwise `any`.

## 3. Boundaries and distinctions

Apply this guidance in the conditions described by the catalog record. Deliberate exceptions need a documented runtime guarantee, compatible toolchain behavior, or an explicit local unsafe boundary.
