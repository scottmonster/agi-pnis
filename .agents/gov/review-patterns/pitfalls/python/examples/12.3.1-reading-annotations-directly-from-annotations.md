# Reading annotations directly from `__annotations__`

## 1. Catalog record

- **Catalog identifier:** 12.3.1
- **Impact:** medium
- **Consensus:** high
- **Definition:** For runtime annotation introspection, use `annotationlib.get_annotations()` on Python 3.14+ or the supported `inspect` helper rather than manually interpreting `__annotations__`.

## 2. Example

### 2.1 Scenario

A framework reads a function's annotations to produce documentation without taking responsibility for their storage format.

### 2.2 Preferred form

```python
from annotationlib import Format, get_annotations


class Customer:
    pass


def render(customer: "Customer") -> str:
    return customer.__class__.__name__


annotations = get_annotations(render, format=Format.STRING)
print(annotations["customer"])
```

### 2.3 Hazardous form

```python
class Customer:
    pass


def render(customer: "Customer") -> str:
    return customer.__class__.__name__


annotations = render.__annotations__
print(annotations["customer"].__name__)
```

### 2.4 Why this difference matters

The raw annotation mapping can contain strings, values, or implementation-dependent representations. Manually assuming one representation makes introspection fragile across annotation modes and Python releases.

## 3. Boundaries and distinctions

Direct access can be appropriate for narrowly controlled code that intentionally needs the raw mapping. Use the supported helper when the consumer needs a defined introspection contract.
