# Excessive token/tool expenditure for the size of the resulting useful change

## 1. Catalog record

- **Catalog identifier:** 13.21
- **Evidence:** a
- **Definition:** Uses disproportionate exploration, command execution, or generated output for a simple task without producing corresponding evidence or value.

## 2. Scenario

### 2.1 Context

A task asks to rename one private variable in a single, identified function.

### 2.2 Safer approach

The agent reads the function and nearby callers, performs the rename, and checks the targeted diff or type checker if relevant.

### 2.3 Failure mode

The agent scans the entire monorepo, writes a long architecture report, runs multiple full builds, and produces a broad refactor for the one local rename.

### 2.4 Why this difference matters

Disproportionate work delays simple requests and creates more opportunities for unrelated changes without better evidence.

## 3. Boundaries and distinctions

The right effort scales with uncertainty and risk, not merely line count. A small edit touching a critical boundary may still justify thorough investigation.
