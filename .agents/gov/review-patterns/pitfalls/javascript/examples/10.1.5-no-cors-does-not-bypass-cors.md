# no-cors does not bypass CORS

## 1. Catalog record

- **Catalog identifier:** 10.1.5
- **Impact:** medium
- **Consensus:** high
- **Definition:** Do not use no-cors as a way to obtain a readable cross-origin response.

## 2. Example

### 2.1 Scenario

A web application needs to read public weather data from another origin.

### 2.2 Preferred form

```javascript
async function loadWeather() {
  const response = await fetch("https://weather.example/api/current");
  if (!response.ok) throw new Error(`Weather request failed: ${response.status}`);
  return response.json();
}

loadWeather().catch(console.error);
```

### 2.3 Hazardous form

```javascript
async function loadWeather() {
  const response = await fetch("https://weather.example/api/current", {
    mode: "no-cors",
  });
  return response.json();
}

loadWeather().catch(console.error);
```

### 2.4 Why this difference matters

`no-cors` produces an opaque response whose status and body are not available to page JavaScript, so it cannot supply the requested weather data.

## 3. Boundaries and distinctions

The remote server must opt in with appropriate CORS response headers, or a same-origin backend can fetch the data under its own security policy.
