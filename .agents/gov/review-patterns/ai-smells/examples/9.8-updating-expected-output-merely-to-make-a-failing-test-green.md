# Updating expected output merely to make a failing test green

## 1. Catalog record

- **Catalog identifier:** 9.8
- **Evidence:** a
- **Definition:** Changes the oracle to match a defective implementation without evidence that the requirement changed.

## 2. Scenario

### 2.1 Context

A formatter must render a negative balance as `-$12.50`.

### 2.2 Safer approach

Compare the failing output with the documented formatting contract, then correct the formatter if the contract has not changed.

### 2.3 Failure mode

Change the expected value to `$-12.50` solely because the new implementation produced it.

### 2.4 Why this difference matters

The test no longer protects the intended behavior and silently ratifies a regression.

## 3. Boundaries and distinctions

Update expected output when a reviewed requirement change justifies it, and record that basis in the change review.
