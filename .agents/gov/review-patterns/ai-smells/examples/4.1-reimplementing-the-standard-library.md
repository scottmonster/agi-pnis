# Reimplementing the standard library

## 1. Catalog record

- **Catalog identifier:** 4.1
- **Evidence:** se
- **Definition:** Custom retry, parsing, filesystem, URL, enum, record, date, collection, or serialization code duplicates mature standard functionality.

## 2. Scenario

### 2.1 Context

An agent needs to resolve relative paths in a TypeScript build tool before reading configuration files.

### 2.2 Safer approach

It uses Node's `node:path` functions, tests the intended path cases, and keeps the project-specific policy separate from path normalization.

### 2.3 Failure mode

It writes a `normalizePath` helper that splits on `/`, manually removes `.` and `..`, and later fails on Windows separators and edge cases already handled by the standard library.

### 2.4 Why this difference matters

The custom implementation creates a maintenance burden and subtle cross-platform defects without adding a needed capability.

## 3. Boundaries and distinctions

Use custom code when the required semantics genuinely differ from the standard facility. This failure is duplication of mature functionality, not adding domain-specific behavior around it.
