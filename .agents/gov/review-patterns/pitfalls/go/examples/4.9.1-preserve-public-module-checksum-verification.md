# Preserve public module checksum verification

## 1. Catalog record

- **Catalog identifier:** 4.9.1
- **Impact:** high
- **Consensus:** high
- **Definition:** Do not globally disable the checksum database merely to make private modules work. Exempt only the required private path patterns.

## 2. Example

### 2.1 Scenario

A build needs both public dependencies and modules from a private organization.

### 2.2 Preferred form

```go
package example

import (
	"context"
	"os"
	"os/exec"
)

func downloadModules(ctx context.Context) error {
	cmd := exec.CommandContext(ctx, "go", "mod", "download")
	cmd.Env = append(os.Environ(),
		"GOPRIVATE=git.example.com/acme/*",
		"GONOSUMDB=git.example.com/acme/*",
	)
	return cmd.Run()
}
```

### 2.3 Hazardous form

```go
package example

import (
	"context"
	"os"
	"os/exec"
)

func downloadModules(ctx context.Context) error {
	cmd := exec.CommandContext(ctx, "go", "mod", "download")
	cmd.Env = append(os.Environ(), "GOSUMDB=off")
	return cmd.Run()
}
```

### 2.4 Why this difference matters

The preferred configuration excludes only private paths from checksum lookup while preserving public module verification. Disabling `GOSUMDB` removes an integrity check for every public dependency in the build.

## 3. Boundaries and distinctions

An organization can use a different trusted checksum service by configuring `GOSUMDB` to its verified endpoint. Private path exceptions should remain narrow and should be reviewed with the proxy configuration.
