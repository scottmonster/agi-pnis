# Do not assume localeCompare returns only -1, 0, or 1

## 1. Catalog record

- **Catalog identifier:** 6.1.7
- **Impact:** low
- **Consensus:** high
- **Definition:** Test `localeCompare()` results by sign, not by exact values such as `=== -1`. For repeated large sorts, use an `Intl.Collator`.

## 2. Example

### 2.1 Scenario

A contact list needs to determine whether a proposed name sorts before the current name.

### 2.2 Preferred form

```javascript
function sortsBefore(left, right) {
  return left.localeCompare(right, "sv") < 0;
}

console.log(sortsBefore("Anders", "Åsa"));
```

### 2.3 Hazardous form

```javascript
function sortsBefore(left, right) {
  return left.localeCompare(right, "sv") === -1;
}

console.log(sortsBefore("Anders", "Åsa"));
```

### 2.4 Why this difference matters

The specification guarantees ordering by negative, zero, or positive sign, not a particular negative or positive magnitude.

## 3. Boundaries and distinctions

Exact equality with zero is safe for equivalence. For repeated sorting with the same collation settings, reuse an `Intl.Collator` for both clarity and setup efficiency.
