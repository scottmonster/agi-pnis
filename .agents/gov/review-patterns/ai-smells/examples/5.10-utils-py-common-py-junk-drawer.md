# `utils.py` / `common.py` junk drawer

## 1. Catalog record

- **Catalog identifier:** 5.10
- **Evidence:** se
- **Definition:** Unrelated operations accumulate in catch-all modules.

## 2. Scenario

### 2.1 Context

`utils.py` already contains date formatting, SQL helpers, authentication checks, file cleanup, and email rendering.

### 2.2 Safer approach

Put the new operation near its domain or create a cohesive module with a clear responsibility.

### 2.3 Failure mode

Add a payment-reconciliation helper to `utils.py` because it is convenient to find.

### 2.4 Why this difference matters

The catch-all module becomes an unstable dependency that obscures ownership and encourages unrelated coupling.

## 3. Boundaries and distinctions

A small cohesive utility module is fine. The failure is a catch-all location for unrelated responsibilities.
