# Do not reuse global or sticky regexes without accounting for lastIndex

## 1. Catalog record

- **Catalog identifier:** 5.1.7
- **Impact:** medium
- **Consensus:** high
- **Definition:** Regexes with `g` or `y` are stateful through `lastIndex`. Repeated calls to `test()` or `exec()` on the same object can therefore produce different results for identical input.

## 2. Example

### 2.1 Scenario

A validator reuses a compiled regular expression for independent form submissions.

### 2.2 Preferred form

```javascript
const identifierPattern = /^[a-z]+$/gu;

function isIdentifier(value) {
  identifierPattern.lastIndex = 0;
  return identifierPattern.test(value);
}

console.log(isIdentifier("admin")); // true
console.log(isIdentifier("admin")); // true
```

### 2.3 Hazardous form

```javascript
const identifierPattern = /^[a-z]+$/gu;

function isIdentifier(value) {
  return identifierPattern.test(value);
}

console.log(isIdentifier("admin")); // true
console.log(isIdentifier("admin")); // false
```

### 2.4 Why this difference matters

The global expression advances `lastIndex` after the first test, so an identical later validation can fail for stateful rather than data-related reasons.

## 3. Boundaries and distinctions

Avoiding `g` and `y` is often clearer for one-off boolean tests. Stateful matching is valid when iterative scanning is intentional and `lastIndex` is managed as part of that algorithm.
