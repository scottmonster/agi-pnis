# Duplicate dependency declarations

## 1. Catalog record

- **Catalog identifier:** 8.12
- **Evidence:** e
- **Definition:** Declares the same package more than once, potentially with conflicting versions or scopes.

## 2. Scenario

### 2.1 Context

An agent adds a JSON parser to a Java service that already declares the parser in its Maven dependency management section.

### 2.2 Safer approach

It searches the build files first, reuses the managed version, and adds the dependency only in the module that needs it.

### 2.3 Failure mode

It adds a second declaration for the same parser in the module's dependency list with a different version, assuming the duplicate is harmless.

### 2.4 Why this difference matters

Conflicting declarations make the resolved version and dependency scope harder to predict, which can cause build or runtime differences across modules.

## 3. Boundaries and distinctions

Separate declarations may be valid when build tooling requires distinct, nonoverlapping artifacts or scopes. The failure is declaring the same package redundantly when one authoritative declaration should control it.
