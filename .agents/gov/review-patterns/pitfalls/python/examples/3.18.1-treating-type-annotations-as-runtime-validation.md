# Treating type annotations as runtime validation

## 1. Catalog record

- **Catalog identifier:** 3.18.1
- **Impact:** high
- **Consensus:** high
- **Definition:** Do not assume annotated function arguments or assignments are runtime checked merely because type hints are present. Add explicit validation where runtime guarantees are required.

## 2. Example

### 2.1 Scenario

An HTTP handler must accept only positive integer page sizes from untrusted request data.

### 2.2 Preferred form

```python
def page_size(value: object) -> int:
    if not isinstance(value, int) or isinstance(value, bool) or value <= 0:
        raise ValueError("page size must be a positive integer")
    return value


size = page_size(25)
```

### 2.3 Hazardous form

```python
def page_size(value: int) -> int:
    return value


size = page_size("25")
```

### 2.4 Why this difference matters

Annotations guide type checkers and readers, but ordinary Python calls do not enforce them. The hazardous call returns a string despite the annotation.

## 3. Boundaries and distinctions

Static type checking remains valuable for development. A validation library can provide the explicit runtime check when its behavior meets the input contract.
