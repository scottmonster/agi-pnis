# No test for newly changed behavior

## 1. Catalog record

- **Catalog identifier:** 9.1
- **Evidence:** a/se
- **Definition:** Changes externally observable behavior without a test that would detect its regression.

## 2. Scenario

### 2.1 Context

A checkout API now returns an order ID after a successful payment.

### 2.2 Safer approach

Add an API test that submits a valid payment and asserts the response includes the created order ID.

### 2.3 Failure mode

Change the handler and rely on a manual browser check, leaving no automated test for the new response field.

### 2.4 Why this difference matters

A later response refactor can remove the field without any test detecting the broken client contract.

## 3. Boundaries and distinctions

The test should cover the changed observable contract, not every internal line that produced it.
