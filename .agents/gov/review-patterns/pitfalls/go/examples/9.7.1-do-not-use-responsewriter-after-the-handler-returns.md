# Do not use `ResponseWriter` after the handler returns

## 1. Catalog record

- **Catalog identifier:** 9.7.1
- **Impact:** medium
- **Consensus:** high
- **Definition:** Complete response-writing operations before `ServeHTTP` returns unless using an API with an explicit alternative lifecycle.

## 2. Example

### 2.1 Scenario

A handler needs background work but must send a complete HTTP response safely.

### 2.2 Preferred form

```go
package example

import "net/http"

func handler(w http.ResponseWriter, r *http.Request) {
	result := compute(r.URL.Query().Get("id"))
	w.WriteHeader(http.StatusOK)
	_, _ = w.Write([]byte(result))
}

func compute(id string) string { return "processed " + id }
```

### 2.3 Hazardous form

```go
package example

import "net/http"

func handler(w http.ResponseWriter, r *http.Request) {
	go func() {
		_, _ = w.Write([]byte("finished")) // Handler may already have returned.
	}()
}
```

### 2.4 Why this difference matters

The server owns `ResponseWriter` only during the handler call. A later goroutine can race with server cleanup or write to a response that is already complete.

## 3. Boundaries and distinctions

Use a protocol designed for a longer response lifecycle, such as streaming within the active handler, WebSockets, or a separate status resource, when asynchronous delivery is required.
