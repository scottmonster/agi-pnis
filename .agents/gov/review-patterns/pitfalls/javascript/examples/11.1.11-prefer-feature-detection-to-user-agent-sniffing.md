# Prefer feature detection to user-agent sniffing

## 1. Catalog record

- **Catalog identifier:** 11.1.11
- **Impact:** medium
- **Consensus:** high
- **Definition:** Test the required capability instead of inferring it from a user-agent string.

## 2. Example

### 2.1 Scenario

An upload screen offers drag-and-drop only when the browser supports the required file APIs.

### 2.2 Preferred form

```javascript
const dropZone = document.querySelector("#drop-zone");
const supportsFileDrop = "draggable" in document.createElement("div") && "FileReader" in window;

if (supportsFileDrop) {
  dropZone.addEventListener("dragover", (event) => event.preventDefault());
} else {
  dropZone.hidden = true;
}
```

### 2.3 Hazardous form

```javascript
const dropZone = document.querySelector("#drop-zone");
const isChrome = navigator.userAgent.includes("Chrome");

if (isChrome) {
  dropZone.addEventListener("dragover", (event) => event.preventDefault());
} else {
  dropZone.hidden = true;
}
```

### 2.4 Why this difference matters

User-agent strings can be reduced, spoofed, or shared by browsers with different capabilities, so the UI can make the wrong availability decision.

## 3. Boundaries and distinctions

Feature detection establishes capability, not product identity. Use server-provided compatibility data only when a true product-specific workaround is unavoidable.
