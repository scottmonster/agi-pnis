# Treat arithmetic contexts as evaluation contexts

## 1. Catalog record

- **Catalog identifier:** 1.7.1
- **Impact:** high
- **Consensus:** high
- **Definition:** Validate untrusted values before inserting them into `$((...))`, `((...))`, array subscripts, or other arithmetic contexts. Bash arithmetic performs recursive variable evaluation and can encounter command substitutions through crafted expressions.

## 2. Example

### 2.1 Scenario

A script accepts a page number from a caller and calculates the next page to fetch.

### 2.2 Preferred form

```bash
#!/usr/bin/env bash

page=${1:-}

if [[ $page =~ ^[0-9]+$ ]]; then
  next_page=$((10#$page + 1))
  printf 'next page: %d\n' "$next_page"
else
  printf 'page must contain decimal digits only\n' >&2
  exit 2
fi
```

### 2.3 Hazardous form

```bash
#!/usr/bin/env bash

page=${1:-}
next_page=$((page + 1))

printf 'next page: %d\n' "$next_page"
```

### 2.4 Why this difference matters

Bash recursively evaluates variable values in arithmetic contexts. A caller can provide an expression rather than a simple number, potentially causing unintended variable access or command substitution during what appears to be numeric conversion.

## 3. Boundaries and distinctions

Arithmetic expressions are useful when every operand is controlled by the script. Validate external values according to the numeric format the operation accepts, including any intended sign, range, and leading-zero policy.
