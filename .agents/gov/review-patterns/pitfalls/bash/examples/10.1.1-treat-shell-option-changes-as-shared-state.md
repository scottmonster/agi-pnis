# Treat shell option changes as shared state

## 1. Catalog record

- **Catalog identifier:** 10.1.1
- **Impact:** medium
- **Consensus:** high
- **Definition:** Options changed with `set` or `shopt` affect later code in the same shell, including callers of sourced files and functions; localize intentional option changes.

## 2. Example

### 2.1 Scenario

A helper gathers optional PNG files while the calling script expects unmatched globs to remain literal.

### 2.2 Preferred form

```bash
collect_pngs() (
  shopt -s nullglob
  local pngs=("$1"/*.png)
  printf '%s\n' "${pngs[@]}"
)

pattern='missing/*.png'
collect_pngs missing
printf 'caller still sees: %s\n' "$pattern"
```

### 2.3 Hazardous form

```bash
collect_pngs() {
  shopt -s nullglob
  local pngs=("$1"/*.png)
  printf '%s\n' "${pngs[@]}"
}

collect_pngs missing
printf '%s\n' missing/*.png
```

### 2.4 Why this difference matters

The hazardous helper leaves `nullglob` enabled, so later unmatched globs silently disappear instead of being handled by the caller's intended logic.

## 3. Boundaries and distinctions

Changing an option globally is appropriate when it is an explicit script-wide policy. A subshell is useful when the change belongs only to one operation.
