# Raising `StopIteration` inside generators

## 1. Catalog record

- **Catalog identifier:** 6.15.1
- **Impact:** medium
- **Consensus:** high
- **Definition:** End a generator with `return` rather than deliberately raising `StopIteration` from generator code.

## 2. Example

### 2.1 Scenario

A generator yields available records and stops when it reaches a sentinel record.

### 2.2 Preferred form

```python
def records(values):
    for value in values:
        if value == "STOP":
            return
        yield value

print(list(records(["a", "STOP", "b"])))  # ['a']
```

### 2.3 Hazardous form

```python
def records(values):
    for value in values:
        if value == "STOP":
            raise StopIteration
        yield value

print(list(records(["a", "STOP", "b"])))
```

### 2.4 Why this difference matters

An escaping `StopIteration` from generator code is transformed into `RuntimeError`, so callers do not observe normal completion.

## 3. Boundaries and distinctions

Raising `StopIteration` is still part of the iterator protocol for a custom iterator's `__next__()` method, but not the way to end generator code.
