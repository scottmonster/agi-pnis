# Fail closed on empty destructive path variables

## 1. Catalog record

- **Catalog identifier:** 1.12.1
- **Impact:** high
- **Consensus:** high
- **Definition:** Before destructive commands, validate required paths and use defensive expansion such as `${dir:?}` where appropriate, together with quoting and option termination.

## 2. Example

### 2.1 Scenario

A release script clears the contents of a staging directory supplied through an environment variable. The directory must be present before deletion can begin.

### 2.2 Preferred form

```bash
#!/usr/bin/env bash

: "${staging_dir:?staging_dir must name the release staging directory}"
rm -rf -- "${staging_dir}"/*
```

### 2.3 Hazardous form

```bash
#!/usr/bin/env bash

rm -rf "$staging_dir"/*
```

### 2.4 Why this difference matters

If `staging_dir` is unset or empty, the hazardous path becomes `/*`, so the command can target the contents of the filesystem root. The required-variable expansion stops the script before `rm` runs, while quoting and `--` preserve the intended operand boundary.

## 3. Boundaries and distinctions

Checking only for nonempty input does not prove that the value is the expected directory. For high-consequence deletion, also constrain it to an approved base directory, reject dangerous values such as `/`, and consider a less destructive workflow.
