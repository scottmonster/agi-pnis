# Escape dynamic values used in CSS selectors

## 1. Catalog record

- **Catalog identifier:** 11.1.3
- **Impact:** medium
- **Consensus:** high
- **Definition:** Correctly escape dynamic literal selector values, such as with CSS.escape.

## 2. Example

### 2.1 Scenario

An application looks up a saved panel by an ID that came from a URL parameter. Valid HTML IDs can contain characters with special meaning in CSS selectors.

### 2.2 Preferred form

```javascript
const panelId = "account:primary";
const panel = document.querySelector(`#${CSS.escape(panelId)}`);

if (panel !== null) {
  panel.hidden = false;
}
```

### 2.3 Hazardous form

```javascript
const panelId = "account:primary";
const panel = document.querySelector(`#${panelId}`);

if (panel !== null) {
  panel.hidden = false;
}
```

### 2.4 Why this difference matters

The hazardous selector treats the colon as selector syntax instead of as part of the ID, which can select the wrong element or throw a selector syntax error for other inputs. `CSS.escape()` encodes the value as a CSS identifier literal.

## 3. Boundaries and distinctions

Escaping a literal value is needed only for the dynamic portions of a selector. Prefer direct DOM APIs such as `getElementById()` when they express the lookup, because they do not require CSS selector construction.
