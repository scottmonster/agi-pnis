# Deleting tests

## 1. Catalog record

- **Catalog identifier:** 9.12
- **Evidence:** a
- **Definition:** Removes coverage that exposes a defect or contract instead of resolving the underlying incompatibility.

## 2. Scenario

### 2.1 Context

A test verifies that expired password-reset links are rejected.

### 2.2 Safer approach

Preserve the test and fix the expiration comparison so expired links remain invalid.

### 2.3 Failure mode

Delete the test because the current implementation accepts an expired link.

### 2.4 Why this difference matters

The build becomes green by discarding an important contract and leaves a security-sensitive defect unguarded.

## 3. Boundaries and distinctions

Remove a test only when it covers an intentionally retired or invalid contract, replacing it where necessary with coverage for the new behavior.
