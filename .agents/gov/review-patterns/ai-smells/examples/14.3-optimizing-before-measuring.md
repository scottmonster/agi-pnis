# Optimizing before measuring

## 1. Catalog record

- **Catalog identifier:** 14.3
- **Evidence:** a
- **Definition:** Performance machinery precedes evidence of a performance problem.

## 2. Scenario

### 2.1 Context

A search endpoint is reported as feeling slow during a local development session, but no latency, query, or load data has been collected.

### 2.2 Safer approach

The agent measures representative requests, examines query plans and application traces, then targets a demonstrated bottleneck if one exists.

### 2.3 Failure mode

It adds a cache, background precomputation, and pagination redesign solely because the endpoint might eventually be expensive.

### 2.4 Why this difference matters

The machinery can add staleness, invalidation bugs, and operational cost while leaving the actual source of delay untouched.

## 3. Boundaries and distinctions

Known service limits or an already measured bottleneck can warrant performance work before broad production traffic arrives. The missing element is evidence for this problem.
