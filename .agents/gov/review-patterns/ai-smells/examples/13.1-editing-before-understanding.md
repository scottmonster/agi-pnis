# Editing before understanding

## 1. Catalog record

- **Catalog identifier:** 13.1
- **Evidence:** a
- **Definition:** Begins patches before gathering enough repository evidence.

## 2. Scenario

### 2.1 Context

A bug report says that CSV imports reject valid UTF-8 filenames. The repository has both a browser uploader and a worker-side importer.

### 2.2 Safer approach

The agent locates the request path, reads the importer and its tests, then makes a small change where filename decoding actually occurs.

### 2.3 Failure mode

The agent immediately edits the browser uploader's accept attribute, even though the rejection happens in the worker after upload.

### 2.4 Why this difference matters

The visible code changes, but the reported behavior remains broken and an unrelated interface contract may be changed.

## 3. Boundaries and distinctions

Quick edits are reasonable when ownership and behavior are already established. This failure concerns patching before enough evidence identifies the relevant path.
