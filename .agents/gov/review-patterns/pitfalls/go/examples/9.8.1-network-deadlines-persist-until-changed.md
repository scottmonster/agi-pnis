# Network deadlines persist until changed

## 1. Catalog record

- **Catalog identifier:** 9.8.1
- **Impact:** medium
- **Consensus:** high
- **Definition:** `Conn.SetDeadline` sets an absolute deadline applying to future and pending I/O until replaced. Refresh it after successful operations when implementing an idle timeout.

## 2. Example

### 2.1 Scenario

A line protocol connection should close after thirty seconds of inactivity, not thirty seconds after initial setup.

### 2.2 Preferred form

```go
package example

import (
	"net"
	"time"
)

func readLine(conn net.Conn, buf []byte) (int, error) {
	if err := conn.SetDeadline(time.Now().Add(30 * time.Second)); err != nil { return 0, err }
	n, err := conn.Read(buf)
	if err != nil { return n, err }
	return n, conn.SetDeadline(time.Now().Add(30 * time.Second))
}
```

### 2.3 Hazardous form

```go
package example

import (
	"net"
	"time"
)

func readLine(conn net.Conn, buf []byte) (int, error) {
	if err := conn.SetDeadline(time.Now().Add(30 * time.Second)); err != nil { return 0, err }
	return conn.Read(buf) // Every later read shares the original absolute deadline.
}
```

### 2.4 Why this difference matters

Deadlines do not reset automatically after successful I/O. A busy connection can unexpectedly time out when the original absolute deadline passes.

## 3. Boundaries and distinctions

Set only read or write deadlines when that better matches the protocol. Clear a deadline with the zero time when a later phase intentionally has no deadline.
