# Transaction-boundary error

## 1. Catalog record

- **Catalog identifier:** 6.23
- **Evidence:** se
- **Definition:** Multi-step state changes can become partially committed.

## 2. Scenario

### 2.1 Context

An order workflow creates an order and decrements reserved inventory.

### 2.2 Safer approach

The agent uses the repository's transaction mechanism so the dependent writes commit or roll back together.

### 2.3 Failure mode

It commits the order before the inventory update, which then fails.

### 2.4 Why this difference matters

The system records a purchasable order without the corresponding inventory state.

## 3. Boundaries and distinctions

The boundary should cover state changes that require atomic consistency; independent, compensatable operations may require a different design.
