# typeof is not universally safe before declaration

## 1. Catalog record

- **Catalog identifier:** 1.1.9
- **Impact:** medium
- **Consensus:** high
- **Definition:** `typeof undeclaredName` returns `"undefined"`, but applying `typeof` to a `let`, `const`, or class binding that is still in its temporal dead zone throws `ReferenceError`.

## 2. Example

### 2.1 Scenario

A startup routine needs to inspect a configuration value after it has been initialized.

### 2.2 Preferred form

```javascript
const configuration = { enabled: true };

function inspectConfiguration() {
  return typeof configuration;
}

console.log(inspectConfiguration());
```

### 2.3 Hazardous form

```javascript
function inspectConfiguration() {
  return typeof configuration;
}

console.log(inspectConfiguration());
const configuration = { enabled: true };
```

### 2.4 Why this difference matters

The hazardous call reads the lexical binding while it is in its temporal dead zone, so `typeof` throws a `ReferenceError`.

## 3. Boundaries and distinctions

`typeof` is safe for an entirely undeclared identifier, but that exception does not apply to uninitialized lexical bindings.
