# Do not pass parseInt directly to map

## 1. Catalog record

- **Catalog identifier:** 3.1.10
- **Impact:** medium
- **Consensus:** high
- **Definition:** Use `array.map(x => parseInt(x, 10))` rather than `array.map(parseInt)`. `map` passes the element index as the callback's second argument, which `parseInt` interprets as its radix.

## 2. Example

### 2.1 Scenario

A CSV import converts decimal text fields into numbers.

### 2.2 Preferred form

```javascript
const fields = ["10", "10", "10"];
const values = fields.map((field) => parseInt(field, 10));

console.log(values); // [10, 10, 10]
```

### 2.3 Hazardous form

```javascript
const fields = ["10", "10", "10"];
const values = fields.map(parseInt);

console.log(values); // [10, NaN, 2]
```

### 2.4 Why this difference matters

`map` supplies `(element, index, array)`; `parseInt` treats the index as its radix, so the results vary by position.

## 3. Boundaries and distinctions

Passing a function directly is safe only when its parameter contract matches the callback arguments supplied by the array method.
