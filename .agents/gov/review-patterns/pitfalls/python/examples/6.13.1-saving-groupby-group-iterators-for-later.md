# Saving `groupby()` group iterators for later

## 1. Catalog record

- **Catalog identifier:** 6.13.1
- **Impact:** medium
- **Consensus:** high
- **Definition:** Materialize a `groupby()` subgroup if it must survive advancing the outer iterator.

## 2. Example

### 2.1 Scenario

A batch processor needs to retain each category's rows after scanning every category.

### 2.2 Preferred form

```python
from itertools import groupby

rows = [("a", 1), ("a", 2), ("b", 3)]
saved = {name: list(group) for name, group in groupby(rows, key=lambda row: row[0])}
print(saved["a"])  # [('a', 1), ('a', 2)]
```

### 2.3 Hazardous form

```python
from itertools import groupby

rows = [("a", 1), ("a", 2), ("b", 3)]
saved = {name: group for name, group in groupby(rows, key=lambda row: row[0])}
print(list(saved["a"]))  # []
```

### 2.4 Why this difference matters

Each subgroup iterator shares `groupby()`'s underlying input, so advancing through later groups exhausts earlier saved iterators.

## 3. Boundaries and distinctions

Keeping a subgroup iterator is appropriate only when it is consumed before the outer `groupby()` iterator advances.
