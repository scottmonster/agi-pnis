# Long method / procedural monolith

## 1. Catalog record

- **Catalog identifier:** 5.1
- **Evidence:** e
- **Definition:** Large amounts of reasoning are compressed into one function.

## 2. Scenario

### 2.1 Context

An order-import handler parses a CSV, validates rows, prices items, writes records, sends notifications, and formats the response in one 300-line function.

### 2.2 Safer approach

Keep the handler as orchestration and extract cohesive parsing, validation, and persistence steps with clear inputs and tests.

### 2.3 Failure mode

Add another pricing exception directly into the already large handler because all of its logic is in one place.

### 2.4 Why this difference matters

The combined control flow is difficult to review, test, and safely change.

## 3. Boundaries and distinctions

A short linear function need not be split. The problem is accumulated, unrelated reasoning in one function, not merely a function with several lines.
