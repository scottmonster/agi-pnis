# Know `sync.Once` failure semantics

## 1. Catalog record

- **Catalog identifier:** 6.3.1
- **Impact:** medium
- **Consensus:** high
- **Definition:** Do not recursively call the same `Once.Do`, and remember that if the function panics, that `Once` is still considered finished.

## 2. Example

### 2.1 Scenario

An optional feature initializes at most once.

### 2.2 Preferred form

```go
package main

import "sync"

type feature struct { once sync.Once; err error }
func (f *feature) initialize() error { f.once.Do(func() { f.err = load() }); return f.err }
func load() error { return nil }
```

### 2.3 Hazardous form

```go
package main

import "sync"

var once sync.Once
func initialize() { once.Do(func() { initialize() }) }
```

### 2.4 Why this difference matters

Recursive `Do` deadlocks. A panic in a `Do` function also marks it finished, so later calls do not retry it.

## 3. Boundaries and distinctions

Use an explicit retry state machine when retry is required. `OnceValues` still has one-time execution semantics.
