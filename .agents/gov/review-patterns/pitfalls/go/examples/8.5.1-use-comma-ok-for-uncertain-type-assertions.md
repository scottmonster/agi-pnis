# Use comma-ok for uncertain type assertions

## 1. Catalog record

- **Catalog identifier:** 8.5.1
- **Impact:** medium
- **Consensus:** high
- **Definition:** Use `v, ok := x.(T)` when failure is a normal possibility. Reserve one-result assertions for invariants whose violation genuinely warrants a panic.

## 2. Example

### 2.1 Scenario

A request metadata field may contain a string value or may be absent or supplied by an extension with a different type.

### 2.2 Preferred form

```go
package metadata

func requestID(values map[string]any) (string, bool) {
	v, ok := values["request_id"].(string)
	return v, ok
}
```

### 2.3 Hazardous form

```go
package metadata

func requestID(values map[string]any) string {
	return values["request_id"].(string)
}
```

### 2.4 Why this difference matters

The one-result assertion panics when the field is missing, nil, or another type. The comma-ok form lets the caller choose a normal fallback or validation error.

## 3. Boundaries and distinctions

A one-result assertion can express a trusted internal invariant where a panic is an intentional failure signal. Do not use it for values that cross a request, plugin, decoding, or other uncertain boundary.
