# Do not mix BigInt and Number arithmetic implicitly

## 1. Catalog record

- **Catalog identifier:** 4.1.7
- **Impact:** medium
- **Consensus:** high
- **Definition:** Convert deliberately before combining `BigInt` and `Number` values, taking precision requirements into account. Most arithmetic operators do not implicitly combine them.

## 2. Example

### 2.1 Scenario

A ledger stores exact cents as `BigInt` and applies a whole-number adjustment supplied by an API.

### 2.2 Preferred form

```javascript
function applyAdjustment(balanceCents, adjustmentCents) {
  return balanceCents + BigInt(adjustmentCents);
}

console.log(applyAdjustment(9007199254740993n, 25));
```

### 2.3 Hazardous form

```javascript
function applyAdjustment(balanceCents, adjustmentCents) {
  return balanceCents + adjustmentCents;
}

console.log(applyAdjustment(9007199254740993n, 25));
```

### 2.4 Why this difference matters

Mixed arithmetic throws a `TypeError`, while casually converting the large balance to `Number` would instead lose precision.

## 3. Boundaries and distinctions

Explicit conversion is safe only when the target representation can preserve the required value. Keep values as `BigInt` when exact large-integer semantics are required.
