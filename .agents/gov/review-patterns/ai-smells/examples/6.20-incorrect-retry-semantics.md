# Incorrect retry semantics

## 1. Catalog record

- **Catalog identifier:** 6.20
- **Evidence:** se
- **Definition:** Retries non-idempotent operations or retries errors that should fail immediately.

## 2. Scenario

### 2.1 Context

A checkout service submits a card charge to a payment provider.

### 2.2 Safer approach

The agent uses the provider's idempotency mechanism and retries only documented transient failures.

### 2.3 Failure mode

It automatically repeats every failed charge request, including requests whose outcome is unknown.

### 2.4 Why this difference matters

One purchase can result in duplicate charges or repeated irreversible actions.

## 3. Boundaries and distinctions

Retries can be correct for an idempotent operation and a known transient failure, with the service's prescribed limits.
