# Do not mark callback parameters optional just because callers may ignore them

## 1. Catalog record

- **Catalog identifier:** 8.1.1
- **Impact:** medium
- **Consensus:** high
- **Definition:** In a callback type, write `index: number`, not `index?: number`, when the API always supplies the argument.

## 2. Example

### 2.1 Scenario

A collection API always supplies an item's position, even though a consumer may choose not to use it.

### 2.2 Preferred form

```typescript
type Visitor<T> = (value: T, index: number) => void;

function visit<T>(values: readonly T[], visitor: Visitor<T>): void {
  values.forEach((value, index) => visitor(value, index));
}

visit(['draft', 'published'], (status, index) => {
  console.log(`${index + 1}: ${status}`);
});
```

### 2.3 Hazardous form

```typescript
type Visitor<T> = (value: T, index?: number) => void;

function visit<T>(values: readonly T[], visitor: Visitor<T>): void {
  values.forEach((value, index) => visitor(value, index));
}

visit(['draft'], (status, index) => {
  console.log(`${index + 1}: ${status}`); // Error: index may be undefined
});
```

### 2.4 Why this difference matters

An optional callback parameter means the implementation is permitted to omit it; TypeScript already allows callers to provide callbacks accepting fewer arguments.

## 3. Boundaries and distinctions

Apply this guidance in the conditions described by the catalog record. Deliberate exceptions need a documented runtime guarantee, compatible toolchain behavior, or an explicit local unsafe boundary.
