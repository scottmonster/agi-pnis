# Prefer Number.isNaN over global isNaN

## 1. Catalog record

- **Catalog identifier:** 1.1.5
- **Impact:** medium
- **Consensus:** high
- **Definition:** Use `Number.isNaN(value)` when asking whether a value is actually the numeric `NaN` value. The global `isNaN()` first coerces its argument to a number.

## 2. Example

### 2.1 Scenario

A parser distinguishes an invalid numeric result from a raw text input.

### 2.2 Preferred form

```javascript
function hasInvalidNumericResult(value) {
  return Number.isNaN(value);
}

console.log(hasInvalidNumericResult("not-a-number"));
```

### 2.3 Hazardous form

```javascript
function hasInvalidNumericResult(value) {
  return isNaN(value);
}

console.log(hasInvalidNumericResult("not-a-number"));
```

### 2.4 Why this difference matters

The global function coerces the string before testing it, so it reports a non-numeric string as though it were the `NaN` number value.

## 3. Boundaries and distinctions

Global `isNaN()` can be appropriate only when its number-coercion behavior is explicitly the desired validation step.
