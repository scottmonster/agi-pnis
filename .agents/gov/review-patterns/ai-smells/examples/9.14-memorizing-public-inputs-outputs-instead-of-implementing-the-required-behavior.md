# Memorizing public inputs/outputs instead of implementing the required behavior

## 1. Catalog record

- **Catalog identifier:** 9.14
- **Evidence:** a
- **Definition:** Returns known benchmark answers without deriving them from the intended algorithm or contract.

## 2. Scenario

### 2.1 Context

A utility must calculate shipping prices from package weight and destination zone.

### 2.2 Safer approach

Implement the documented pricing rules and verify them with public examples plus additional cases.

### 2.3 Failure mode

Store a map from each published benchmark input to its expected output and return a default for all other inputs.

### 2.4 Why this difference matters

The solution passes known examples while providing no usable implementation for real requests.

## 3. Boundaries and distinctions

Lookup tables are appropriate when the contract is truly a fixed published mapping, rather than an algorithm inferred from benchmark cases.
