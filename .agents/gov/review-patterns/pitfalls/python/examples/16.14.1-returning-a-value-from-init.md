# Returning a value from `__init__()`

## 1. Catalog record

- **Catalog identifier:** 16.14.1
- **Impact:** low
- **Consensus:** high
- **Definition:** `__init__()` must initialize the instance and return `None`; use `__new__()` or another construction mechanism when object creation itself must be customized.

## 2. Example

### 2.1 Scenario

A class validates and stores a normalized account name when an account is constructed.

### 2.2 Preferred form

```python
class Account:
    def __init__(self, name: str) -> None:
        self.name = name.strip().title()


account = Account("  mina  ")
print(account.name)
```

### 2.3 Hazardous form

```python
class Account:
    def __init__(self, name: str) -> str:
        self.name = name.strip().title()
        return self.name


account = Account("  mina  ")
print(account.name)
```

### 2.4 Why this difference matters

The hazardous constructor raises `TypeError` because Python requires `__init__()` to return `None`, even though its instance assignments have already run.

## 3. Boundaries and distinctions

Use a class method or factory function when construction should produce a separate result. Use `__new__()` only for the specialized cases where object allocation must be customized.
