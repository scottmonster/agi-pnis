# Avoid __proto__ mutation

## 1. Catalog record

- **Catalog identifier:** 2.11.1
- **Impact:** medium
- **Consensus:** high
- **Definition:** Do not use `__proto__` to change prototypes; use explicit prototype APIs only when required.

## 2. Example

### 2.1 Scenario

A factory creates dictionary objects that should not inherit object methods.

### 2.2 Preferred form

```javascript
function createDictionary() {
  return Object.create(null);
}

const dictionary = createDictionary();
dictionary.name = "Ada";
```

### 2.3 Hazardous form

```javascript
const dictionary = {};
dictionary.__proto__ = null;
dictionary.name = "Ada";
```

### 2.4 Why this difference matters

`__proto__` is a legacy accessor with surprising behavior and should not be used for mutable prototype changes.

## 3. Boundaries and distinctions

`Object.setPrototypeOf()` is explicit when a prototype change is genuinely necessary, though changing prototypes can still harm performance and reasoning.
