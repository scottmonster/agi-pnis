# Blind extraction of untrusted tar archives

## 1. Catalog record

- **Catalog identifier:** 2.12.1
- **Impact:** high
- **Consensus:** high
- **Definition:** Do not blindly extract untrusted tar archives. Use appropriate extraction filters, inspect archive contents, constrain destination handling, and apply resource limits as necessary.

## 2. Example

### 2.1 Scenario

A service accepts a tar upload and unpacks it into a workspace for later processing.

### 2.2 Preferred form

```python
from pathlib import Path
import tarfile


def extract_upload(archive_path: Path, destination: Path) -> None:
    with tarfile.open(archive_path) as archive:
        archive.extractall(destination, filter="data")
```

### 2.3 Hazardous form

```python
from pathlib import Path
import tarfile


def extract_upload(archive_path: Path, destination: Path) -> None:
    with tarfile.open(archive_path) as archive:
        archive.extractall(destination)
```

### 2.4 Why this difference matters

Archive members can contain unsafe paths, links, or metadata. The data filter is a safer default for untrusted content.

## 3. Boundaries and distinctions

Filtering alone does not solve every risk, including archive size exhaustion, so untrusted uploads may also need inspection and resource limits.
