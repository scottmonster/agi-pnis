# Map and Set do not serialize meaningfully with plain JSON.stringify

## 1. Catalog record

- **Catalog identifier:** 9.1.4
- **Impact:** medium
- **Consensus:** high
- **Definition:** Do not use plain JSON.stringify when Map or Set contents must be preserved.

## 2. Example

### 2.1 Scenario

A saved search must preserve both its keyed filters and its selected columns.

### 2.2 Preferred form

```javascript
const search = {
  filters: new Map([["status", "open"]]),
  columns: new Set(["id", "title"]),
};

const saved = JSON.stringify({
  filters: [...search.filters],
  columns: [...search.columns],
});
const restored = JSON.parse(saved);

console.log(new Map(restored.filters).get("status")); // open
console.log(new Set(restored.columns).has("title")); // true
```

### 2.3 Hazardous form

```javascript
const search = {
  filters: new Map([["status", "open"]]),
  columns: new Set(["id", "title"]),
};

console.log(JSON.stringify(search)); // {"filters":{},"columns":{}}
```

### 2.4 Why this difference matters

Plain JSON has no built-in representation for Map entries or Set members, so both collections become empty objects in the saved payload.

## 3. Boundaries and distinctions

An array representation works when its ordering and element types are acceptable to the application. Use a tagged schema or another format when collection type information must be reconstructed automatically.
