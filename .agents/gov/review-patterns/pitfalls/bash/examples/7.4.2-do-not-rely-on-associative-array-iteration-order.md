# Do not rely on associative-array iteration order

## 1. Catalog record

- **Catalog identifier:** 7.4.2
- **Impact:** medium
- **Consensus:** high
- **Definition:** Bash associative arrays do not provide an insertion-order contract. Maintain a separate ordered key list or sort keys when deterministic ordering is required.

## 2. Example

### 2.1 Scenario

A deployment report must list environments in the same approved order every time. The lookup table maps each environment to its owner.

### 2.2 Preferred form

```bash
declare -A owner=([development]=Ava [staging]=Ben [production]=Cleo)
environments=(development staging production)

for environment in "${environments[@]}"; do
  printf '%s: %s\n' "$environment" "${owner[$environment]}"
done
```

### 2.3 Hazardous form

```bash
declare -A owner=([development]=Ava [staging]=Ben [production]=Cleo)

for environment in "${!owner[@]}"; do
  printf '%s: %s\n' "$environment" "${owner[$environment]}"
done
```

### 2.4 Why this difference matters

The hazardous loop exposes hash-table iteration order, which Bash does not promise to be insertion order or stable. A separate ordered list makes the report deterministic.

## 3. Boundaries and distinctions

Direct associative-array iteration is fine when the result is order-independent. Sorting keys is another option when the desired order is lexical rather than domain-specific.
