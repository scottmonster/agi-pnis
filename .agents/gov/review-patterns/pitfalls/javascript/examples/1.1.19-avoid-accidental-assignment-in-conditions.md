# Avoid accidental assignment in conditions

## 1. Catalog record

- **Catalog identifier:** 1.1.19
- **Impact:** medium
- **Consensus:** high
- **Definition:** Do not write `if (x = value)` when comparison is intended. If assignment in a condition is deliberate, make that intent syntactically obvious.

## 2. Example

### 2.1 Scenario

A handler should take an elevated path only for an administrator role.

### 2.2 Preferred form

```javascript
function canManageUsers(role) {
  if (role === "admin") {
    return true;
  }

  return false;
}

console.log(canManageUsers("viewer"));
```

### 2.3 Hazardous form

```javascript
function canManageUsers(role) {
  if (role = "admin") {
    return true;
  }

  return false;
}

console.log(canManageUsers("viewer"));
```

### 2.4 Why this difference matters

The assignment evaluates to the truthy string `"admin"`, so the elevated path always runs and the input variable is overwritten.

## 3. Boundaries and distinctions

Assignment in a condition can be deliberate, such as consuming a value from an iterator, but it should be parenthesized or otherwise made unmistakable.
