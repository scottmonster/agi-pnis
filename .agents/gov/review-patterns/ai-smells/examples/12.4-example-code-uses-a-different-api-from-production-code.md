# Example code uses a different API from production code

## 1. Catalog record

- **Catalog identifier:** 12.4
- **Evidence:** se
- **Definition:** Demonstrates calls, names, or semantics that diverge from the currently supported interface.

## 2. Scenario

### 2.1 Context

Production exports `createSession({ token })`, while the quickstart example calls the removed `new Session(token)` constructor.

### 2.2 Safer approach

Run the quickstart against the released package or share executable fixtures so the example calls the same supported interface as production consumers.

### 2.3 Failure mode

Update the production API but leave the old constructor call in the quickstart because it is only explanatory code.

### 2.4 Why this difference matters

Users copy a call that fails immediately or learn semantics that do not match the interface they receive.

## 3. Boundaries and distinctions

This is divergence between an example and a supported API. It differs from prose that names a nonexistent command or configuration key.
