# Prefer signal names over numeric signal values

## 1. Catalog record

- **Catalog identifier:** 8.5.2
- **Impact:** medium
- **Consensus:** high
- **Definition:** Use symbolic signal names such as `TERM`, `INT`, and `HUP` rather than relying on signal numbers where portability matters.

## 2. Example

### 2.1 Scenario

A supervisor stops a background worker during shutdown.

### 2.2 Preferred form

```bash
worker() {
  while :; do sleep 1; done
}

worker &
worker_pid=$!
kill -TERM "$worker_pid"
wait "$worker_pid"
```

### 2.3 Hazardous form

```bash
worker() {
  while :; do sleep 1; done
}

worker &
worker_pid=$!
kill -15 "$worker_pid"
wait "$worker_pid"
```

### 2.4 Why this difference matters

The name states the intended signal directly and avoids depending on numeric mappings as an interface. This makes signal-handling code clearer during review and safer to move across systems.

## 3. Boundaries and distinctions

Some fundamental signal numbers are widely conventional, but symbolic names are still clearer. Check a target platform's supported signals when portability is a requirement.
