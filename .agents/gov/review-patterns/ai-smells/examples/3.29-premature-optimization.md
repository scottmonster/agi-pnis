# Premature optimization

## 1. Catalog record

- **Catalog identifier:** 3.29
- **Evidence:** se
- **Definition:** Replaces clear code with clever data structures, vectorization, memoization, pooling, or hand-tuned algorithms without evidence of a bottleneck.

## 2. Scenario

### 2.1 Context

A readable loop formats a few dozen items for a weekly report.

### 2.2 Safer approach

Keep the clear loop and profile production-like workload before optimizing.

### 2.3 Failure mode

Replace it with pooling and memoization based only on a guess that it might be faster.

### 2.4 Why this difference matters

Optimization complexity can make behavior harder to verify and maintain without a measured benefit.

## 3. Boundaries and distinctions

Optimization is appropriate after evidence identifies a material bottleneck and the tradeoff is understood.
