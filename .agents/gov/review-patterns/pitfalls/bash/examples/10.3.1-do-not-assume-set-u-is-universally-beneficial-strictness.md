# Do not assume `set -u` is universally beneficial strictness

## 1. Catalog record

- **Catalog identifier:** 10.3.1
- **Impact:** medium
- **Consensus:** medium
- **Definition:** `set -u` catches some unset-variable references, but optional values and array edge cases mean it should be adopted deliberately rather than universally.

## 2. Example

### 2.1 Scenario

A command accepts an optional label as its first positional argument.

### 2.2 Preferred form

```bash
set -u

label=${1-}
if [[ -n $label ]]; then
  printf 'label: %s\n' "$label"
else
  printf 'no label supplied\n'
fi
```

### 2.3 Hazardous form

```bash
set -u

printf 'label: %s\n' "$1"
```

### 2.4 Why this difference matters

With no argument, the hazardous form exits on an unset positional parameter even though the absence of a label is valid for this command.

## 3. Boundaries and distinctions

`set -u` can be valuable when unset values are always defects. Use defaults or explicit presence checks at interfaces where absence is meaningful.
