# Assuming `asyncio.gather()` cancels siblings on first failure

## 1. Catalog record

- **Catalog identifier:** 10.1.1
- **Impact:** medium
- **Consensus:** high
- **Definition:** Use `TaskGroup` when one child failure should cancel the remaining child tasks. Do not assume default `gather()` provides those failure semantics.

## 2. Example

### 2.1 Scenario

Two child operations belong to one request and continuing either one after the other fails would be incorrect.

### 2.2 Preferred form

```python
import asyncio

async def fail() -> None:
    raise RuntimeError("request failed")

async def send_notification() -> None:
    await asyncio.sleep(10)

async def handle_request() -> None:
    async with asyncio.TaskGroup() as group:
        group.create_task(fail())
        group.create_task(send_notification())

asyncio.run(handle_request())
```

### 2.3 Hazardous form

```python
import asyncio

async def fail() -> None:
    raise RuntimeError("request failed")

async def send_notification() -> None:
    await asyncio.sleep(10)

async def handle_request() -> None:
    await asyncio.gather(fail(), send_notification())

asyncio.run(handle_request())
```

### 2.4 Why this difference matters

With its default behavior, `gather()` propagates the first exception while sibling awaitables can continue running. A task group cancels the sibling as part of the failed operation.

## 3. Boundaries and distinctions

Use `gather()` when independent tasks are intended to continue despite a sibling failure, and explicitly manage cancellation when that policy is required.
