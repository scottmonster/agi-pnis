# Configuration-schema conflict

## 1. Catalog record

- **Catalog identifier:** 2.11
- **Evidence:** e
- **Definition:** Invents config keys, flags, environment variables, or values the project does not understand.

## 2. Scenario

### 2.1 Context

A deployment reads its service port from a documented application configuration schema.

### 2.2 Safer approach

The agent inspects the schema and deployment examples, then changes the supported `server.port` setting if needed.

### 2.3 Failure mode

It adds `SERVER_LISTEN_PORT=8081`, assuming the application reads that environment variable.

### 2.4 Why this difference matters

The deployment appears configured but continues using its default port, causing a hard-to-diagnose operational failure.

## 3. Boundaries and distinctions

New configuration can be implemented deliberately, but a declared value is not functional until the project's configuration path recognizes it.
