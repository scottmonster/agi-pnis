# Do not pass an expanding glob to one `test -e` expression

## 1. Catalog record

- **Catalog identifier:** 6.5.1
- **Impact:** medium
- **Consensus:** high
- **Definition:** `[ -e directory/* ]` is unsafe as an existence test because zero, one, and multiple glob matches all produce different argument structures. Use an array, loop, or deliberate glob-option technique.

## 2. Example

### 2.1 Scenario

A job runner determines whether an inbox has entries.

### 2.2 Preferred form

```bash
#!/usr/bin/env bash
files=("$1"/*)
if ((${#files[@]} != 1)) || [[ -e ${files[0]} ]]; then echo 'has entries'; fi
```

### 2.3 Hazardous form

```bash
#!/usr/bin/env bash
if [ -e "$1"/* ]; then echo 'has entries'; fi
```

### 2.4 Why this difference matters

Multiple matches turn a one-pathname test into a malformed expression with several operands.

## 3. Boundaries and distinctions

The array form relies on Bash leaving unmatched globs literal. A scoped `nullglob` or loop is another deliberate strategy.
