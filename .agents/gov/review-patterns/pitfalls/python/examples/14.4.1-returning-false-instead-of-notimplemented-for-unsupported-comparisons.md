# Returning `False` instead of `NotImplemented` for unsupported comparisons

## 1. Catalog record

- **Catalog identifier:** 14.4.1
- **Impact:** medium
- **Consensus:** high
- **Definition:** Custom rich comparison and numeric methods should return `NotImplemented` when the operand type is unsupported.

## 2. Example

### 2.1 Scenario

A value object supports equality only with other values of the same class.

### 2.2 Preferred form

```python
class Ticket:
    def __init__(self, number: int) -> None:
        self.number = number

    def __eq__(self, other: object) -> object:
        if not isinstance(other, Ticket):
            return NotImplemented
        return self.number == other.number


print(Ticket(4) == Ticket(4))
print(Ticket(4) == 4)
```

### 2.3 Hazardous form

```python
class Ticket:
    def __init__(self, number: int) -> None:
        self.number = number

    def __eq__(self, other: object) -> bool:
        if not isinstance(other, Ticket):
            return False
        return self.number == other.number


print(Ticket(4) == 4)
```

### 2.4 Why this difference matters

Returning `NotImplemented` tells Python that this operand pair is unsupported and permits the normal reflected-operation protocol. Returning `False` incorrectly claims a definitive comparison result.

## 3. Boundaries and distinctions

Return a real boolean after handling a supported operand type. `NotImplemented` is for unsupported operand types, not for an ordinary unequal value of a supported type.
