# Use structuredClone rather than JSON round-tripping for general deep cloning

## 1. Catalog record

- **Catalog identifier:** 9.1.1
- **Impact:** medium
- **Consensus:** high
- **Definition:** Use structuredClone for general deep cloning of supported JavaScript data.

## 2. Example

### 2.1 Scenario

A dashboard copies a report before a user edits its nested filters locally.

### 2.2 Preferred form

```javascript
const report = {
  createdAt: new Date("2026-09-04T12:00:00Z"),
  filters: new Map([["region", "west"]]),
};

const editableReport = structuredClone(report);
editableReport.filters.set("region", "east");

console.log(report.filters.get("region")); // west
console.log(editableReport.createdAt instanceof Date); // true
```

### 2.3 Hazardous form

```javascript
const report = {
  createdAt: new Date("2026-09-04T12:00:00Z"),
  filters: new Map([["region", "west"]]),
};

const editableReport = JSON.parse(JSON.stringify(report));

console.log(editableReport.filters); // {}
console.log(typeof editableReport.createdAt); // string
```

### 2.4 Why this difference matters

JSON serialization changes Dates and loses Map contents, so an apparently independent copy can already have incorrect data before editing begins.

## 3. Boundaries and distinctions

`structuredClone()` is not a universal clone operation. Choose an explicit representation when the source contains unsupported values or needs property-descriptor semantics preserved.
