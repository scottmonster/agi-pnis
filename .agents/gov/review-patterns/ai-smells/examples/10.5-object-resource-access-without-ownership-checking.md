# Object/resource access without ownership checking

## 1. Catalog record

- **Catalog identifier:** 10.5
- **Evidence:** e
- **Definition:** Uses a caller-controlled identifier to access an object without confirming the caller is entitled to that specific object.

## 2. Scenario

### 2.1 Context

The web app exposes `GET /documents/{id}` to signed-in customers.

### 2.2 Safer approach

Query the document through an access predicate that includes the authenticated user or tenant, then return not found or forbidden as appropriate.

### 2.3 Failure mode

The agent loads the document solely by the path ID after checking that the requester has a valid session.

### 2.4 Why this difference matters

Changing the ID can reveal or modify another customer’s object despite valid authentication.

## 3. Boundaries and distinctions

Role authorization may be necessary too, but this failure specifically concerns object-level entitlement for a caller-controlled reference.
