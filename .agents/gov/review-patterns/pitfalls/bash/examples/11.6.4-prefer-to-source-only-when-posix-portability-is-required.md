# Prefer `.` to `source` only when POSIX portability is required

## 1. Catalog record

- **Catalog identifier:** 11.6.4
- **Impact:** low
- **Consensus:** high
- **Definition:** Bash supports both `source file` and `. file`; POSIX specifies the dot command. Bash-targeted code may use either, but portable shell libraries should use `.` and account for its lookup rules.

## 2. Example

### 2.1 Scenario

A reusable settings file must be loaded by a script that promises POSIX `sh` compatibility.

### 2.2 Preferred form

```bash
#!/bin/sh

. ./project-settings.sh
echo "environment: $PROJECT_ENVIRONMENT"
```

### 2.3 Hazardous form

```bash
#!/bin/sh

source ./project-settings.sh
echo "environment: $PROJECT_ENVIRONMENT"
```

### 2.4 Why this difference matters

`source` is a Bash spelling, so the hazardous form can fail in a POSIX shell even though the sourced file itself is portable.

## 3. Boundaries and distinctions

Bash accepts both commands. Use `.` when portability is required, and ensure the file location works with the dot command's lookup rules.
