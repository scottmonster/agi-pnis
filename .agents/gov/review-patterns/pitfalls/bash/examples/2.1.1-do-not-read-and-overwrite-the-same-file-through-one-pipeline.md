# Do not read and overwrite the same file through one pipeline

## 1. Catalog record

- **Catalog identifier:** 2.1.1
- **Impact:** high
- **Consensus:** high
- **Definition:** Avoid constructs where a command reads a file while shell redirection simultaneously opens that same file for output. Write to a separate temporary file and replace the original after success.

## 2. Example

### 2.1 Scenario

A maintenance script normalizes a configuration file by removing blank lines. The original must remain intact until the transformation succeeds.

### 2.2 Preferred form

```bash
#!/usr/bin/env bash
set -euo pipefail

config_file='service.conf'
temporary_file=$(mktemp "${config_file}.XXXXXX")
trap 'rm -f -- "$temporary_file"' EXIT

grep -v '^[[:space:]]*$' -- "$config_file" > "$temporary_file"
mv -- "$temporary_file" "$config_file"
trap - EXIT
```

### 2.3 Hazardous form

```bash
#!/usr/bin/env bash
set -euo pipefail

config_file='service.conf'
grep -v '^[[:space:]]*$' -- "$config_file" > "$config_file"
```

### 2.4 Why this difference matters

Bash opens the redirection target before `grep` reads its input, so the hazardous form truncates the file before the transformation can consume it. The temporary file allows replacement only after a successful read and write.

## 3. Boundaries and distinctions

This applies when the command reads the original through the same path it redirects to. An in-place editing tool may be appropriate only when its documented backup and failure behavior meets the data-integrity requirement.
