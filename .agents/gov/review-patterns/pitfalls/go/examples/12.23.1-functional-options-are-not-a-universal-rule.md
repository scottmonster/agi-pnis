# Functional options are not a universal rule

## 1. Catalog record

- **Catalog identifier:** 12.23.1
- **Impact:** medium
- **Consensus:** medium
- **Definition:** Choose configuration structs, functional options, or another pattern according to the API's compatibility and usability needs rather than treating functional options as mandatory Go style.

## 2. Example

### 2.1 Scenario

A client has a small, cohesive set of configuration values that callers commonly want to inspect and validate together.

### 2.2 Preferred form

```go
package api

import (
	"fmt"
	"time"
)

type ClientConfig struct {
	Endpoint string
	Timeout  time.Duration
}

type Client struct {
	config ClientConfig
}

func NewClient(config ClientConfig) (*Client, error) {
	if config.Endpoint == "" {
		return nil, fmt.Errorf("endpoint is required")
	}
	if config.Timeout <= 0 {
		return nil, fmt.Errorf("timeout must be positive")
	}
	return &Client{config: config}, nil
}
```

### 2.3 Hazardous form

```go
package api

import (
	"fmt"
	"time"
)

type Client struct {
	endpoint string
	timeout  time.Duration
}

type Option func(*Client)

func WithEndpoint(endpoint string) Option {
	return func(client *Client) { client.endpoint = endpoint }
}

func WithTimeout(timeout time.Duration) Option {
	return func(client *Client) { client.timeout = timeout }
}

func NewClient(options ...Option) (*Client, error) {
	client := &Client{}
	for _, option := range options {
		option(client)
	}
	if client.endpoint == "" || client.timeout <= 0 {
		return nil, fmt.Errorf("invalid client configuration")
	}
	return client, nil
}
```

### 2.4 Why this difference matters

For this small configuration, options hide the required fields, make conflicting or repeated options possible, and produce less specific validation. A configuration struct makes the supported settings visible and validates their relationship in one place.

## 3. Boundaries and distinctions

Functional options are useful when an API has many optional settings, defaults must remain compatible as it evolves, or options need behavior beyond data. A configuration struct, a required-argument constructor, or a builder can be clearer when those benefits do not apply.
