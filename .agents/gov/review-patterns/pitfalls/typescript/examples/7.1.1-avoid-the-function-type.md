# Avoid the `Function` type

## 1. Catalog record

- **Catalog identifier:** 7.1.1
- **Impact:** medium
- **Consensus:** high
- **Definition:** Describe callable values with an actual call signature instead of `Function`.

## 2. Example

### 2.1 Scenario

A formatter callback receives an invoice label and must return display text.

### 2.2 Preferred form

```typescript
function formatInvoice(formatter: (label: string) => string): string {
  return formatter('invoice-42');
}

console.log(formatInvoice((label) => label.toUpperCase()));
```

### 2.3 Hazardous form

```typescript
function formatInvoice(formatter: Function): string {
  return formatter('invoice-42');
}

console.log(formatInvoice((sequence: number) => sequence.toFixed(2)));
// `Function` permits the incompatible callback, which receives a string at runtime.
```

### 2.4 Why this difference matters

`Function` provides almost no useful information about accepted arguments or returned values and enables unsafe calls.

## 3. Boundaries and distinctions

Apply this guidance in the conditions described by the catalog record. Deliberate exceptions need a documented runtime guarantee, compatible toolchain behavior, or an explicit local unsafe boundary.
