# Do not use `new` for slices and maps by habit

## 1. Catalog record

- **Catalog identifier:** 13.10.1
- **Impact:** low
- **Consensus:** high
- **Definition:** Use a zero slice or `make` for slices and maps rather than creating pointers such as `new([]T)` or `new(map[K]V)` without a specific pointer requirement.

## 2. Example

### 2.1 Scenario

A cache needs a map that can immediately accept entries.

### 2.2 Preferred form

```go
package example

func cache() map[string]int {
	counts := make(map[string]int)
	counts["open"] = 1
	return counts
}
```

### 2.3 Hazardous form

```go
package example

func cache() *map[string]int {
	counts := new(map[string]int)
	(*counts)["open"] = 1
	return counts
}
```

### 2.4 Why this difference matters

`make` returns an initialized map ready for assignment. `new(map[string]int)` returns a pointer to a nil map, so the assignment panics and the extra pointer has no useful purpose.

## 3. Boundaries and distinctions

Use `new` when a pointer to a zero value is itself required. A nil slice is already ready for `append`, while a map must be initialized before writes.
