# Do not use forEach when you need early exit

## 1. Catalog record

- **Catalog identifier:** 3.1.14
- **Impact:** medium
- **Consensus:** high
- **Definition:** `forEach()` cannot be stopped with a normal `break`. Use `for...of`, `some()`, `every()`, `find()`, or another operation whose control semantics match the task.

## 2. Example

### 2.1 Scenario

A validator needs to stop as soon as it finds the first invalid score.

### 2.2 Preferred form

```javascript
const scores = [82, 91, -1, 77];
let invalidScore;

for (const score of scores) {
  if (score < 0) {
    invalidScore = score;
    break;
  }
}

console.log(invalidScore); // -1
```

### 2.3 Hazardous form

```javascript
const scores = [82, 91, -1, 77];
let invalidScore;

scores.forEach((score) => {
  if (score < 0) {
    invalidScore = score;
    return;
  }
  console.log(`Checked ${score}`);
});

console.log(invalidScore); // -1
```

### 2.4 Why this difference matters

`return` exits only the callback, not `forEach`, so the loop still visits later values after it has found the invalid score.

## 3. Boundaries and distinctions

`forEach` is appropriate when every element should be visited. Use `some`, `find`, or a loop when the task requires early exit.
