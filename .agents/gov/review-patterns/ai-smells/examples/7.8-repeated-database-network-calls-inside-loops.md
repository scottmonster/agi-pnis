# Repeated database/network calls inside loops

## 1. Catalog record

- **Catalog identifier:** 7.8
- **Evidence:** se
- **Definition:** Performs one remote operation per iteration instead of batching, prefetching, or reusing a result where appropriate.

## 2. Scenario

### 2.1 Context

An agent builds a handler that enriches 500 order lines with product data from a service.

### 2.2 Safer approach

It collects unique product IDs and uses the service's batch endpoint, reusing each returned product record.

### 2.3 Failure mode

It makes one network request inside the loop for every order line, including repeated IDs.

### 2.4 Why this difference matters

The handler adds remote latency and load for every iteration, increasing the chance of timeouts.

## 3. Boundaries and distinctions

Per-item remote calls can be necessary when no batch operation exists or each request depends on the previous result; batch, prefetch, or reuse only where appropriate.
