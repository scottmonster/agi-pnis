# Use `10#` carefully for signed decimal input

## 1. Catalog record

- **Catalog identifier:** 7.6.1
- **Impact:** medium
- **Consensus:** high
- **Definition:** Prefixing a numeric magnitude with `10#` can force decimal interpretation, but blindly constructing `10#$value` is not a complete solution for signed input. Validate the format and handle the sign separately when necessary.

## 2. Example

### 2.1 Scenario

A command-line offset may be a zero-padded positive or negative decimal quantity. The script must normalize it before arithmetic.

### 2.2 Preferred form

```bash
raw_offset=-08

if [[ $raw_offset =~ ^-?[0-9]+$ ]]; then
  sign=1
  magnitude=$raw_offset
  if [[ $raw_offset == -* ]]; then
    sign=-1
    magnitude=${raw_offset#-}
  fi
  offset=$((sign * 10#$magnitude))
  printf 'Normalized offset: %d\n' "$offset"
else
  printf 'Invalid offset: %s\n' "$raw_offset" >&2
  exit 2
fi
```

### 2.3 Hazardous form

```bash
raw_offset=-08
offset=$((10#$raw_offset))
printf 'Normalized offset: %d\n' "$offset"
```

### 2.4 Why this difference matters

The decimal-base prefix applies to a magnitude, not a signed representation. The hazardous expression can fail for an otherwise valid negative input, while the preferred form validates and applies the sign separately.

## 3. Boundaries and distinctions

For unsigned decimal input, a validated `10#` conversion is sufficient. Do not accept signs, whitespace, or other syntax unless the input contract explicitly supports them.
