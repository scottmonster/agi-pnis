# Process substitution is not portable POSIX `sh`

## 1. Catalog record

- **Catalog identifier:** 11.6.2
- **Impact:** low
- **Consensus:** high
- **Definition:** `<(...)` and `>(...)` are Bash extensions rather than portable POSIX shell syntax. Use pipes, temporary files, or explicit descriptors when POSIX-shell portability is required.

## 2. Example

### 2.1 Scenario

A portable script compares sorted copies of two configuration files.

### 2.2 Preferred form

```bash
#!/bin/sh

left_sorted=$(mktemp)
right_sorted=$(mktemp)
trap 'rm -f "$left_sorted" "$right_sorted"' 0 1 2 15
sort ./left.conf >"$left_sorted"
sort ./right.conf >"$right_sorted"
diff -u "$left_sorted" "$right_sorted"
```

### 2.3 Hazardous form

```bash
#!/bin/sh

diff -u <(sort ./left.conf) <(sort ./right.conf)
```

### 2.4 Why this difference matters

Process substitution can work in Bash while producing a syntax error in a POSIX shell before the comparison begins.

## 3. Boundaries and distinctions

Process substitution is concise and valid for Bash-targeted scripts. Choose a portable data-flow mechanism when the interpreter may be POSIX `sh`.
