# Prefer non-capturing regex groups when capture data is unnecessary

## 1. Catalog record

- **Catalog identifier:** 5.1.9
- **Impact:** low
- **Consensus:** high
- **Definition:** Use `(?:...)` for grouping required only for precedence or quantification, reserving capturing groups for values that will actually be consumed.

## 2. Example

### 2.1 Scenario

A parser accepts a version label with an optional `beta` suffix and extracts only the numeric version.

### 2.2 Preferred form

```javascript
function parseVersion(label) {
  const match = /^(\d+)(?:-beta)?$/u.exec(label);
  return match ? Number(match[1]) : null;
}

console.log(parseVersion("42-beta")); // 42
```

### 2.3 Hazardous form

```javascript
function parseVersion(label) {
  const match = /^(\d+)(-beta)?$/u.exec(label);
  return match ? Number(match[2]) : null;
}

console.log(parseVersion("42-beta")); // NaN
```

### 2.4 Why this difference matters

The unnecessary capture shifts capture numbering, making later maintenance more likely to read the wrong match result.

## 3. Boundaries and distinctions

Use a capturing group when its substring is part of the required result. Named capturing groups can make required captures clearer in complex patterns.
