# Defend dynamic property writes against prototype pollution

## 1. Catalog record

- **Catalog identifier:** 2.6.1
- **Impact:** high
- **Consensus:** high
- **Definition:** Validate untrusted property names and paths to prevent prototype traversal or mutation.

## 2. Example

### 2.1 Scenario

An API applies a user-provided setting name to a configuration object.

### 2.2 Preferred form

```javascript
const blockedKeys = new Set(["__proto__", "constructor", "prototype"]);

function setOption(options, key, value) {
  if (blockedKeys.has(key)) throw new Error("unsafe option name");
  options[key] = value;
}
```

### 2.3 Hazardous form

```javascript
function setOption(options, key, value) {
  options[key] = value;
}

setOption({}, "__proto__", { isAdmin: true });
```

### 2.4 Why this difference matters

Unvalidated dynamic writes can alter an object's prototype or enable prototype-pollution paths when keys are built from untrusted input.

## 3. Boundaries and distinctions

For nested paths, validate every segment. A null-prototype dictionary can reduce inherited-property hazards but does not replace input validation.
