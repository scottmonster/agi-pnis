# Excessive layering

## 1. Catalog record

- **Catalog identifier:** 3.14
- **Evidence:** e/se
- **Definition:** Controller → Service → Manager → Repository → Adapter where most layers only forward arguments.

## 2. Scenario

### 2.1 Context

A controller loads an order and returns its summary.

### 2.2 Safer approach

Keep only boundaries that transform responsibility, such as the controller and a meaningful order data access component.

### 2.3 Failure mode

Route the call through controller, service, manager, repository, and adapter even though each only passes arguments onward.

### 2.4 Why this difference matters

Readers must traverse several files to find behavior, and every forwarding layer expands change cost.

## 3. Boundaries and distinctions

Layers that own distinct policy, translation, or infrastructure concerns can be useful; pure forwarding is the distinguishing problem.
