# Do not use `int` as an external fixed-width representation

## 1. Catalog record

- **Catalog identifier:** 8.7.1
- **Impact:** medium
- **Consensus:** high
- **Definition:** Use fixed-width integer types when a value's binary width is part of a file format, protocol, hash, or persistent representation.

## 2. Example

### 2.1 Scenario

A file format stores a record count in exactly four big-endian bytes.

### 2.2 Preferred form

```go
package format

import "encoding/binary"

func encodeCount(count uint32) []byte {
	b := make([]byte, 4)
	binary.BigEndian.PutUint32(b, count)
	return b
}
```

### 2.3 Hazardous form

```go
package format

import "encoding/binary"

func encodeCount(count int) []byte {
	b := make([]byte, 8)
	binary.BigEndian.PutUint64(b, uint64(count))
	return b
}
```

### 2.4 Why this difference matters

`int` is 32 or 64 bits depending on the target architecture. Encoding it as the external representation changes the wire shape across builds and does not match the four-byte format.

## 3. Boundaries and distinctions

`int` remains suitable for in-memory indexes, slice lengths, and values whose width is not externally observable. Choose signed or unsigned fixed-width types according to the external specification.
