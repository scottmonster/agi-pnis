# Assignment-expression targets leaking from comprehensions

## 1. Catalog record

- **Catalog identifier:** 6.16.1
- **Impact:** medium
- **Consensus:** high
- **Definition:** Do not assume a walrus target inside a comprehension is scoped like the comprehension's loop variable. Choose names with the containing-scope binding in mind.

## 2. Example

### 2.1 Scenario

A parser filters nonempty lines and needs the trimmed result only inside that transformation.

### 2.2 Preferred form

```python
lines = [" first ", "   ", "second"]
cleaned = [line.strip() for line in lines if line.strip()]
print(cleaned)  # ['first', 'second']
```

### 2.3 Hazardous form

```python
lines = [" first ", "   ", "second"]
cleaned = [trimmed for line in lines if (trimmed := line.strip())]
print(cleaned)
print(trimmed)  # 'second', bound in the containing scope
```

### 2.4 Why this difference matters

Unlike the comprehension loop variable, an assignment-expression target binds in the surrounding scope and can unexpectedly overwrite or leave state behind.

## 3. Boundaries and distinctions

Use a walrus expression deliberately when the containing-scope binding is useful and its lifetime and name collision risks are clear.
