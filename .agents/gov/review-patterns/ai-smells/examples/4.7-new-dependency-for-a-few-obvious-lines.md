# New dependency for a few obvious lines

## 1. Catalog record

- **Catalog identifier:** 4.7
- **Evidence:** se
- **Definition:** Adds package, update surface, and supply-chain risk for trivial functionality.

## 2. Scenario

### 2.1 Context

An agent needs to clamp a numeric request parameter between a configured minimum and maximum.

### 2.2 Safer approach

It writes and tests the small expression using the language's existing numeric functions, keeping the behavior clear at the call site.

### 2.3 Failure mode

It adds a general-purpose utility package solely for its `clamp` helper, changing the lockfile and dependency audit surface for a one-line operation.

### 2.4 Why this difference matters

The package introduces version updates, transitive code, and supply-chain exposure that are disproportionate to the trivial function gained.

## 3. Boundaries and distinctions

A dependency is reasonable when it provides substantial, well-maintained capability that the project genuinely needs. This failure concerns a few obvious lines, not reuse of a meaningful library.
