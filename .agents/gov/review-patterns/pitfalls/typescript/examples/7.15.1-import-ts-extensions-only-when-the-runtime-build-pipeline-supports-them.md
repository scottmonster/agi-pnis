# Import `.ts` extensions only when the runtime/build pipeline supports them

## 1. Catalog record

- **Catalog identifier:** 7.15.1
- **Impact:** medium
- **Consensus:** high
- **Definition:** Use `allowImportingTsExtensions` only in no-emit/declaration-only or compatible runtime workflows rather than assuming emitted JavaScript can resolve `.ts` files.

## 2. Example

### 2.1 Scenario

A no-emit test workflow runs TypeScript source directly, whereas the production application emits JavaScript for Node.js.

### 2.2 Preferred form

```typescript
// tsconfig.tests.json
// {
//   "compilerOptions": {
//     "noEmit": true,
//     "allowImportingTsExtensions": true
//   }
// }

// Run by a TypeScript-aware runtime configured to load .ts files.
import { parseSettings } from './parse-settings.ts';

console.log(parseSettings('{"port":3000}'));

// parse-settings.ts
export function parseSettings(source: string): { port: number } {
  return JSON.parse(source) as { port: number };
}
```

### 2.3 Hazardous form

```typescript
// tsconfig.json
// {
//   "compilerOptions": {
//     "outDir": "dist",
//     "allowImportingTsExtensions": true
//   }
// }

import { parseSettings } from './parse-settings.ts';

console.log(parseSettings('{"port":3000}'));

// This configuration is rejected unless noEmit or emitDeclarationOnly is set.
// A JavaScript output file retaining './parse-settings.ts' would not run in
// ordinary Node.js without a loader that understands TypeScript source.
```

### 2.4 Why this difference matters

The compiler does not rewrite a `.ts` module specifier into the JavaScript file that `tsc` emits. `allowImportingTsExtensions` therefore requires a no-emit or declaration-only workflow, unless another build tool takes responsibility for rewriting imports. Treat the emitted specifier and the runtime resolver as a single contract.

## 3. Boundaries and distinctions

For JavaScript emitted for Node ESM, source imports normally use the final `.js` specifier, for example `./parse-settings.js`. Source-first runtimes, test runners, and bundlers may support `.ts` imports, but document that capability and test the actual execution path. Declaration-only output does not itself make a `.ts` specifier runnable at runtime.
