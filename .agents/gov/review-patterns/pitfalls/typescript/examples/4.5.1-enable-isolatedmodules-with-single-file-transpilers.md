# Enable `isolatedModules` with single-file transpilers

## 1. Catalog record

- **Catalog identifier:** 4.5.1
- **Impact:** high
- **Consensus:** high
- **Definition:** Enable `isolatedModules` when Babel, SWC, esbuild, or another tool transpiles files without whole-program type information.

## 2. Example

### 2.1 Scenario

A single-file transpiler compiles a module that re-exports a type.

### 2.2 Preferred form

```typescript
// tsconfig.json: { "compilerOptions": { "isolatedModules": true } }
// models.ts
export interface User { id: string }

// index.ts
export type { User } from './models.js';
```

### 2.3 Hazardous form

```typescript
// models.ts
export interface User { id: string }

// index.ts. A single-file transform cannot know this export is type-only.
export { User } from './models.js';
```

### 2.4 Why this difference matters

It catches TypeScript constructs whose correct JavaScript transformation depends on information unavailable to a single-file transpiler.

## 3. Boundaries and distinctions

Apply this guidance in the conditions described by the catalog record. Deliberate exceptions need a documented runtime guarantee, compatible toolchain behavior, or an explicit local unsafe boundary.
