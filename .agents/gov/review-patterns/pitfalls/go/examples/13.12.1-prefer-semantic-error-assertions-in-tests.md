# Prefer semantic error assertions in tests

## 1. Catalog record

- **Catalog identifier:** 13.12.1
- **Impact:** low
- **Consensus:** high
- **Definition:** When the error's identity or type is the contract, test with `errors.Is` or `errors.As` rather than comparing the entire error string.

## 2. Example

### 2.1 Scenario

A test verifies that a storage operation preserves the documented `ErrNotFound` identity after adding context.

### 2.2 Preferred form

```go
package store

import (
	"errors"
	"fmt"
	"testing"
)

var ErrNotFound = errors.New("not found")

func load(id string) error { return fmt.Errorf("load %q: %w", id, ErrNotFound) }

func TestLoadMissing(t *testing.T) {
	if err := load("42"); !errors.Is(err, ErrNotFound) {
		t.Fatalf("load missing: got %v, want errors.Is(..., ErrNotFound)", err)
	}
}
```

### 2.3 Hazardous form

```go
package store

import (
	"errors"
	"fmt"
	"testing"
)

var ErrNotFound = errors.New("not found")

func load(id string) error { return fmt.Errorf("load %q: %w", id, ErrNotFound) }

func TestLoadMissing(t *testing.T) {
	if got := load("42").Error(); got != "load \"42\": not found" {
		t.Fatalf("got %q", got)
	}
}
```

### 2.4 Why this difference matters

`errors.Is` tests the promised sentinel through wrapping. Exact text testing fails when harmless context or wording changes, even though callers can still detect the same error.

## 3. Boundaries and distinctions

Compare text when that text is the documented user-visible contract. Use `errors.As` when the contract is an error type rather than a sentinel identity.
