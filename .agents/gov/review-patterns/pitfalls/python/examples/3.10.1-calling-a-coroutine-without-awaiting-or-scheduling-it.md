# Calling a coroutine without awaiting or scheduling it

## 1. Catalog record

- **Catalog identifier:** 3.10.1
- **Impact:** high
- **Consensus:** high
- **Definition:** Await coroutine objects or explicitly schedule them as tasks. Merely calling an `async def` function does not execute its body.

## 2. Example

### 2.1 Scenario

An order handler must record an audit event before it reports success. The asynchronous audit operation must actually run.

### 2.2 Preferred form

```python
import asyncio


async def write_audit_event(order_id: str) -> None:
    await asyncio.sleep(0)
    print(f"audited {order_id}")


async def handle_order(order_id: str) -> None:
    await write_audit_event(order_id)
    print(f"handled {order_id}")


asyncio.run(handle_order("A-42"))
```

### 2.3 Hazardous form

```python
import asyncio


async def write_audit_event(order_id: str) -> None:
    await asyncio.sleep(0)
    print(f"audited {order_id}")


async def handle_order(order_id: str) -> None:
    write_audit_event(order_id)
    print(f"handled {order_id}")


asyncio.run(handle_order("A-42"))
```

### 2.4 Why this difference matters

Calling an async function only creates a coroutine object. The hazardous form never runs its body and typically produces an unawaited-coroutine warning.

## 3. Boundaries and distinctions

Use `create_task()` or a `TaskGroup` for genuinely concurrent work, while retaining lifecycle control. Await directly when the caller needs the operation's result or completion.
