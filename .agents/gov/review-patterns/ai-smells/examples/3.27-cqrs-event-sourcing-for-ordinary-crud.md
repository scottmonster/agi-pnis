# CQRS/event sourcing for ordinary CRUD

## 1. Catalog record

- **Catalog identifier:** 3.27
- **Evidence:** se
- **Definition:** Introduces command models, event stores, projections, and reconciliation without corresponding domain requirements.

## 2. Scenario

### 2.1 Context

An internal tool creates and edits employee contact records.

### 2.2 Safer approach

Use ordinary validated CRUD with the required audit fields.

### 2.3 Failure mode

Model every edit as an event stream with command handlers, projections, and reconciliation for the simple records.

### 2.4 Why this difference matters

The architecture adds eventual consistency and recovery responsibilities absent from the domain need.

## 3. Boundaries and distinctions

CQRS or event sourcing can fit audit, temporal, or complex workflow requirements; ordinary CRUD alone does not establish those requirements.
