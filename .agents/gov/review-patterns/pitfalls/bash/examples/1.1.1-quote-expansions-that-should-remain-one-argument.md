# Quote expansions that should remain one argument

## 1. Catalog record

- **Catalog identifier:** 1.1.1
- **Impact:** high
- **Consensus:** high
- **Definition:** Use `"$var"` and `"$(command)"` when the expansion is intended to produce one argument. Unquoted parameter and command expansions are subject to word splitting and pathname expansion.

## 2. Example

### 2.1 Scenario

A deployment script creates a directory from an operator-supplied release name. The name can contain spaces or glob characters.

### 2.2 Preferred form

```bash
release_name='April reports [final]'
destination="/srv/releases/$release_name"

mkdir -p -- "$destination"
printf 'Created directory: %s\n' "$destination"
```

### 2.3 Hazardous form

```bash
release_name='April reports [final]'
destination="/srv/releases/$release_name"

mkdir -p -- $destination
printf 'Created directory: %s\n' $destination
```

### 2.4 Why this difference matters

The unquoted expansion can split a single pathname into several arguments and can expand wildcard characters against files in the current directory. The command may create unintended directories or report a misleading result.

## 3. Boundaries and distinctions

Leave an expansion unquoted only when splitting or pathname expansion is intentionally required and its input is controlled. Quoting does not make arbitrary data safe for every command, so command-specific option handling still matters.
