# Order-dependent behavior

## 1. Catalog record

- **Catalog identifier:** 6.26
- **Evidence:** se
- **Definition:** Correctness accidentally depends on iteration, import, registration, startup, or test order.

## 2. Scenario

### 2.1 Context

Each test must start with an empty in-memory feature registry.

### 2.2 Safer approach

The agent initializes or resets the registry explicitly in test setup.

### 2.3 Failure mode

It relies on a previous test to register a feature before the current test runs.

### 2.4 Why this difference matters

The suite passes in one order and fails in isolation or on another runner.

## 3. Boundaries and distinctions

An explicitly documented ordering constraint can be valid, but hidden dependency on incidental execution order is not.
