# Do not rely on garbage collection for essential cleanup

## 1. Catalog record

- **Catalog identifier:** 12.1.6
- **Impact:** high
- **Consensus:** high
- **Definition:** Make correctness-critical cleanup deterministic rather than dependent on WeakRef or finalizer timing.

## 2. Example

### 2.1 Scenario

A page opens a WebSocket to receive live updates and must close it when the view is left.

### 2.2 Preferred form

```javascript
function subscribeToUpdates(url) {
  const socket = new WebSocket(url);

  return () => {
    socket.close(1000, "View closed");
  };
}

const unsubscribe = subscribeToUpdates("wss://updates.example.test");
window.addEventListener("pagehide", unsubscribe, { once: true });
```

### 2.3 Hazardous form

```javascript
const finalizer = new FinalizationRegistry((socket) => {
  socket.close(1000, "Collected");
});

function subscribeToUpdates(url) {
  const view = {};
  const socket = new WebSocket(url);
  finalizer.register(view, socket);
  return view;
}

let currentView = subscribeToUpdates("wss://updates.example.test");
currentView = null;
```

### 2.4 Why this difference matters

Finalization is not prompt or guaranteed before page shutdown, so the socket can remain open long after the view is gone. An explicit lifecycle action releases the resource at the required time.

## 3. Boundaries and distinctions

Weak references and finalizers can support optional cache or diagnostic behavior, but they are unsuitable for correctness-critical cleanup such as sockets, locks, or subscriptions.
