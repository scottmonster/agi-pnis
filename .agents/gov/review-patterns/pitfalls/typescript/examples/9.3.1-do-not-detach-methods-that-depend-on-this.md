# Do not detach methods that depend on `this`

## 1. Catalog record

- **Catalog identifier:** 9.3.1
- **Impact:** medium
- **Consensus:** high
- **Definition:** Bind the method, wrap it, use an arrow-property function, or annotate `this: void` when a method genuinely does not depend on a receiver.

## 2. Example

### 2.1 Scenario

A counter's increment operation is passed to code that calls it without a receiver.

### 2.2 Preferred form

```typescript
class Counter {
  private value = 0;

  increment(): number {
    this.value += 1;
    return this.value;
  }
}

const counter = new Counter();
const increment = counter.increment.bind(counter);
console.log(increment());
```

### 2.3 Hazardous form

```typescript
class Counter {
  private value = 0;

  increment(): number {
    this.value += 1;
    return this.value;
  }
}

const counter = new Counter();
const increment = counter.increment;
increment(); // runtime TypeError: this is undefined
```

### 2.4 Why this difference matters

Extracting a method from its object loses its receiver even though its type may otherwise look callable.

## 3. Boundaries and distinctions

Apply this guidance in the conditions described by the catalog record. Deliberate exceptions need a documented runtime guarantee, compatible toolchain behavior, or an explicit local unsafe boundary.
