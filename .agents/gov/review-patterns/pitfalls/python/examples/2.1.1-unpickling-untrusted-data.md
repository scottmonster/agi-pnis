# Unpickling untrusted data

## 1. Catalog record

- **Catalog identifier:** 2.1.1
- **Impact:** high
- **Consensus:** high
- **Definition:** Never load untrusted or unauthenticated data with `pickle`. Use a non-executable serialization format when the input crosses a trust boundary.

## 2. Example

### 2.1 Scenario

A web service receives a profile document uploaded by an untrusted customer.

### 2.2 Preferred form

```python
import json


def load_profile(payload: bytes) -> dict[str, str]:
    value = json.loads(payload)
    if not isinstance(value, dict) or not all(isinstance(v, str) for v in value.values()):
        raise ValueError("invalid profile")
    return value


print(load_profile(b'{"name": "Ada"}'))
```

### 2.3 Hazardous form

```python
import pickle


def load_profile(payload: bytes) -> object:
    return pickle.loads(payload)


uploaded_payload = b"untrusted bytes"
print(load_profile(uploaded_payload))
```

### 2.4 Why this difference matters

Pickle data can direct Python to execute code during loading, so decoding an uploaded payload can become remote code execution.

## 3. Boundaries and distinctions

Pickle may be acceptable for data kept entirely within a trusted, authenticated boundary, but it is not a safe interchange format.
