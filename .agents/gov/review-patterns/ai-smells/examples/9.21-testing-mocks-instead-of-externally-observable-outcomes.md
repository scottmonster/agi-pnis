# Testing mocks instead of externally observable outcomes

## 1. Catalog record

- **Catalog identifier:** 9.21
- **Evidence:** se
- **Definition:** Verifies that test doubles received expected calls while failing to establish the user-visible behavior.

## 2. Scenario

### 2.1 Context

Submitting a refund should reduce the displayed order balance and return a confirmation.

### 2.2 Safer approach

Submit a refund through the public endpoint and assert the response and persisted balance visible to the caller.

### 2.3 Failure mode

Assert only that a mocked payment gateway received `refund(orderId)`.

### 2.4 Why this difference matters

The call can occur with the wrong amount or without updating the customer-facing state, yet the test still passes.

## 3. Boundaries and distinctions

Mock interaction assertions help verify adapter behavior, but they should not substitute for outcome checks where users rely on the result.
