# Trap inheritance is option-dependent

## 1. Catalog record

- **Catalog identifier:** 8.4.1
- **Impact:** medium
- **Consensus:** high
- **Definition:** `ERR`, `DEBUG`, and `RETURN` traps are not uniformly inherited by functions, command substitutions, and subshells; options such as `errtrace` and `functrace` affect inheritance.

## 2. Example

### 2.1 Scenario

A script relies on an ERR trap to report failures inside helper functions.

### 2.2 Preferred form

```bash
set -E
trap 'printf "failure at line %s\n" "$LINENO" >&2' ERR

run_task() {
  false
}

run_task
```

### 2.3 Hazardous form

```bash
trap 'printf "failure at line %s\n" "$LINENO" >&2' ERR

run_task() {
  false
}

run_task
```

### 2.4 Why this difference matters

Without `errtrace`, an ERR trap set in the caller is not reliably inherited by functions. Diagnostic or cleanup behavior can vanish at an execution boundary.

## 3. Boundaries and distinctions

`set -E` addresses ERR trap inheritance, while `set -T` addresses DEBUG and RETURN traps. Trap behavior also has contexts where ERR is not triggered, so it is not a substitute for explicit error handling.
