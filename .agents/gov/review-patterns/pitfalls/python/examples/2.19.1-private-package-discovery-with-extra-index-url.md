# Private package discovery with `--extra-index-url`

## 1. Catalog record

- **Catalog identifier:** 2.19.1
- **Impact:** high
- **Consensus:** high
- **Definition:** Do not rely on `pip --extra-index-url` to securely combine a private package repository with a public index for uniquely named private packages.

## 2. Example

### 2.1 Scenario

A deployment installs an internal package that must not be substituted by a package from a public repository.

### 2.2 Preferred form

```python
from pathlib import Path


def requirements_file() -> str:
    return "--index-url https://packages.example.test/simple\ninternal-payroll==4.2.0\n"


Path("requirements.txt").write_text(requirements_file(), encoding="utf-8")
```

### 2.3 Hazardous form

```python
from pathlib import Path


def requirements_file() -> str:
    return (
        "--index-url https://pypi.org/simple\n"
        "--extra-index-url https://packages.example.test/simple\n"
        "internal-payroll\n"
    )


Path("requirements.txt").write_text(requirements_file(), encoding="utf-8")
```

### 2.4 Why this difference matters

An extra index is not a secure namespace boundary. A public distribution with the same name can participate in resolution and create dependency-confusion risk.

## 3. Boundaries and distinctions

Using multiple indexes can be acceptable when names, versions, provenance, and the resolver behavior are deliberately controlled for the threat model.
