# Chaining mutating methods that return `None`

## 1. Catalog record

- **Catalog identifier:** 16.12.1
- **Impact:** low
- **Consensus:** high
- **Definition:** Do not assume in-place mutators such as `list.sort()` return the modified object. Perform the mutation separately.

## 2. Example

### 2.1 Scenario

A report needs sorted scores before selecting the best score.

### 2.2 Preferred form

```python
def best_score(scores: list[int]) -> int:
    scores.sort()
    return scores[-1]


print(best_score([72, 91, 85]))
```

### 2.3 Hazardous form

```python
def best_score(scores: list[int]) -> int:
    return scores.sort()[-1]


print(best_score([72, 91, 85]))
```

### 2.4 Why this difference matters

`list.sort()` changes the list in place and returns `None`, so indexing its result raises a `TypeError` instead of returning a score.

## 3. Boundaries and distinctions

Use `sorted(scores)` when a separate sorted list is clearer or the original order must remain unchanged. Not every method that changes an object returns `None`, so consult its API contract.
