# Legacy `and/or` conditional expressions

## 1. Catalog record

- **Catalog identifier:** 16.5.1
- **Impact:** low
- **Consensus:** high
- **Definition:** Use `a if condition else b` rather than the historical `condition and a or b` idiom.

## 2. Example

### 2.1 Scenario

A display helper uses a supplied label when a user has permission, including an intentionally empty label.

### 2.2 Preferred form

```python
def display_label(can_view: bool, label: str) -> str:
    return label if can_view else "hidden"
```

### 2.3 Hazardous form

```python
def display_label(can_view: bool, label: str) -> str:
    return can_view and label or "hidden"
```

### 2.4 Why this difference matters

When `can_view` is true and `label` is an empty string, the hazardous expression returns `"hidden"`. The conditional expression always selects the intended branch.

## 3. Boundaries and distinctions

Boolean `and` and `or` remain appropriate for boolean logic and carefully chosen defaults. Use a conditional expression when selecting between values, especially if a branch can be falsey.
