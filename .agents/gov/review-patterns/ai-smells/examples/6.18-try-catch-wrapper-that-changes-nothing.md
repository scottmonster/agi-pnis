# Try/catch wrapper that changes nothing

## 1. Catalog record

- **Catalog identifier:** 6.18
- **Evidence:** se
- **Definition:** Catches an exception solely to rethrow it unchanged or destroy traceback context.

## 2. Scenario

### 2.1 Context

A file import function delegates parsing to a shared parser.

### 2.2 Safer approach

The agent either lets the parser error propagate with its traceback or adds meaningful import-specific context while preserving the cause.

### 2.3 Failure mode

It catches every parser error and raises a new identical-looking error without the original cause.

### 2.4 Why this difference matters

The wrapper adds code while making the original failure harder to diagnose.

## 3. Boundaries and distinctions

Translation is useful when it communicates a meaningful boundary or recovery action; a no-op wrapper does neither.
