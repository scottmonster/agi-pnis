# Iterator implementations must stop after `yield` returns false

## 1. Catalog record

- **Catalog identifier:** 11.2.1
- **Impact:** medium
- **Consensus:** high
- **Definition:** A push iterator must return when its `yield` callback returns false rather than continuing to call it.

## 2. Example

### 2.1 Scenario

An iterator yields rows from a small in-memory batch. A range consumer stops after the first row.

### 2.2 Preferred form

```go
package example

import "iter"

func rows(values []string) iter.Seq[string] {
	return func(yield func(string) bool) {
		for _, value := range values {
			if !yield(value) {
				return
			}
		}
	}
}

func preferred() string {
	for value := range rows([]string{"first", "second"}) {
		return value
	}
	return ""
}
```

### 2.3 Hazardous form

```go
package example

import "iter"

func rows(values []string) iter.Seq[string] {
	return func(yield func(string) bool) {
		for _, value := range values {
			yield(value) // calls yield again after the consumer stopped
		}
	}
}
```

### 2.4 Why this difference matters

Returning false is the consumer's stop signal. Continuing violates the iterator protocol and can trigger a runtime failure.

## 3. Boundaries and distinctions

This is specific to push iterators whose producer invokes `yield`. A producer that has naturally exhausted its input has no early-stop work to perform.
