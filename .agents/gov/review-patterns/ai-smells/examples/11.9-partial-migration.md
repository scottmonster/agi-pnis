# Partial migration

## 1. Catalog record

- **Catalog identifier:** 11.9
- **Evidence:** a/se
- **Definition:** Some callers/data paths use the new contract and others silently remain old.

## 2. Scenario

### 2.1 Context

A service changes from a `full_name` field to separate `given_name` and `family_name` fields.

### 2.2 Safer approach

The agent inventories API, import, background-job, and admin callers, updates them consistently, and tests each path.

### 2.3 Failure mode

The web form uses the new fields, but the CSV importer and nightly sync continue sending `full_name` without an explicit compatibility path.

### 2.4 Why this difference matters

Data handling varies by entry point and failures may remain hidden until a less-used workflow runs.

## 3. Boundaries and distinctions

Incremental migration can be safe when old callers are explicitly supported and tracked; silent mixed contracts are the risk.
