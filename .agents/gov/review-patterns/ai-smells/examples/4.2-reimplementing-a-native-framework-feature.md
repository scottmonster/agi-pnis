# Reimplementing a native framework feature

## 1. Catalog record

- **Catalog identifier:** 4.2
- **Evidence:** se
- **Definition:** Hand-written middleware, routing, validation, migration, authentication, scheduling, or caching replaces a built-in facility.

## 2. Scenario

### 2.1 Context

An agent adds request validation to a service built with a framework that already supports schema-based validation on route handlers.

### 2.2 Safer approach

It defines the route schema through the framework's validation feature and lets the framework produce consistent validation errors and API documentation.

### 2.3 Failure mode

It creates custom middleware that parses every request body, calls validators by route name, and assembles its own error responses.

### 2.4 Why this difference matters

The hand-written layer can drift from framework lifecycle behavior, error formatting, and future framework updates.

## 3. Boundaries and distinctions

A custom layer can be appropriate for requirements the framework cannot express. The failure is replacing an adequate built-in facility, not extending it for a real gap.
