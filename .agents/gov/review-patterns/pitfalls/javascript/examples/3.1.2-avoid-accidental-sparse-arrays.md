# Avoid accidental sparse arrays

## 1. Catalog record

- **Catalog identifier:** 3.1.2
- **Impact:** medium
- **Consensus:** high
- **Definition:** Distinguish an actual element whose value is `undefined` from a missing array slot. Avoid creating holes unless sparse-array semantics are intentional.

## 2. Example

### 2.1 Scenario

A form builder needs a three-item list whose entries may intentionally be unset.

### 2.2 Preferred form

```javascript
const fields = [undefined, undefined, undefined];
const visited = [];

fields.forEach((field, index) => visited.push(index));
console.log(visited); // [0, 1, 2]
```

### 2.3 Hazardous form

```javascript
const fields = new Array(3);
const visited = [];

fields.forEach((field, index) => visited.push(index));
console.log(visited); // []
```

### 2.4 Why this difference matters

The first array has elements whose values are `undefined`; the second has holes, which many iterative methods skip.

## 3. Boundaries and distinctions

Sparse arrays are valid when missing-slot behavior is intentional. Use them only when every consuming operation is chosen with their semantics in mind.
