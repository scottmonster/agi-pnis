# Handle lone surrogates before URI encoding when necessary

## 1. Catalog record

- **Catalog identifier:** 5.1.3
- **Impact:** medium
- **Consensus:** high
- **Definition:** Be aware that `encodeURI()` and `encodeURIComponent()` can throw on lone UTF-16 surrogates. `String.prototype.toWellFormed()` can normalize malformed UTF-16 when that behavior is appropriate.

## 2. Example

### 2.1 Scenario

A search page places arbitrary pasted text into a query parameter.

### 2.2 Preferred form

```javascript
function makeSearchUrl(query) {
  const wellFormedQuery = query.toWellFormed();
  return `/search?q=${encodeURIComponent(wellFormedQuery)}`;
}

console.log(makeSearchUrl("broken\uD800text"));
```

### 2.3 Hazardous form

```javascript
function makeSearchUrl(query) {
  return `/search?q=${encodeURIComponent(query)}`;
}

console.log(makeSearchUrl("broken\uD800text")); // URIError
```

### 2.4 Why this difference matters

A lone surrogate can turn ordinary URI construction into an exception path when input is not guaranteed to be well-formed UTF-16.

## 3. Boundaries and distinctions

Replacing malformed code units is suitable only when preserving the exact malformed input is unnecessary. Systems requiring lossless handling should reject or represent such input explicitly instead.
