# Class fields do not behave exactly like constructor assignments

## 1. Catalog record

- **Catalog identifier:** 2.1.1
- **Impact:** medium
- **Consensus:** high
- **Definition:** Verify inherited setter and accessor behavior before replacing constructor assignments with class fields.

## 2. Example

### 2.1 Scenario

A base class validates a `status` value through a setter.

### 2.2 Preferred form

```javascript
class Job {
  set status(value) {
    if (value !== "ready") throw new Error("invalid status");
    this._status = value;
  }
}

class ImportJob extends Job {
  constructor() {
    super();
    this.status = "ready";
  }
}
```

### 2.3 Hazardous form

```javascript
class Job {
  set status(value) {
    if (value !== "ready") throw new Error("invalid status");
    this._status = value;
  }
}

class ImportJob extends Job {
  status = "ready";
}
```

### 2.4 Why this difference matters

The field defines an own data property and bypasses the inherited setter, while the constructor assignment invokes validation.

## 3. Boundaries and distinctions

Class fields are suitable when an own data property is intentional and inherited accessor behavior is not needed.
