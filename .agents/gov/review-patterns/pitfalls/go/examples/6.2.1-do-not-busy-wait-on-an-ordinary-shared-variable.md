# Do not busy-wait on an ordinary shared variable

## 1. Catalog record

- **Catalog identifier:** 6.2.1
- **Impact:** medium
- **Consensus:** high
- **Definition:** A loop that repeatedly reads an unsynchronized variable waiting for another goroutine to change it is not valid synchronization. Use a channel, mutex, condition, or atomic operation.

## 2. Example

### 2.1 Scenario

A caller waits for a worker to finish initialization.

### 2.2 Preferred form

```go
package main

func initialize(done chan<- struct{}) { close(done) }
func main() { done := make(chan struct{}); go initialize(done); <-done }
```

### 2.3 Hazardous form

```go
package main

var ready bool
func initialize() { ready = true }
func main() { go initialize(); for !ready {} }
```

### 2.4 Why this difference matters

The loop races with the writer and wastes CPU. Closing the channel efficiently waits and synchronizes publication.

## 3. Boundaries and distinctions

Atomics can fit a carefully designed low-level state transition. Adding sleeps does not make an ordinary shared variable valid synchronization.
