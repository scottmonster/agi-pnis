# Mutable default arguments

## 1. Catalog record

- **Catalog identifier:** 1.1.1
- **Impact:** high
- **Consensus:** high
- **Definition:** Do not use mutable objects such as `[]` or `{}` as function defaults when a fresh object is intended. Defaults are evaluated once when the function is defined. Prefer `None` or another sentinel and create the object inside the function.

## 2. Example

### 2.1 Scenario

A request handler collects tags for each incoming request. Each call needs its own list.

### 2.2 Preferred form

```python
def add_tag(tag: str, tags: list[str] | None = None) -> list[str]:
    if tags is None:
        tags = []
    tags.append(tag)
    return tags


print(add_tag("new"))
print(add_tag("sale"))
```

### 2.3 Hazardous form

```python
def add_tag(tag: str, tags: list[str] = []) -> list[str]:
    tags.append(tag)
    return tags


print(add_tag("new"))
print(add_tag("sale"))
```

### 2.4 Why this difference matters

The hazardous default list is shared by every call, so one request's tags appear in a later request.

## 3. Boundaries and distinctions

An immutable default such as `None`, `0`, or a string is safe to share. A mutable default is appropriate only when intentional shared state is clearly part of the API.
