# Avoid catastrophic-backtracking regexes on untrusted input

## 1. Catalog record

- **Catalog identifier:** 5.1.6
- **Impact:** high
- **Consensus:** high
- **Definition:** Be cautious with ambiguous nested quantifiers, overlapping alternatives, and similar patterns when input size is attacker-controlled or otherwise unbounded. Test worst-case non-matches, not only successful examples.

## 2. Example

### 2.1 Scenario

An endpoint validates a large identifier received from an untrusted client.

### 2.2 Preferred form

```javascript
function isValidIdentifier(value) {
  return /^[a-z]+!$/u.test(value);
}

const requestValue = "a".repeat(20_000);
console.log(isValidIdentifier(requestValue)); // false
```

### 2.3 Hazardous form

```javascript
function isValidIdentifier(value) {
  return /^(a+)+!$/u.test(value);
}

const requestValue = "a".repeat(20_000);
console.log(isValidIdentifier(requestValue)); // can take an impractically long time
```

### 2.4 Why this difference matters

Nested ambiguous quantifiers can force exponential backtracking on a long non-match, allowing a client to tie up the JavaScript thread.

## 3. Boundaries and distinctions

Not every nested quantifier is unsafe. Assess the pattern's alternatives and worst-case inputs, especially where input length is unbounded or attacker-controlled.
