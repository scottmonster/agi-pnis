# Shell injection through `subprocess`

## 1. Catalog record

- **Catalog identifier:** 2.4.1
- **Impact:** high
- **Consensus:** high
- **Definition:** Prefer `subprocess` with `shell=False` and pass arguments as a sequence. Use `shell=True` only when shell behavior is actually required and carefully quote untrusted data.

## 2. Example

### 2.1 Scenario

A backup tool lists a directory chosen by an operator.

### 2.2 Preferred form

```python
import subprocess


def list_directory(directory: str) -> str:
    result = subprocess.run(
        ["ls", "--", directory],
        check=True,
        capture_output=True,
        text=True,
    )
    return result.stdout


print(list_directory("reports"))
```

### 2.3 Hazardous form

```python
import subprocess


def list_directory(directory: str) -> str:
    result = subprocess.run(
        f"ls {directory}",
        shell=True,
        check=True,
        capture_output=True,
        text=True,
    )
    return result.stdout


print(list_directory("reports"))
```

### 2.4 Why this difference matters

With `shell=True`, shell metacharacters in the directory value can change the command and execute unintended operations.

## 3. Boundaries and distinctions

Use `shell=True` only for genuine shell syntax. If a trusted command template needs an untrusted value, quote it for the target shell and keep the trust boundary explicit.
