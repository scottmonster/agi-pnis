# Non-standard NaN and Infinity in JSON

## 1. Catalog record

- **Catalog identifier:** 8.5.1
- **Impact:** medium
- **Consensus:** high
- **Definition:** Use `allow_nan=False` when output must conform strictly to the JSON specification.

## 2. Example

### 2.1 Scenario

An API serializes measurements for a client that requires strict JSON.

### 2.2 Preferred form

```python
import json

measurement = {"value": float("nan")}
try:
    json.dumps(measurement, allow_nan=False)
except ValueError:
    payload = json.dumps({"value": None})

assert payload == '{"value": null}'
```

### 2.3 Hazardous form

```python
import json

measurement = {"value": float("nan")}
payload = json.dumps(measurement)

assert payload == '{"value": NaN}'
```

### 2.4 Why this difference matters

Python's default output permits JavaScript-style `NaN` and infinity tokens, which strict JSON consumers can reject.

## 3. Boundaries and distinctions

The default may be suitable only when every consumer deliberately accepts Python's non-standard extension.
