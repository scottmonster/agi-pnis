# Installation commands unrelated to the task

## 1. Catalog record

- **Catalog identifier:** 8.18
- **Evidence:** se
- **Definition:** Installs packages or tools that the requested change neither needs nor uses.

## 2. Scenario

### 2.1 Context

An agent is asked to correct a validation message in an existing Python service. The repository already provides its test environment and the change needs no new library.

### 2.2 Safer approach

It reads the project setup instructions, uses the existing environment, edits the message and its test, then runs the relevant test command.

### 2.3 Failure mode

It installs a global formatter and several debugging packages before inspecting the code, despite not using them to implement or verify the requested message change.

### 2.4 Why this difference matters

Unrelated installation expands the execution surface, can modify the environment or dependency state, wastes time, and makes the work harder to reproduce or audit.

## 3. Boundaries and distinctions

Installing a documented prerequisite or a tool genuinely required to build, test, or implement the requested change is appropriate. The failure is adding software without a task-specific need, not using necessary project tooling.
