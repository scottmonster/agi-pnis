# Optional call does not prove a property is callable

## 1. Catalog record

- **Catalog identifier:** 1.1.22
- **Impact:** medium
- **Consensus:** high
- **Definition:** `obj.method?.()` suppresses the call only when the property is nullish. It still throws if the property exists but is not a function.

## 2. Example

### 2.1 Scenario

An integration may expose an optional completion callback from external configuration.

### 2.2 Preferred form

```javascript
function notify(integration, message) {
  if (typeof integration.onComplete === "function") {
    integration.onComplete(message);
  }
}

notify({ onComplete: "not a callback" }, "saved");
```

### 2.3 Hazardous form

```javascript
function notify(integration, message) {
  integration.onComplete?.(message);
}

notify({ onComplete: "not a callback" }, "saved");
```

### 2.4 Why this difference matters

Optional call skips only missing values. A present string is still invoked and throws because it is not callable.

## 3. Boundaries and distinctions

Optional call is concise when a present property is guaranteed to be a function. Validate callability when external data can supply other values.
