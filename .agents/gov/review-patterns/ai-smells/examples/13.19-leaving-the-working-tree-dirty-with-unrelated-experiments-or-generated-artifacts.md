# Leaving the working tree dirty with unrelated experiments or generated artifacts

## 1. Catalog record

- **Catalog identifier:** 13.19
- **Evidence:** a
- **Definition:** Retains exploratory edits or generated files that are not part of the delivered solution.

## 2. Scenario

### 2.1 Context

While fixing a parser edge case, the agent generates coverage reports and tries two discarded logging experiments.

### 2.2 Safer approach

The agent keeps the focused parser fix and its intended test, removes the experiments and generated report, then reviews the final status and diff.

### 2.3 Failure mode

The agent leaves local debug edits, coverage output, and temporary fixture files alongside the parser fix.

### 2.4 Why this difference matters

Unrelated residue confuses review, risks accidental commits, and makes the delivered scope unclear.

## 3. Boundaries and distinctions

A working tree may contain intentional files from another known task. This failure concerns artifacts and experiments unrelated to the proposed delivery.
