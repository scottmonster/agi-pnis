# Hardcoded secret/password/token/API key

## 1. Catalog record

- **Catalog identifier:** 10.1
- **Evidence:** e
- **Definition:** Places a credential directly in code where it can be disclosed through source access, builds, logs, or artifacts.

## 2. Scenario

### 2.1 Context

A service needs credentials for its production payment provider.

### 2.2 Safer approach

Read the credential from the approved secret store at runtime, grant it only to the service identity, and keep it out of source and test output.

### 2.3 Failure mode

The agent adds the production API key as a string constant in the payment client so the integration works locally.

### 2.4 Why this difference matters

The key can spread through commits, builds, review tools, and deployment artifacts, requiring rotation and risking unauthorized use.

## 3. Boundaries and distinctions

This concerns real credentials. A clearly nonfunctional placeholder or test fixture is different, provided it cannot authenticate anywhere.
