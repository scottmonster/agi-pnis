# Promise.finally can replace the original failure

## 1. Catalog record

- **Catalog identifier:** 7.1.11
- **Impact:** medium
- **Consensus:** high
- **Definition:** Use `.finally()` for cleanup that should normally preserve the prior outcome. If the callback throws or returns a rejected promise, that new failure becomes the chain's rejection.

## 2. Example

### 2.1 Scenario

A database operation must release a connection while preserving its original success or failure.

### 2.2 Preferred form

```javascript
function release(connection) {
  connection.released = true;
}

const connection = { released: false };
Promise.reject(new Error("query failed"))
  .finally(() => release(connection))
  .catch((error) => console.error(error.message));
```

### 2.3 Hazardous form

```javascript
function release() {
  throw new Error("release failed");
}

Promise.reject(new Error("query failed"))
  .finally(() => release())
  .catch((error) => console.error(error.message));
```

### 2.4 Why this difference matters

The thrown cleanup error replaces the original query failure, obscuring the more relevant cause.

## 3. Boundaries and distinctions

Cleanup may intentionally replace the prior outcome, but that policy should be explicit because finally does not automatically preserve it after a throw or rejection.
