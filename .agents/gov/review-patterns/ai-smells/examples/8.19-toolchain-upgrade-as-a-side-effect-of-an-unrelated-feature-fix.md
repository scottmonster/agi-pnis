# Toolchain upgrade as a side effect of an unrelated feature/fix

## 1. Catalog record

- **Catalog identifier:** 8.19
- **Evidence:** se
- **Definition:** Changes compiler, runtime, or build-tool versions without a requirement that justifies the compatibility risk.

## 2. Scenario

### 2.1 Context

An agent is asked to fix an off-by-one error in a TypeScript pagination helper. The repository’s CI image, Node version, and TypeScript version are already supported and the bug is independent of them.

### 2.2 Safer approach

It fixes the boundary condition, adds a regression test, and runs the project’s existing test and type-check commands with the pinned toolchain.

### 2.3 Failure mode

It upgrades Node, TypeScript, and the CI action while changing the pagination helper, without evidence that any upgrade is needed for the fix.

### 2.4 Why this difference matters

The small bug fix now carries compatibility, generated-output, and CI behavior changes that are difficult to isolate, test, and roll back.

## 3. Boundaries and distinctions

A toolchain upgrade is appropriate when the requested feature, security requirement, or supported-platform policy requires it, preferably as an explicitly reviewed change. This failure is an unjustified side effect of unrelated work.
