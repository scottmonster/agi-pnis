# DI container in a small application

## 1. Catalog record

- **Catalog identifier:** 3.11
- **Evidence:** se
- **Definition:** Framework-driven dependency wiring replaces three or four explicit constructor calls.

## 2. Scenario

### 2.1 Context

A command-line app wires a reader, service, and writer at startup.

### 2.2 Safer approach

Construct the three dependencies explicitly in the composition root.

### 2.3 Failure mode

Add a DI container, registration module, lifecycle declarations, and runtime resolution for the same objects.

### 2.4 Why this difference matters

Dependency relationships become less visible and startup failures move from direct code to container configuration.

## 3. Boundaries and distinctions

A container may pay off in a large application with complex lifetimes; explicit wiring is often clearer for a small fixed graph.
