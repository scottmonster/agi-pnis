# Command substitution removes trailing newlines

## 1. Catalog record

- **Catalog identifier:** 4.5.1
- **Impact:** medium
- **Consensus:** high
- **Definition:** Do not use ordinary command substitution when final newline characters are significant.

## 2. Example

### 2.1 Scenario

A report generator must retain its final blank lines exactly when writing an archive artifact.

### 2.2 Preferred form

```bash
#!/usr/bin/env bash

generate_report() {
  printf 'summary\n\n'
}

archive_file=report.txt
generate_report >"$archive_file"
```

### 2.3 Hazardous form

```bash
#!/usr/bin/env bash

generate_report() {
  printf 'summary\n\n'
}

report=$(generate_report)
printf '%s' "$report" >report.txt
```

### 2.4 Why this difference matters

Command substitution removes all trailing newline characters. Writing the generator's output directly preserves the stream instead of silently changing the artifact.

## 3. Boundaries and distinctions

Command substitution is suitable when trailing newlines do not carry meaning. Shell variables also cannot represent NUL bytes, so use files or file descriptors for arbitrary byte streams.
