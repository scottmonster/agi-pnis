# Uninitialized variable/state

## 1. Catalog record

- **Catalog identifier:** 6.8
- **Evidence:** e
- **Definition:** Reads or depends on a value before it has been assigned a valid initial state.

## 2. Scenario

### 2.1 Context

A parser accumulates the first validation error while scanning records.

### 2.2 Safer approach

The agent initializes `first_error` to `None` and checks it after the loop.

### 2.3 Failure mode

It reads `first_error` after an all-valid input even though no assignment occurred.

### 2.4 Why this difference matters

Successful inputs can fail because the state required by the final branch was never established.

## 3. Boundaries and distinctions

The issue is initialization order, not a declared variable having an incompatible value type.
