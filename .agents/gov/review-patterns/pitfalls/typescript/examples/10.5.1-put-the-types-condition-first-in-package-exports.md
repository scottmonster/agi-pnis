# Put the `"types"` condition first in package exports

## 1. Catalog record

- **Catalog identifier:** 10.5.1
- **Impact:** medium
- **Consensus:** high
- **Definition:** When publishing conditional package exports with dedicated declaration paths, place the `"types"` condition before runtime conditions.

## 2. Example

### 2.1 Scenario

A dual-format library publishes separate ESM, CommonJS, and declaration entrypoints.

### 2.2 Preferred form

```typescript
const packageJson = {
  exports: {
    ".": {
      types: "./dist/index.d.ts",
      import: "./dist/index.js",
      require: "./dist/index.cjs",
    },
  },
} as const;

export default packageJson;
```

### 2.3 Hazardous form

```typescript
const packageJson = {
  exports: {
    ".": {
      import: "./dist/index.js",
      require: "./dist/index.cjs",
      types: "./dist/index.d.ts",
    },
  },
} as const;

export default packageJson;
```

### 2.4 Why this difference matters

Conditional exports are examined in object order. If a runtime branch wins before the declaration branch is considered, TypeScript can resolve the wrong target or fail to locate the intended declarations.

## 3. Boundaries and distinctions

The ordering requirement matters when a package uses a dedicated `"types"` condition. A package with one unconditioned declaration path should use the package layout that its supported resolution modes expect.
