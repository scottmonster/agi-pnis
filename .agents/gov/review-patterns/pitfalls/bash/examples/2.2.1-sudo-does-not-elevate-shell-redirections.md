# `sudo` does not elevate shell redirections

## 1. Catalog record

- **Catalog identifier:** 2.2.1
- **Impact:** high
- **Consensus:** high
- **Definition:** `sudo command > privileged-file` runs `command` through `sudo`, but the invoking shell performs `> privileged-file`. Use an appropriate privileged writer such as `sudo tee` or explicitly run the required shell operation under the elevated context.

## 2. Example

### 2.1 Scenario

An administrator needs to install one line into a root-owned configuration file from an unprivileged interactive shell.

### 2.2 Preferred form

```bash
#!/usr/bin/env bash
set -euo pipefail

setting='enabled=true'
printf '%s\n' "$setting" | sudo tee /etc/example-service.conf > /dev/null
```

### 2.3 Hazardous form

```bash
#!/usr/bin/env bash
set -euo pipefail

setting='enabled=true'
sudo printf '%s\n' "$setting" > /etc/example-service.conf
```

### 2.4 Why this difference matters

In the hazardous form, the current shell tries to open `/etc/example-service.conf` before `sudo` starts `printf`. The shell therefore receives a permission error even though the command itself would run as root.

## 3. Boundaries and distinctions

`sudo tee` is useful for simple stream writes. For compound privileged shell operations, run a carefully quoted script or command under the elevated shell context instead.
