# Use `IFS= read -r` for literal text lines

## 1. Catalog record

- **Catalog identifier:** 2.10.1
- **Impact:** high
- **Consensus:** high
- **Definition:** For line-oriented input where whitespace and backslashes are data, use `while IFS= read -r line; do ...; done`.

## 2. Example

### 2.1 Scenario

A script copies a text manifest whose entries may begin with spaces or contain literal backslashes.

### 2.2 Preferred form

```bash
#!/usr/bin/env bash
set -euo pipefail

while IFS= read -r line; do
  printf '%s\n' "$line"
done < manifest.txt
```

### 2.3 Hazardous form

```bash
#!/usr/bin/env bash
set -euo pipefail

while read line; do
  printf '%s\n' "$line"
done < manifest.txt
```

### 2.4 Why this difference matters

Default `read` uses `IFS` processing and treats backslashes specially, so the hazardous loop can strip meaningful leading or trailing whitespace and alter backslashes. `IFS= read -r` preserves each text line as data.

## 3. Boundaries and distinctions

Deliberate field parsing may require a chosen `IFS` or another parser. This idiom is for reading whole literal text lines, not for parsing CSV or arbitrary binary records.
