# Excessive fragmentation

## 1. Catalog record

- **Catalog identifier:** 5.7
- **Evidence:** e
- **Definition:** Straightforward logic is split across tiny classes/functions/files that must all be followed to understand one operation.

## 2. Scenario

### 2.1 Context

Saving a profile requires following `NormalizeName`, `BuildProfile`, `PersistProfile`, and `ReturnProfile` classes, each with one trivial method.

### 2.2 Safer approach

Keep closely related, simple steps together while extracting only meaningful independent behavior.

### 2.3 Failure mode

Turn a two-line normalization into another file and one-method class to make the code look more modular.

### 2.4 Why this difference matters

Readers spend more effort navigating indirection than understanding the operation.

## 3. Boundaries and distinctions

Extraction is useful for reusable or independently complex behavior. It is excessive when trivial steps must be chased across files solely to follow one flow.
