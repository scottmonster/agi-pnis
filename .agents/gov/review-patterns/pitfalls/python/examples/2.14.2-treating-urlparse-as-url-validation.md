# Treating `urlparse()` as URL validation

## 1. Catalog record

- **Catalog identifier:** 2.14.2
- **Impact:** high
- **Consensus:** high
- **Definition:** Treat `urlparse()` and `urlsplit()` as parsers rather than validators. Perform explicit scheme, hostname, port, and other policy checks before using parsed values for security decisions.

## 2. Example

### 2.1 Scenario

An HTTP client must fetch only HTTPS URLs for hosts in an approved domain.

### 2.2 Preferred form

```python
from urllib.parse import urlsplit


def approved_url(value: str) -> str:
    parts = urlsplit(value)
    if parts.scheme != "https" or parts.hostname != "api.example.test":
        raise ValueError("unapproved URL")
    if parts.port not in (None, 443):
        raise ValueError("unapproved port")
    return value
```

### 2.3 Hazardous form

```python
from urllib.parse import urlsplit


def approved_url(value: str) -> str:
    urlsplit(value)
    return value
```

### 2.4 Why this difference matters

Parsing succeeds for many inputs that do not meet an application's security policy. Explicit checks enforce the intended destination constraints.

## 3. Boundaries and distinctions

Validation criteria are application-specific. A parser is still useful as the first step before applying the relevant policy checks.
