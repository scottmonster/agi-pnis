# Prefer Web Storage methods over property syntax

## 1. Catalog record

- **Catalog identifier:** 10.1.12
- **Impact:** medium
- **Consensus:** high
- **Definition:** Use storage getItem, setItem, and removeItem methods rather than property syntax.

## 2. Example

### 2.1 Scenario

A settings page persists the selected color theme in local storage.

### 2.2 Preferred form

```javascript
function saveTheme(theme) {
  localStorage.setItem("theme", theme);
}

function clearTheme() {
  localStorage.removeItem("theme");
}

saveTheme("dark");
console.log(localStorage.getItem("theme")); // dark
```

### 2.3 Hazardous form

```javascript
function saveTheme(theme) {
  localStorage.theme = theme;
}

function clearTheme() {
  delete localStorage.theme;
}

saveTheme("dark");
console.log(localStorage.theme); // dark
```

### 2.4 Why this difference matters

Property syntax can collide with Storage object members and obscures the storage API’s key-value operations, making unusual keys and maintenance behavior less clear.

## 3. Boundaries and distinctions

Property access can work for simple keys in many browsers, but the named Web Storage methods are the defined, unambiguous interface for persisted entries.
