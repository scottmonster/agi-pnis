# Check runtime support when using explicit resource management

## 1. Catalog record

- **Catalog identifier:** 11.4.1
- **Impact:** low
- **Consensus:** high
- **Definition:** When using `using`, `await using`, `DisposableStack`, or related facilities against older runtimes, configure the appropriate libraries and provide the required runtime support or polyfills.

## 2. Example

### 2.1 Scenario

An application deploys `using` to a runtime where disposal support is not otherwise guaranteed.

### 2.2 Preferred form

```typescript
// tsconfig.json includes "lib": ["ES2022", "ESNext.Disposable"].
// The application also loads a Symbol.dispose polyfill before this module.
class FileHandle implements Disposable {
  [Symbol.dispose](): void {
    console.log('closed');
  }
}

export function readConfig(): void {
  using file = new FileHandle();
  console.log('read');
}
```

### 2.3 Hazardous form

```typescript
class FileHandle implements Disposable {
  [Symbol.dispose](): void {
    console.log('closed');
  }
}

export function readConfig(): void {
  using file = new FileHandle();
  console.log('read');
}

// On an older runtime without Symbol.dispose or compatible helpers, disposal
// fails despite TypeScript accepting the source.
```

### 2.4 Why this difference matters

TypeScript can typecheck or downlevel parts of the feature, but runtime disposal symbols and supporting objects must actually exist.

## 3. Boundaries and distinctions

Apply this guidance in the conditions described by the catalog record. Deliberate exceptions need a documented runtime guarantee, compatible toolchain behavior, or an explicit local unsafe boundary.
