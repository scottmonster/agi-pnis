# Capture `PIPESTATUS` immediately

## 1. Catalog record

- **Catalog identifier:** 5.5.1
- **Impact:** medium
- **Consensus:** high
- **Definition:** Bash's `PIPESTATUS` array describes the most recently executed foreground pipeline. Copy it before running another command or pipeline.

## 2. Example

### 2.1 Scenario

A conversion job needs to distinguish input failure from output failure in a two-stage pipeline.

### 2.2 Preferred form

```bash
input=${1:?provide an input file}
output=${2:?provide an output file}

gzip -dc -- "$input" | sed 's/error/warning/g' >"$output"
statuses=("${PIPESTATUS[@]}")

if (( statuses[0] != 0 || statuses[1] != 0 )); then
  printf 'conversion failed: gzip=%d sed=%d\n' "${statuses[0]}" "${statuses[1]}" >&2
  exit 1
fi
```

### 2.3 Hazardous form

```bash
input=${1:?provide an input file}
output=${2:?provide an output file}

gzip -dc -- "$input" | sed 's/error/warning/g' >"$output"
printf 'conversion finished\n' >&2
statuses=("${PIPESTATUS[@]}")

printf 'recorded status: %d\n' "${statuses[0]}"
```

### 2.4 Why this difference matters

`printf` replaces the pipeline as the most recent foreground command, so the hazardous form records `printf` status rather than the statuses of `gzip` and `sed`.

## 3. Boundaries and distinctions

`pipefail` can make the pipeline's aggregate status more useful, but it does not preserve per-stage diagnostics. Copy `PIPESTATUS` when those individual statuses matter.
