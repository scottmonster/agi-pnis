# Control command lookup in security-sensitive scripts

## 1. Catalog record

- **Catalog identifier:** 3.11.1
- **Impact:** high
- **Consensus:** high
- **Definition:** Use a trusted `PATH` or explicit executable paths for security-sensitive command execution.

## 2. Example

### 2.1 Scenario

A privileged maintenance script must invoke standard system utilities.

### 2.2 Preferred form

```bash
#!/usr/bin/env bash
PATH='/usr/bin:/bin'
export PATH

/usr/bin/id
/bin/mkdir -p /var/tmp/maintenance-output
```

### 2.3 Hazardous form

```bash
#!/usr/bin/env bash
PATH='/tmp/user-tools:/usr/bin:/bin'
export PATH

id
mkdir -p /var/tmp/maintenance-output
```

### 2.4 Why this difference matters

Commands without slashes are found through `PATH`, so an earlier hostile directory can substitute a different executable under the script's authority.

## 3. Boundaries and distinctions

An inherited `PATH` can be practical for ordinary user scripts, but it is not an appropriate trust boundary for privileged execution.
