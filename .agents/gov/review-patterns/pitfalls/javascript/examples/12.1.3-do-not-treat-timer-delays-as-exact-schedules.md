# Do not treat timer delays as exact schedules

## 1. Catalog record

- **Catalog identifier:** 12.1.3
- **Impact:** medium
- **Consensus:** high
- **Definition:** Do not treat timeout or interval delays as exact execution deadlines.

## 2. Example

### 2.1 Scenario

A browser client shows a countdown until a reservation expires one minute after it is created.

### 2.2 Preferred form

```javascript
const expiresAt = Date.now() + 60_000;
const countdown = document.querySelector(".countdown");

function updateCountdown() {
  const remainingMs = Math.max(0, expiresAt - Date.now());
  countdown.textContent = String(Math.ceil(remainingMs / 1_000));
  if (remainingMs > 0) setTimeout(updateCountdown, 250);
}

updateCountdown();
```

### 2.3 Hazardous form

```javascript
let remainingSeconds = 60;
const countdown = document.querySelector(".countdown");

const timer = setInterval(() => {
  remainingSeconds -= 1;
  countdown.textContent = String(remainingSeconds);
  if (remainingSeconds === 0) clearInterval(timer);
}, 1_000);
```

### 2.4 Why this difference matters

Timer callbacks can be delayed by event-loop work or browser throttling, so decrementing once per callback can display an expiration time that has already passed.

## 3. Boundaries and distinctions

Timers remain useful for requesting future work, but their delay is not a real-time guarantee. Enforce an actual reservation deadline on the server or another authoritative clock when correctness or security depends on it.
