# Overly complex build logic

## 1. Catalog record

- **Catalog identifier:** 8.15
- **Evidence:** e
- **Definition:** Uses intricate scripts, conditionals, or custom steps where a simpler declarative build would be clearer and more reliable.

## 2. Scenario

### 2.1 Context

An agent needs the build to compile TypeScript, copy static assets, and package the resulting application.

### 2.2 Safer approach

It uses the repository's standard package scripts and the bundler's declarative asset-copy configuration, with one command that CI and local developers can run.

### 2.3 Failure mode

It writes a custom shell script with nested operating-system checks, manual directory traversal, temporary-file cleanup, and several conditionally invoked tools for the same three build stages.

### 2.4 Why this difference matters

The script becomes difficult to review, debug, and run consistently, while each conditional path creates another opportunity for platform-specific breakage.

## 3. Boundaries and distinctions

Custom build steps are appropriate when declarative tooling cannot express a real project requirement. This failure is complexity without that requirement, not the presence of any custom build logic.
