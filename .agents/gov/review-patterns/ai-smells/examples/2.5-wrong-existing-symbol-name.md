# Wrong existing symbol name

## 1. Catalog record

- **Catalog identifier:** 2.5
- **Evidence:** e
- **Definition:** Calls something close to the real project function but not the actual function.

## 2. Scenario

### 2.1 Context

The repository exports `validatePurchase` from its order validation module.

### 2.2 Safer approach

The agent follows the module export and calls `validatePurchase(order)`.

### 2.3 Failure mode

It calls `validateOrder(order)` because that name seems more natural.

### 2.4 Why this difference matters

Near matches can evade casual review while still causing an unresolved import or an unintended call.

## 3. Boundaries and distinctions

This concerns choosing the wrong name for functionality that exists nearby, rather than creating a wholly invented local concept.
