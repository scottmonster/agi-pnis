# Use literal unions for closed value sets

## 1. Catalog record

- **Catalog identifier:** 6.12.1
- **Impact:** medium
- **Consensus:** high
- **Definition:** Prefer `"open" | "closed"` over plain `string` when the actual domain contains a known finite set of string values.

## 2. Example

### 2.1 Scenario

An order workflow accepts only the states it can actually process.

### 2.2 Preferred form

```typescript
type OrderStatus = 'draft' | 'paid' | 'shipped';

function nextAction(status: OrderStatus): string {
  switch (status) {
    case 'draft': return 'request payment';
    case 'paid': return 'ship order';
    case 'shipped': return 'send tracking update';
  }
}

console.log(nextAction('paid'));
```

### 2.3 Hazardous form

```typescript
function nextAction(status: string): string {
  if (status === 'draft') return 'request payment';
  if (status === 'paid') return 'ship order';
  if (status === 'shipped') return 'send tracking update';
  return `unknown workflow state: ${status}`;
}

console.log(nextAction('accidentally-approved'));
```

### 2.4 Why this difference matters

The type then rejects invalid states and improves narrowing, autocomplete, and exhaustive handling.

## 3. Boundaries and distinctions

Apply this guidance in the conditions described by the catalog record. Deliberate exceptions need a documented runtime guarantee, compatible toolchain behavior, or an explicit local unsafe boundary.
