# Prefer top-level `import type` when every imported binding is type-only

## 1. Catalog record

- **Catalog identifier:** 7.4.1
- **Impact:** medium
- **Consensus:** high
- **Definition:** Under `verbatimModuleSyntax`, prefer `import type { A, B } from "mod"` over `import { type A, type B } from "mod"` when there are no runtime bindings.

## 2. Example

### 2.1 Scenario

A route handler needs only the `RequestContext` and `RouteResult` types from a sibling routing module. Loading that module runs an unrelated registration side effect.

### 2.2 Preferred form

```typescript
// src/handler.ts
import type { RequestContext, RouteResult } from './routing.js';

export function handle(context: RequestContext): RouteResult {
  return { status: 200, body: context.requestId };
}

// The entire import is erased from emitted JavaScript.
```

### 2.3 Hazardous form

```typescript
// src/handler.ts
import { type RequestContext, type RouteResult } from './routing.js';

export function handle(context: RequestContext): RouteResult {
  return { status: 200, body: context.requestId };
}

// With verbatimModuleSyntax, this can emit `import {} from './routing.js'`.

// src/routing.ts
console.log('registering development routes'); // Unwanted runtime side effect.
export interface RequestContext { requestId: string; }
export interface RouteResult { status: number; body: string; }
```

### 2.4 Why this difference matters

`import type` declares that the entire statement is compile-time only and has no runtime module-loading role. Under `verbatimModuleSyntax`, an all-inline-type import can instead emit an empty import, which still evaluates the module. That can unexpectedly run module initialization despite the handler using no runtime binding.

## 3. Boundaries and distinctions

Use inline `type` specifiers when a statement deliberately imports both values and types, such as `import { createRouter, type RouteResult } from './routing.js'`. This is a readability convention, not a substitute for verifying emitted JavaScript or the runtime module graph. With `verbatimModuleSyntax`, retain correct runtime extensions for every value import.
