# Predictable randomness where security requires unpredictability

## 1. Catalog record

- **Catalog identifier:** 10.14
- **Evidence:** e
- **Definition:** Uses a guessable random source for secrets, tokens, nonces, or other security-sensitive values.

## 2. Scenario

### 2.1 Context

A password-reset endpoint creates a one-time link token.

### 2.2 Safer approach

Generate sufficient token material with the platform’s cryptographically secure random source, store a verifier, and expire it promptly.

### 2.3 Failure mode

The agent uses the ordinary pseudo-random generator because it is already imported for UI sampling.

### 2.4 Why this difference matters

An attacker who can predict the generator may guess another user’s reset token.

## 3. Boundaries and distinctions

Ordinary pseudo-randomness is often suitable for simulations, shuffling, or display variation. Security-sensitive values require unpredictability.
