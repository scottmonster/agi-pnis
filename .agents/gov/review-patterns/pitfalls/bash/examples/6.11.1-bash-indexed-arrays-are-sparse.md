# Bash indexed arrays are sparse

## 1. Catalog record

- **Catalog identifier:** 6.11.1
- **Impact:** medium
- **Consensus:** high
- **Definition:** `${#array[@]}` is the number of assigned elements, not necessarily one more than the largest index. Iterate `"${!array[@]}"` when actual indices matter.

## 2. Example

### 2.1 Scenario

A script reports every explicitly assigned build slot.

### 2.2 Preferred form

```bash
#!/usr/bin/env bash
declare -a slots=([0]=linux [3]=macos)
for index in "${!slots[@]}"; do echo "slot $index: ${slots[index]}"; done
```

### 2.3 Hazardous form

```bash
#!/usr/bin/env bash
declare -a slots=([0]=linux [3]=macos)
for ((index = 0; index < ${#slots[@]}; index++)); do echo "slot $index: ${slots[index]}"; done
```

### 2.4 Why this difference matters

The count is two, so the hazardous loop misses assigned index three and assumes a dense array.

## 3. Boundaries and distinctions

Dense arrays controlled internally may be iterated by count. Use actual indexes when deletions or explicit high indexes are possible.
