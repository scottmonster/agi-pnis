# `maps.Clone` is shallow

## 1. Catalog record

- **Catalog identifier:** 7.10.1
- **Impact:** medium
- **Consensus:** high
- **Definition:** `maps.Clone` creates an independent map structure but copies keys and values using assignment. Nested slices, maps, pointers, and other reference-bearing values remain shared.

## 2. Example

### 2.1 Scenario

A request needs an editable copy of a user's nested labels.

### 2.2 Preferred form

```go
package profile

import "maps"

func copyLabels(source map[string][]string) map[string][]string {
	result := maps.Clone(source)
	for key, labels := range result {
		result[key] = append([]string(nil), labels...)
	}
	return result
}
```

### 2.3 Hazardous form

```go
package profile

import "maps"

func appendLabel(source map[string][]string) {
	copy := maps.Clone(source)
	copy["role"][0] = "admin" // Also changes source["role"][0].
}
```

### 2.4 Why this difference matters

The cloned map has independent keys, but its slice values still reference the same backing arrays.

## 3. Boundaries and distinctions

`maps.Clone` is sufficient when values are immutable or assignment-copyable without shared mutable state.
