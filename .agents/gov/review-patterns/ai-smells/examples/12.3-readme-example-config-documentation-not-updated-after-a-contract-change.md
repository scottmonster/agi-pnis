# README/example/config documentation not updated after a contract change

## 1. Catalog record

- **Catalog identifier:** 12.3
- **Evidence:** se
- **Definition:** Leaves users with stale instructions, examples, or configuration details after behavior changes.

## 2. Scenario

### 2.1 Context

The service changes its required `PORT` configuration key to `HTTP_PORT`, and deployment code is updated, but the README still instructs users to set `PORT`.

### 2.2 Safer approach

Treat the README setup command and sample configuration as contract consumers, update them in the same change, and verify the documented setup works.

### 2.3 Failure mode

Merge the contract change with only code and deployment edits, leaving the old setup instructions untouched.

### 2.4 Why this difference matters

New deployments follow the stale instructions and fail or start with an unintended configuration even though the code change itself is valid.

## 3. Boundaries and distinctions

This requires an implemented contract that changed. It differs from inventing a configuration key that never existed at all.
